## Intent
Settle the pixel-scaling recipe by a landed story before the rest of the web is quoted (D5, §10): a first `apps/studio-web` that draws a pixel floor and one character on a PixiJS v8 canvas, crisp at device pixel ratio 1, 2 and 3 on desktop and iPad, as a nested studio project the host verify leg builds and tests. Nothing in `apps/supervisor` changes; the record in `kb/` quotes the rest of the epic.

## Acceptance Criteria
- AC1: **Given** the one repository, **when** the story lands, **then** `apps/studio-web` exists as a Vite plus React plus TypeScript project (its own `package.json`, `bun install --frozen-lockfile`, `bun run build` to `apps/studio-web/dist`, `bun run test` with vitest), it is a nested studio project like `apps/supervisor` (its own `.tk-studio/config.yaml`, `verify.host` naming its build and tests), the repository's `tools/verify_host.py` runs its build and tests when `apps/studio-web` changed, and nothing in `apps/supervisor` changes yet.
- AC2: **Given** a browser at device pixel ratio 1, 2 or 3 (desktop and iPad Safari), **when** the spike's page opens, **then** one PixiJS v8 `Application` fills its container with `resolution` from the device pixel ratio, nearest-neighbour scaling (`TextureSource.scaleMode = "nearest"`), an integer zoom chosen from the ratio and the container's size so a 16-pixel tile renders as a whole number of device pixels, a floor of tiles and one character sprite from a committed placeholder sheet (`apps/studio-web/public/sprites/placeholder.png`, our own pixels, D6) stand on the canvas with crisp edges, and a React DOM HUD over the canvas shows the zoom, the ratio and the frame rate; the recipe is one exported function (`pickZoom(ratio, width, height, tile)`) with unit tests for the three ratios and three container sizes.
- AC3: **Given** the spike landed, **when** the story closes, **then** `kb/studio-web-renderer-spike.md` records the recipe, what each ratio showed on the desktop monitor and the iPad (the operator's attended check, named as such when not yet done), the frame cost of the canvas idle, and the quote for the rest of the epic by analogy with EP-29's per-story price; the design spec's README §6.3 gains one line pointing at the record.

## Code Map
- `apps/supervisor/` — the nested-project pattern to copy, not touch (AC1 forbids a change there): `package.json` (`"type": "module"`, scripts `test`, `typecheck`; devDependency `typescript ^5.6`), `tsconfig.json` (`moduleResolution: bundler`, `strict`, `noEmit`), `bun.lock` (committed; `--frozen-lockfile` needs one), `.gitignore` (node_modules, `*.tsbuildinfo`, `.env*`, `.bmad-loop/runs|cache|policy.toml|routing.current.json`, `_bmad/render/`), `.tk-studio/config.yaml` (`project_id`, `vcs: git`, `planning.backend: bmad-files`, `verify.host` as ONE argv line, never a shell, see `apps/supervisor/src/hostverify.ts:75-115`).
- The nearest-root rule (`plugins/tk-studio/lib/config.py:28`, contract 0.1.22 §1): a folder holding `.tk-studio/config.yaml` is a studio root; `apps/studio-web/.tk-studio/config.yaml` with `project_id: studio-web` makes it one. No registry write, no `jobs/`, no `plan-counter.yaml`: the supervisor's extras are its own job definitions, not the pattern.
- Root `.gitignore:16-32` mirrors `apps/supervisor/.gitignore` with `apps/supervisor/**/` prefixes (git honours both). Add the same for `apps/studio-web` plus `apps/studio-web/dist/`: the build output is never committed (the release motion builds it from the tag, `tools/release_archive.py:86` already maps `studio-web` to `apps/studio-web/dist`), and an unignored `dist` would dirty the tree after the verify gate and break the engine's commit.
- `tools/verify_host.py` — argv-only gates in `GATES` (lib suite, conformance), `run_gate`, `main`. Add a third gate `("studio-web", ROOT / "apps" / "studio-web", ["bun", "run", "verify"])` run only when `apps/studio-web` changed: `git diff --name-only <base> -- apps/studio-web` with `<base>` = `git merge-base HEAD main` (fall back to `origin/main`; when neither resolves or git fails, run the gate anyway, never skip silently); print the skip with its reason the way the gates print their verdict; `verify_host: ok (...)` names the gates that ran. `bun` is on the agent PC's host PATH (the supervisor's own `verify.host` is `bun test`). No existing unit test covers this script; keep the predicate in one small function.
- `apps/studio-web/.tk-studio/config.yaml` `verify.host: bun run verify` where `package.json` scripts carry `"build": "vite build"`, `"test": "vitest run"`, `"verify": "bun run build && bun run test"` (a package script may use `&&`; `verify.host` may not).
- Renderer: `pixi.js` v8 (`Application.init({resizeTo: container, resolution: devicePixelRatio, autoDensity: true, antialias: false})`; `TextureSource.defaultOptions.scaleMode = "nearest"` or per-texture `scaleMode: "nearest"`; `Assets.load` the sheet; `Sprite`/`TilingSprite` for the floor). Export pure functions from `src/renderer/`: `pickZoom(ratio, width, height, tile)` (integer ≥ 1 such that `tile * zoom` device pixels divides evenly: zoom = max(1, floor(min(width, height) * ratio / (tile * N))) for a target of N visible tiles, documented in the record), and scene builders (`createApp`, `drawFloor`, `placeCharacter`) so later stories' tests drive the scene without WebGL (30.4's rule). Keep the Pixi import out of `pickZoom.ts` so vitest runs it with no DOM.
- HUD: `src/App.tsx` React DOM over the canvas: zoom, ratio, frame rate (`app.ticker.FPS`, sampled each second).
- Placeholder sheet: our own pixels (D6). Generate it with a committed script (`apps/studio-web/scripts/make-placeholder.ts`, writes `public/sprites/placeholder.png`: a 16×16 floor tile and one 16×16 (or 16×32) character, flat colours, no anti-aliasing) so provenance is in the repository; 30.7 deletes the sheet.
- vitest: `pickZoom.test.ts` over ratios 1, 2, 3 × three container sizes (desktop 1920×1080, iPad landscape 1180×820, iPad portrait 820×1180 in CSS pixels); assert integer zoom, `tile*zoom*ratio` integral, and monotonicity in ratio.
- Record: `kb/studio-web-renderer-spike.md` with the kb frontmatter (`title`, `description`, `rank`, see `kb/trial-record-opus-5-5.md:1-5`), then `uv run python plugins/tk-studio/lib/kb.py index --directory .` regenerates `kb/index.md` (committed). The attended desktop/iPad observation cannot happen in a headless run: write the section as "attended check not yet done" per ratio (AC3 allows it). Idle frame cost: measure from the ticker in a headless-browser run if one is available, else name it `not recorded` with the reason. The quote: EP-29's per-story price is not in any committed doc (grep of docs/, kb/, handoffs); read it from the ledger's `job-run` events on the box when reachable (`tk-studio-report`, the supervisor's `GET /runs`), else write `not recorded: no committed source` (the trial-record convention, `kb/trial-record-opus-5-5.md`) and quote by story count against §10's "Epic-21-sized or larger".
- Design README §6.3: `_bmad-output/planning-artifacts/design/studio-design-spec-2026-10-09/README.md:134-140`; add one bullet after **Renderer** pointing at `kb/studio-web-renderer-spike.md`. The epics document, the plan files and `stories.yaml` are never edited.
- Read-only seams: `apps/supervisor/**` (AC1), `plugins/tk-studio/**` (no plugin surface changes; the lib suite and conformance stay green untouched), `tools/release_archive.py` (already knows `studio-web`; 30.2 wires the release).
