## Intent
The supervisor serves the built web on its own origin behind the session cookie, so the web needs no second server and no second sign-in (§6.3, D7). `GET /app` and every path under it serve files from the web's `dist`, with the single-page fallback, a traversal refusal and the session's cache headers. A missing build is the named 503 `WebNotBuilt`, plus a note on the read-only page. The release motion builds the web from the tag, and the installer's landed web slot carries it. `GET /` keeps serving the read-only page until 30.6.

## Acceptance Criteria
- AC1: **Given** `apps/studio-web/dist` present beside the supervisor (built by the release motion's `--app studio-web`, or by hand from the checkout), **when** a signed-in browser requests `GET /app` or any path under it, **then** the supervisor serves the file from `dist` with the right content type, or `index.html` for a path with no file (the single-page fallback), never a path outside `dist` (`..` and absolute paths answer 404), and every answer carries the session's cache headers; a request with no session answers the sign-in page of Story 29.1 with a return to the requested path; `GET /` keeps serving the read-only page until Story 30.6 moves the home.
- AC2: **Given** no `dist` beside the supervisor, **when** `GET /app` is requested, **then** the answer is 503 `WebNotBuilt` naming the build command, and the read-only page's header says the web is not built; `bun test` covers the directory route, the fallback, the traversal refusal and the missing build.
- AC3: **Given** the release motion, **when** `tools/release_archive.py run --app studio-web --version X.Y.Z` runs, **then** it builds `dist` from the tag, zips it, publishes and records it under the roster's `studio-web` component as the other apps are, and the installer's supervisor slot unpacks it beside the supervisor; the runbook §4 gains the web's row.

- **Locating the web (new `apps/supervisor/src/web.ts`).** No app-root helper exists; anchors use `import.meta.dir` (`registry.ts:62`, `client.ts:11`). Resolve the web's root per request, in order:
  1. `deps.web?.dir` (tests, and an explicit override).
  2. The installed slot. The supervisor runs from `<root>/supervisor/<ver>/src`, so `join(import.meta.dir, "..", "..", "..", "current.json")` gives `current.json`. Its `"studio-web": {version, path}` entry (`tools/installer/cli/tk_studio_cli/apps.py:11-16`, `write_current` `:356`) points at the web slot, whose root holds `index.html` (the release zip is `dist`'s contents).
  3. The source checkout: `join(import.meta.dir, "..", "..", "studio-web", "dist")`.

  A root counts as built when `index.html` exists in it. Pure helpers to export:
  - `webRoot(opts) -> string | null`
  - `resolveWebPath(root, urlPath) -> {file} | {fallback} | {refused}`
  - `contentType(file)`: `Bun.file(path).type` or a small extension map. HTML, JS, CSS, JSON and SVG get `; charset=utf-8` where textual. Unknown is `application/octet-stream`.
- **Traversal.** The WHATWG `URL` parser already collapses `..` and `%2e%2e` in `url.pathname`, so also refuse on the decoded segments.
  - Split the path after `/app` on `/`, then `decodeURIComponent` each segment. A decode error gets 404.
  - Refuse a segment that is `..` or `.`, or that holds `/`, `\`, `:` or NUL after decoding. Refuse an absolute path, including a drive letter.
  - Then check that `resolve(root, ...segments)` stays under `resolve(root)`, comparing case-folded on Windows. A missing file (no extension or any extension) falls back to `index.html`. A refused path is 404, never the fallback.
  - Tests must drive the raw cases through `handler(new Request(...))`, including `%2e%2e/`, `..%2f`, `%5c` and `/app//etc/passwd`. Build a `Request` whose URL keeps the encoding.

## Risks and open decisions
- **oversize.** 11 files, past the L band's five, because the story spans three surfaces (the route, the release and the docs). Halt `blocked` if the Files list grows past this plan's eleven.
- **The sandbox refuses symlinks**, so `bun install` gets EPERM in the worktree (30-1). Verify bun in a /tmp copy of the committed files, record the in-worktree gate `unverifiable-here` with the exact commands, and treat the host leg as binding. `apps/supervisor`'s `bun test` is not in `tools/verify_host.py`'s gates, so record its /tmp result in the Auto Run Result. Adding a supervisor gate to `verify_host.py` is out of scope.
- **The release is the operator's.** The loop never runs `release_archive.py run` (studio customization). A real cut, and the installer unpacking a real web zip, are `unverifiable-here` with the command `uv run python tools/release_archive.py run --app studio-web --version 0.1.0`. The fake-`_run` tests are the evidence.
- **Block If:** `cookieRoute`'s allowlist, or the sign-in `next`, would need a change to the bearer API, the account JSON answers, or `GET /`'s behaviour beyond the not-built note. Stop and record it; AC1 keeps `GET /` unchanged.
- Not a Block If: whether the contract names `/app` or `next`. This plan rules that it does not, with the 0.1.25 bump left to 30.5/30.6. A reviewer who disagrees records it as a deviation naming 30-5 and 30-6.
