## Intent
The spike page becomes the Office screen. For the selected project, each registry agent stands as one character at a desk on the PixiJS floor. Its pose is a looping frame set for its office state (§7.3), fed by 30-3's store. A React DOM HUD shows the project's run and the story in flight, a bubble marks `waiting-for-human` and `blocked`, and a project switcher is remembered per browser (§6.3, F3, CAP-10…12). The pure parts (state to frames, the bubble rule, the HUD model, the switcher) are functions vitest drives without WebGL. The canvas is driven through `scene.ts`.

## Acceptance Criteria
- AC1: **Given** the registry's agents for the selected project (`GET /agents?project=<id>`) and the store of Story 30.3 **When** the Office screen renders **Then** each agent is one character at a desk on the PixiJS floor, named by its role, whose pose is one of the eight office states of §7.3 (`offline`, `idle`, `thinking`, `reading`, `typing`, `running`, `waiting-for-human`, `blocked`), each state a distinct, looping frame set from the sheet; a state change swaps the frame set within one frame without a flicker; `waiting-for-human` and `blocked` add a React DOM bubble over the character naming what it waits for (the projection's reason)
- AC2: **Given** a project with a live run **When** the HUD renders **Then** it shows the project, the run id and state, the story in flight with its progress (`office.progress`: done, failed and total stories, the current story's phase), the engine run id and the time since the last event; with no live run it shows the last ended run's end state and PR link; a project switcher lists the registry's projects and remembers the choice per browser
- AC3: **Given** the screen **When** it is tested **Then** vitest covers the state-to-frames mapping for all eight states, the bubble rule, the HUD's fields from a fixture store, and the project switcher; the canvas is driven through the renderer's exported scene functions so the tests need no WebGL

## Code Map
- **The store (30-3, `apps/studio-web/src/live/store.ts`).**
  - `createOfficeStore()` exposes `getState()` and `subscribe()` (for `useSyncExternalStore`), plus `applySnapshot`, `applyDelta` and `setStatus`. `LiveState` is `{view: OfficeView | null, lastId, status}`.
  - The mirrored types are `OfficeAgent {agent_id, project, role, state, current_run, current_story}`, `OfficeRun {run_id, project, state: string | null, engine_run_id, epic: OfficeEpic, stories: OfficeStory[]}`, `OfficeEpic {spec_folder, done, deferred, failed, total, current_story}` and `OfficeStory {key, title?, status, phase, overlay, extra?}`. Also `OFFICE_STATES` and `LIVE_RUN_STATES`.
  - Run rows may hold `state: null` (a progress-born row) and `engine_run_id: null` (any row born after the snapshot). Render them as pending and "—".
  - The store keeps no event time. "The time since the last event" needs a `lastEventAt` (client receive time, `Date.now()` injectable), set on every applied snapshot and delta. Extend `LiveState` in place, and keep `getState()`'s stable reference.
- **The stream (`src/live/stream.ts`).** Untouched. `App.tsx` already holds the module-level `officeStore` and opens one stream per mount.
- **The registry, `GET /agents?project=<id>`** (`apps/supervisor/src/api.ts:651`, read-only). It answers `{ok, rebuilt_at, agents}`. Each row has `agent_id` `<project>/<role>`, `role` (`orchestrator`, `session`, `implementer`, `reviewer`, `consult`, `advisor`, `planner`), `model`, `effort`, `advisor`, `persona`, `live_state`, `current_run`, `current_story` and `jira_account` (contract §1, `driver-contract.md:107`).
  - `GET /agents` with no project lists every project's rows. The switcher's project list is the distinct `project`/`agent_id` prefixes from it.
  - Use the absolute URL `/agents` (the page has `<base href="/app/">`) and `fetch` with the cookie on the same origin. Inject `fetch` for tests.
  - The desk set is the registry's rows. The pose comes from the store's agent with the same `agent_id`, falling back to the row's `live_state`.
- **The renderer (`src/renderer/scene.ts`)**, as 30-3's gate recorded:
  - It exports `loadSheet`/`SHEET_URL` (the one loader, `sprites/placeholder.png`, cutting frames by `Rectangle`), `drawFloor(world, texture, cols, rows)`, `placeCharacter(world, texture, col, row)`, `layoutScene`, `floorSize` and `TILE = 16`.
  - Extend `Sheet` to hold frame sets per state, for example `frames: Record<OfficeState, Texture[]>` plus `desk`. Add pure builders that take `Container`/`Texture` only: a desk row layout (`placeDesks(world, sheet, agents)` returning a sprite per agent) and `setPose(sprite, frames)`.
  - The swap without a flicker is `AnimatedSprite.textures = frames` followed by `play()`, done in place on the same sprite and never by destroying and re-adding it. A plain `Sprite` with a ticker-driven frame index also works.
  - Tests construct `Container`, `Texture.EMPTY` or `new Texture()` without a renderer, as 30.1's comment intends.
- **The placeholder sheet (`scripts/make-placeholder.ts` → `public/sprites/placeholder.png`).**
  - Today it is 32x16: the floor at x 0 and one character at x 16, built from hand pixel rows, `node:zlib` and a hand CRC, with byte-reproducible output.
  - Extend it with a desk tile and eight state frame sets, at least two frames each so every set loops. They can share one body with distinct pixels per state (colour, pose, a marker), so every set is distinct.
  - Regenerate with `bun run sprites` and commit the png. 30.7 deletes this sheet.
- **`App.tsx`** is the spike page. The canvas `useEffect` is at `:33-102`, and the HUD is the `<div>` at `:104-127` with the zoom, ratio, fps and stream lines. Move the Office composition into an `OfficeScreen` component, or keep it in `App` if the file stays small. Keep the spike HUD lines; the README may call them debug lines.
- **vitest** runs `environment: "node"` and `include: ["src/**/*.test.ts"]`. There is no DOM, so put the logic in `.ts` modules and keep the `.tsx` thin. `localStorage` is injectable (`{getItem, setItem}`, default `globalThis.localStorage`).

## Risks and open decisions
- **Block If (operator ruling required, replan queue "operator — from 30-3", 2026-10-19).** The 0.1.24 projection the store mirrors carries no per-agent reason, no ended run and no PR. AC1's bubble "naming what it waits for (the projection's reason)" and AC2's "with no live run it shows the last ended run's end state and PR link" have no source within SPEC Constraints, which limit the web to the contract §1 surfaces plus `/board` and `/status`. Halt `blocked` unless the operator has ruled one of these and recorded it:
  - (a) an additive projection field (`reason` on agent rows and `office.agent`, and a per-project `last_run {run_id, state, pr}`), touching `apps/supervisor` and contract §1. This adds files and folds into the 0.1.25 bump.
  - (b) the web reads `GET /runs/{id}`, named in 0.1.25's web surfaces.
  - (c) the ACs narrowed by `bmad-correct-course`: the bubble names the run's `paused`/`blocked` state and the current story, and the ended-run line waits for 30.5's `/board`.
  - Never pick one alone.
- **oversize.** This plan has eleven files under (c), more under (a), against L's five-plus. Halt `blocked` if the Files list grows past the plan's count plus whatever the operator's ruling adds.
- **One loader, one store, one stream.** Extend `loadSheet`, the 30-3 store and `openOfficeStream`; never add a second of any.
- **No flicker.** Swap the textures on the existing sprite. Destroying and re-adding a sprite on a state change fails AC1. `layoutScene` currently rebuilds the world on resize, which is acceptable; a state change must not trigger it.
- **The sandbox refuses symlinks**, so verify bun in a /tmp copy. The host leg is binding. A new web dependency (none expected) regenerates `bun.lock`.
- **unverifiable-here.** The attended desktop and iPad look of the eight loops and the bubbles; a real supervisor's state change swapping a pose live.
