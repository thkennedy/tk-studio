## Intent
The web holds one `EventSource` per tab on the supervisor's office stream (Story 29.3) and folds it into one client store. The snapshot arrives first, then each delta. Deltas are deduplicated by id. The stream survives drops (the browser's own reconnect sends `Last-Event-ID` and gets the replay), 15 s of silence and the iPad's backgrounding (a watchdog closes and reopens, and the store is never cleared). This story is web-only. It consumes the contract §1 surface as it stands at 0.1.24 and changes nothing in `apps/supervisor` or the contract (§6.3, CAP-7…9).

## Acceptance Criteria
- AC1: **Given** a signed-in tab **When** the web mounts **Then** it opens one `EventSource` on `GET /office/events` (Story 29.3's stream), applies the `event:snapshot` first and every `office.agent`, `office.progress` and `office.run` delta after it into one client store, and reconnects with `Last-Event-ID` after a drop so no delta is lost or applied twice (the store ignores an id at or below the last applied)
- AC2: **Given** no event for 15 seconds, or the tab returning from the background (`visibilitychange` to visible) **When** the watchdog fires **Then** the stream is closed and reopened with the last id, the HUD shows "reconnecting" until the snapshot arrives, and the store's state is never cleared in between (iPad Safari backgrounds streams the way iOS does)
- AC3: **Given** the store **When** it is tested **Then** vitest covers the snapshot, each delta kind, a duplicate delivery, a gap filled by a resume, and the watchdog's reopen, with a fake `EventSource`

## Code Map
- **The server side (read-only, `apps/supervisor`).**
  - `src/api.ts:382-415` `officeSse`. A frame is `id:<boot>-<seq>\nevent:<kind>\ndata:<json>\n\n`. The first frame is `event:snapshot`, whose `data` is `{at, agents, runs, problems, id}` (the `GET /office` answer without `ok`). A valid `Last-Event-ID` header instead replays the buffered deltas after it, possibly none, and sends **no snapshot**. The heartbeat is a `: heartbeat` **comment** every 10 s. Only `Accept: text/event-stream` gets the stream; `EventSource` sends that header itself.
  - `src/office.ts:632-641` `since(id)`. It returns null (and the snapshot is sent again) for an id that is malformed, from another boot, ahead of the hub, or older than the 1000-delta ring. A supervisor restart is a new boot, and a fresh snapshot follows.
  - Types to mirror (do not import across apps), from `office.ts:291-300`, `:498-500`:
    - `OfficeAgent {agent_id, project, role, state, current_run, current_story}`
    - `OfficeStory {key, title?, status, phase, overlay, extra?}`
    - `OfficeEpic {spec_folder, done, deferred, failed, total, current_story}`
    - `OfficeRun {run_id, project, state, engine_run_id, epic, stories}`
    - `OfficeView {at, agents, runs, problems}`
    - the eight `OFFICE_STATES` (`:20`)
  - Delta payloads (`office.ts:585-615`; contract §1 "The stream", `driver-contract.md:118-150`):
    - `office.agent {agent_id, state, from, at, current_run, current_story}`
    - `office.progress {run_id, epic, story?}`
    - `office.run {run_id, project, state, from}`
  - Emission order inside one poll: agents, then progress, then runs. So **a run new to the live set sends its epic-only `office.progress` before its `office.run`**. The store must accept progress for a `run_id` it has not seen: create the row, with `state` unknown until the `office.run` that follows. A run leaving the live set sends `office.run` with `state` = its queue state (non-live) or `null`; drop it from `runs` when `state` is null or not in `queued|running|paused|external` (`LIVE_RUN_STATES`, `office.ts:266`). A delta never carries `engine_run_id` or `title`, so keep what the snapshot gave, `null` for a run born after it. An agent's first appearance (`from: null`) carries no `project` or `role`: derive them from `agent_id` `<project>/<role>`. An agent that leaves the registry gets no event; only the next snapshot drops it.
  - Auth: same origin. The cookie rides `EventSource` automatically, so `withCredentials` is not needed. With no session the answer is 401 JSON. `EventSource` then fails with `readyState === CLOSED` and the browser does not retry, so the client must.
- **The web (`apps/studio-web`).**
  - `src/App.tsx` (the 30.1 spike page: canvas plus a React DOM HUD at `:89-107`, one `useEffect` mount at `:20-87`) and `src/main.tsx` (wraps `<App/>` in `StrictMode`, which mounts, unmounts and remounts in dev).
  - `vite.config.ts` has `base: "/app/"` **plus an injected `<base href="/app/">`** (30.2). A relative URL such as `office/events` therefore resolves to `/app/office/events` and gets the SPA fallback's HTML. **Every supervisor URL must be absolute: `/office/events`.**
  - vitest runs `environment: "node"` and `include: ["src/**/*.test.ts"]`. There is no DOM in tests, so inject the `EventSource` constructor, the visibility source (`{visibilityState, addEventListener("visibilitychange")}`) and the timers (`setTimeout`/`clearTimeout`, or vitest's fake timers). The defaults are `globalThis.EventSource` and `document`.
  - The renderer (`src/renderer/scene.ts`, `pickZoom.ts`) is untouched; 30.4 joins the store to the canvas.
- **Shape to build.**
  - `src/live/store.ts` (pure, no DOM):
    - `type LiveId = {boot: string; seq: number}` and `parseId("<boot>-<seq>")` (null when malformed).
    - `OfficeStore` holds `{view: OfficeView | null, lastId: string | null, status: "connecting" | "live" | "reconnecting"}`, with `getState()` and `subscribe(fn)` for React's `useSyncExternalStore`, `applySnapshot(id, data)`, `applyDelta(id, kind, data)` and `setStatus(s)`.
    - **Rule:** a snapshot always replaces `view` atomically (never cleared first), rebases `lastId` and sets `status: "live"`. A delta applies only when its boot equals `lastId`'s boot and its seq is greater; otherwise it is ignored (a duplicate, or a stale boot).
    - Unknown kinds are ignored.
  - `src/live/stream.ts`: `openOfficeStream(store, deps?)` returns `{close()}`.
    - It opens exactly one `EventSource("/office/events")` and listens on `snapshot`, `office.agent`, `office.progress` and `office.run` with `addEventListener`. Named events never reach `onmessage`.
    - Each listener parses `ev.data` and takes `ev.lastEventId` as the frame's id.
    - **Watchdog:** a 15 s timer re-armed on every received event (`WATCHDOG_MS = 15_000`, exported). It also fires on `visibilitychange` when `visibilityState === "visible"`. Firing sets `status: "reconnecting"`, closes the current source, then opens one new source; the old one is closed before the new one opens. The view is never cleared.
    - `error` with `readyState === CLOSED` (the browser gave up, e.g. 401 or 503): reopen after a capped backoff (e.g. 1 s doubling to 30 s, reset by a snapshot), with status `reconnecting`. `error` with `readyState === CONNECTING` is the browser's own retry: leave it alone, set `reconnecting`, and it resends `Last-Event-ID` itself.
    - `close()` clears every timer and listener.
  - `App.tsx`: open the stream once in a `useEffect`, closed in its cleanup, so StrictMode's double mount leaves one open source. Read the store with `useSyncExternalStore`. The HUD gains one line: `stream live` / `connecting` / `reconnecting`, plus the agent and live-run counts. Keep the zoom, ratio and fps lines.

## Risks and open decisions
- **oversize.** 6 files and about 500 new lines (two of the files are tests), past M's five files and 300 lines. Halt `blocked` if the Files list grows past these six.
- **Ruling on "reopened with the last id" (not a Block If).** A fresh `EventSource` cannot set a `Last-Event-ID` header. Only the browser's own reconnect on the same object sends it, which is AC1's drop-and-resume. The watchdog's reopen is a new object, so the supervisor answers it with the snapshot. AC2 names that outcome ("until the snapshot arrives"). The store keeps `lastId` across the reopen and rebases on the snapshot, so no delta is applied twice. Record this as a score-1 `DRIFT … affects: none`. Do not add a query parameter or touch `apps/supervisor`.
- **Block If:** honouring the last id on the watchdog's reopen is judged to need a supervisor or contract change (a `?last_event_id=` query, or a named heartbeat event). 30.3 is web-only, and the contract's 0.1.25 bump belongs to 30.5/30.6. Halt and record it.
- **The heartbeat is invisible to `EventSource`.** `: heartbeat` is an SSE comment, so it never fires a listener. On a quiet office, the 15 s watchdog therefore reopens every 15 s, and each reopen costs one snapshot and a brief "reconnecting". That is AC2 taken literally, and acceptable for v0. Name it under the Auto Run Result's residual risks. A named heartbeat event (a supervisor and contract change) is a candidate for the operator's 0.1.25 bump; do not do it here.
- **The sandbox refuses symlinks** (30-1), so verify bun in a /tmp copy and record the in-worktree gate `unverifiable-here` with the command. A new web dependency is not expected; if one is added, `bun.lock` must be regenerated and committed. `tools/verify_host.py` on the host is binding.
- **unverifiable-here.** The iPad check is attended: open `/app` on the iPad, signed in; background Safari for over a minute; return. The HUD shows "reconnecting", then "stream live", and the agents and runs are not blanked in between. The live stream against a real supervisor is also unverifiable here: a run's state change appears without a reload.
