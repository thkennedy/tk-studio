## Intent

The Opus 5.5 trial needs every landed loop story priced in dollars per model and per leg, and timed, so routes are judged on money and wall-clock time, not token counters. The v2 weighted-token method assumes one price and cannot price mixed-model routes. On the sbx engine the transcripts live only inside the microVM. So at the story boundary a studio-side meter copies the story's session and subagent transcripts into the run directory, prices them against a committed, dated price table, and records one `observation` per story. Band L, reason: a new lib module with its CLI, a price table, a plugin hook, and a test file, more than 300 new lines across 6 files.

## Acceptance Criteria

1. **Given** a bmad-loop run on the sbx engine **When** a story reaches its boundary **Then** the session transcripts and subagent transcripts for that story are copied out of the microVM into the run's directory in the mounted checkout (gitignored), so they reach the host and its nightly backup
2. **Given** a story's transcripts and a committed price table (model id → input, output, cache-write and cache-read $ per MTok, with the table's date) **When** the meter prices the story **Then** it reports dollars per model and per leg (session, implementer, reviewers, consult, seam, review, triage, supervise), the story's wall-clock from first dispatch to landed commit, its attempt count, and the route in force (from `routing.current.json`); a model missing from the price table is a named refusal, never a guessed price
3. **Given** a priced story **When** the meter records it **Then** one `observation` event per story lands in this machine's ledger, carrying the story key, route, dollars, wall-clock and attempts, and the lib suite pins the pricing arithmetic, the missing-price refusal, and a mixed-model story

## Code Map

Verified against run `20260928-090746-8360` (story 20-2) on 2026-09-28.

- **Where transcripts are.** The engine's hook relay `.bmad-loop/bmad_loop_hook.py` writes one file per session event into `<run_dir>/events/<ts>-<task_id>-<Event>.json` carrying `session_id` and `transcript_path`. Example: `/home/agent/.claude/projects/-c-GitHub-tk-studio/<session>.jsonl`. `task_id` is `<story_key>-<role>-<n>`: `-dev-1` is the dev session and `-review-1` the review session; triage sessions follow the same pattern. A session's subagent transcripts sit beside it at `<transcript stem>/subagents/agent-*.jsonl`, each with an `agent-*.meta.json` holding `agentType`, `description` (for example `"Edge case hunter review 20-2"`) and `model`. `tool-results/` is not needed.
- **Usage records.** Take assistant lines with `message.usage`, with `message.model` and `message.id`. Claude Code writes **one line per content block, all repeating the same usage**: 6 unique ids across 10 lines in one subagent file. **Dedupe by `message.id`, then sum**, or cost comes out about 1.7× too high. Price these fields: `input_tokens`, `output_tokens`, `cache_creation_input_tokens` (split in `usage.cache_creation` into `ephemeral_1h_input_tokens` and `ephemeral_5m_input_tokens`; the loop writes 1h), and `cache_read_input_tokens`.
- **Timing and attempts.** `<run_dir>/journal.jsonl` is one JSON per line with `ts` in epoch seconds and `kind`. For the story it carries `story-start`, `session-start` (with `role`, `model`, `story_key`), `session-end`, `dev-decision` (`attempt`), `story-done` (`commit`) and `plugin-hook`. Wall-clock is the story's first `session-start` (first dispatch) to its `story-done`. Attempts come from `<run_dir>/state.json` `tasks[<story_key>].attempt`. The journal's own `tokens` / `tokens_weighted` on `session-end` are weighted counters, and this story never uses them for dollars.
- **Story boundary hook.** bmad-loop fires `self._emit("post_commit", task)` right after `journal.append("story-done", …)`. That is only a *landed* story; `post_story` fires for failed ones too. A declarative `[hooks.post_commit]` in `.bmad-loop/plugins/studio-pipeline/plugin.toml` runs a `cmd` with `BMAD_LOOP_RUN_DIR`, `BMAD_LOOP_RUN_ID`, `BMAD_LOOP_REPO_ROOT` and `BMAD_LOOP_STORY_KEY` in its environment (`bmad_loop/plugins/bus.py` ~L78–99). Copy the shape of the existing `[hooks.pre_commit]`: `uv run --no-project python "{scripts}/…"`, `blocking = false`, `fail_closed = false`. The hook runs where the engine runs, inside the microVM, which is where `~/.claude/projects` is. The engine is not modified (AD-2: the studio reaches the substrate only through its CLI and plugin surface).
- **Where the copies go.** `<run_dir>/transcripts/<story_key>/<task_id>/` holds the session `.jsonl` plus `subagents/`. `.bmad-loop/runs/` is already in `.gitignore` (line 6), and so is `.bmad-loop/archive/`, where old runs move. So no ignore change is needed. The run dir sits in the mounted checkout, so the files reach the host.
- **Route in force.** `<repo_root>/.bmad-loop/routing.current.json` (gitignored, written by `lib/pipeline.py apply`) has keys `story` and `written_at`, one object per leg (`session`, `implementer`, `reviewers`, `consult`, `seam`, `review`, `triage`, `supervise`, `planner`) with `model` and sometimes `effort`, plus `consult_triggers`. Record the leg→model map.
- **Legs.** The dev session transcript is `session`. The review role session is `review`, and so is the `pre_commit_gate` gate session (role review, off by default). The triage role session is `triage`. Dev-session subagents map by `meta.json` `description` / `agentType`: consult prompts start from `consult.md`, and review layers name a hunter or reviewer. Everything else is `implementer`. `seam` and `supervise` have no sessions in this repo yet (the seam check is not ported, per the `plugin.toml` header), so they report `0` / absent, never an error. The mapping is a heuristic: put it in one function with a named unknown-leg bucket, never a silent drop.
- **Ledger write.** `plugins/tk-studio/lib/observe.py` `record_observation(source, description, evidence, project)` goes through `ledger.emit` (AD-12, the one write path). The `observation` payload in `contracts/events/taxonomy.v1.json` (~L72–78) has only `source` / `description` / `evidence` strings. Use `source="other"` and a description prefixed `meter:`, mirroring the existing `consult:` convention in `_bmad/custom/bmad-build-auto.toml`. Carry `story=<key> route=<leg:model,…> usd=<total> usd_by_model=<…> usd_by_leg=<…> wall_clock_s=<n> attempts=<n>` in the description. `evidence` is the project-relative transcripts dir. Emit **after** pricing succeeds: a refusal emits nothing.
- **Tests.** `plugins/tk-studio/lib/tests/test_observe.py` isolates the store with `TK_STUDIO_HOME` in a tempdir. Reuse that pattern and read events back the way that test does. Fixtures are small inline JSONL written to a tempdir run dir (events, journal, state.json, transcripts). No real transcripts.
- **Conformance.** `plugins/tk-studio/contracts/conformance/manifest.json` gives each headless surface drives (see `tk-studio-observe`, ~L233: `headless-clean` + `blocked-on-ambiguity`). If `meter.py` is a studio surface, whether the runner requires every lib CLI to be listed is for the implementer to check against `runner.py`.

## Files

- `plugins/tk-studio/lib/meter.py` (new): stdlib-only; `collect(run_dir, story_key)` copy-out, `price(...)` → per model / per leg / total, timing and attempts, `record(...)` → one observation; CLI `meter.py story --run-dir D --story-key K [--repo-root R] [--prices P] [--no-record]` printing JSON with an AD-11 `{"ok": false, "error": …}` refusal and exit 2
- `plugins/tk-studio/lib/prices.json` (new): `{"date": "YYYY-MM-DD", "source": "…", "models": {"<model id>": {"input": …, "output": …, "cache_write": …, "cache_read": …}}}` in $ per MTok
- `.bmad-loop/plugins/studio-pipeline/meter_hook.py` (new): resolves the studio root (`TK_STUDIO_ROOT`, else `BMAD_LOOP_REPO_ROOT` when it holds `plugins/tk-studio/lib/meter.py`) and runs `meter.py story` with the hook env; always exits 0 and prints the meter's JSON, so a meter failure never blocks the run
- `.bmad-loop/plugins/studio-pipeline/plugin.toml` (modify): add `[hooks.post_commit]` and a header comment line
- `plugins/tk-studio/lib/tests/test_meter.py` (new)
- `plugins/tk-studio/contracts/conformance/manifest.json` (modify, only if the runner requires every lib surface listed)

3. `uv run python ../contracts/conformance/runner.py run`: `ok: true`.
4. Live smoke (read-only on the real run, no ledger write): `uv run python meter.py story --run-dir ../../../.bmad-loop/runs/20260928-090746-8360 --story-key 20-2-contract-0-1-18-names-the-supervisor-and-hermes --no-record` returns a priced JSON with dev and review sessions and 5 subagents, all `claude-opus-5-5`. Or it returns the named missing-price refusal if the table lacks that model. It copies into that run dir's `transcripts/`, which is gitignored. Afterwards `git status --short` is clean.

Tests to add (`test_meter.py`):

- **Arithmetic:** a hand-computed story, e.g. 1M input + 1M output + 1M cache-write + 1M cache-read at a fixture table, equals the sum of the four prices exactly. Duplicate lines with the same `message.id` count once.
- **Missing price:** a transcript naming a model absent from the table refuses, and the error names the model. No observation is emitted and no partial dollars are reported.
- **Mixed model:** a dev session on model A with an implementer subagent on model B gives per-model and per-leg dollars that each sum to the total.
- **Timing and attempts:** wall-clock is first `session-start` to `story-done` for that key only, with another story's lines interleaved. Attempts come from `state.json`.
- **Copy-out:** session and subagent files, including `.meta.json`, land under `<run_dir>/transcripts/<key>/<task_id>/`. A `transcript_path` that no longer exists is reported by name, never silently skipped.
- **One event:** a priced story emits exactly one `observation` with `source == "other"`, a description starting `meter:` that holds the story key, route, dollars, wall-clock and attempts. Re-running for the same story does not emit a second one; the idempotence marker lives in the run dir, for example `transcripts/<key>/metered.json`.

## Risks and open decisions

- **Block If** a price figure the table needs is not stated in the repo. The epic and the kb give input/output for Opus 5.5, Opus 5, Fable 5.1 and Sonnet 5, and cache-read only for Opus 5.5 ($0.20). They give no cache-write price for any model. That is a pricing fact (SPEC open question 2), not a design choice the session may make, so consult → `escalate`. Do not derive it from a multiplier convention: Opus 5.5's $0.20 cache read is 0.05× input, which breaks the usual 0.1× rule. Everything else in the story can be built and tested against a fixture table while the committed table waits on the operator.
- **Block If** the price table must split cache-write into 5m and 1h rates. The AC names one cache-write column. Transcripts carry both, and the loop writes 1h. If the operator's figures differ by TTL, that changes the AC's table shape, so consult.
- **Block If** a structured `observation` payload (numeric fields) is needed. That would change `taxonomy.v1.json`, a contract surface, and pull in `driver-contract.md` under AD-19. The plan keeps the payload shape and carries the fields in `description`. Record a DRIFT if the implementer finds that insufficient.
- Leg attribution for subagents is a heuristic over `meta.json` `description`. Name the unknown bucket in the output and never fold it into `implementer` silently. Record `DRIFT` at score 1 if the rule differs from the Code Map.
- Run retention (`cleanup.run_retention = 10`, `archive_old`) eventually deletes or archives run dirs, so the host's nightly backup must see them first. That is outside this story. Note it, and do not change policy.
- SPEC open question 1 (does Epic 20 get retroactive pricing?) is Story 24.2's to settle. Epic 20's transcripts still exist in the microVM (run `20260928-090746-8360`), and the CLI can price them after the fact, but this story does not do it.
