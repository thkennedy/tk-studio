## Intent

The Epic 34 retro found that a slice run's red often meant the box, not the game. Four causes:
- The leg's guard ties the tools' own wall clocks, so the guard's kill wins and no report is read.
- `match` is judged by its exit code alone.
- `proofCommit` stages `.candidates/` and ignored paths, and commits no proof without a green assets step.
- A judge infrastructure failure reads as a rubric `fail`.

This story makes the leg fail for the right reasons and keep its proof (DW-94 B1–B4, B8, B12, B13; DW-88; DW-89; DW-70; AI-2). It also makes `sheet` sample the report's citable frames, keeps the drives' bounds under the runner's cap, tests the nt tree-kill where it runs, and gives the rubric ids one home. Contract 0.1.30 gains an additive 35.3 paragraph naming `inconclusive`. Repo: tk-studio (`apps/supervisor`, `plugins/tk-studio`).

## Acceptance Criteria

AC1. **Given** the slice host leg **When** a tool overruns or fails **Then** the leg's guard is the tool's own `--wall` plus a margin (`hostverify.ts:547-549, :445`; `assets.py:172`), so the tool's kill writes its report and the leg reads `wall-clock` from it; a crashed, `not-run` or write-back-failed `match` is `fault` from the status block's `reason`, `writeback` and `not-run` fields, red (`hostverify.ts:449`; `assets.py:1917-1923`); `proofCommit` runs `git check-ignore` and stages the art path without `.candidates/` (`worktree.ts:461-465`); the proof folder is committed whenever `report.json` exists, a `skipped: no manifest` assets step included (`worktree.ts:547`)

AC2. **Given** `playable.py sheet` and the conformance drives **When** they run **Then** `sheet --report` samples from the report's `frames[]`, the judge's citable set, never every movie frame (`playable.py:756-757`); `e2e_vertical_slice.py` and `e2e_engine_gate.py` assert their bounds under `runner.py`'s cap or raise it through the manifest's `timeout` (DW-70 closed with them); the nt `taskkill /T /F` path of `kill_tree` is tested on nt (`test_playable.py:666`, `test_assets.py:865`)

AC3. **Given** the judge **When** the pin, `sbx exec` or the status block fails **Then** `playable.verdict: inconclusive` names the infrastructure reason and the run ends `partial` without a rubric fail (`hostverify.ts:426, :619-630`); the rubric ids live in the core's list, read by the supervisor and pinned to the skill's text by a test (`hostverify.ts:478`, `playable_judge.py:51-60`, `skills/tk-studio-playable-judge/SKILL.md:38-42`); the contract (0.1.30, additive) names `inconclusive`; DW-88, DW-89 and DW-94 close by this PR

## Settled shape

None needs a SPEC design note. Every artifact this story's criteria name is produced by this story. The planner's rulings, binding unless the dev session records a deviation:

- **Margin.** `TOOL_WALL_MARGIN_S = 30` in `hostverify.ts`. This is above `KILL_TREE_TIMEOUT_S` (10) plus report-write time.
  - Each tool gets its own wall `toolWall = min(max(1, guardS), 86400)`: assets via `--wall <toolWall>` (new in the argv), playable via `--wall-clock <toolWall>`. Each `runStep` for those tools runs under `toolWall + TOOL_WALL_MARGIN_S`.
  - The host, engine, sheet and judge steps keep `guardS`.
  - When the tool's own wall fires, the leg's reason is read from the tool: assets `block.reason` (`wall clock: …`), playable `report.json failed.invariant: "wall-clock"`. A guard trip still reads `timed out (guard…)`.
- **`match`.** A `match` is red with `status: "fault"` and `AssetsStepRun` gaining `reason?`, `writeback?` and `not_run?` (the count) in these three cases:
  - (a) it crashed: non-zero exit with no status block;
  - (b) `counts["not-run"] > 0`;
  - (c) `writeback` is non-null.
  `redReason` names which, from the block's `reason`. A `match` exit 1 whose block shows only ordinary rung outcomes (failed/candidate rows, no not-run, no writeback) keeps today's non-red `fault`; the CAP-2 note's "a `fault` row counting green" keeps holding for it.
- **Proof commit.** The close-out (`worktree.ts:601`) and the re-run (`hostleg.ts sliceCommit`) both commit when `input.slice && ran && report.json exists in the playable store`. That covers assets `green`, `skipped: no manifest`, and a non-red fault. A red assets step still commits nothing, so red art is never placed.
  - `proofCommit` drops the `!verify.assets` throw and stages only paths that exist.
  - Before `git add` it runs `git check-ignore --stdin`, adds the art path with the pathspec `:(exclude)<art_path>/.candidates`, and records any ignored paths it skipped as `skipped_ignored[]` on the commit result.
- **`inconclusive`.**
  - `PlayableStep.verdict` gains `"inconclusive"` with `reason: "infrastructure: <pin|sbx|status-block|auth>: <detail>"`. It applies when the judge cannot run or answer: no sandbox, a thrown invoke, `ran: false`/`pin`, an auth preflight `blocked`, or `conformance_failure`.
  - `green` is false. `isRed` is false for the playable part. The run ends `partial` via an explicit `inconclusive` branch at `worktree.ts:969`, with the reason `host verify inconclusive (playable): <reason>`.
  - `prSection` renders `Playable: inconclusive — <reason>`. No finding is recorded.
  - The judge's own `blocked` with a game cause stays `fail`.
- **Rubric ids.**
  - A new verb, `playable_judge.py rubric`, prints `{ids: [...], rubric: [{id, line}]}` in a `complete` status block (additive on the judge lib surface, named in the 35.3 paragraph).
  - `hostverify.ts` runs it once per judge step (same runner, `guardS`) and validates findings against its ids. An unreadable answer is `inconclusive` (`infrastructure: rubric: …`).
  - `PLAYABLE_RUBRIC` is removed.
  - `test_playable_judge.py` pins `RUBRIC_IDS` to the `SKILL.md` table's ids, parsed from the table, and to `driver-contract.md:456-457`.
