## Intent

Tim's design (2026-10-28): every stage of a story's life leaves a start and a stop stamp with the model, the effort and the tokens it used, in the story's own spec (`## Stage Log`), mirrored as timestamped comments and a worklog on the story's Jira issue so Jira's server clock cross-checks the box's. Elapsed is derived at read time, never stored; gaps are gaps. The EP-34 retro had to infer stage times from PR timestamps; the ledger's `job-run` line carries one cost per run and only the launch session's turns.

## Acceptance Criteria

AC1. **Given** a story run by the loop **When** a stage starts and stops **Then** the spec's `## Stage Log` carries one row per stage occurrence (stage, pass, started, ended, session_id, model, effort, tokens_in, tokens_out, cost_usd, outcome); the engine hook writes its rows from bmad-loop's per-pass session records, the supervisor appends its legs through the plan pull-back, the operator's planning stage through `plansync.py stage --start|--stop`; elapsed never stored.

AC2. **Given** a Jira-bound project **When** a row is written **Then** the supervisor posts the start and finish comments (the shapes in the story) and a worklog at the stop; a failed post retries next tick and never blocks the run; the epic's issue gets a rollup comment at the retro.

AC3. **Given** the ledger and the retro **When** `measurepush.py push` and `tk-studio-report` run **Then** a `stage` event (taxonomy, additive) carries each row; the report rolls up per story and epic beside Jira's stamps with the skew named; the contract names the table, the comments, the worklog and the event; conformance drives the writers and the poster with fakes.

## Settled shape

- Rows append only; one row per stage occurrence; the engine's clock for its rows, the host's for the supervisor's; Jira's `created` is the external clock; the comment body carries the row's own timestamp so skew is measurable.
- The sandboxed engine never calls Jira; the supervisor posts, retries on the next tick, never blocks a run on Jira.
- The planning stage of the epic is one row on the epic's plan entry; the planning stage of a story is the planner-tier plan session (bootstrap or gate).
