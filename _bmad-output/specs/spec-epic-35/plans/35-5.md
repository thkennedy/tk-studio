## Intent

The engine's sandbox gate and the host's gate disagree today for reasons that have nothing to do with the code under test. Story 35.5 closes four of those reasons (holes 78, 84, 85, 90; DW-78, DW-80, DW-81; the retro's C1, C6, C7, AI-7):
- the 15 Story 32.8 delivery tests are red only in the sandbox;
- two eval cases cannot run on the host;
- a bare `godot` on the host leg reaches WinGet's GUI build;
- an unplaced engine job can be claimed on the host tier.

It also writes the plugin's Windows notes for sandbox-written tests. Contract 0.1.30 gains an additive Story 35.5 paragraph (`requires.tier`, `placement:TierRequired`, the `godot` shim, the `maintenance-evals` type and its surface). Repo: tk-studio (`apps/supervisor`, `plugins/tk-studio` lib, jobs, skills and contracts, `kb/`).

## Acceptance Criteria

AC1. **Given** the sandbox `claude-tk-studio` at main **When** `bun test test/delivery.test.ts` runs there **Then** the 15 Story 32.8 closeout-pass tests pass, the cause reproduced and fixed in the tests or the code (a path, a locale, the sandbox's bun at `~/.bun/bin`, whichever it is) and named in the plugin's sandbox notes, so the engine's gate may run the whole supervisor suite again (hole 84, DW-80)

AC2. **Given** the plugin's eval cases **When** the shipped `maintenance-conformance` job type (or a `maintenance-evals` sibling of it) runs on the sandbox tier **Then** it runs `claude plugin eval` for the cases the host cannot (`tk-studio-playable-judge-verdict`, `asset-ladder-generated-rung`: the sandbox has the tree and a shell), writes the scores to the run workspace and a `job-run` ledger line, and `kb/acceptance-record-34-8-vertical-slice-on-tua.md`'s step 7 names the tier per case, the host keeping `gds-engine-godot-4-pinned-facts` (hole 85, DW-81); the operator queues it once and fills the record's eval row

AC3. **Given** the engine step of the host leg and the plugin's docs **When** a project's command calls a bare `godot`, and when a sandbox-written test reaches the host **Then** the step's PATH holds a tk-studio shim named `godot` that execs `$env:GODOT` (or the leg refuses a bare `godot` with the reason; the planner picks and the runbook row says which; hole 78, DW-78), and the plugin's Windows notes for sandbox-written tests name case-folding file systems, PATHEXT, YAML backslashes, HKCU reads and append-mode handles (holes 74, 77, 82, 83) with one lib-suite example each that runs on Windows

AC4. **Given** an engine job type (`run-epic`, `run-vertical-slice`, 35.7's `run-sweep`) **When** a project submits an instance of it with no per-job placement on the sandbox tier (hole 90: an unplaced `run-epic-35` claimed on the host tier and ran the launch skill as a host `claude -p` for five turns before blocking) **Then** the job type declares the tier it requires (`requires: {tier: sbx}` in `job.schema.json`, additive) and `submit` refuses a host placement for it with `placement:TierRequired` before any process starts; the contract (0.1.30, additive) and the runbook's planning checklist name the supervisor's per-job config entry

## Settled shape

Each bullet is appended to `SPEC.md` `## Design notes (settled shape, planner, 2026-10-27)`:

1. **CAP-12: `requires`.** An optional entry: `requires?: {tier: "sbx" | "host"}` in `job.schema.json` `definition.fields`. An instance's own `requires` overrides its type's (the existing overlay rule). `submit` refuses a resolved placement whose tier differs, with `placement:TierRequired`, before `queue.enqueue`. Nothing is queued or spawned. `run-epic`, `run-vertical-slice` and `maintenance-evals` ship with `{tier: "sbx"}`, and 35.7's `run-sweep` ships it too. The API answers 400 by name.
2. **CAP-11: the `godot` shim.** A named placeholder rule. The planner picks the shim: hole 78's bare `godot` was inside a gate script, which an argv[0] refusal cannot see. The rule applies only when `GODOT` is an absolute path to a file:
   - The engine step makes a per-step shim dir (under its `tk-sup-hv-` temp dir) holding `godot`: `#!/bin/sh` `exec "$GODOT" "$@"`. On win32 it also holds `godot.cmd`: `@"%GODOT%" %*`.
   - The shim dir is prepended **before** the `GODOT` folder under the same PATH key.
   - An argv[0] of `godot`/`godot.exe` (case-insensitive, no path separator) is spawned as `$GODOT` itself, because a shell-less spawn on Windows finds only `.exe`/`.com`.
   - The `engine` member gains `godot_shim?: "<shim dir>"` (absent when `GODOT` is unset or not absolute; the command then still runs as in 0.1.29).
   - The runbook's hole 78 row says `shim`.
3. **CAP-10: `maintenance-evals`.** A named placeholder rule:
   - A shipped sibling job type of `maintenance-conformance` (which stays a host core job): one-shot, `requires: {tier: "sbx"}`, `target.skill: "tk-studio-evals"`, payload `{cases, runs: 3}`.
   - The surface `tk-studio-evals` runs `lib/evals.py run`, which calls `claude plugin eval <plugin> --trust-plugin --allow-tools Bash Write --no-publish --case <c> --runs <n> --json <out>/<c>.json` per case and writes `<out>/scores.json` `{cases: {<c>: {runs, passed, score}}, cli: "<claude --version>"}`.
   - The status block's `artifacts` lists `scores.json`, and its `reason` is `<c> <passed>/<runs>; …`. `finish` lands it in the run's `run.json`, and the `job-run` line is `_finalize_run`'s.
   - The record's step 7 names the host for `gds-engine-godot-4-pinned-facts` and the sandbox for the other two.
4. **CAP-9/CAP-11: the plugin's sandbox notes and Windows notes.** A named placeholder rule: two new sections of `plugins/tk-studio/README.md`, `## Sandbox notes for the suites` (the `TK_STUDIO_ROOT` cause, the injected-env rule, the bun path, the residual list) and `## Windows notes for sandbox-written tests` (five bullets, each naming its hole and one lib-suite test that runs on Windows).
