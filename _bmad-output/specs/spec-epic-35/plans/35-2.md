## Intent

Two holes left Epic 34 stories without a plan or without records. The launch bootstrap plans the first story only, so a relaunch reached 34.6 with no `plans/34-6.md` and two un-noted open questions (hole 81, DW-79). A resumed run then landed 34-5 by hand and relaunched straight into 34.6, so 34-5 got no gate file, no `## Reconcile` and no cost line (hole 89, DW-83). The fix has two parts. First, the bootstrap plans every manifest entry in list order, and the launch refuses the story it would start when one of that story's SPEC open questions has no design note. Second, of the AC's either/or, this plan picks the refusal: the supervisor never relaunches or resumes a paused run across a story boundary while a graceful stop is in force. It records why and keeps (or re-issues) the stop. Contract 0.1.30 gains an additive 35.2 paragraph.

## Acceptance Criteria

AC1. **Given** an epic launched with `bootstrap: true` **When** the bootstrap runs at the planner tier **Then** `plans/<story>.md` exists for every story in `stories.yaml` in list order (a Code Map and the band each), and a story whose SPEC open questions (`CAP-N`) have no design note is refused with the questions listed (the status block `blocked`, the reason naming the CAPs) before any dev session; the launch's advisory row names the stories still without a plan

AC2. **Given** a paused run resumed after an operator answer **When** the resumed run lands commits for more than one story (the 34.5 shape) **Then** the gate writes a result file per story and each spec gets its `## Reconcile`, the close-out writes one `job-run` ledger line per story (the cost split by the engine's per-story turns, or one line naming both with the cost) and the PR body lists both; or the supervisor refuses a resume that would cross a story boundary with the reason and the graceful stop re-armed — the planner picks one and the contract names it (0.1.30, additive)

AC3. **Given** the lib suite, the supervisor suites and conformance **When** they run **Then** the plan-per-story rule, the refusal and the per-story records are covered with fakes; the runbook's rule "never amend after a resume" stays and its row points at this story; DW-79 and DW-83 close by this PR

## Settled shape

- CAP-3: the launch's open-question refusal, a named placeholder rule. `launch.py check` adds a gap `open questions` for the story the launch will start (the first manifest entry whose spec is not `status: done`) when one of its CAPs has a `- CAP-N:` line under `## Open Questions` and no bullet under `## Design notes (settled shape, planner, …)` names that CAP or the story. The detail is `<story id>: CAP-N has no design note — <question, clipped>` (`; ` between CAPs), so `check_block` makes the status block `blocked` with every CAP in the reason before any engine starts. A later story's un-noted CAPs never make a gap. They appear in the advisory row below, and the gate's planning of that story (task-planning §3) notes them or escalates. So earlier stories proceed. This resolves the CAP-3 open question (only that story blocks, and only when it is next). Basis: epics.md Story 35.2 AC1 ("the status block `blocked`, the reason naming the CAPs … before any dev session"), the launch's `check_block` (launch.py:647-660) and the substrate's one-story-at-a-time cadence. Appended to SPEC.md.
- CAP-3: the plan-coverage advisory row, a named placeholder rule. The row is `story plans`, `ok: True`, after `playable path`. Its detail is `all <n> planned` or `without a plan: <id>, …` (manifest order), followed by `; un-noted open questions: CAP-N (<id>), …` when a later story has some. It never becomes a gap. The bootstrap (task-planning §1) writes `plans/<N>-<M>.md` for every entry in list order, each with a Code Map and a `band`. The launch commit names every plan it wrote. Basis: AC1 ("the launch's advisory row names the stories still without a plan").
- CAP-4: the planner's pick is the refusal, never per-story records, as a named placeholder rule.
  - **When it applies.** A graceful stop is in force when the paused engine's run dir holds `stop-request.json` with `mode: "graceful"`. It is read before the archive step.
  - **The relaunch.** In `closeOutLanded`, with a stop in force, the commit, the meter and `noteEngineCost` still run, so the landed story keeps its harvest commit and its metered cost. The archive and the relaunch do not run, and the run stays `paused`. The pass records one event `story-boundary` `{story_key, engine_run_id, code: "StoryBoundary", reason: "a graceful stop is in force (requested <at>): relaunching would start the next story in this run", graceful_stop: "kept"}` and one notifier line. It records the event only once since the run's latest `paused`, and the pass skips that run afterwards.
  - **`POST /runs/{id}/resume`.** On a story that has not landed, with a stop in force, the resume re-issues `launchStopGraceful` on the resumed engine once its pid is read. It records `graceful-stop` `{engine_run_id, rearmed: true, ok, detail}`. Its answer is unchanged.
  - **Records.** No `job-run` line per story, no PR-body change, no gate per story.

  Basis: epics.md Story 35.2 AC2 (the refusal half), DW-83, runbook :1577 and closeout.ts:368-401. Appended to SPEC.md.

## Risks and open decisions

- **oversize**: 14 files plus a fixture, across lib, the skill, the gate plugin's planner text, the supervisor, the contract, conformance and two ledgers. The code itself is M-sized: one parser and two rows in launch.py, one guard and one re-arm in closeout.ts. Halt (the `halt` consult) if the Files list grows past this; never split the story.
- Block If the dev session finds the refused relaunch's run cannot be ended by the operator's existing verbs (`POST /runs/{id}/cancel` from `paused` closing out with its PR and the job-run line) without a new state or verb. Consult (`deviation-gt-0`); never invent a state.
- Block If `stop-request.json` turns out not to be the engine's only record of a graceful stop, for example if `bmad-loop resolve --resume` clears it or `state.json` carries the stop instead. Read the pinned bmad-loop's run-dir writer before relying on the file, and consult if the source differs. Never call bmad-loop internals.
- Block If a test or a reader pins the bootstrap commit message `…first-story plan…` outside the Files list (grep first). Changing it outside Files is a deviation.
- `.bmad-loop/plugins/studio-pipeline/task-planning.md` is the gate plugin's planner text, which every later gate session reads. Change only §1, §3's open-question rule and §4's finish line, and keep `test_planner_rules.py` green.
- The SPEC parser must handle Epic 34's and 35's real SPECs (the two design-note heading dates, the `resolves the CAP-N open question` tails) and a SPEC with no `## Open Questions` (no gap). Run `check` against `spec-epic-35` and record its output in the Auto Run Result. After this gate, CAP-7 (35.4) is the only un-noted CAP, and it must show in the advisory row, never as a gap.
- AC2's per-story-records half is deliberately not built (the planner's pick). The contract paragraph names the refusal and says so.
