## Intent

33.8's verify verb (`POST /runs/{id}/verify`, `bun src/cli.ts verify <id>`) re-runs the host leg in a throwaway `.verify` worktree, removes it, and on green only flips a draft PR ready: it never edits the PR body (so 4 of Epic 34's 7 PR bodies read Red at merge, hole 88 / DW-82) and never commits the art and proof a slice re-run places (DW-76, B9). This story makes the re-run a whole leg: it reuses the close-out's own motions (`proofCommit` on a slice run, `prBody`/`prSection` for the body) so a green re-run commits and pushes placed art and proof on the run branch, rewrites the PR body's `## Host verify` section and status block with the latest leg (a one-line history of the legs kept), marks the PR ready and records `rerun: true`; a red re-run rewrites the section red, leaves the PR a draft and says why. Contract 0.1.30 opens Epic 35's entry, additive.

## Acceptance Criteria

AC1. **Given** a run whose close-out ended `partial` on a red host leg and a fix pushed to its branch **When** `POST /runs/{id}/verify` runs the leg green **Then** the PR body's `## Host verify` section and its status block carry the latest leg's result (the first leg's text replaced, a one-line history of the legs kept), the PR is marked ready, and the `host-verify` event names `rerun: true`; a red re-run rewrites the section red, leaves the PR a draft and says why (`apps/supervisor/src/hostleg.ts:20, :108`)

AC2. **Given** a slice run (`type: run-vertical-slice`) **When** the re-run's assets step places art or its playable step writes proof **Then** the re-run commits and pushes them on the run's branch as the close-out does (`host leg: placed assets and proof (run <id>)`, `worktree.ts proofCommit`), so the `.verify` worktree is no longer throwaway for a slice (DW-76 decided: the re-run is a whole leg), and the per-leg proof store (`<store>/sheets/`, 34.8's DRIFT) is read by the closeout and the PR body the same way

AC3. **Given** the supervisor suites and conformance **When** they run **Then** the body rewrite, the slice re-run's commit and the ready/draft transitions are covered with fakes (`test/hostleg.test.ts`, `test/worktree.test.ts`, the `e2e_vertical_slice` drive); the contract (0.1.30, additive) names the re-run's commit and the PR-body rule; DW-76 and DW-82 close by this PR

## Settled shape

- CAP-1 — `rerun: true` on the re-run's `host-verify` event: optional entry: the event keeps its 0.1.28 member `rerun {by, head, worktree, pr, pr_ready?}` (present on a re-run leg only, absent on the close-out's leg: a reader's `rerun: true` is that member's presence, `!!event.rerun`, and the cli verb prints `rerun: true` beside its fields) and the object gains `commit?: {sha, frames, sheet?} | "skipped: <why>" | "error: <clipped>"` (the slice commit), `pushed?: "<branch>" | "error: <clipped>"`, `pr_body?: "edited" | "error: <clipped>"` and `pr_draft?: "undone" | "already" | "not open" | "error: <clipped>"` (the red flip); `pr_ready?` keeps its 0.1.28 values on green — per `plugins/tk-studio/contracts/driver-contract.md` 0.1.28 paragraph (`rerun {by, head, worktree, pr, pr_ready?}`) and `kb/agent-pc-setup-runbook.md:1292`. Appended to SPEC.md design notes.
- CAP-1 — the one-line history of the legs: named placeholder rule: the first line under `## Host verify` is `Legs: <k> — ` followed by one entry per leg, oldest first, joined by `; `: `close-out <green|red|skipped> <recorded_at>` for the leg the close-out ran, `re-run <green|red|skipped> <recorded_at> (by <api|cli>)` for each `rerun`; `<k>` the count; the legs are the run's `host-verify` events after its latest `launched` (the `recordedVerify` rule) plus the one being written; a leg recorded before 35.1 renders the same way (its `recorded_at` is the event's). Then the latest leg's section as `prSection` renders it today. A close-out's first body carries `Legs: 1 — close-out <verdict> <at>` so the two renderers are one — per epics.md Story 35.1 AC1 ("the first leg's text replaced, a one-line history of the legs kept") and driver-contract 0.1.28 (`rerun {by, head}`).
- CAP-1 — "its status block": named placeholder rule: the PR body's `## Launch status block` is re-rendered by `prBody` from the record (`launchedCloseOutInput`: the launch's block, the engine run id, the recorded cost), its content unchanged unless the record changed; no new field is added to the fenced block — the latest leg's result is the `## Host verify` section's. Per driver-contract 27.4/0.1.28 ("the body regenerated with its `## Host verify`").
- CAP-2 — when the re-run commits: named placeholder rule: exactly the close-out's condition (`worktree.ts:545`: a slice run, a ran leg, `assets.verdict === "green"` — a `fault` row counts green), through the same exported `proofCommit`, before the push and the body edit, on pass and fail of the playable step alike; a red slice re-run (`verify.host` or the engine red) places nothing and commits nothing; a commit or push failure is the event's `rerun.commit: "error: …"` and the leg still records, the PR left as it was — per driver-contract "The slice's host leg (0.1.29, Story 34.8)" ("After a green (or fault) assets step the close-out copies … and commits"). 35.3 widens the condition to "whenever `report.json` exists" in that one place.
- CAP-2 — the cut: named placeholder rule: `<run.worktree>.verify` is cut on the local branch `supervisor/run-<id>` reset to the remote tip (`git worktree add --relative-paths -B <branch> <path> <tip>`; a stale local branch from a kept worktree is moved, never a second worktree on it — if `git worktree add` refuses because another worktree holds the branch, the re-run is `VerifyFailed` naming it) so `proofCommit`'s branch check and `git push origin <branch>` (never forced) hold; a non-slice re-run uses the same cut (one motion), commits nothing — per driver-contract 0.1.28 (the cut "at the tip of the run's pushed branch").
