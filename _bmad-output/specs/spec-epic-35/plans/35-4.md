## Intent

Story 34.5's per-run engine MCP has fixed ports. The server is on `engine.mcp.port` (8000 on TUA) and the forwarder on `TK_SUPERVISOR_ENGINE_MCP_PORT` (default 8788), so a second flagged run on the box fails `engine-mcp:start-failed`. The start is also recorded only after the three children are `unref`'d, and a failed record is swallowed, which leaves orphans. Nothing warns when a project's start line lacks the verify-only allowlist, and the 34.5 spec never proved that the sandbox reaches the forwarder.

This story does five things (the retro's B6, B7, AI-5; DW-83's 34.5 debt):
- resolves per-run ports;
- records the start before letting go of the children, and kills them on a failed record;
- names the stop on the release events;
- adds the `--exclude-domains` advisory to `launch.py check` and to the pin;
- asks the operator, through the consult log, for the TUA reachability proof.

Contract 0.1.30 gains an additive Story 35.4 paragraph. Repo: tk-studio (`apps/supervisor`, `plugins/tk-studio/lib`, the contract, `kb/`).

## Acceptance Criteria

AC1. **Given** a flagged run's pin **When** the MCP starts **Then** the forwarder and the server take free per-run ports (`port: 0` resolved, `{port}` substituted into `engine.mcp.start`; `env.ts:117-124`, `enginemcp.ts:410`), two flagged runs on one box no longer serialise into `start-failed`, the start is recorded in the queue before the three children are `unref`'d (`enginemcp.ts:447-449`), a failed `queue.note` kills them and ends the pin with the reason, and the release stops them and the event says so

AC2. **Given** a project's tracked config **When** `tk-studio-launch check` or the pin reads an `engine.mcp.start` without `--exclude-domains` (or the server's equivalent filter) **Then** an advisory names the verify-only rule (`kb/engine-mcp-godot.md`) and the run proceeds; the contract (0.1.30, additive) names the per-run ports and the advisory

AC3. **Given** TUA on the box **When** the operator runs one flagged run at the engine's request through the consult log **Then** the sandbox's call reaches `127.0.0.1:<port>/mcp` through the forwarder behind the per-run bearer (the reachability proof the 34.5 spec left open) and `kb/engine-mcp-godot.md` records it; the supervisor suites cover the ports, the record-before-unref and the kill with fakes

## Settled shape

The SPEC design notes (`## Design notes (settled shape, planner, 2026-10-27)`, appended 2026-10-29 by the 35-3 gate) are binding:

- **CAP-7, fixed port.** A fixed port is kept as the pin, and `port: 0` is the per-run opt-in. A set `TK_SUPERVISOR_ENGINE_MCP_PORT` keeps the forwarder fixed; unset means a per-run forwarder port. This resolves SPEC Open Question CAP-7.
- **CAP-7, the events.** `engine-mcp-start`/`-stop` gain `port`, `forwarder_port` and `ws_port?`. `pin-released`/`pin-kept` gain `engine_mcp?: "stopped" | "stop pending"`. The start is recorded before the unrefs, and a failed record is `engine-mcp:start-failed` (`the start could not be recorded: …`) with all three killed.
- **CAP-8.** An optional `engine.mcp.filter` (default `--exclude-domains`). The advisory row `engine mcp` comes after `story plans` and is never a gap. `engine-mcp-start` gains `advisory?`.

Planner rulings beyond the notes:
- `{ws_port}` is resolved like `{port}` only when the start line carries it. A start line with `port: 0` but no `{port}` is `engine-mcp:no-config` (`engine.mcp.start has no {port} for port: 0`): the server cannot be told its port.
- A resolved port is free only at the moment of resolution. The existing `portAnswers` pre-check and `awaitPort`'s "another listener answered" detection stay as the race guards.

## Risks and open decisions

- Block If the godot-ai add-on in the editor cannot follow a non-default WebSocket port (`{ws_port}`). The kb's launch shape says that the add-on "adopts the running server", and nothing says how it finds the server's port. Two concurrent real runs would then still collide on 9500. Keep the fakes' two-run test (the AC's bar), record the gap in the kb and the 35.4 paragraph as `measured on the box only`, and consult rather than inventing an env var.
- Block If the sandbox's network policy allows the tailnet address per port, not per host (runbook §3.8, `:1412`). A per-run forwarder port would then be unreachable without a policy change, and the loop never changes sbx network policy. Consult. Do not fall back to a fixed port silently.
- Block If moving `queue.note` before `unref` changes what `recoverEngineMcps` sees for a start whose note succeeded and whose process then dies before `unref`. Recovery already kills a recorded start whose driver is gone, so this should hold. Confirm it with the `consult ruling 2` tests (`enginemcp.test.ts:535-610`).
- Do not touch the 0.1.29 Story 34.5 contract sentences pinned by `test_driver_contract.py`. Name the new behaviour in the 35.4 paragraph only, as 35.3 did for `inconclusive`.
- 35.3 has landed (its 0.1.30 paragraph at `:1767`). Place 35.4 after it; never reorder earlier paragraphs.
