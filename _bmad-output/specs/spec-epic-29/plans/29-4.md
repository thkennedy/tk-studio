## Intent

AD-2 says the plugin publishes the contract and the supervisor owns its own surfaces. Stories 29.1–29.3 added supervisor surfaces the studio web of EP-30 will consume: the account, the registry and the office projection. The driver contract does not name them yet, and it does not name the web as a consumer. This story is docs and tests only. It makes an additive contract bump that names the studio web in §1 and documents those surfaces as the supervisor's, never the plugin's. It then brings runbook §4.2, §4.5 and §7, and the supervisor README's API and environment tables, into line with the code. No code changes, and `tk-studio doctor` is unchanged.

## Acceptance Criteria

AC1. **Given** `plugins/tk-studio/contracts/driver-contract.md`, **when** the story closes, **then** a minor bump (the next after Story 28.6's) names the studio web among the consumers in §1 and documents, as supervisor surfaces consumed by the web and never plugin surfaces, the account (`POST /auth/account`, `POST /auth/signin`), the registry (`GET /agents`) and the projection (`GET /office`, `GET /office/events`, the three `office.*` event kinds and the eight states); nothing in the plugin's own surfaces changes; conformance is green and the lib suite is green.

AC2. **Given** the operator's runbook and the supervisor's README, **when** the story closes, **then** runbook §4.5 (the smoke test) signs in with the account and keeps the token path for `curl`; §4.2's table drops the OAuth rows and names nothing new that is a secret (the account record is the store's); §7's smoke table gains the `/agents` and `/office` answers; the README's API table and environment table match the code; `tk-studio doctor` is unchanged.

Story 28.6 landed 0.1.23 on `main` (`52960b4`), but this run branch was cut before it, so its header still reads `**0.1.22**`. Merging main brings 28.6's 0.1.23 clause between them, and the test slices must not depend on 0.1.23 being absent or present.
- **What the contract documents about the projection** (optional entry): the eight states, the three kinds, the `event:snapshot` first frame, ids `<boot>-<seq>` with `Last-Event-ID` replay (the snapshot again when the id is too old or from another boot), the 10 s heartbeat, and `overlay: "done"|"failed"|null`. Also the landed rules from the 29-3 reconcile, stated in full or by a link to the README bullet:
  - (a) `office.agent` may repeat a state when only `current_run`/`current_story` changed. A new run sends an epic-only `office.progress` beside its `office.run`. An agent leaving the registry gets no event, and only the next snapshot drops it.
  - (b) Run selection per project: the newest `paused` live run, else the newest non-queued live run, else the newest queued live run, else the latest run when `blocked`.
  - (c) The `thinking` launch leg covers a run with no `launched` yet, or none since the latest `close-out`/`engine-resume`. The host-verify `running` state needs a `launched` with no `host-verify` after the latest one.
  - (d) Progress is `done / total`. The denominator is fixed at the first `stories-validated`. `done` comes from the journal's terminal kinds and, after a relaunch, from a manifest story whose story spec is `status: done`. The journal wins.

  Out of the contract: `OFFICE_MAP`'s `when`/`signal` columns and the helper exports (`OFFICE_RANK`, `mapRoles`, `selectRun`, `engineRunDir`, `LIVE_RUN_STATES`, `officeStates`, `officeCachedPaths`, `specsDone`, `launchedSinceMove`).
- **Section placement** (named placeholder rule): a new §1 subsection after the Driver roster, titled with its version (the `(0.1.22)` subsections' convention). It opens by stating that these are supervisor surfaces (AD-2): the plugin publishes their description, but neither implements nor serves them. Response shapes may be summarized and linked to `apps/supervisor/README.md` rather than copied in full.
