## Intent

After the merge, `apps/supervisor` is a nested studio project inside tk-studio (AD-21). Today every surface takes the root from whatever `--directory` the model fills in. There is no walk-up, so from inside the nested folder nothing reliably finds the nested root. This story adds one nearest-root rule in `lib/config.py`: the project root is the nearest ancestor-or-self holding `.tk-studio/config.yaml`, and the studio root is the outer home. Every listed surface uses the rule, activation reports both roots and names a nested project, the pipeline plugin's nested copy is pinned, and the driver contract states the rule. This lands before the merge, so it changes only tk-studio, and the fixtures stand in for `apps/supervisor`.

## Acceptance Criteria

AC1. **Given** a working directory inside `apps/supervisor` **When** any surface resolves the project root (activation and the drift check, `config.py resolve`, `plansync`, `jobrun`, `meter`, `observe`, the registry, the launch skill) **Then** the nearest ancestor holding `.tk-studio/config.yaml` wins (the nested root), never the outer one; `TK_STUDIO_ROOT` keeps meaning the outer repository root, the plugin's home; activation reports both and names the project nested

AC2. **Given** the supervisor's tracked `.tk-studio/config.yaml` carrying `project_id: supervisor` **When** the registry entry's `root` is amended to the nested root (`registry.py amend`) **Then** `registry.py show`, activation and the launch skill agree on the root; the store paths stay per project (`~/.tk-studio/projects/supervisor/`), the nested project's plan counter and `plansync` never mint into the outer project's counter, and nothing of the outer project's store is read or written from the nested root

AC3. **Given** `apps/supervisor/.claude/settings.json` and `apps/supervisor/.bmad-loop/plugins/studio-pipeline/` **When** a Claude session or the engine starts in the nested root **Then** `$CLAUDE_PROJECT_DIR` is the nested root, the hooks resolve their scripts relative to it, and the pipeline plugin copy names the spine and the driver contract by a path relative to the nested root (`../../_bmad-output/...`, `../../plugins/tk-studio/contracts/...`) so `$TK_STUDIO_ROOT` is no longer required inside the microVM; the two copies of `task-planning.md`, `consult.md`, `gate.md` and `reconcile.md` differ only in those paths and the project's name, and a lib test pins that

AC4. **Given** the lib suite and conformance **When** they run **Then** nested-root resolution is pinned for every surface above with a fixture holding an outer and a nested project, the drift check reports a nested root distinctly, and the driver contract states the nearest-root rule in a minor bump

## Risks and open decisions

- **Oversize.** About 20 files, past band L's stated reason (one rule applied across eight surfaces plus contract, conformance and the renderer). The plan does not split the story. Halt if the Files list grows past the list above; that would be a `bmad-correct-course` for the operator.
- **"Minor bump" against the contract's change policy.** The policy (`driver-contract.md` §Change policy) makes an additive rule a patch bump (`0.1.21 → 0.1.22`). `0.2.0` is reserved for breaking changes. SPEC's constraint reads "a minor, additive bump". Planner reading: ship `0.1.22, additive` and record a `DRIFT:` line, affects none. Block If: making the rule work requires changing an existing payload field's meaning (for example, a given `--directory` that is itself a root resolving elsewhere). That would be breaking: halt and consult, and never pick `0.2.0` alone.
- **ADR gate 5 against AC3.** The ADR's sealed-plugin rule says "the supervisor consumes the contract through `TK_STUDIO_ROOT` and the released surface, never a relative path into `plugins/tk-studio`" (adr-repository-structure §3 gate 5). AC3 asks the pipeline copy's prose to name `../../plugins/tk-studio/contracts/...`. Planner reading: gate 5 governs code and conformance consuming the contract. A markdown pointer an agent reads is not consumption, and the AC is the newer, literal text (D3 as amended 2026-10-16). Flagged for the operator. Block If: any supervisor-side code or test (not prose) would need a relative path into `plugins/tk-studio`.
- **Pending SPEC.md bullets.** The two bullets in "Settled shape" were not appended, because gate sessions may not write SPEC.md. The operator appends them to `## Design notes (settled shape, planner, 2026-10-16)`.
- **The supervisor's current pipeline copy is not visible here.** Per `kb/agent-pc-setup-runbook.md:743-757` it is adapted "for a non-Python repo". Any difference beyond paths and name is lost when the merge writes the rendered copy. The operator checks this in the merge PR.
- **The supervisor's own `_bmad/custom/bmad-build-auto.toml`** resolves the studio root as env var, then project root, then registry (tk-studio's copy, `:25`). That copy is not in this repository, so it is out of reach here; it is 28.3's or the merge's. Not a Block If.
- **What stops the run after this story.** Story 28.3 needs the merged tree (SPEC Open Question 2). After 28-2 commits, the next gate will plan 28-3 on a pre-merge tree. The operator should stop the run after 28-2.
- **Block If:** a surface can only reach the nested root by reading or writing the outer project's store or counter, or the work needs a registry-schema field. In either case, halt.
