## Intent

The supervisor's move into `apps/supervisor` (AD-21, ADR §5) must be a replay of a passed rehearsal, never an improvisation. This story writes `tools/restructure/rehearse.py`: a stdlib script that clones both repositories into a scratch folder it creates, rewrites the supervisor's history under `apps/supervisor/`, merges it into the tk-studio clone on `restructure/supervisor-into-monorepo`, runs the ADR's checks on the merged clone, and writes a report ending in one verdict line. The lib suite pins it against a fake pair of small repositories. Running it on the real repositories is the operator's step and is `unverifiable-here` for this story.

## Acceptance Criteria

AC1. **Given** a fresh `git clone --no-local` of the supervisor repository and a fresh clone of tk-studio, both in a scratch folder the script creates, **when** `tools/restructure/rehearse.py` runs (stdlib Python; `git` and `uvx git-filter-repo` through subprocess argv, never a shell), **then** it rewrites the supervisor clone's history under `apps/supervisor/` with `git filter-repo --to-subdirectory-filter apps/supervisor`, asserts there are no tags and no signed commits to lose and no `node_modules` path anywhere in the rewritten history, fetches the rewrite into the tk-studio clone on branch `restructure/supervisor-into-monorepo`, merges it with `--allow-unrelated-histories`, and asserts the merge produced no conflict (every path is new).

AC2. **Given** the merged clone, **when** the checks run, **then** the report records each with its exit code, duration and last output lines: `tk activate` clean from the nested root `apps/supervisor` (the plugin's own entry point); `bmad-loop` finds its run workspace from the nested root; the supervisor's `bun test` passes from `apps/supervisor`; tk-studio's `tools/verify_host.py` passes from the repository root; the four loop hooks of `apps/supervisor/.claude/settings.json` fire with `$CLAUDE_PROJECT_DIR` equal to the nested root; the size of the clone after the merge (the design spec's open question).

AC3. **Given** a check the script's host cannot run (a Windows-only check inside the Linux engine; a Claude session's hook firing where no session can start), **when** the report is written, **then** the check is listed under `unverifiable-here` with the exact command for the agent PC, never as a pass, and the script's exit status does not count it as failed.

AC4. **Given** the report `_bmad-output/implementation-artifacts/restructure-rehearsal-<date>.md`, **when** the script ends, **then** it follows the order of ADR §5 steps 1 to 5, ends with a one-line verdict (`rehearsal passed` or the first failed step), the script exits non-zero when any step or check failed, it never touches `C:\GitHub\tk-studio`, the live supervisor checkout or any remote, and the lib suite pins it against a fake pair of small repositories (a fake `git-filter-repo` only where the real one is unavailable).

## Code Map

- `_bmad-output/planning-artifacts/briefs/adr-repository-structure-2026-10-09.md` §5: the step list the report follows (1 freeze, 2 rewrite, 3 merge, 4 nested project checks, 5 sandboxes) and the exact commands. Steps 1 and 5 hold operator/sandbox actions: the report lists them with what the script checked (step 1: the source clones are fresh and taken with `--no-local`; `core.longpaths` is read, never set, and its absence on Linux is `unverifiable-here` with `git config --global core.longpaths true` for the agent PC) and what it cannot (step 5's sandbox provisioning is `unverifiable-here` with the runbook command).
- `tools/verify_host.py`: the shape to copy. Stdlib, argparse, `subprocess.run(argv, cwd=..., capture_output=True, text=True, encoding="utf-8", errors="replace")`, `time.monotonic()` durations, a tail of N lines, `FileNotFoundError` → rc 127 with a named message. `ROOT = Path(__file__).resolve().parent.parent` is the pattern; rehearse.py lives one level deeper (`tools/restructure/`), so its repository root is `parents[2]`. Its check command from the merged clone's root is `uv run python tools/verify_host.py`.
- `tk activate` = `plugins/tk-studio/skills/tk-studio-activate/scripts/drift_check.py --directory <nested root>`, run with `uv run` from the merged clone's **own** `plugins/tk-studio` (the plugin's own entry point, not the installed skills dir). "Clean" = exit 0 and JSON `result` not `drift`/`error`; record `result` and `fixes[]` verbatim. Before Story 28.2 lands this check is expected to report the outer root; that is a recorded failure, not a script bug (SPEC assumption).
- `bmad-loop` workspace: `bmad-loop list --json` with `cwd` = the nested root (its `--project` defaults to cwd); pass = exit 0 and the JSON parses. Also run `bmad-loop validate --project <nested> --json` and record it (informational; a dirty-tree line is expected in a scratch clone and is not a failure).
- `bun test` from `apps/supervisor`: `bun` is absent on this host (`which bun` empty in the engine unless `WITH_BUN=1`); a missing executable is `unverifiable-here` with the agent-PC command `cd C:\GitHub\tk-studio\apps\supervisor; bun install --frozen-lockfile; bun test`, never a pass and never a failure.
- Hooks: read `apps/supervisor/.claude/settings.json` in the merged clone, enumerate the `hooks` entries (expect four). Verifiable here: each hook command's script path, with `$CLAUDE_PROJECT_DIR` substituted by the nested root, exists in the merged clone (static check, recorded per hook). The live firing needs a Claude session: `unverifiable-here` with the command (start `claude` in `C:\GitHub\tk-studio\apps\supervisor`, trust the folder, run one prompt, confirm each hook's marker/log). Never execute a hook command.
- Clone size: `git count-objects -vH` in the merged clone plus the total bytes of its working tree (excluding `.git`) and of `.git`; recorded, never a pass/fail.
- `uvx git-filter-repo`: `uvx` is not on this host's PATH, `uv` is (`/usr/local/bin/uv`). Resolve the filter-repo argv in order: `--filter-repo <argv0>` flag (tests point it at the fake) → `git-filter-repo` on PATH → `uvx git-filter-repo` when `uvx` exists → `uv tool run git-filter-repo`. Record which one ran.
- History assertions after the rewrite (all through `git` argv in the rewritten clone): tags `git tag --list` empty; signed commits `git log --format=%G? --all` has only `N`; `node_modules` absent: `git log --all --name-only --format=` contains no path segment `node_modules`; rewritten paths all start `apps/supervisor/` (`git ls-tree -r --name-only HEAD`).
- Merge: in the tk-studio clone `git checkout -b restructure/supervisor-into-monorepo`; `git remote add svc <rewrite dir>`; `git fetch svc`; `git merge --allow-unrelated-histories --no-edit svc/<branch>` (branch = the rewrite's HEAD branch, default `main`, flag `--supervisor-branch`); conflict check = merge rc 0 and `git diff --name-only --diff-filter=U` empty; then `git remote remove svc`. Commits in scratch clones need an identity: pass `-c user.name=rehearse -c user.email=rehearse@localhost` per command, never touch global config.
- Safety guard: refuse (exit 2, named reason, before any write) when the scratch folder or the report path resolves inside either source, when a source is a URL other than a local path or `file://` and `--allow-remote-source` is absent (the rehearsal reads remotes only by cloning, never pushes or fetches into them), or when `--scratch` resolves to/inside `C:\GitHub\tk-studio`, `/c/GitHub/tk-studio` or the given supervisor checkout. Every git command in the script carries `cwd` inside the scratch folder; the script never runs `push`, never adds a remote except the local `svc` remote inside the scratch clone, and removes `origin` from both clones right after cloning (filter-repo does it for the rewrite).
- Report location: default `<repo root of the script>/_bmad-output/implementation-artifacts/restructure-rehearsal-<UTC YYYY-MM-DD>.md`, overridable with `--report` (tests point it into a temp dir). Written atomically (temp + `os.replace`). Sections in ADR §5 order: `## Step 1 — Freeze`, `## Step 2 — Rewrite`, `## Step 3 — Merge`, `## Step 4 — Nested studio project`, `## Step 5 — Sandboxes`, then `## unverifiable-here` (each with its exact agent-PC command), then the last line `Verdict: rehearsal passed` or `Verdict: failed at <step/check>`. Each check row: name, command, cwd (relative to the scratch folder), exit code, duration, last N output lines in a fenced block.
- Exit codes: 0 rehearsal passed; 1 a step or check failed; 2 refused before starting (guard, bad args). A step 2/3 failure stops later steps (they are reported as `not run`).
- `plugins/tk-studio/lib/tests/test_release_roster.py:32`: the precedent for a lib test importing a repo-side tool, `sys.path.insert(0, str(PLUGIN_ROOT.parents[1] / "tools"))`. For this story insert `tools/restructure`.
- `plugins/tk-studio/lib/tests/test_installer_apps.py:282`: the socket guard pattern; the new test applies the same guard (no network).
- `plugins/tk-studio/lib/tests/test_utf8_guard.py`: its static sweep covers lib and skills scripts; give `rehearse.py`'s `main()` the same `sys.stdout.reconfigure(encoding="utf-8")` guard anyway (house rule AD-11).
- No test in the suite builds git repositories yet: the new test builds them with real `git` (present: 2.53) in a `tempfile.TemporaryDirectory`, with `-c` identities, `GIT_CONFIG_GLOBAL=/dev/null`-style isolation via env (`GIT_CONFIG_NOSYSTEM=1`, `HOME` = temp dir) so the developer's config never leaks in.

Story-specific (inside the new test, no network): a fake supervisor repo (a few commits, a `.gitignore` naming `node_modules/`, a `.claude/settings.json` with four hooks whose scripts exist, a `package.json`) and a fake tk-studio repo (a few commits plus a minimal `tools/verify_host.py` stub that exits 0 and a stub `plugins/tk-studio/skills/tk-studio-activate/scripts/drift_check.py`) with a fake `git-filter-repo` executable (a small Python script that performs `--to-subdirectory-filter` for the fake's simple history, e.g. by rebuilding commits with `git read-tree --prefix`/`commit-tree`) used only when the real one is absent. Cases:

- happy path: exit 0, report sections in ADR §5 order, last line `Verdict: rehearsal passed`, branch `restructure/supervisor-into-monorepo` exists in the scratch tk-studio clone with every supervisor path under `apps/supervisor/`; `bun` absent → listed under `unverifiable-here`, exit still 0; hook live-firing under `unverifiable-here`.
- a tag in the supervisor fake → exit 1, `Verdict: failed at Step 2 — tags present`.
- a commit adding `node_modules/x.js` in the fake's history → exit 1 naming the `node_modules` assertion.
- a tk-studio fake already holding `apps/supervisor/<same path>` → merge conflict → exit 1 naming Step 3.
- a failing check (stub `verify_host.py` exits 1) → exit 1, `Verdict: failed at Step 4 — verify_host`, the check's exit code and tail in the report.
- guard: `--scratch` inside a source → exit 2, nothing written; the source repos' HEAD, refs and remotes unchanged after every case (compare `git for-each-ref` before/after).
- the argv-only rule: a static assertion that `rehearse.py` contains no `shell=True` and no `os.system`.

## Risks and open decisions

- Size: two new files, well over 300 new lines between script and test — band L by line count (the script is one coherent unit; splitting it would cut the report from its checks). If the Files list grows past these three files, halt: that is scope creep, not this story.
- Writing a fake `git-filter-repo` that rewrites history correctly is the fiddliest part; keep the fake history linear and tiny. If the real `git-filter-repo` is importable/on PATH in the engine, the test prefers it (AC4).
- The real rehearsal run (on `thkennedy/tk-studio-supervisor` and this repository) is the operator's, after Story 28.2: record it as `unverifiable-here` in the Auto Run Result with the command `uv run python tools/restructure/rehearse.py --supervisor C:\GitHub\tk-studio-supervisor` on the agent PC. Never clone a GitHub remote from the lib suite.
- Block If: an AC can only be met by writing outside the scratch folder other than the report, by setting global git config, or by executing a hook command — consult; never do it.
