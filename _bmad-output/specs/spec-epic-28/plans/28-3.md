## Intent

The attended merge PR (ADR §5 steps 1 to 3 and 7) puts the supervisor's rewritten history under `apps/supervisor`. This story makes the merged tree point only at itself. It does the ADR §5 step 3 fix-ups on the merged `main`: the root `.gitignore`, README and the two runbooks, `release_archive.py --app supervisor` reading `apps/supervisor` (ADR §6 second prefix), the one-mount engine sandbox (`launch-epic.sh`, `resume-run.sh`, `provision-engine.sh`), and both host gates green. It runs in the **second launch**, on the merged tree only. On a pre-merge tree it has nothing to fix up (epic narrative: "Stories 28.3 and 28.4 on the merged tree").

## Acceptance Criteria

AC1. **Given** the merge landed on `main` through the attended PR **When** the fix-ups are applied **Then** the root `.gitignore` carries the supervisor's ignore entries under `apps/supervisor/`; `README.md`, the runbook §3.8 and §4 and the offline-install runbook point at `apps/supervisor`; `tools/release_archive.py --app supervisor` reads `apps/supervisor` in this repository (the second prefix, ADR §6) and both rosters' supervisor entries drop their foreign `source`; `tk-studio update` on each channel still resolves every component against the rosters' digests

AC2. **Given** the engine sandboxes **When** `claude-tk-studio` is recreated with one read-write mount of `C:\GitHub\tk-studio` and the read-only skills store **Then** `launch-epic.sh` and `resume-run.sh` take `ROOT=/c/GitHub/tk-studio/apps/supervisor` for a supervisor epic and the repository root for a plugin epic; the `tk-studio:ro` second mount is gone from the runbook and the provisioning (`WITH_BUN=1` provisions bun for the nested project); `check-skills-mount.sh` holds; `claude-tk-studio-supervisor` is retired from the runbook; the two loops serialise on the checkout lock

AC3. **Given** the supervisor's own `.tk-studio/config.yaml` (`verify.host: bun test`) and its transcribed plan **When** a supervisor run goes through the supervisor itself **Then** the project served is the nested root and its `verify.host` is the one read at the run's base; `apps/supervisor/_bmad-output/planning-artifacts/epics.md` stays the nested project's transcription (Epics 21 to 23 and 27 keep their numbers) and the repository root's plan stays canonical; the supervisor's `TK_STUDIO_ROOT` is still the outer root

AC4. **Given** the host gates **When** this story's work is verified **Then** `tools/verify_host.py` from the root and `bun test` from `apps/supervisor` are green on both hosts (the Windows run attended), and the old repository's README (one commit there, before archiving) points at `tk-studio/apps/supervisor`

## Risks and open decisions

- **Block If: the merged tree is absent.** If `apps/supervisor/` is missing at the run's base (the attended merge PR has not landed), HALT `blocked` with `28-3 needs the merged tree (attended merge PR, ADR §5 steps 1-3 and 7)`. Write no fix-up against a tree that has no supervisor. The run that planned this story was stopped after 28-2 for this reason (stop request 2026-10-16T21:38).
- **Block If: dropping `source` without a release.** Meeting AC1's "drop their foreign `source`" would need a hand-edited roster or a tag or release on any remote. Never do either; record the AC1 roster clause `unverifiable-here` with the Settled-shape command.
- **Block If: the checkout lock does not serialise.** If the supervisor's checkout lock is keyed by project root rather than the git checkout, two loops in one checkout would not serialise (AC2). Fixing that is supervisor `src` work, outside Files. Consult; a `bmad-correct-course` may be needed.
- **Block If: a fix-up needs a supervisor-side code or test path into `plugins/tk-studio`.** ADR §3 gate 5 forbids it; prose pointers are fine (28-2 reading).
- **The old repository's README** is one commit on `thkennedy/tk-studio-supervisor`. It is outward-facing and on another repository, so the engine never pushes it. List it `unverifiable-here` with its text and the command.
