## Intent
A new `plansync.py publish` verb publishes the project's design pages (brief, GDD, scope of work, decisions) to the folders that 31.2's setup recorded in the Confluence space. Each page is created or updated by a stable title, carries a provenance footer, has its Markdown converted to Confluence storage format with images attached, and is skipped when its content hash is unchanged (§6.8 b, AD-22). `plansync.py sync` keeps promoting epics and stories to Jira as today; each issue description gains links to the published design pages. The plan stays canonical (AD-5): publish only writes to Confluence and to a local page index, and never changes an entity field.

## Acceptance Criteria
- AC1: **Given** the planning artifacts under `_bmad-output/planning-artifacts/` and the design folder **When** `plansync.py sync` runs with the Jira binding (today's promote) and the new `publish` verb runs **Then** each design page is created or updated in the space's folder by a stable title, with a provenance footer naming the source file and the commit, Markdown converted to Confluence storage format (headings, lists, tables, code, links; images attached), and unchanged pages are skipped by content hash; epics and stories promote as before, now with a link to their design pages; the plan stays canonical (AD-5): nothing from Confluence changes an entity field
- AC2: **Given** the publish **When** it is tested **Then** the lib suite covers the conversion, the hashing, the idempotence and the provenance with a fake Confluence REST; the contract's §2 names `publish` (additive)

## Settled shape
- **1. Design-page sources (optional entry; SPEC.md bullet "CAP-5 — design-page sources").** The categories and their default globs, project-relative, case-insensitive on the file name:
  - `brief`: `_bmad-output/planning-artifacts/briefs/*/brief.md`
  - `gdd`: `_bmad-output/planning-artifacts/**/gdd*.md`
  - `scope-of-work`: `_bmad-output/planning-artifacts/**/scope-of-work*.md`
  - `decisions`: `_bmad-output/planning-artifacts/design/*/decisions*.md`
  
  A `--source <category>=<path>` flag (repeatable) replaces a category's default for that run. Each category publishes into the folder recorded at `planning.confluence.folders.<category>` (31.2, Settled shape 1). A category with no source is named in `skipped[]` and is not an error. The `records` folder is not published by 31.3. The stable title is `<Category title>: <slug>`, where `<Category title>` is the `FOLDERS` title (Brief, GDD, Scope of Work, Decisions) and `<slug>` is the parent directory's name when the file is `brief.md`, `README.md` or `index.md`, else the file stem. Two sources with one title are refused by name before any call.
- **2. The content hash and the footer (named placeholder rule; SPEC.md bullet "CAP-5 — publish hash and provenance").**
  - The hash is `sha256` over the title, the converted storage body (footer excluded) and each attachment's `sha256`, in order.
  - The footer is the page's last element, `<p><em>Published by tk-studio from <code>{source}</code> at commit <code>{sha}</code>. content-hash: sha256:{hex}</em></p>`.
  - The skip reads the remote page's storage body (`GET /pages/{id}?body-format=storage`) and compares the footer hash, so no local hash state is needed and a fresh clone stays idempotent.
  - A page edited in Confluence without a matching footer hash is overwritten (AD-5: local wins for published content) and named in `notes[]`.
- **3. The page index the Jira link reads (optional entry; SPEC.md bullet "CAP-5 — published page index").**
  - Publish writes `.tk-studio/confluence-pages.json` atomically: `{"pages": [{"category", "source", "title", "page_id", "webui"}]}`, ids and paths only, never a credential. It is tracked and named in `written[]`; `configlib.assert_tracked_safe` is not needed for JSON, but there must be no token-shaped value.
  - `jirabackend.promote` reads it when present. Each epic's and story's description gains a final line `Design pages: [Title|https://<planning.jira.site>/wiki<webui>], …` covering the project's published pages in index order. The plan has no per-entity page mapping, so "their design pages" means the project's.
  - When the index is absent, the description is unchanged, and an existing project's hashes do not move until publish first runs.
