## Intent
Verify what Jira Free and Confluence Free actually allow before 31.2 to 31.7 build the project template, the two statuses and the sync-back on them (§6.8 "verify before building", decisions Appendix C). Research and record, not code: a chartered `tk-studio-research` run whose graded findings land in the run workspace, then `kb/atlassian-free-tier.md` with each finding's source, date and a fits / fits-with-workaround / does-not-fit verdict, the attended steps and the two token variables named, Appendix C's two rows answered by reference, and each named workaround queued as a story-level note for the story it bends. A documented "does not fit" on the statuses or the API halts the epic with the alternative named.

## Acceptance Criteria
- AC1: **Given** an Atlassian site on the free plans with the owner seat and the agent user seat (created by Tim, attended; the story names the exact steps and the two API tokens' environment variables, never the values) **When** the research runs (the `tk-studio-research` surface, a digest to disk) **Then** `kb/atlassian-free-tier.md` records, with the source and the date: whether a Free Jira project allows the two custom statuses and a workflow transition between them; the project-permission model available (who can transition, comment, attach); the REST API's rate limits and the token's scope; Confluence Free's space, page and attachment limits; and whether the Rovo MCP server adds anything the REST API with an API token does not (the adapter uses REST today); each finding ends in "fits", "fits with a workaround (named)" or "does not fit", and a "does not fit" on the statuses or the API halts the epic with the alternative named.
- AC2: **Given** the record **When** the story closes **Then** `decisions.md` Appendix C's open questions are answered by reference to it, and the stories below carry the workarounds it names (a story-level note, never a silent change).
