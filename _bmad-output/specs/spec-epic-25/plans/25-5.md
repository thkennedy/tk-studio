## Intent

A fresh machine today reaches a working studio only by reading runbook §7 by hand. The meta-CLI landed in 25.4 with a minimal `doctor`: plugin folder mode and supervisor/web slots, no roster comparison, no `/status` probe. This story extends that `doctor`. It runs the runbook's smoke checks and the two trust holes (14 and 15 in the design spec's feature ledger), and for each check reports pass or fail plus the fix. A `--json` headless form ends with the AD-11 status block, and §7 shrinks to the rows the CLI cannot check.

## Acceptance Criteria

- AC1. **Given** `tk-studio doctor` **When** it runs **Then** it checks and reports, each with pass, fail and the fix:
  - Claude Code version against the roster floor;
  - the skills-dir plugin against the roster (Story 25.3's cases);
  - the per-user store;
  - `sbx daemon status` **only** (it never runs an sbx command that would auto-start the daemon);
  - folder trust (`hasTrustDialogAccepted`) for every root in the registry (holes 14 and 15);
  - long paths;
  - the PATH launcher;
  - the Tailscale certificate age against its 90-day life;
  - the supervisor's slot or checkout and whether `/status` answers;
  - and, when a Hermes home exists on the box, whether `auth.adopt_external_logins` is on (a warning that names the setting and the Claude-login risk).
- AC2. **Given** `--json` **When** it runs headless **Then** the output is one JSON object and ends with the status block (AD-11); a conformance drive covers it.
- AC3. **Given** runbook §7 **When** the story lands **Then** its smoke table says "run `tk-studio doctor`" and keeps only the rows the CLI cannot check (RDP scope, the Startup shortcut's visible tab).

## Risks and open decisions

- **oversize.** About 10–12 files, which is past M. Banded L, the stated reason being the shared-module copies plus the conformance extension.
  - Block If: the Files list grows past this plan. Record a deviation and halt; a `bmad-correct-course` split is the operator's call.
- **The AC2 JSON shape.** It is "one JSON object and ends with the status block". The landed JSON line puts extra top-level fields beside `status/intent/artifacts`, which `status-block.schema.json` forbids.
  - Block If: meeting AC2 would need a change to `status-block.schema.json` or to the landed verbs' JSON line. Nest the checks (for example under `checks`) and keep the other verbs unchanged.
- **The conformance drive for a non-skill CLI.** The runner discovers surfaces only from `skills/*/SKILL.md`.
  - Block If: covering the CLI would need a non-additive change to the driver contract's §8 or to the manifest shape. An additive runner section and a 0.1.20 changelog clause are within scope.
- **Sharing the plane and the registry read.** Use the byte-identical stdlib copy rule, never an import from `plugins/` and never a second parser.
  - Block If: the extraction changes the drift check's landed results (25.3's tests pin them).
- **sbx.** Run only `sbx daemon status`, through the runner. Never run any other sbx verb (the auto-start risk).
  - A missing `sbx` is `skipped`, not `fail`.
- **Read-only.** Doctor writes nothing and deletes nothing, not even a leftover `cli-update.cmd`; it only reports it. The only processes it starts are `claude --version`, `sbx daemon status` and `git config --get core.longpaths`, all through the runner. Its only network call is the `/status` probe, through the injected probe.
- **Platform scope.** Windows-only checks (LongPathsEnabled, the Startup shortcut, HKCU) report `skipped: windows only` elsewhere.
- **The Hermes home path.** It is `%LOCALAPPDATA%\hermes`, per `_hermes_pair`. When the folder is absent, the check is not reported.
