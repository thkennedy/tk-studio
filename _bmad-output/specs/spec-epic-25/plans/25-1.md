## Intent

AD-21 needs one source of truth for which app releases go together: a committed roster per channel (`tools/installer/rosters/{stable,latest}.json`) that pins each app's release by tag, URL and SHA-256, and pins uv and Bun by version and SHA-256. The plugin-only `tools/release_archive.py` becomes a single script that cuts any app by its tag prefix with `--latest=false`, verifies the round trip, and records the result in the roster. A lib guard pins the roster's shape. Its `plugin` entry joins the existing version gate, so the gate goes from three files to four. Band L, reason: generalising a 215-line script, two new data files, a guard inside the drift check, and a new test file plus extended tests; about 6 files and more than 300 changed lines.

## Acceptance Criteria

1. **Given** `tools/installer/rosters/stable.json` and `latest.json` **When** they are read **Then** each carries `schema`, `channel`, `requires` (at least `claude-code` as a version floor), and `components` with `plugin`, `supervisor`, `studio-web` and `cli` as `{tag, url, sha256}` and `uv` and `bun` as `{version, sha256}`; a lib guard pins the shape, refuses a missing or malformed digest by name, and asserts the plugin entry agrees with `released-roster.json` and the plugin's `plugin.json` version (the existing gate ×3 becomes gate ×4)
2. **Given** `tools/release_archive.py` **When** it is run with `--app <plugin|supervisor|studio-web|cli>` **Then** it builds the deterministic zip (or wheel, for `cli`) from that app's subtree at the `<prefix>--vX.Y.Z` tag, publishes it with `gh release create --latest=false`, re-downloads and verifies the digest, and records `{tag, url, sha256}` under the right roster component; the plugin's motion is unchanged in effect; `make_latest: false` is asserted by the lib suite against a fake `gh`
3. **Given** the supervisor repository, which has no tags today **When** the story closes **Then** `supervisor--v0.1.0` is cut from its `main` by the operator with the exact commands the story provides (the script runs against that checkout until EP-31), and the roster's `supervisor` entry points at that asset; an entry whose URL is on another repository is allowed by the schema and named in the roster's `source` field
4. **Given** the lib suite and conformance **When** the story closes **Then** both are green, and the roster guard runs in the drift check's plugin plane (Story 25.3 wires the rest)

## Code Map

Investigated 2026-10-14 at `fda7fd5` (branch `loop/epic-25`).

- **`tools/release_archive.py`** (215 lines, plugin only, stdlib). Constants `PLUGIN_SUBDIR = "plugins/tk-studio"`, `ROSTER` (= `plugins/tk-studio/.claude-plugin/released-roster.json`) and `PLUGIN_MANIFEST`. `run(dry_run)` does the following in order:
  1. reads the version from `plugin.json` and checks it against `released-roster.json` `version`, failing before any `gh` call;
  2. checks the tag exists (`git tag -l`);
  3. gets the commit and its epoch;
  4. runs `git -c core.autocrlf=false archive --format=zip <tag>:<subdir>`, then `normalize_zip` (sorted, STORED, `create_system = 3`, commit-dated);
  5. computes the SHA-256;
  6. if the release does not exist, runs `gh release create <tag> --verify-tag --title … --notes …`. **It does not pass `--latest=false` today**: that is the AC2 change;
  7. runs `gh release upload --clobber`, then `gh release download` and re-hashes;
  8. writes `archive: {url, sha256}` into `released-roster.json`.

  The URL is built from `gh repo view --json nameWithOwner`. Every subprocess goes through `_run(args)`, and every failure goes through `_fail(reason)` (JSON `{"ok": false, "error": …}`, exit 1). The CLI is `run [--dry-run]`. Reuse `normalize_zip`, `_sha256` and the verify round trip unchanged. Generalise by an app table: `{app: (tag_prefix, subtree, artifact_kind)}`:
  - `plugin` → `tk-studio--v`, `plugins/tk-studio`, zip;
  - `supervisor` → `supervisor--v`, `.` in its own checkout until EP-31 (later `apps/supervisor`), zip;
  - `studio-web` → `studio-web--v`, `apps/studio-web/dist` (D5: Vite build output), zip;
  - `cli` → `cli--v`, `tools/installer/cli`, wheel via `uv build`.

  `--app plugin` must keep the plugin path byte-for-byte equivalent: same asset name `tk-studio-<v>.zip`, same `released-roster.json` `archive` write, plus the new roster component write.

- **Running against another checkout (AC3).** Add `--repo <checkout path>` (default `REPO_ROOT`), so `git`/`gh` run with `cwd` at the supervisor checkout while the roster write still targets this repository's `tools/installer/rosters/`. `_run` hard-codes `cwd=str(REPO_ROOT)`, so thread the cwd through. The URL comes from `gh repo view` in that checkout (`thkennedy/tk-studio-supervisor`). When that differs from this repository's `nameWithOwner`, write `source: "<owner/repo>"` on the component (AC3).

## Risks and open decisions

- **Block If** the roster must carry `{tag, url, sha256}` for an app that has no release when the story runs. Today that is three of the four:
  - `studio-web`: `apps/studio-web` does not exist; D5 builds it in a later epic;
  - `cli`: the wheel arrives in Story 25.4;
  - `supervisor`: the operator cuts `supervisor--v0.1.0` (AC3), and the engine cannot.

  AC1 requires every component as `{tag, url, sha256}`, and the guard must refuse a missing digest. A placeholder or optional entry changes the schema that 25.2–25.4 consume. So that is the operator's call, not the session's. Never fabricate a tag, URL or digest.
- **Block If** a single `sha256` cannot honestly pin `uv`/`bun`, because both ship one archive per platform. Do not choose a platform for the schema. Name the gap.
- **Operator step (AC3), unverifiable here.** The session writes the exact commands to the runbook and stops there. The commands are: in a `thkennedy/tk-studio-supervisor` checkout on `main`, `git tag supervisor--v0.1.0 && git push origin supervisor--v0.1.0`, then from this repository `uv run tools/release_archive.py run --app supervisor --version 0.1.0 --repo <checkout>`. The session must not cut or push tags on another repository. This repository's checkout in the sandbox does not include the supervisor repository.
- The plugin's motion must stay unchanged in effect. If generalising changes the plugin zip's bytes (dry-run digest ≠ recorded 0.2.16 digest), halt rather than re-record.
- Do not bump the plugin version in this story; 0.3.0 is Story 25.7's. The guard and drift-check change ride the next release.
- **Sealing:** a roster read relative to `PLUGIN_ROOT` would pass in a checkout and break in a skills-dir install (25.2). Any such read is a deviation to record.
