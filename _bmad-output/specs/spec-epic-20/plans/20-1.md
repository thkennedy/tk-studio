## Intent

`jobrun.py finish` gains an optional run cost that lands in both `run.json` and the terminal `job-run` event as `total_cost_usd`, so every terminal run reaches the ledger with its dollars (Plan Phase 1 acceptance (d)). An absent cost leaves 0.1.16 behavior untouched, and an invalid one is refused before anything is written or emitted. The taxonomy declares the field optional so the ledger validator accepts it. The contract's §4 `finish` row is Story 20.2's, not this one's.

## Acceptance Criteria

1. **Given** a run finished through `jobrun.py finish` with a cost figure **When** the terminal transition is recorded **Then** the `job-run` event payload carries `total_cost_usd` as a non-negative number, the run's `run.json` records the same figure, and there is still exactly one emitter and one event per terminal transition (AD-12)
2. **Given** a `finish` without a cost figure, as every driver sends today **When** it runs **Then** the behavior and the event are identical to 0.1.16: the field is absent, never zero-filled
3. **Given** a cost argument that is negative, non-numeric, or not finite **When** `finish` runs **Then** it refuses with a named error and records and emits nothing — never a guessed value (AD-3)
4. **Given** `contracts/events/taxonomy.v1.json` **When** the story lands **Then** `job-run.payload.total_cost_usd` is declared optional with a note naming its source (the worker's `--output-format json` result), and the lib suite pins the present, absent, and refused cases with the full suite green

## Code Map

- `plugins/tk-studio/lib/jobrun.py`
  - `finish()` (~L493): builds `changes`, calls `joblib.update_run`, then `_finalize_run` on terminal states. Add a keyword `total_cost_usd: float | None = None`. **Validate before `update_run`**: once `update_run` writes, the terminal state is immutable and AC3's "records nothing" is lost. Raise `JobRunError` with a named message (e.g. `total_cost_usd must be a finite non-negative number, got <v>`). Reject `bool` explicitly, since `isinstance(True, int)` holds. When valid, put `changes["total_cost_usd"] = float(value)`.
  - `_emit_job_event()` (~L93): builds the payload from `record`. Add `if "total_cost_usd" in record: payload["total_cost_usd"] = record["total_cost_usd"]`. Use key presence, not truthiness, so a cost of `0` is carried (AC1 says non-negative). **It swallows every exception** (`except Exception: pass`), so a payload field the taxonomy does not declare makes the event vanish silently. The taxonomy change is what keeps AC1 from failing invisibly.
  - `main()` (~L515): the `finish` subparser adds `--status-block`. Add `--total-cost-usd`, parsed as a **string** and validated in `finish()` or a helper. With `type=float`, argparse would accept `nan`/`inf` and exit 2 with argparse's own usage text on garbage, not the module's `{"ok": false, "error": …}` JSON (AD-11). `JobRunError` already maps to exit 2 with JSON.
  - The module docstring's CLI block (~L45–46) lists the `finish` flags: add the new flag.
- `plugins/tk-studio/lib/job.py` `update_run()` (~L558): merges arbitrary `changes` into run.json. `total_cost_usd` is not in `_RUN_IMMUTABLE_KEYS`, so no change is needed here (read-only seam).
- `plugins/tk-studio/lib/ledger.py` `validate()` (~L75–107): `type: "number"` maps through `_TYPE_MAP`, rejects bools, and refuses fields outside the schema. Read-only seam: no change. It does not check finiteness, which is why `finish` must.
- `plugins/tk-studio/contracts/events/taxonomy.v1.json` `job-run.payload` (~L62–69): add `"total_cost_usd": { "type": "number", "required": false, "note": "…source: the worker's --output-format json result (total_cost_usd); absent when the driver sent none, never zero-filled" }`. Leave `taxonomy_version` at 1: adding an optional field is additive, and no test pins the version.
- `plugins/tk-studio/lib/tests/test_jobrun.py`: reuse `_declare`, `_skill_defn`, `_ledger_events`, and `_cli` (see `test_finish_completes_skill_run_and_emits_once` ~L212 and `test_job_run_event_type_is_in_the_taxonomy` ~L350). Read `run.json` through `joblib.read_run(key, run_id)`.
- `plugins/tk-studio/skills/tk-studio-job/SKILL.md` (~L55) documents the `finish` call. Optionally note the new flag there. It is the wrapper's instructions, so a mention that finish takes `--total-cost-usd` when the worker reports one is in scope, but it is **not** required by any AC.

Tests to add (in `test_jobrun.py`):

## Risks and open decisions

- **Block If** the cost must be computed studio-side (for example, by parsing a worker transcript). The AC and spec say it is supplied to `finish`, so consult rather than build a parser.
- **Block If** `taxonomy_version` would need to change. The plan holds that an optional field is additive. Any test or conformance check that disagrees is a consult trigger, not a unilateral bump.
- The flag name is not fixed by the story (spec open question). `--total-cost-usd` mirrors the field and the worker's JSON key, so use it unless an existing driver already sends another name. Record it as a DRIFT at score 0–1 if it differs.
- The contract text is Story 20.2's: the §4 `finish` row and the version bump. Do not edit `driver-contract.md` or bump the gate ×3 here. The verify gate's AD-19 note ("a story that changes a contract surface also updates driver-contract.md") conflicts with the epic's split.
