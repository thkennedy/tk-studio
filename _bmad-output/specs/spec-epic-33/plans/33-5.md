## Intent
The roster gate (`tests.test_release_roster`) runs inside the engine today only because the operator hand-edited the gitignored overlay `.bmad-loop/policy.toml` on the agent PC (hole 62, twice: 31.5, 32.2). Any other box, or a rewritten overlay, loses it, and then a skill without its roster row passes the engine and fails on the host leg. This story moves the command into a tracked source. `launch.py check`, the readiness check every launch runs in the worktree whose overlay `materialise` copied in, reconciles the overlay's `[verify] commands` from that source: it adds what is missing, keeps the operator's extras and reports what it did.

## Acceptance Criteria
- AC1: **Given** the engine policy the launch materialises into every run worktree (`.bmad-loop/policy.toml`, a gitignored operator overlay today) **When** the launch's readiness check runs **Then** the `[verify] commands` list is reconciled from a tracked source (`plugins/tk-studio/pipeline/verify-commands.toml`, or the project's `.tk-studio/config.yaml` `engine.verify_commands`): a missing command is added, an operator's extra commands are kept, and the reconciliation is reported in the check's result; the tracked list carries `uv run --directory plugins/tk-studio/lib python -m unittest tests.test_release_roster` for tk-studio; a project without the list is unchanged; conformance covers the reconciliation and the lib suite covers the merge rules
- AC2: **Given** a story that adds a skill without its roster row **When** the engine's verify runs after a clean review **Then** the command fails, bmad-loop routes the failure to a dev fix session, and the host leg never sees the roster miss; the runbook's hole-62 row points at the tracked source

## Settled shape
1. **Sources, resolution order.** Read only from the project root and only from tracked files. `config.local.yaml` and the user tier are never read for this.
   - (a) `.tk-studio/config.yaml` `engine.verify_commands`: when the key is present, it is the source, a list of non-empty strings. An empty list means nothing is tracked.
   - (b) Otherwise `<root>/plugins/tk-studio/pipeline/verify-commands.toml` `commands = [...]`. That path exists only in tk-studio's own repo, so the plugin file is the tk-studio list and is never applied to another served project.
   - (c) Otherwise no source: the check reports `skipped (no tracked list)` and writes nothing.
   - This answers SPEC Open Question 1, with the config key as the per-project override.
2. **The tracked file.** `plugins/tk-studio/pipeline/verify-commands.toml`: a header comment (what it is, hole 62, read by `launch.py check`), then `commands = ["uv run --directory plugins/tk-studio/lib python -m unittest tests.test_release_roster"]`.
3. **Merge rule.** `desired` = the policy's current `verify.commands` in order (missing = `[]`), followed by each tracked command it lacks, in tracked order. Commands compare by exact string. The operator's extras are kept and never reordered or removed. A tracked command that is already present is never duplicated.
   - When nothing is added: `unchanged`, and the file stays byte-identical.
4. **The write.**
   - Re-read with `tomllib` after placing, and require `verify.commands == desired` and every other top-level table unchanged. On any mismatch, restore the original bytes and report a gap.
   - Placement:
     - `[verify]` exists with `commands`: replace that key's value up to its closing `]` (a bracket scan that honours TOML strings; a multi-line array becomes one line, and comments inside it are lost).
     - `[verify]` exists without `commands`: insert the line after the header.
     - No `[verify]`: insert `[verify]\ncommands = [...]\n\n` before the managed routing block's fence, else at the end.
   - Strings are written as TOML basic strings (`json.dumps` per item).
   - The file's newline convention is kept (CRLF stays CRLF).
5. **Refusals, each a named gap (`blocked`), never a guess.**
   - A source that does not parse, or whose list is not strings.
   - A `policy.toml` that does not parse, or whose `verify.commands` is not a list of strings.
   - A `verify.commands` the placement cannot locate (a dotted key, an inline table).
   - The detail names the file and says to fix it by hand.
   - No policy at all: `skipped (no .bmad-loop/policy.toml; bmad-loop init creates it)`, advisory, never invented (pipeline.py's rule).
6. **Reporting.**
   - A `checks[]` row `{"check": "verify commands", "ok": <bool>, "detail": …}`. Detail examples: `added 1 from plugins/tk-studio/pipeline/verify-commands.toml; kept 0 operator commands`, `unchanged (1 tracked, 0 operator)`, `skipped (no tracked list)`.
   - The result key `verify_commands {source, tracked[], added[], kept[], policy}`. `source` is the project-relative file, `.tk-studio/config.yaml engine.verify_commands`, or `null`. `kept[]` holds the operator commands not in the tracked list. `policy` is `written | unchanged | skipped (…) | refused`.
   - The key is present on every `check` result, `start` carries it through `checks`, and an early return still has it.
   - This story does not add a SPEC.md design-note bullet: SPEC.md is outside the gate's write surface. This section governs.

## Risks and open decisions
- band L: 9 files (two new) across lib, contract, conformance and docs. That is the contract and conformance obligation of AD-19, not size. The code is about 150-250 lines in `launch.py` plus the tests.
- The supervisor runs the installed plugin's `launch.py`, not the worktree's. The reconciliation takes effect on a box only after the plugin release that carries it is installed. Until then the hand line in the agent PC overlay stays the gate. The runbook row should say so in one clause. Releasing is outside the loop.
- Writing in `check` relaxes the documented "check writes nothing". The epic's SPEC Constraints settle it ("reconciled from a tracked source by the readiness check"), so it is not a Block If. Keep the `[limits]` read-only guarantee and its test.
- Block If the reconciliation would need the supervisor (`apps/supervisor`) to change, for example if `materialise` must call it. The AC places it in the launch's readiness check only.
- Block If bmad-loop's `[verify] commands` turns out to run with a cwd other than the project root (the tracked command's `--directory plugins/tk-studio/lib` assumes the root). Record the observed cwd and halt rather than rewriting the command.
