## Intent
The supervisor's console is its only log today: a tab that dies takes its cause with it (hole 66). This story tees every console line of `start.ps1` and its three bun processes (`serve`, `tick`, `drain`) into one file per UTC day under `<TK_SUPERVISOR_WORK>\supervisor\logs\`, redacted as the status page redacts, with explicit `started` / `stopped (<why>)` / `uncaught: <error>` lines; serves the last 20 lines on `GET /status` (`log {path, last_lines[]}`, contract 0.1.28 additive) and the HTML page; and teaches `tk-studio doctor` to read the newest log's last `stopped` or `uncaught` line when the API does not answer.

## Acceptance Criteria
- AC1: **Given** `start.ps1` and the three bun processes it runs (`serve`, `tick`, `drain`) **When** the supervisor runs **Then** every line the console shows is also appended to `<TK_SUPERVISOR_WORK>\supervisor\logs\supervisor-<YYYY-MM-DD>.log` (one file per UTC day, the last 14 kept, each line stamped `<ISO time> [serve|tick|drain|keeper|pacer]`), with explicit `started`, `stopped (<why>)` and `uncaught: <error>` lines from the script and from each process's exit; a line never carries a value of a `TK_SUPERVISOR_*` variable or any token (the page's redaction applies); `GET /status` gains `log {path, last_lines[]}` (the last 20 lines, redacted; contract 0.1.28, additive) and the HTML status page shows them
- AC2: **Given** the log **When** `tk-studio doctor` runs **Then** it reports the newest log's last `stopped` or `uncaught` line and its age when the API does not answer, and "no log" when the folder is absent; `bun test` covers the line shape, the rotation and the redaction with a fake clock; the runbook's hole-66 row names the file

## Code Map
- **`apps/supervisor/start.ps1` (modify): the console-hosted script, two roles in one file.** The main script (the pacer: steps 1, 3, 4, 5) and its `-ServeOnly` child (the keeper, step 2, started by `Start-SupervisorKeeper` with `-NoNewWindow`, sharing the console). Every line it prints today is `Write-Host` / `Write-Warning` with a `[supervisor]` prefix, names only, never a value (its NFR5 rule, line "Only names are ever printed"). The three bun processes run as `& $Bun src/cli.ts serve` (keeper, foreground loop), `& $Bun src/cli.ts recover | Out-Host` (`Invoke-SupervisorRecover`) and `& $Bun @Arguments | Out-Host` (`Invoke-PacerStep`, `src/tick.ts` then `src/cli.ts drain`); their JSON and stderr go to the console. Exit codes are read from `$LASTEXITCODE` (`$PSNativeCommandUseErrorActionPreference = $false`); the keeper restarts `serve` on exit (75 = certificate renewal). The script's end is the `finally { Stop-SupervisorKeeper }` after the `while ($true)` pacer loop; a Ctrl+C lands there.
  - Change: one function `Write-SupervisorLog -Tag <keeper|pacer> -Text <line>` (defined right after step 1's environment import, so the log folder `<TK_SUPERVISOR_WORK>\supervisor\logs` is known; when `TK_SUPERVISOR_WORK` is absent the function only writes to the host and the start warns once, naming the variable) replaces every `Write-Host`/`Write-Warning` in the script: it writes the host line as today and appends `<ISO UTC time> [<tag>] <text>` to today's file (`[DateTime]::UtcNow.ToString("yyyy-MM-dd")`; `Add-Content -Encoding utf8NoBOM`). The tag is `keeper` under `-ServeOnly`, `pacer` otherwise. The script's lines name variables, never values, so the function redacts only as a belt: each exported `TK_SUPERVISOR_*TOKEN*`/`*SECRET*` value replaced by `[redacted]` (Settled shape 2).
  - Explicit lines: `started` (after step 1, both roles; the keeper's reads `started (keeper)`), `stopped (<why>)` in the `finally` (`Ctrl+C` when `$_` is empty, else the error's message; the keeper's loop has no end but the script's `finally` logs for it when it stops the keeper tree: `stopped (keeper tree stopped by the pacer)`), and `uncaught: <message>` from a `trap { ...; continue }`-free `catch` around the main body (`try { … } catch { Write-SupervisorLog -Tag pacer -Text "uncaught: $($_.Exception.Message)"; throw } finally { … }`), the keeper's loop likewise.
  - The three processes run under the tee (Settled shape 3): `& $Bun src/log.ts --tag serve -- src/cli.ts serve`, `& $Bun src/log.ts --tag drain -- src/cli.ts recover` (recover is the drain's own rule: tag `drain`), `& $Bun src/log.ts --tag tick -- src/tick.ts`, `& $Bun src/log.ts --tag drain -- src/cli.ts drain`. The wrapper echoes the child's lines to the same console streams and answers the child's exit code, so `$LASTEXITCODE`, the 75 rule and `Out-Host` behaviour are unchanged; drop the `| Out-Host` (the wrapper writes to the console itself).
- **`apps/supervisor/src/log.ts` (new): the tee and the pure helpers (`bun test`'s subject).**
  - `LOG_TAGS = ["serve", "tick", "drain", "keeper", "pacer"] as const`; `KEEP_DAYS = 14`; `TAIL_LINES = 20`.
  - `logDir(env): string | undefined` = `join(workDir(env), "supervisor", "logs")` (`workDir` from `./env`); `logPath(env, now: () => number)` = `supervisor-<UTC yyyy-mm-dd>.log` in it; `dayOf(ms)`.
  - `formatLine(tag, text, now)` → `${new Date(now()).toISOString()} [${tag}] ${text}` (one line; an embedded newline in `text` becomes a space; CR dropped).
  - `redactLine(text, env, token = "")` = `redactCredentials(text, env, token)` from `./page` (Settled shape 2; the exact page rule, so the two cannot drift).
  - `appendLine(env, tag, text, now)`: `mkdirSync(dir, {recursive: true})`, `appendFileSync(path, line + "\n")` (one write per line, append mode: three wrappers and the script share the file); when the day file is new, `rotateLogs(dir, now)`.
  - `rotateLogs(dir, now, keep = KEEP_DAYS)`: the `supervisor-YYYY-MM-DD.log` files sorted by name (the date sorts), every one beyond the newest `keep` unlinked; answers the removed names. Other files in the folder are never touched.
  - `readLogTail(env, now, n = TAIL_LINES): {path, last_lines} | {path, last_lines: [], note}` (Settled shape 1): today's file, else the newest present file in the folder (the AC's "newest log"); `tailLines(path, n)` from `./page` (the chunked backwards read), each line through `redactLine`; the `note` is `"no log"` when the folder or every file is absent, `"TK_SUPERVISOR_WORK is not set"` when unset (`path: null` then).
  - `runUnderLog(argv, env, now, io)` (the wrapper's body, injectable for the test): `spawn(process.execPath, childArgs, {stdio: ["inherit", "pipe", "pipe"], env, windowsHide: false})`; each stdout line → `process.stdout.write(line + "\n")` and `appendLine(tag, line)`; each stderr line → `process.stderr.write` and the same append; at spawn `started` (`started: bun <args>`), at exit `stopped (exit <code>)` or `stopped (signal <sig>)`; when the exit is non-zero and a stderr line matched `/^(error|uncaught|unhandled)/i`, also `uncaught: <that line>`; the wrapper exits with the child's code (`null` → 1). Partial last lines are flushed at exit. Ctrl+C reaches the child through the shared console; the wrapper forwards nothing and never kills by name.
  - `main(argv)`: `--tag <one of LOG_TAGS>` (else usage, exit 2), `--` then the bun script and its args; under `bun test` nothing changes (`underBunTest` is not consulted: the wrapper has no notifier).
