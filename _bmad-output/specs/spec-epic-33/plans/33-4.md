## Intent
The supervisor's suites run on the Windows host only by a hand recipe (holes 51, 56). A Windows-only failure therefore reaches `main` unless someone remembers the recipe, as hole 63's EBUSY on open SQLite queues did. Every run of the suites also leaks `tk-sup-*` temp folders: about 90,000 in the host's Temp (hole 64), and 1.3 M inodes in the engine sandbox's `/tmp` (hole 70, from 33-1's replan). This story adds a `supervisor` gate to `tools/verify_host.py` that runs each suite file on its own when `apps/supervisor` changed. It also adds one shared test helper, `apps/supervisor/test/tmp.ts`, that owns every temp folder and queue the suites make and removes them, and a doctor warning for a Temp folder that is filling up again.

## Acceptance Criteria
- AC1: **Given** a run whose diff touches `apps/supervisor` **When** the host leg runs **Then** `verify_host.py` adds a `supervisor` gate after `conformance`: each `test/*.test.ts` file but the e2e command-line suite in its own `bun test` under a per-file timeout (420 s), with every `TK_SUPERVISOR_*` variable stripped from its environment and `TMPDIR`/`TEMP` pointing at a per-run folder under the run's worktree that the gate removes afterwards, then `bunx tsc --noEmit -p apps/supervisor`; the gate's lines name each file's pass/fail counts and the slowest file; an unchanged `apps/supervisor` skips it like the studio-web gate; the recipe the handoff carried (hole 51/56) retires
- AC2: **Given** the suites **When** they create temp directories and queues **Then** a shared helper `apps/supervisor/test/tmp.ts` owns `mkdtemp`, the queues opened inside it and the removal in `afterAll` (queues closed first, hole 63), every suite uses it, and a run of the whole gate leaves no `tk-sup-*` folder behind; `tk-studio doctor` warns when the user's Temp holds more than 500 `tk-sup-*` folders and names the cleanup; the runbook's hole-64 row is updated

## Settled shape
1. **The e2e suite (SPEC Open Question 2).** The excluded file is `apps/supervisor/test/command-line.test.ts`, the suite that spawns `bun src/cli.ts`. The gate excludes it by that exact name, and `tsc` still type-checks it through `tsconfig.json`'s `include`. A new `*.test.ts` file joins the gate by the glob. Appended to SPEC.md.
2. **The per-run temp folder.** It is `<worktree root>/.verify-tmp/supervisor-<UTC yyyymmddThhmmssZ>-<pid>/`, created before the first file. `TMPDIR`, `TEMP` and `TMP` all point at it, `TMP` because Windows' `GetTempPath` reads `TMP` first. The gate removes it in a `finally` (`shutil.rmtree(…, ignore_errors=False)`, retried 3× at 1 s on `PermissionError`). It also removes `.verify-tmp/` when it is left empty. A removal that still fails is printed as `== supervisor: could not remove <path>: <error>` and fails the gate. The root `.gitignore` gains `/.verify-tmp/` so that a killed leg never dirties the tree. Appended to SPEC.md.
3. **The gate's lines.** For each file: `== supervisor: <file> <p> pass, <f> fail in <s>s`, plus `(timed out after 420s)` or `rc=<n>` when red. Then `== supervisor: tsc ok|FAILED rc=<n> in <s>s`. The closing line is `== supervisor: ok|FAILED in <s>s; <n> files, <P> pass, <F> fail; slowest <file> <s>s`. A timeout kills the child (`subprocess.run(timeout=420)`; the tree is killed on win32 with `taskkill /T /F /PID`) and counts as a fail. A failing file's tail goes into the gate's output, so the existing `--tail` repeat shows it. `verify_host: ok (…)` names `supervisor` when it ran. The order is lib suite, conformance, supervisor, studio-web.
4. **`tmp.ts`.** Its exports:
   - `tempDir(prefix: string): string`: `mkdtempSync(join(tmpdir(), prefix))`, recorded.
   - `track<T extends { close(): void }>(q: T): T`: records a queue, or any closable, to close first.
   - `cleanupTemp(): void`: closes the tracked items, swallowing errors, then removes every recorded folder (`rmSync({recursive, force, maxRetries: 5, retryDelay: 200})`).
   - Its registration: `preload.ts` registers `afterAll(cleanupTemp)` once, as a global hook. bun runs a preload's `afterAll` after every file of the process, and each gate file is its own process. A `process.on("exit")` fallback calls `cleanupTemp` for the paths a crash or `process.exit` skips; the replan from 33-1 asks for removal "under every exit".
   - The rule for suites: every `mkdtempSync(join(tmpdir(), …))` in `test/` becomes `tempDir(…)`, and every `new Queue(…)` a fixture opens in such a folder is wrapped in `track(…)`. `grep -n mkdtempSync apps/supervisor/test` leaves only `tmp.ts`. Folders that tests remove themselves stay removed: `force: true` makes a second removal a no-op.
   - Appended to SPEC.md.
5. **The doctor check.** `supervisor-temp` `{check, status, detail, fix}` counts the directories named `tk-sup-*` directly under `tempfile.gettempdir()`, read from `ctx.env`'s `TMP`/`TEMP`/`TMPDIR` when they are set, so a test can inject them.
   - `warn` when the count is above 500: `"<n> tk-sup-* folders in <temp>"`, with the fix `"close every bun test, then remove them: PowerShell Get-ChildItem $env:TEMP -Directory -Filter 'tk-sup-*' | Remove-Item -Recurse -Force (Linux: find \"${TMPDIR:-/tmp}\" -maxdepth 1 -name 'tk-sup-*' -exec rm -rf {} +)"`.
   - `pass` otherwise: `"<n> tk-sup-* folders in <temp>"`.
   - `skipped` when the folder cannot be read.
   - It never fails, and doctor never deletes.
   - Appended to SPEC.md.

## Risks and open decisions
- **oversize**: about 45 files, nearly all a mechanical `mkdtemp` → `tempDir` swap across 31 suites. That is over band L's stated reason, but the AC names "every suite". Do not split. Halt if the Files list grows beyond the list above.
- The whole host leg runs under the job's single wall-clock guard (`hostVerify` `guardS`). Thirty-odd files, each run cold, add minutes. Record the gate's total time in the Auto Run Result. Block If a measured or estimated total exceeds the guard named in the job definition.
- Block If a `src/` producer of `tk-sup-*` folders (`delivery.ts:258`, `inbox.ts:312`, `worktree.ts`) is found to leak: fixing it is outside Files.
- Block If routing every suite's temp folder through `tmp.ts` changes any existing assertion beyond the path, for example a test that asserts its folder exists after a `describe` ends.
- Block If bun's preload `afterAll` does not run as a global hook in the installed bun version. Fall back to the per-file `afterAll` imported from `tmp.ts`, recorded as a deviation.
