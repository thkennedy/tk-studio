## Intent

The Epic 37 retrospective found three defects on the fourth sweep's path (AI-3). B1: the paused-sweep stop deadline never resets, so one early `unknown` blip arms a later stop of a healthy engine, and an unanswered stop then frees the lock and pin while the engine may still run. B2: a `ledger-resolve` refusal settles the ledger pass silently. B4: a missing id stays `pending`, and the printed remedy is relative to the studio checkout. DW-165 adds a fourth: a sweep bundle's engine passes leave no Stage Log row anywhere. This story makes the deadline a per-streak window, holds the lock and pin on an unanswered `blocked` end, ends a refused ledger pass loudly with a remedy that runs from any root, refuses a missing id by name (`LedgerMissingId`), and writes each bundle's passes into the sweep PR body's `## Stage Log`. It extends the 0.1.34 contract entry additively. After it, the fourth sweep waits only on Tim's `max_runs`.

## Acceptance Criteria

AC1. **Given** `sweepStopPastDeadline` (`sweep.ts:576-578`: measured from the first `unknown` or erroring note, a `running` probe never clears it, `sweep.test.ts:1316` pinning that as intended) and the stop at `worktree.ts:1173-1186` **When** an early `unknown` probe is followed by `running` probes and a later blip **Then** the deadline measures from the first note of the latest non-`running` streak (a `running` probe resets it; the rule named in the README), so a healthy engine is never stopped on an old blip, and `stopUnanswered`'s `blocked` end releases the lock and the pin only after a stop confirmed or the engine's own exit; `sweep.test.ts` pins the reset and the `:1316` case is rewritten to the new rule

AC2. **Given** `ledgerPass` (`sweep.ts:716-718`: a non-retryable refusal read as `settled` with no notifier line) and `LedgerDuplicateId` (`plansync.py ledger-resolve`, exit 2) **When** `ledger-resolve` refuses **Then** the pass ends with a `ledger-resolve {ok: false, settled: true, ended: "refused", reason}` note and one notifier line naming the refusal and the remedy (as B4's wait end does), never a silent settle; pinned with a fake refusal

AC3. **Given** B4's remedy line (`sweep.ts:629-630`: `ledger-resolve --ids <old ids>` with a relative plugin path; a missing id stays `pending`, `plansync.py:3481-3483`) and a sweep bundle's engine passes (DW-165: no Jira story, so no stage-log row anywhere) **When** an id in the sweep's record no longer names an open entry, and when a bundle's passes end **Then** `ledger-resolve` refuses a missing id by name (`LedgerMissingId`, exit 2, naming the id and the counter) instead of `pending`, the remedy line carries the verb's absolute path under the studio install and the run's `root` (`--directory`), and the test runs the remedy under a fixture root rather than reading the line's text; a bundle's passes write their Stage Log rows into the sweep PR body's `## Stage Log` (the story-doc shape: stage, start, stop, model, tokens, cost) and DW-165 closes with the Jira half declared not owed (a bundle has no issue) on the entry; the contract names the refusal and the rows (0.1.34, additive)

## Settled shape

Each ruling below carries its SPEC design-note bullet (the planner appends these to SPEC.md's design-notes section).

1. **The deadline's streak (CAP-7).**
   - The clock reads three notes per engine run: `engine-probe {phase: "unknown"}`, `engine-stop {error}` and the new `engine-probe {engine_run_id, phase: "running"}`.
   - A sweep's `running` probe writes the `running` note only when a streak is open: a non-`running` note (`engine-probe` unknown, or `engine-stop` with `error`) after the latest `running` note. So a healthy engine writes nothing per tick.
   - `noteEngineProbe(queue, run, phase, error?)` dedups per streak, not per engine run. The paused branch's error-note dedup (:1198) also becomes per streak: a first `error` after the latest `running` note.
   - `sweepStopPastDeadline` takes the first non-`running` note after the latest `running` note (all notes when none). It is past when `now - at > SWEEP_STOP_DEADLINE_MS`. An old `engine-probe` with no `phase` reads as non-`running`.
   - `answered` (:1177) and `asked` (:1294) read the latest streak only. `engineEndStatus` is unchanged (any `engine-stop` for the engine run).
   - README rule: "the deadline runs from the first note of the latest non-`running` streak; a `running` probe resets it". This answers the retrospective's B1 open question (`RETROSPECTIVE.md:161`) as epics.md words it: a wall-clock window, not a probe count.
   - Design note: `- CAP-7 — the paused-sweep stop deadline's clock: named placeholder rule: the first note of the latest non-running streak (an engine-probe {phase: "unknown"} or an engine-stop carrying error after the latest engine-probe {engine_run_id, phase: "running"}, which a sweep's running probe writes only when a streak is open); noteEngineProbe and the paused branch's error note dedup per streak; answered/asked read that streak — per _bmad-output/planning-artifacts/epics.md §Story 38.3, _bmad-output/specs/spec-epic-37/RETROSPECTIVE.md §B1`

2. **The held end (CAP-7).**
   - When `stopUnanswered` ends the run `blocked` and no stop for the engine answered `stopped` in this streak, the end holds:
     - `endEngine(runId, state, reason, {detail, holdEngine: <engine_run_id>})` → `writeEnd` with `engineRunId` set and no `keepEngine`, so the checkout lock stays (`handToEngine`, `detail.lock = {handed_to_engine: <eid>}`);
     - `PendingTransition` carries `holdEngine` and `applyTransition` passes it;
     - `release()` is skipped at :1338 and in the pending replay :1148;
     - the `ended` detail gains `engine_held: {engine_run_id}`.
   - `queue.ts` exports `heldEngine(events): string | undefined`: the engine run id of the latest `ended.detail.engine_held` with no later `engine-released` note naming it. `sandboxHolders` counts a terminal run whose `heldEngine` is set, so another run's release never stops the sandbox under it.
   - A new pass `releaseHeldEngines(queue, deps)` in `worktree.ts`, called once per `sweepEngines` tick over `queue.runs()` (terminal sweep runs with `heldEngine`). Each tick it runs `engineStatus` on the kept worktree (tier-aware):
     - `ended` → `queue.releaseEngineLock(run_id, "its engine exited")`, then `release()` (the pin), then note `engine-released {engine_run_id, by: "exit", engine}`;
     - `running`/`paused` → one `stopSweepEngine`; `stopped` releases the same way with `by: "stop"`;
     - `unknown` → nothing (fail closed, as `launchStatusProbe`).
   - A worktree that is gone counts as `ended` (`sweepEngines`' own rule :1159-1160).
   - Line texts:
     - the asked line ``paused sweep <id>: stop unanswered for 30 min — ended blocked, lock and pin held until a stop is confirmed or the engine exits``;
     - the probe line ``sweep <id>: the status probe answered `unknown` for 30 min — ended blocked, lock and pin held until a stop is confirmed or the engine exits``;
     - the probe-path stop that already answered `stopped` (:1376's case) keeps ``… — ended blocked, lock and pin released`` and releases at once.
   - The raced path (:1316-1331, a cancel won) keeps the cancel's own lock and pin handling (DW-64/38.5 territory).
   - Design note: `- CAP-7 — stopUnanswered's blocked end: named placeholder rule: endEngine {holdEngine: <engine_run_id>} keeps the checkout lock as the engine's (handToEngine) and skips releasePin, ended.detail.engine_held {engine_run_id}; releaseHeldEngines each tick releases the lock (releaseEngineLock), the pin and notes engine-released {engine_run_id, by: "exit"|"stop"} on the probe's ended or a stop answered stopped, never on unknown; sandboxHolders counts a held run; the lines end "lock and pin held until a stop is confirmed or the engine exits" — per apps/supervisor/README.md §Engine kill (Story 27.2, sbx) (the hold-while-it-runs rule), apps/supervisor/src/queue.ts writeEnd/handToEngine`

4. **`LedgerMissingId` (CAP-9).**
   - `class LedgerMissingId(Refusal)` lives in `dwledger.py`.
