## Intent

The first 37.6 run (`q-run-epic-37-20261106T102330Z-04109a`, engine `20261106-102516-76a4`) did no work. Both dev attempts halted on a stale render snapshot (hole 65's view, five of ten generation files `-?????????` inside the sandbox) and wrote `status: 'halted'`. Because that word is not `blocked`, nothing paused and Story 33.6's auto-resume never fired. The close-out saw `no_changes: true` but still ran a 2134 s host leg, the run ended `complete`, the notifier said `complete`, ST-166 stayed `in-progress`, and the two halted sessions left no Stage Log row (hole 114, DW-180, the retrospective's C3/AI-2).

This story covers four things:
- **The no-story end.** It becomes `partial`, with the engine's last record as its reason and no leg.
- **The auto-resume.** It keys on the render failure's signature, whatever status word the session wrote. On the ended path it relaunches once.
- **The plan and the Stage Log.** The plan-status pass returns the story to `draft`, and a halted attempt keeps its Stage Log row.
- **The renderer.** It re-reads its outputs after the staging rename and falls back to a direct write. This is a registered base patch beside DW-110's.

Everything is read on the supervisor's side. The engine is never edited (AD-4).

## Settled shape

1. **CAP-4 — the no-story end (`worktree.ts sweepEngines`).**
   - **The leg skip.** Before the leg, `const ahead = await commitsAhead(run, deps)`: `git log --oneline <base_ref>..HEAD`, factored out of `closeOut` :793-796 and used by both. A failed probe returns `undefined` and the leg runs as today. When the end is not paused, not a sweep, not killed, has no `existingPr` and `ahead` is `[]`, the leg is skipped with one `host-verify {skipped: true, reason: "no changes"}` (constant `NO_CHANGES_SKIP = "no changes"`, beside `PAUSED_DIRTY`). The skip sits beside the `PAUSED_DIRTY` skip, **before** 38.1's `noteCloseOutLease`: a skipped leg notes no `host-verify-leg` lease (`verify_host.py live_legs` reads a lease with no later `host-verify` as live, 38.1's deferred stale-lease finding).
   - **The story.** The key is the latest `story-start` in the engine journal's current segment (`<served>/.bmad-loop/runs/<eid>/journal.jsonl`, read as `storyLandedBeforeStop` reads it). When the key is known, its spec is not `done` (`findSpec`, else the stashed copy) and `c.no_changes` holds, the end is `state = "partial"` with `reason = noStoryReason(...)`. A run with no `story-start` keeps today's end, but still skips the leg.
   - **`noStoryReason`.** Built before `closeOut` removes the worktree:
     - Reads the story's spec: `findSpec(served, key)`, else the single `.md` under `<run dir>/deferred/<key>/`.
     - Takes its frontmatter `status` word, else the last session's `result_json.status`, else `unknown`.
     - Takes the HALT text: `blockingCondition(text)`, else the first non-empty line of its `## Auto Run Result` section that is not `Status:`, else the last journal `dev-decision.reason` for the key.
     - Counts the attempts: `dev-decision` entries for the key in the segment.
     - Text: `no story landed: story <key> ended <word> after <n> dev attempt(s): <halt text, clip 300>; engine ended '<status>'`.
   - **The notice.** `noticeText` then reads `supervisor: run <id> ended partial` / `reason: no story landed: …`. That pair is the AC's `partial: no story landed`, and the suite pins both substrings.
   - **The cost.** `finishStudio`'s `--total-cost-usd` is `input.costUsd`, else `queue.accountedCost(run.run_id, "worker")` (`cancelCostUsd`'s fallback). The fake's `finish` argv must carry it (1.22 in the fixture).
2. **CAP-5 — the render signature (`closeout.ts`).**
   - **The predicate.** `renderSignature(text)` is true when `snapshotFolders(text)` names exactly one folder **and** the text matches one of `RENDER_HALT_MESSAGES`, `render_skill.py`, or `RENDER_UNREADABLE_RE = /\?{9}|No such file or directory|Permission denied|ENOENT|EACCES|cannot (?:access|open|read)|unreadable/i`. The text is the paused reason plus `\n` plus the spec's `## Auto Run Result` section.
   - **`staleRenderView` drops three checks:** the `stage === "escalation"` check, the `DEV_ESCALATION` check and the `status === "blocked"` check. It requires instead: `renderSignature`, a spec found (stories, else the stashed copy) whose status is anything but `done`, the spec untracked, and the folder resolving under `<served>/_bmad/render/`.
   - **The folder check is unchanged:** `snapshotReady`, meaning the host sees the snapshot complete or a failed first render. A stale view is sandbox-only by definition, so no in-VM probe is added.
   - **The removal is unchanged:** rename aside `<gen>.stale-<pid>-<ms>`, remove the spec, remove the aside and staging, best effort.
3. **CAP-5 — the ended path pauses, then the pass relaunches once.**
   - **The pause.** In `sweepEngines`, a no-story end (shape 1) whose spec carries `renderSignature`, whose folder passes `snapshotReady`, and that has no `auto-resume attempt: 1` for the key, **or** has one but no attempt 2 since, is closed out as a pause:
     - `closeOut(run, {paused: true, …})`: no commits, so `no_changes`, the worktree and branch kept.
     - The `host-verify` skip note is still recorded once.
     - The transition is `paused` with detail `{engine: {...st.detail, paused_story_key: key, paused_stage: "no-story", paused_reason: <the no-story reason>}, no_story: {story_key, word, attempts}, ...closeOutDetail(c)}`.
   - **The resume.** `closeOutPaused`'s 33.6 branch then runs unchanged. In `autoResume`, when the latest `paused` event's `engine.status` is in `ENGINE_ENDED`, the resume step is **the 27.3 relaunch**: `relaunchEpic(queue, run, detail, deps)`, extracted from `closeOutLanded`'s tail, archive → `deps.relaunch` → `resumeFromPause(run_id, "close-out", {reason: "stale-render-view", halted_story: key, archive})` (no `story_key`, so `finishedStories` never counts it) → drive. Otherwise it stays `resumePaused`.
   - **The once-only marker** stays `auto-resume {reason: "stale-render-view", snapshot, story_key, engine_run_id, attempt: 1, resumed, notify}`, gaining `via: "resume" | "relaunch"` and `status_word`.
   - **A second occurrence** records `attempt: 2` with `secondHaltLine`, and the run stays paused for the operator, as today.
4. **CAP-5 — plan-status `draft`.**
   - **Where.** In `reviewPass`, a terminal run with no PR (`runPr` undefined, not `external`) gets a `draft` call for each story that has an ok `in-progress` event and no `draft` event.
   - **How.** Under the per-story lease `draft:<key>`, it calls `plansync.py status --status draft --note "run <run_id> ended without a PR: <run.reason, clip 200>"` and records `plan-status {phase: "draft", story_key, id, owner, directory, ok, previous_status?, error?, …}`.
   - **Retries.** A transient failure is retried and bounded by `PLAN_RETRY_LIMIT`, as `storyInProgress` does. `Phase` gains `"draft"`.
5. **CAP-6 — the halted Stage Log row.**
   - **The outcome rule.** `plansync._session_outcome(session)` returns `session["status"]`, unless it is `completed` and `result_json.status` is a non-empty string other than `done`, `in-review` or `ready-for-dev`. In that case it returns that word (`halted`). Both `stage_from_pass` (:3134) and `_backfill_rows` (:3034) use it, so the halted row reads `outcome: halted`, `started`/`ended` from the journal pair, and tokens/cost from the transcript, else the session record's `usage` and `meter._session_usd`.
   - **The row survives a no-PR end.** At the no-story end (shape 1, and the pause in shape 3), before `closeOut`, the supervisor runs the timeout row's path once against the run root: `uv run <plugin>/lib/plansync.py stage --from-pass --run-dir <served>/.bmad-loop/runs/<eid> --story <key> --worktree <run.root>[/<prefix>]` on the host. It backfills every session and writes the current one into the checkout's buffer `<spec folder>/stages/<key>.jsonl`, because the spec is absent there. It records one `stage-carry {story_key, ok, rows?, buffered?, error?}` note, never blocking. The rows flush into the spec the first time the merge pass's stage append (`plansync.py stage --append --directory <owner root>`) opens it after the story lands (`_StageDoc.commit`).
