## Intent

Three of Epic 35's host-leg reds were the box, the clock or the planner, never the code: a lib test pinned the live SPEC's design-note set (hole 96, DW-111), a conformance drive's own suite bound overran as its bun suite grew (hole 97, DW-112), and a test wrote text in Windows' default code page that the Linux gate could not read (hole 103, DW-132). This story adds a lib-suite guard against exact-set assertions over live planning artifacts, derives every bun-suite drive's bound from its manifest `timeout` through one shared helper with a preload default for git- and uv-spawning tests, brings the claim-path `TierRequired` into the host gate in-process (B11), writes the Stories-row regex rule into the planner's guidance (C8), has the operator run the nt `kill_tree` tests once through the consult log, and adds a conformance rule that every text-mode open under the lib, the installer and the app scripts names its encoding (binary modes exempt), fixing the existing call sites and creating `AGENTS.md` with the pitfall line.

## Acceptance Criteria

AC1. **Given** the lib suite and the supervisor suites **When** a test asserts the exact state of a planning artifact under `_bmad-output` (a live spec's design-note set, a stories list) **Then** a guard in the lib suite finds the exact-set assertion over a live spec folder and fails naming it; shape tests read fixtures, and a real-artifact test asserts only what cannot change (the capability count, the story map; `test_launch.py`; DW-111, hole 96)

AC2. **Given** every conformance drive that runs a bun suite, and every test that spawns git or uv under bun **When** the drive and the test run **Then** the drive's suite bound derives from its manifest `timeout` with headroom through one helper the drives share (`contracts/conformance/`, `runner.py`), and git- or uv-spawning tests carry a preload default above bun's 5 s (DW-112, hole 97); an in-process drain test asserts the claim-path `TierRequired` inside the host gate (B11); the planner's contract-test guidance carries the Stories-row regex rule (C8); the nt `kill_tree` tests run once on the host by the operator through the consult log and the spec records the result (35.3's `unverifiable-here`)

AC3. **Given** a text-mode `write_text`, `read_text`, `open` or `Path.open` under `plugins/tk-studio/lib`, `tools/installer` and `apps/*/scripts` **When** conformance runs **Then** a call with no explicit `encoding=` fails the run naming the call site (binary modes exempt), the existing call sites are fixed, and `AGENTS.md` carries the pitfall line (DW-132, hole 103); the contract (0.1.31, additive) names the rule; DW-111, DW-112 and DW-132 close by this PR

## Risks and open decisions

- **oversize**: ~30 files (eleven of them the mechanical `encoding=` edits), ~620 new lines plus ~150 one-line edits. Halt (`halt` consult) if the Files list grows past the band — the dev session never splits the story.
- Block If a lib test's `read_text`/`write_text` must stay default-encoded to reproduce a Windows defect (a test that asserts the code-page behaviour itself): mark the one call with an explicit `encoding=locale.getpreferredencoding(False)` and a comment, never a bare call — a consult (`deviation-gt-0`) if more than one such site exists.
- Block If `setDefaultTimeout` is not exported by the sandbox's bun (`bun:test` added it in 1.1): read `bun --version` in the sandbox and record it; a missing export is a Block If naming the version, never a per-test timeout sprinkled across twelve files.

- 36.7's `plugins/tk-studio/README.md` Windows-notes bullet for this encoding rule lands in 36.7 (its AC), not here; this story's doc is `AGENTS.md`.
