## Intent

A sweep's records stop short of a story's: `## Metered cost` and the `job-run` line carry the launch worker's turns only (the engine spent millions of weighted tokens per sweep; hole 102, DW-131), `meteredCost` reads a `run.json total_cost_usd` the engine never writes, the `sweep-triage` ledger event lands in the sandbox's own ledger (DW-116), `## Sweep` is lost on a 33.8 re-run (DW-123), the engine's own non-finished end is overridden by the bundle count (DW-118), the ledger pass's `pending` is a counted retry that gives up after 24 ticks (DW-122), a re-run's judge cost reaches no ledger line (DW-67) and a resumed run's body reads `not metered` (DW-119). This story prices the engine's per-bundle sessions through the lib's one price table, emits the triage event on the host, makes the ledger pass wait, keeps the engine's end, rebuilds `## Sweep` from the record on a re-run, and extends the 0.1.31 contract entry. The serve process changes (the watch and ledger passes).

## Acceptance Criteria

AC1. **Given** a `run-sweep` close-out, a 33.8 re-run and a resumed run's close-out **When** `## Metered cost` and the `job-run` ledger line are written **Then** the engine run's journal per-bundle token totals are priced with the routing's model rates (one pricing table in lib, read by the close-out and `report.py`) into `## Metered cost` as the worker's turns plus the engine, one line per bundle, and into the job-run line's `total_cost_usd`; the sweep's `ended` event carries `engine_cost_usd`; a re-run's judge lands as its own job-run line (`hostleg.ts runLeg`; DW-67); a resumed run meters its worker sessions as a first-launch run does and the PR body reads the number (`closeout.ts`; DW-119)

AC2. **Given** the sweep's triage and its ledger pass **When** the supervisor copies `triage.json`, and when `ledger-resolve` answers `pending` only **Then** the host side emits the `sweep-triage` ledger event with the payload the queue store holds (one shape for both records; `launch.py:1576`; DW-116), and the ledger pass waits uncounted and lease-free as the stage pass does (`planstatus.ts:513`, `sweep.ts:414`), the retry count kept for errors (`PLAN_RETRY_LIMIT`; DW-122); the flip's status line names the bundle once (`resolved … by #N (sweep bundle X)`, the doubled note of #290 and #293 gone)

AC3. **Given** a sweep whose engine ended `failed` or `blocked` after its last bundle, and a sweep's re-run **When** `sweepEndState` runs (`worktree.ts:1078`) and `rewriteBody` renders the body (`hostleg.ts:209`) **Then** the engine's own end is kept (`partial` at best when every bundle landed; DW-118) and `rewriteBody` passes `sweepSummary(queue, run)` so `## Sweep` survives (DW-123); one test each; the contract (0.1.31, additive) names the priced cost and the event; the entries close by this PR

## Risks and open decisions

- **oversize**: ~20 files, ~900 new or changed lines; the code is M-sized across five supervisor modules and one lib verb, the tests carry the rest. Halt (`halt` consult) if the Files list grows past the band — the dev session never splits the story.
- Block If the bundles of a real sweep carry no `transcripts/<key>/metered.json` **and** the `state.json` sessions carry no `usage` (the reporter could not read the #290/#293 run dirs): the price-run answer is `not metered` per bundle by Settled shape 1; if the operator finds the hook never metered a bundle, that is a `meter_hook.py` defect for a follow-up DW, never a number invented here — ask through the consult log (`operator step`).
- Block If the `job-run` consumers (`jobRunCosts`, `runCost`, `spendByEpic`) double-count the judge line or drop the run's own line once `run_id` carries a suffix: the shape in Settled shape 3 is additive; a consumer that keys on the bare id must split on `:verify-` — a consult (`deviation-gt-0`) if more than the three named readers change.
- Not a Block If: the AC's `launch.py:1576` and `worktree.ts:1078` anchors drift (the emit is at :1719-1731 now; 36.1 edits :1078's neighbours); re-grep. The AC's "`sweepSummary(queue, run)`" is met by the record-based summary (Settled shape 5), stated as such in the spec, not a deviation.
- The pending wait replaces a test that pinned the give-up; the whole `sweep.test.ts` already runs a 25-pass loop under the 60 s bound (hole 97) — the wait test should be faster, and 36.4 derives the bound from the manifest.
- `bun` is absent on the launch host: the supervisor suites run in the engine sandbox; a hand-run `launch.py sweep` on the host still emits the lib's event into the host ledger — the host emitter and the lib's never both fire for one supervisor run (`run-sweep` requires the sbx tier).
