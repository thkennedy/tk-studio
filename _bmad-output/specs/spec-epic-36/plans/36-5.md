## Intent

The supervisor causes blocks it then refuses to clear: a run that blocks before any engine starts hands the checkout lock to an "unverified" engine holder and its own `on_status [blocked]` stop refuses the resubmission (holes 90 and 93, DW-105); `submit` never checks that a sandbox-tier job's target skill is in the sbx skills store, and a status block missing `intent` is read as absent and resumed into a `partial` (hole 98, DW-113); the one-minute tick's `recoverQueue` respawns the engine hold every minute (133 `hold` events on one run; hole 94, DW-109); a core's own `blocked` status never lifts into the run state, so `atlassian-sync-back`'s stop never fires (DW-38); the pin-restart episode is bounded per run, not per sandbox (DW-56, DW-58); the pin never prunes the engine sandbox's `/tmp` (DW-60); a long pacer pass is invisible until it ends (DW-63); and doctor's "last end" is usually a routine tee line (DW-55). This story records the supervisor's own faults as its own and clears them: the lock released and `cancel` answering, an own-block marker both stop evaluators honour, the store checked at `submit`, a malformed block named, a detached hold the tick adopts instead of respawning, the lifted core status, the per-sandbox restart bound with the `/tmp` prune, the pacer pass visible while it runs, and doctor reading a process-level end. The serve process changes.

## Acceptance Criteria

AC1. **Given** a run that ends `blocked` before an engine started, and a job whose `stop.on_status` holds `blocked` **When** the close-out runs and the next submission arrives **Then** the checkout lock is released (no unverified engine holder for later claims to re-probe), `cancel` answers it, and the stop skips a block whose reason is the supervisor's own (placement, lock, pin, render) so the next submission is woken, the loop-caused blocks of holes 90 and 93 the test cases (DW-105); a sandbox-tier job whose target skill is absent from the skills store (`sbx skills ls`, or the store's `plugin.json`) is refused at `submit` naming the release and the import, and a status block missing `intent` is reported malformed, not absent (DW-113, hole 98)

AC2. **Given** the one-minute tick beside a live serve, and a core job whose JSON status is `blocked` **When** `recoverQueue` → `respawnHolds` runs, and when `jobrun.execute_core` records the run **Then** the tick spawns no hold (the serve process, which lives, owns them) or detaches and records its holds so the serve adopts them, one test that a tick beside a live serve spawns none, and a run's `hold` events count the restarts, not the ticks (DW-109, hole 94); the core's own `status` lifts into the run `state` so `stop.on_status: ["blocked"]` fires for `atlassian-sync-back` and every shipped core (DW-38)

AC3. **Given** the pin, the pacer and doctor **When** a sandbox stays logged out across several queued runs, a pass runs long, and the newest log ends on a tee line **Then** the pin-restart episode is bounded per sandbox across the queue, any run's open pin-restart since the sandbox's last healed probe counting (`sandbox.ts openPinRestart`; DW-56, DW-58), the pin prunes `tk-sup-*` and `tmp.*` from the engine sandbox's `/tmp` (`cli.ts pinBeforeClaim`; DW-60), the slow-pass warning, the notifier line and `pacer.json` are written while the pass runs (`log.ts runUnderLog`; DW-63), and doctor ranks a keeper, pacer or serve end or a non-zero exit above the routine `[tick]`/`[drain] stopped (exit 0)` lines (`doctor.py _last_end`; DW-55); the supervisor suites and the lib suite cover each with fakes; the contract (0.1.31, additive) names the refusal and the lifted status; the entries close by this PR

## Settled shape

1. DW-105 — the supervisor's own block: optional entry: `own_block?: "placement" | "lock" | "pin" | "auth" | "worktree" | "engine-mcp" | "render"` on the run's end detail (`ended`/`blocked` events) and, through `jobrun.py finish --own-block <kind>`, on `run.json` (`job.schema.json` `run.fields`, additive); set where the block is built (`invokeSkill`'s pin/auth/engine-MCP reasons, `endAfterDriveFailure`'s `WorktreeFailed`/`StartError`s, a `render` end the resume path records), never by matching the reason text. Effects: `writeEnd` releases the checkout lock (`keepEngine: true`, no launch probe) when the end carries `own_block` and the run has no `launched` event and no recorded engine name; `cancel` on a terminal run whose `kind='engine'` lock row names it releases the row (`lock-released {holder: {id: null}, own_block}`), 200 by name; `mirror`'s and `recover`'s stop evaluation and `jobrun.py evaluate_stop` skip a run whose record carries `own_block`, so `stop.on_status [blocked]` fires only for the engine's own `blocked`. Appended to SPEC.md design notes.
2. DW-113 — the store check at `submit`: for a job whose resolved placement is the sbx tier, `sbx skills ls` (argv through the `SandboxDeps.run` seam) must list the target skill's name (one name per line, first whitespace-separated token; a tolerant parse), else `refusal("skills-store:SkillMissing", "<skill> is not in the sbx skills store (<store path>; plugin <store plugin.json version | unknown>); import the release: sbx skills import <release archive>")` — the release named from the store's `plugin.json` when the host can read `%LOCALAPPDATA%\DockerSandboxes\sandboxes\state\agent-skills\<plugin>/.claude-plugin/plugin.json`, else `unknown`; `POST /jobs` 400 by name; the drain's claim path refuses `skill-missing:<skill>` (the run stays `queued`). The real `sbx skills ls` output is the operator's capture through the consult log (`operator step`); the parser is written tolerant and pinned to the captured sample once it lands. A status block that is a balanced object with string `status` and no string `intent` is `conformance failure (AD-11): status block malformed: missing intent`, ended `partial` without a resume.
3. DW-109 — the hold: (B) detach-and-record. `defaultHold` spawns the hold detached and unref'd (`stdio: "ignore"`), `spawnRecordedHold` records `{pid, start}` as today, and `respawnHolds` spawns only when the recorded hold pid is dead (the pid + start-time match is the adoption rule for every later process, tick or serve); `HoldChild.done` resolves on `exit`; the hold ends itself with the engine (`tail --pid`). One test: a tick's `recoverQueue` beside a live recorded hold spawns none; a run's `hold` events are its real restarts.
4. DW-38 — "every shipped core": `execute_core` lifts the core's own `status` into the run `state` when it is a terminal state (`complete | partial | blocked`), `reason` from the block's `reason`; a core that prints `ok: false` with no `status` (today's `maintenance-conformance` runner) lifts to `blocked` with `reason: "core answered ok: false without a status"`, `ok: true` without `status` stays `complete`; the `job-run` line carries the lifted state.
5. DW-56/58 — the per-sandbox episode: `Queue.openPinRestartOn(sandbox)` = the latest `pin-restart` on any run recording that sandbox whose `probe_after` is not `null` and that is later than the sandbox's last **healed** signal — a `pin-restart` with `probe_after: null`, or a `pinned` whose probe was clean; guard (d) reads it instead of the run's own episode; `claim-refusal-cleared` is unchanged.
6. DW-63 — the pacer while it runs: optional entry: `pacer.json` gains `running?: {tag, started_at, elapsed_ms, ids: [...]}` written when the slow-pass timer fires and refreshed by `finish` (removed at the end of the pass); the three exact-key pins and the `page.ts`/`api.ts` readers accept the optional member; the slow-pass warning and the one notifier line fire from the timer, `finish` never repeats them. Appended to SPEC.md design notes.
7. DW-60 — the prune: `find /tmp -maxdepth 1 ( -name tk-sup-* -o -name tmp.* ) -mmin +1440 -exec rm -rf -- {} +` through `sbx exec` after a successful `pinWithRestart` in `pinBeforeClaim` (and the drive's pin, one helper), skipped when another live run holds the sandbox, recorded on the `pinned` detail as `tmp_pruned`.
