## Intent

Every pause path today either parks the run or strips it: the resume's graceful-stop re-arm runs `launch.py stop` on the host for a sandbox run (DW-120), a block the operator resolves by resuming leaves the story's Jira issue in `Blocked - Awaiting User` with the owner tagged (hole 101, DW-130), a failed first render defeats the hole-65 auto-resume three ways (hole 95, DW-110), a paused sweep's stop is retried every tick with no bound and, once stopped, the host leg runs on the half-written tree whose WIP `git worktree remove --force` then deletes (DW-121), a story-boundary refusal keeps the run `paused` with the lock and pin (DW-115), a killed engine's draft PR is marked ready (DW-64), a killed relaunch loses `launched.end` (DW-65), and an engagement's cap or ask block is never closed after the owner's go (DW-47). This story gives each pause a bounded, recorded exit through the API: a tier-routed re-arm, a `track.py unblock`, a once-only auto-resume for the failed render with a base patch for the rename, a deadline on the paused-sweep stop with the WIP committed and the leg skipped, the boundary ending the run (the retrospective's B3/B4 decided), the draft kept, the guard's reason kept, and the engagement block closed. The serve process changes.

## Acceptance Criteria

AC1. **Given** a sandbox-tier run resumed over `POST /runs/{id}/resume` or the hole-65 auto-resume **When** `closeout.ts` re-arms the graceful stop (`:919 launchStopGraceful`) and the run had ended `blocked` with a `track-block` **Then** the re-arm runs on the run's tier as `stopSweepEngine` does, with a test that has no host injection (DW-120); the resume calls a story-side `track.py unblock --story <key> --reason` once per `track-block` since the latest pause (`Blocked - Awaiting User` → `Block Resolved` with a `Resolved:` agent comment and no owner mention, idempotent), recorded as `track-unblock`, and a plan-status pass that holds an AD-5 conflict ends `partial` and notifies instead of `ok: true` (DW-130, hole 101); a failed first render (an empty or absent generation beside its staging folder) counts as the one snapshot and auto-resumes once, and `render_skill.py`'s staging rename retries on `EACCES`/`EPERM` as a studio-managed base patch (DW-110, hole 95)

AC2. **Given** a paused sweep, and a run refused at a story boundary **When** the stop does not answer `stopped`, and when `resume` answers `StoryLanded` **Then** the stop retry is bounded (a count or a deadline), then a notifier line and a `blocked` end that releases the lock and the pin, and a paused bundle's WIP is committed as WIP on the run branch or the sweep is kept paused for the operator, never the leg on a half-written tree (`worktree.ts:1012-1021`; DW-121); the story-boundary refusal ends the run at the boundary (push, PR, release) rather than parking it (`queue.ts:1254`; DW-115; B3/B4 decided here, the contract naming it)

AC3. **Given** a resumed or relaunched engine the supervisor killed, and an engagement whose owner answered go or continue after a cap or ask block **When** the close-out skipped the host verify, and when `approve.ts runStep` runs **Then** the PR stays a draft (`worktree.ts closeOut ~:480-483`; DW-64), a killed relaunch keeps `launched.end` with the guard's reason (`sweepEngines`' relaunched predicate; DW-65), and the cap or ask block is closed and the owed questions block after it (`approve.ts runStep`, `questions.ts closeStep`; DW-47); the supervisor suites cover each with fakes; the contract (0.1.31, additive) names `track-unblock` and the bounded stop; the entries close by this PR
