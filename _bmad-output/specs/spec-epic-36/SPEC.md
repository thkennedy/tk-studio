# Epic 36: Loop Hygiene 3, What the Sweeps Taught the Loop

## Why

A pain to solve. Epic 35 closed on 2026-10-29 `accepted-with-open-items` (`spec-epic-35/RETROSPECTIVE.md`, PR #280), and on Tim's call of the same day ("sweeps first") three `run-sweep` runs went before any new surface: the first blocked on hole 98, the second (#290) and the third (#293) landed fifteen bundles and closed sixteen ledger entries, leaving 84 open, 68 of them handed back by the triage as human decisions. What the sweeps taught: the host leg's verdict is derived three times and only two of them know `inconclusive`, so the board shows an inconclusive leg green while the plan status writes it red (DW-100); a sweep's `## Metered cost` and job-run line carry the worker's turns only while the engine spent millions of weighted tokens per sweep (hole 102, DW-131), its `sweep-triage` event lands in the sandbox's own ledger (DW-116), `## Sweep` is lost on a re-run (DW-123), the engine's own `failed`/`blocked` end is overridden by the bundle count (DW-118) and the ledger pass's `pending` is a counted retry that gives up after 24 ticks (DW-122); the resume's stop re-arm runs on the host for a sandbox run (DW-120), a paused sweep is either stuck or stripped (DW-121), a story-boundary refusal parks the run (DW-115), a failed first render is not auto-resumed (hole 95, DW-110), and a block the operator resolves by resuming leaves the story's Jira issue in `Blocked - Awaiting User` for hours (hole 101, DW-130); the host leg went red three times on things no bundle changed: a test pinning a live planning artifact (hole 96, DW-111), a drive's budget (hole 97, DW-112) and a Windows default encoding the Linux gate cannot see (hole 103, DW-132); the supervisor's tick respawns the engine hold every minute (hole 94, DW-109), a run that blocks before any engine starts keeps the checkout lock and its own `on_status [blocked]` stop refuses the resubmission (hole 90, DW-105), `submit` does not check that a sandbox-tier job's target skill is in the skills store (hole 98, DW-113), a core's own `blocked` status never lifts into the run state (DW-38); `plansync setup`'s workflow update is still refused by Jira (hole 92, DW-127); and Epics 34 and 35 left the supervisor with an eleven-module import cycle and three dynamic-import dodges (DW-85) and the READMEs without rows for `tk-studio-evals`, `maintenance-evals`, `run-sweep`, `evals.py` and `report.py` (AI-7). This is the third loop-hygiene pass (Epics 33 and 35 were the first two), planned from the retrospective's action items (AI-1, AI-2, AI-8, the docs half of AI-7), the observation ledger's holes 92 and 94 to 103 (each a row of the runbook's fixes table with the fix to make) and the deferred-work ledger's sweep-era entries DW-105 to DW-132 with the older medium entries the triage keeps handing back (DW-38, DW-47, DW-55, DW-56, DW-58, DW-60, DW-62 to DW-65, DW-67, DW-71, DW-85 to DW-87, DW-90, DW-91, DW-100), in that order of authority, then the handoff's day-7u to day-7y addenda and the contract at 0.1.30.

## Constraints

- Where things run (kept from Epic 35): engines only in the project's Docker Sandbox, never with bypass on the host; the host leg runs deterministic scripts and the engine binaries, never a model; secrets by name only; the engine never runs on the host.
- Surface rules: every surface change is additive on the contract at 0.1.31 and up, ends in a status block (AD-11), is covered by conformance (AD-19) and lands its cost in the ledger.
- Cadence: a fix to the loop lands through the loop, one story per run with a graceful stop after each and the host leg green before the PR; an operator PR that touches lib, its tests or the contract runs the whole host gate before merge (hole 86); seven stories in dependency order: the verdict first, the sweep's records and the resume paths, the gates, the supervisor's and the Jira seat's faults, the cycles and the docs last.
- The host leg stays the gate of record; a story whose fix changes the serve process says so in its spec so the operator stops the supervisor tab before the loop builds `apps/supervisor` and restarts it through the scheduled task after the merge.
- Decisions taken, not reopened: the retrospective's dispositions stand; its open questions B3/B4 (a paused run's exit) are decided in Story 36.3 — the boundary ends the run, never parks it.
- A story that must touch `_bmad-output` planning artifacts or the Jira seat does so through the lib verbs, never a hand edit.
- Tier asks: where a story's proof needs the host or the sandbox tier (the nt `kill_tree` tests, a hold count on a live run, a real `plansync setup` against the owner's site), the engine asks through the spec's consult log and the operator session does that step and answers with the evidence.
- Repo: tk-studio only (`apps/supervisor` board, planstatus, hostverify, hostleg, worktree, sweep, closeout, queue, approve, questions, sandbox, cli, log, hygiene; `plugins/tk-studio/lib` `launch.py`, `report.py`, `meter.py`, `track.py`, `plansync.py`, `jirabackend.py`, `engage.py`, `assets.py`, `playable.py`, `doctor.py`, `jobrun`; the contracts and conformance drives; the studio-pipeline plugin and its mirror; `tools/installer`; the READMEs, `kb/` and the runbook).

## Success signal

- An inconclusive leg files its run under `needs_you` on every screen. A sweep's engine cost reads in the PR body, the job-run line and the rollup, its triage event sits in the host's ledger, `## Sweep` survives a re-run and the engine's own end is kept. Every pause has a recorded exit through the API: the re-arm on the run's tier, the Jira block closed by the resume, the paused sweep bounded, the story-boundary refusal ending the run. The host leg goes red only on code: no live-artifact pin, no drive budget of its own, no unencoded text open. The supervisor releases the blocks it caused and refuses by evidence at `submit`; a fresh project's `plansync setup` needs no manual workflow edit; a game project is one by the registry. Zero cycles among the named modules and every shipped verb in a README row. Conformance green at 0.1.31 or later; every story's cost in the ledger.
