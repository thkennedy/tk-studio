# Epic 39: The Studio as a Place: the Front End the Owner Works In

## Why

A vision to realize and a pain to solve. Tim's direction of 2026-11-07, given while Epic 38's first run was in flight: build out the web UI (animated studio, agents and sub-agents as characters, a user messaging system, kanban, task progress, a studio chat, model and effort settings) so he interacts with the studio as a user would, unifies inputs and outputs in one place, and stops giving instructions through the Claude Code app as his primary means of interaction. Three asks sit in that: see the studio work, talk to it, unify its inputs and outputs (the addendum `studio-design-spec-2026-11-07-front-end/README.md` §0 to §2 is the brief and the gap table). The base is the studio web of Epics 29 to 32 (`apps/studio-web`: one figure per role, a row board, the inbox and issue view over the sync-back's `inbox.json`, the engagement chat over `POST /chat/{id}`, the status screen, the sprite pipeline of our own pixels; `apps/supervisor/src/web.ts`, `office.ts`, `board.ts`, `inbox.ts`, `chat.ts`, `api.ts`): it has no URLs, no sessions or sub-agents, no kanban, no run timeline, no studio chat, read-only model and effort, and the sandbox's Claude login is a monthly terminal chore that fails silently (hole 69, TKSTUDIO-233; asked for as a page, not a vault, on 2026-11-08). The nine stories run in the order of the owner's use: addresses first, the login's clock second, the studio chat third, then what there is to see (39.4 to 39.6), then what there is to answer (39.7: DW-178 and DW-48), then the settings, then the records. The contract moves from 0.1.34 to 0.1.35 (additive) at 39.1.
