## Intent

The owner wants to tell at a glance whether a run is healthy and how long it has left (addendum §3.2 F-A). Today the web cannot show this: it has no run page, the Status screen lists live run ids with no job, story, clock or Cancel, and the office HUD shows `done / total` and the story's phase but no stage, no clock and no phased bar. This story:
- adds a run page at `/app/run/<id>` (`src/run/*`). It draws a timeline from the queue events of `GET /runs/{id}`, cut into sessions by the Stage Log of `GET /stories/{id}` (39.4) and by the office's live `stage`. It shows a clock against the guard that applies, the cost per stage (else the run total), the events with `detail` folded, Cancel with its consequence stated first, and an ended run's final state in words.
- turns the Status screen into the queue (queued, claimed, running, paused), above the counts.
- gives `office.progress` (and the snapshot's `runs[]`) a `stage` field (`office.ts`; contract 0.1.35, additive).
- gives the office HUD the stage, the run's clock and a phased bar. Every HUD value is held at least 1 s, and the clock and the bars lerp (pure functions, pinned in vitest).

## Settled shape

1. **`stage` (CAP-17, SPEC design note; contract 0.1.35).**
   - **Where it appears:**
     - `OfficeRun` gains `stage: string`. It is on every snapshot's `runs[]` entry and on every `office.progress` delta: `{run_id, epic, stage}` (epic-only), or `{run_id, epic, stage, story}` per changed story.
     - A change of `stage` alone is an epic-only `office.progress` (the hub's skip at :837 also compares `stage`).
   - **The value:** one per `OFFICE_MAP` row, computed by a new `stage` column on each row (`(s: OfficeSignals) => string`). It is applied per live run in `liveRuns` with that run's own signals:

     | Row | `stage` |
     |---|---|
     | 3 queued | `queued` |
     | 4 waiting | `waiting for a ruling` |
     | 5 launch | `launching` |
     | 6 planner gate | `studio gate` |
     | 7 dev | `dev attempt <n> of <m>` |
     | 8 review | `review pass <n> of <m>`; role `triage`: `triage` |
     | 9 engine verify | `committing` when the phase is `committing`, else `engine verify` |
     | 10 host-verify | `host verify leg` |
     | 11 otherwise | `close-out` when a `closing-out` lease is held (the latest `closing-out` event's `detail.owner` non-null, no `closed_out` after it) or the engine ended; else `between sessions` |

     Rows 1 and 2 never reach `runs[]`, which holds only live runs. Their `stage` is `no run` and `blocked`, for completeness.
   - **The counts:**
     - `<n>` is the open session's task-id ordinal (`/-(\d+)$/` on `session.task_id`). Without one, `state.json tasks[<current>].attempt` or `.review_cycle`, else 1.
     - `<m>` is `state.json` `policy_snapshot.limits.max_dev_attempts` (dev) or `.max_review_cycles` (review) when a positive integer, else the engine defaults 2 and 3. It is never below `<n>`.
     - So a band-M run with `max_review_cycles = 2` in its policy reads the AC's "review pass 2 of 2" on its second review session.
   - **New signals:** `OfficeSignals` gains:
     - `phase: string | null` (the current story's `state.json` phase, already read at :551);
     - `limits: {max_dev_attempts: number; max_review_cycles: number}`;
     - `closingOut: boolean`;
     - `attempt: number | null` and `reviewCycle: number | null` (from `state.json tasks[<current>]`).

     `NO_SIGNALS` gets `null`/defaults. No new file is read: `state.json` is already cached.
   - **The web's store:** the mirrored `OfficeRun` gains `stage?: string | null`. `applyProgress` sets `stage` when the delta carries a string and keeps the row's otherwise. A row born of `applyRun` has `stage: null`.
2. **The timeline (CAP-16, SPEC design note): `runTimeline(input)` in `src/run/model.ts`, pure.**
   - **Input:**
     - `{run, events}` (the `GET /runs/{id}` answer);
     - `stageRows: StageRowLike[] | null` (39.4's Stage Log rows, or null);
     - `liveStage: string | null` (the store's `runs[].stage` for this run);
     - `now: number`.
   - **Output:** `{segments: Segment[], open: Segment | null, ended: {state, words} | null}`, where `Segment = {kind, label, start, end: string | null, outcome?: string, suites?: {name, seconds}[]}`.
   - **The one mapping table** (events in `seq` order; a segment closes at the first closing event after its opening one; `end: null` while open):

     | Opens | Segment `kind` / `label` | Closed by |
     |---|---|---|
     | `enqueued` | `queued` / `queued` (`queued (waiting for the checkout lock)` once a `lock-wait` follows) | `claimed`, `ended` |
     | `claimed` | `launch` / `launch` (a run with no `launched` event at all: `worker` / `worker`) | `launched`; for `worker`: `paused`, `ended` |
     | `launched` | `engine` / `engine` | `engine-gone`; a `host-verify-leg` or `closing-out` with non-null `owner`; `paused`; `ended` |
     | inside an `engine` span | `session` / `dev attempt <p>`, `review pass <p>`, `studio gate`, `triage`: one per Stage Log row whose stage is `dev\|review\|gate\|triage` and whose start falls in `[engine start, engine end or now]`; `<p>` the row's `pass`, else its ordinal among that stage's rows in the span | the row's stop; a row with no stop is open |
     | (live run, engine span open, no open Stage Log row) | `session` / `liveStage` (else `Loading the stage…`) from the engine start (or the last session's stop) | — (open) |
     | `host-verify-leg` with non-null `owner` | `host-leg` / `host leg` (`by: "close-out"` or none) or `re-run` / `re-run` (any other `by`, e.g. `api`) | the next `host-verify` (outcome `green`, `inconclusive (guard)` when its `guard` is set and no suite is red, `red`, `skipped`; `suites` from `suite_durations`), `ended` |
     | `host-verify` with no lease open before it (pre-38.1, or a skipped leg) | `host-leg` (or `re-run` with `rerun`) from `detail.started_at` (else the event's `at`) to the event | itself |
     | `closing-out` with non-null `owner` | `close-out` / `close-out` | `closing-out` with `owner: null`, `closed_out`, `paused`, `ended` |
     | `paused` | `paused` / `paused: <run.reason or the event's detail.reason, else "no reason recorded">` | `close-out`, `engine-resume`, `resumed`, `ended` |
     | `ended` | — (a marker: `ended`) | — |

   - **Suite order:** `suites` lists `lib suite`, `conformance`, `supervisor`, `studio-web` first (38.1's `LEG_SUITES`, mirrored), then the rest by name.
   - **The final state in words** (`endedWords`):
     - `Complete`, `Partial`, `Blocked`, `Cancelled`, each followed by `: <run.reason>`, else `: no reason recorded`;
     - an `external` run is never ended here.
   - **39.6's seam:** `runTimeline`'s input gains `sessions` (the snapshot's `sessions[]` for this run). Its rows replace the Stage Log rows and the live stage. This is in 39.6's plan, not here.
3. **The clock (CAP-16, SPEC design note): `runClock({run, events}, now)` in `src/run/model.ts`, pure, shared by the run page, the Status rows and the HUD.**
   - **The rules, first match wins:**

     | Case | Anchor | Guard |
     |---|---|---|
     | A host leg open: the latest `host-verify-leg` with non-null `owner` and no `host-verify` after it | the lease's `at` | the lease's `guard_s`, else `legGuard(JSON.parse(run.definition))` mirrored (`host_verify_seconds`, else `max_wall_clock_seconds`, else 600); `guard: "host leg"` |
     | Running, a `worker` event recorded since the latest `claimed`/`close-out`/`engine-resume`, and the engine not ended (no `engine-gone`, `closing-out` with an owner, or lease after it) | the latest `worker` event's `at` | its `detail.guard_s`, else `run.worker_guard_s`, else the definition's `guards.max_wall_clock_seconds`, else 600 (the `sbxDeadline` rule); `guard: "worker"` |
     | Queued | `created` | none: `<HH:MM:SS> queued (no guard until a worker starts)` |
     | Running, no worker yet | the latest `claimed` | none: `<HH:MM:SS> since the claim (the guard starts with the worker)` |
     | Paused | the latest `paused` | none: `<HH:MM:SS> paused` |
     | Close-out between legs | the segment's start | none: `<HH:MM:SS> in close-out` |
     | Ended | none | the clock stops: `<HH:MM:SS> in all, claim to end` (the latest `claimed` to `ended`) |

   - **The label:**
     - guarded: exactly `HH:MM:SS of HH:MM:SS`, e.g. `01:12:40 of 02:00:00`. Elapsed is floored to whole seconds; hours are two digits or more.
     - past the guard: `… of … (over the guard)`.
     - The context line names the guard: `engine: the worker's guard` / `host leg: the leg's own guard`.
   - **The answer:** `{elapsed_s, guard_s: number | null, guard: "worker" | "host leg" | null, label, over}`.
4. **The cost per stage (CAP-16, SPEC design note): `costView({storyId, stageRows, cost_usd, window})`.**
   - **The story:** `storyIdOf(events)` is the latest `plan-status` event whose `detail.id` matches `^ST-\d+$` (36.6's `in-progress` event names it on a running launched run). None: the story is unknown.
   - **The read:** `GET /stories/<id>?project=<run.project_id>` (39.4).
   - **Row fields:** rows are read by CAP-12's names (`stage`, `start`, `stop`, `model`, `tokens`, `cost`). The Stage Log table's own column names (`stagelog.py STAGE_COLUMNS`: `pass`, `started`, `ended`, `cost_usd`) are accepted as well. A cost is a number, or a string `^\$?\d+(\.\d+)?$`; `—` is no cost.
   - **The rows that count:** only those whose start falls in the run's window (`claimed` to `ended`, or now) count. A story's earlier runs never count.
   - **The sources:**
     - `stage-log`: the sums per stage in first-seen order, and their total;
     - `run-total`: `cost_usd`, when no counted row has a cost or the story is unknown;
     - `none`: `cost_usd` null.
   - **The labels:**
     - `Cost by stage, from the Stage Log of <ST id>`;
     - `Run total (no story known for this run)`;
     - `Run total (the Stage Log has no costed rows for this run)`;
     - `Run total (the story could not be read: <error>)`;
     - `Not metered yet`;
     - `Loading the Stage Log…` while the story read is pending.
5. **Cancel (CAP-16/17, SPEC design note).**
   - **Consequence first, two steps.** `Cancel…` reveals the sentence `CANCEL_CONSEQUENCE` and a `Cancel run <id>` confirm button: "Cancel stops this run for good: a launched engine is stopped gracefully, the worker is killed and the run ends cancelled; it cannot be resumed. Commits already made stay on the run's branch."
   - **Who may cancel** (`canCancel(run)`):
     - `queued`, `running` and `paused` may;
     - `external` is disabled, with `Started outside the queue: the supervisor never cancels it`;
     - a terminal run shows no Cancel.
   - **The call:** `postCancel(runId, csrf)` posts with `x-csrf-token`. The token comes from `GET /inbox?project=<project>` (`csrfOf`).
   - **The answers in words:**
     - 200: `Cancelled.`, then a re-read;
     - 409 `RunTerminal`: `Already ended: <state>`;
     - 409 `ExternalRun`: as above;
     - 403 `CsrfRefused`: `The page's token was refused; reload the page`;
     - 404 `RunNotFound`;
     - other: `<url> answered <status> <error>`.
6. **The events list (CAP-16).** `eventRows(events)`: one row per event, oldest first. Each row is a `<details>`:
   - its summary is `<seq> · <local time> · <kind>` plus ` · <from> → <to>` when the state moved;
   - its body is `JSON.stringify(detail, null, 2)`, folded by default.
7. **The Status queue (CAP-17, SPEC design note): `queueRows(statusAnswer, details, live, now)` in `src/status/model.ts`.**
   - **The rows:** one per `GET /status` `live[]` run, grouped in the AC's order `queued`, `claimed`, `running`, `paused` (then `external`), and by `created` within a group.

9. **The hold and the lerp (CAP-17, SPEC design note), in `src/office/model.ts`, pure, injected clock.**
   - **The constants:** `HOLD_MS = 1000`, `LERP_MS = 500`.
   - **The hold:** `hold(prev: Held<T> | null, raw: T, now): Held<T>`, where `Held = {value, since}`.
     - The first value shows at once.
     - A raw value equal (JSON) to the shown one keeps `prev`.
     - A different raw value replaces the shown one only when `now - since >= HOLD_MS`. It then shows with `since = now`.
     - Otherwise `prev` stays. So a burst A→B→A inside 1 s never shows B.
   - **The lerp:** `tween(prev: Tween | null, target: number, now): Tween` with `valueAt(tw, now)`.
     - `Tween = {from, to, start}`.
     - A new target starts from `valueAt(prev, now)` (a retarget mid-tween never jumps).
     - The value at `start + LERP_MS` is the target.
   - **What is held:** the stage, the story, the run id, the findings count, the clock's guard and label context, and each phase's status.
   - **What is held, then lerped:** the clock's `elapsed_s`, the project bar's fraction and each phase's fill.
   - **The animation clock:** `OfficeScreen` drives `now` with `requestAnimationFrame` while any tween is in flight, and with the existing 1 s timer (:102) otherwise.
   - Movement is on until 39.8's toggle exists (CAP-25). No toggle is added here.
