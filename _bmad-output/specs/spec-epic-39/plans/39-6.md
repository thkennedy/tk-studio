## Intent

Today the office draws one still figure per role, posed from `OFFICE_MAP`. The owner wants to see the studio work: every live session as a character at its role's desk, each sub-agent it spawns as a smaller character beside it, and a click that shows what that character is up to (addendum §3.4).

The story has three parts:
- **The hooks.** The engine's Claude Code sessions register `SubagentStart`, `SubagentStop` and `PreToolUse` hooks. The hook appends tool-name-only lines to `.bmad-loop/runs/<engine-run-id>/agents.jsonl`.
- **The projection.** It reads that file, the journal and the queue's lease events into `sessions[]` and `studio`. It streams `office.session` (and `office.studio`) deltas.
- **The renderer.** It draws the sessions with the existing role and `session` frames and a new `subagent` region. It adds the walk-in and walk-out, the point bubbles, the 1 s hold, the `!` bubble and blocked badge, the side panel and the closed state.

2. **The line (CAP-18).**
   - The hook writes one line per event to `<BMAD_LOOP_RUN_DIR>/agents.jsonl`: one `json.dumps(…, ensure_ascii=True, separators=(",", ":"))` plus `\n`, in a single `write` call to an `open(path, "a", encoding="utf-8")`. It writes nothing else, no other file, and prints nothing to stdout or stderr. A PreToolUse hook's stdout may be read as a decision.
   - The line is exactly seven keys: `{"at": "<UTC ISO, ms, Z>", "session_id": <str|null>, "agent_id": <str|null>, "parent": <str|null>, "description": <str|null>, "event": "PreToolUse"|"SubagentStart"|"SubagentStop", "tool": <str|null>}`.
   - `event` is argv[1]. Missing, it falls back to the payload's `hook_event_name`. Any other value writes nothing.
   - `session_id` and `agent_id` come from the payload. An id is kept only when it matches `^[A-Za-z0-9_.:-]{1,128}$`, else null.
   - `parent` is the `session_id` for `SubagentStart`, `SubagentStop` and a `PreToolUse` that carries `agent_id` (fired inside a sub-agent); otherwise null.
   - `description` is the payload's `agent_type` on `SubagentStart`/`SubagentStop`, kept when it matches `^[A-Za-z0-9_.: -]{1,80}$`; otherwise null. Never the Agent tool's `description` or `prompt`: those are tool input.
   - `tool` is `tool_name` on `PreToolUse`, kept when it matches `^[A-Za-z0-9_.:-]{1,128}$`, else null. It is null on the sub-agent events.
   - Never read: `tool_input`, `tool_use_id`, `transcript_path`, `agent_transcript_path`, `last_assistant_message`, `cwd`, `prompt`.
   - stdin is read as `sys.stdin.buffer.read()` and decoded UTF-8 with `errors="replace"`. A non-object payload is `{}`.
   - The whole body sits in `try/except BaseException`, and `main` returns 0 on every path.
   - Design note: `- CAP-18 — agents.jsonl line: optional entry: one line per hook event {at (UTC ISO ms Z), session_id, agent_id, parent (the session_id on SubagentStart/SubagentStop and on a PreToolUse fired inside a sub-agent, else null), description (SubagentStart/Stop agent_type, else null), event, tool (PreToolUse tool_name only)}, ids and names kept only when they match a name pattern, never tool_input, prompts, transcript paths or last_assistant_message; nothing printed, exit 0 on every path — per _bmad-output/planning-artifacts/design/studio-design-spec-2026-11-07-front-end/README.md§3.4`

4. **The kind and role mapping (CAP-19).** This is pure, in `apps/supervisor/src/sessions.ts`, over the journal entries since the latest `run-start`/`run-resume` (as `analyseRun` :537), the run's queue events, `agents.jsonl` and the session-start join.
   - **engine:** a journal `session-start` opens the session; its `session-end`, or a `run-complete`/`run-stop`/`run-crash` after it, or a queue `engine-gone` after the latest `launched`, closes it. Role:
     - `task_id` contains `-studio-pipeline.gate-` → `planner` (OFFICE_MAP row 6);
     - journal role `dev` → `implementer`;
     - `review` or `triage` → `reviewer`;
     - anything else → `session`.
   - **sub-agent:** an `agents.jsonl` `SubagentStart` whose `parent` maps to an open engine session opens it, and its `SubagentStop` (same `agent_id`) or its parent's end closes it. Its role is the parent's.
   - **The Claude session to engine task join:** `<run dir>/events/*-SessionStart.json`, the relay's files `{ts, event, task_id, session_id, …}`, which the engine never deletes (`signals.py SignalWatcher` keeps a consumed set).
     - The listing is cached per directory by its entry count. Only new files are parsed. The cache is added to `pruneCaches` and `officeCachedPaths`.
     - A line whose `session_id` has no join yet goes to the run's only open engine session when exactly one is open. Otherwise it is held until the join appears.
   - **launch** (orchestrator):
     - Open: the run is `running` with no `launched` after the latest move (`close-out`/`engine-resume`; `signals.launching`, OFFICE_MAP row 5), and a `session` or `worker` event exists after that move.
     - `started_at`: the first such event's `at`.
     - Closed: `launched`, or the run leaving `running`.
   - **host-verify** (orchestrator):
     - Open: the latest `host-verify-leg` has a non-null `owner` and no later `host-verify`/`host-verify-leg`; or OFFICE_MAP row 10's signal (`engineEnded && !hostVerified`).
     - `started_at`: the lease's `at`; else the latest `engine-gone` after `launched`; else the journal's end entry `ts`.
     - Closed: `host-verify`.
   - **closeout** (orchestrator):
     - Open: the latest `closing-out` has a non-null `owner` and no later `closed_out`; or the run is live, the engine ended, `host-verify` follows the latest `launched`, and no `closed_out` follows it.
     - `started_at`: the lease's `at`, else that `host-verify`'s `at`.
     - Closed: `closed_out`.
   - Design note: `- CAP-19 — session kinds: named placeholder rule: engine = journal session-start until its session-end (or run-complete/stop/crash, engine-gone), desk planner for a -studio-pipeline.gate- task, implementer for dev, reviewer for review|triage, session otherwise; sub-agent = agents.jsonl SubagentStart until SubagentStop or its parent's end, its parent's desk, joined to the engine task by the relay's <run dir>/events/*-SessionStart.json session_id; launch = a session/worker event with no launched since the latest close-out/engine-resume; host-verify = a held host-verify-leg lease or the engine ended with no host-verify; closeout = a held closing-out lease or host-verify done with no closed_out; the three legs at the orchestrator's desk — per _bmad-output/planning-artifacts/design/studio-design-spec-2026-11-07-front-end/README.md§3.4`

5. **State and grace (CAP-19).**
   - **Engine and sub-agent states** come from the latest `PreToolUse` line of that session: top-level lines (no `agent_id`) for the engine session, `agent_id` lines for a sub-agent.
     - `Read`, `Grep`, `Glob` → `reading`; `Edit`, `Write` → `typing`; `Bash` → `running`; any other tool, or none yet → `thinking`. The AC's table is literal: `MultiEdit` and `NotebookEdit` are `thinking`.
     - launch is `thinking`; host-verify and closeout are `running`.
     - A closed session is raw `offline`.
   - **The hub's grace.** It applies `graced()` to each session under its own `sessionGrace` map. A working-to-working change is rank-equal, so it is instant. A closed session (raw `offline`) keeps its shown state for `graceMs` (20 000), and only then leaves the view.
   - **The wire.** The snapshot and deltas never carry `offline`. `projectOffice` (raw) lists open sessions only. The hub keeps the held ones from its previous view.
   - Design note: `- CAP-19 — session state: named placeholder rule: the latest PreToolUse tool of that session (Read|Grep|Glob reading, Edit|Write typing, Bash running, any other or none thinking; a sub-agent by its agent_id lines), launch thinking, host-verify and closeout running; a closed session keeps its shown state for the hub's graceMs (20 s, §7.3 demotion, its own grace map) and then leaves sessions[] — per _bmad-output/planning-artifacts/design/studio-design-spec-2026-10-09/README.md§7.3`

6. **Points and recent (CAP-19 → CAP-20).**

Each journal point goes to the latest engine session of that `story_key` that started before the entry, open or within its grace. A point whose session already left goes nowhere.

     - `started`;

     - `sub-agent started: <name>` / `sub-agent stopped: <name>` (on the parent);

     - `review: <status>`;

7. **`studio` and the deltas (CAP-19).**
