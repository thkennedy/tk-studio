## Intent

Today the `post_commit` meter runs inside the microVM and records its observation only in the sandbox's own ledger (`~/.tk-studio/measurements/agent-claude-tk-studio.jsonl`). Recreating the sandbox loses that ledger (hole 23): seven Epic 25 observations had to be re-recorded by hand, and 26-1 to 26-3 sit in the sandbox ledger right now. The fix has four parts:

- The meter also writes the observation envelope beside `metered.json` on the mounted checkout.
- A host-side `meter.py harvest` appends each envelope once to the host ledger.
- `evolve.py draft` stops clustering `meter:` observations (PROP-067).
- Runbook §3.8 gains the recreate step.

Band M: the story touches 5 files and adds about 250–300 lines, most of them tests.

## Acceptance Criteria

1. **Given** the `post_commit` meter hook inside a sandbox **When** it prices a landed story **Then** it also writes the full observation envelope to `<run_dir>/transcripts/<story>/observation.json` on the mounted checkout beside `metered.json`, so the record survives the sandbox
2. **Given** `meter.py harvest --run-dir <dir>` run on the host **When** it finds observation files not yet harvested **Then** it appends each to the host ledger through `observe.record_observation` exactly once (a harvested marker beside the file), reports the story keys and dollars, and the seven re-recorded Epic 25 observations of 2026-10-15 are not duplicated (the marker is seeded for them)
3. **Given** `evolve.py draft` **When** it clusters observations **Then** observations whose description starts with `meter:` are excluded from clustering and counted in the result as `measurements_skipped`; PROP-067's cluster is not re-created on a rerun, and the lib suite pins the exclusion
4. **Given** runbook §3.8 **When** the story closes **Then** the sandbox recreate step says to run the harvest and to export the sandbox's own ledger (`~/.tk-studio/measurements/*.jsonl` inside the microVM) to the host before `sbx rm`, with the exact commands

## Settled shape

Gate session: these rulings are recorded here only. The SPEC.md bullet below is **not** appended (see Risks).

1. **`observation.json` (CAP-12).**
   - `record()` writes the exact envelope `record_observation` returned (`ts`, `event`, `user`, `machine`, `project?`, `payload`) to `<run_dir>/transcripts/<story_key>/observation.json`, atomically with `indent=2` and a trailing newline. It writes it after the emit and before `metered.json`.
   - It is written on every metered run, host or sandbox, with no sandbox detection. The harvest tells the two apart by identity (shape 2).
   - `--no-record` writes neither file.
   - A `metered.json` already present short-circuits as today, so a pre-26.4 story never gains an `observation.json` later.
2. **`meter.py harvest --run-dir <dir>` (CAP-13).**
   - **Scan.** It scans `<dir>/transcripts/*/observation.json` in sorted order. A missing `<dir>` is the refusal `run dir <dir> does not exist` (exit 2).
   - **Validate first.** Every candidate file is validated before anything is appended. A file that is not JSON, or whose `payload` lacks a string `description`/`source`, is the refusal `observation <path> is unreadable: <why>` (exit 2, nothing appended).
   - **Per story dir, in this order.** The marker is `harvested.json` beside the file, written atomically as `{"story_key", "harvested_at" (UTC ISO ms), "how": "appended"|"in-ledger"|"seeded", "ledger": <ledger file name>}`.
     - (a) `harvested.json` exists: report under `already_harvested`, do nothing.
     - (b) The key is in `HARVEST_SEEDED` (a module `frozenset` of the seven Epic 25 keys, commented "re-recorded on the host ledger 2026-10-15, loop deficiency 23; measurements/tim-Tim-PC-2.jsonl l.118–124"): write the marker with `how: "seeded"`, append nothing, report under `seeded`.
     - (c) The envelope's `<user>-<machine>.jsonl` equals `ledger.ledger_path().name` (it was emitted into this very ledger, meaning the meter ran on the host): write the marker with `how: "in-ledger"`, append nothing, report under `in_ledger`.
     - (d) Otherwise: `observe.record_observation(payload["source"], payload["description"], evidence=payload.get("evidence"), project=envelope.get("project"))`, then the marker with `how: "appended"`, report under `harvested`.
   - **Order.** Append comes before the marker. A crash in between can re-append once on the next harvest, which is accepted and noted in the docstring. Marker-first could lose the record, which is the failure this story fixes.
   - **Dollars.** Each `harvested` item is `{"story_key", "usd_total"}`, with `usd_total` read from `metered.json` beside the file (`null` if absent).
   - **Result.** `{"ok": true, "run_dir", "ledger": <path>, "harvested": [...], "usd_total": <sum of harvested, rounded 6>, "already_harvested": [...], "in_ledger": [...], "seeded": [...]}`, exit 0. There is no AD-11 block, because this is a lib CLI like `story`.
   - **What it never touches.** Story dirs with only `metered.json` (pre-26.4, including 26-1 to 26-3 of this run) are never harvested and are not reported. The sandbox-ledger export (AC4) recovers them.
3. **`evolve.py draft` exclusion (CAP-14).**
   - In `draft`, before `cluster(events)`, split off observation events whose `payload.description` is a string that `startswith("meter:")`. Cluster only the rest.
   - `measurements_skipped` is their count. It is also `0` on the no-measurements early return, so the result shape stays the same.
   - `stranded` excludes any row whose key equals `_slug(e)` of a skipped measurement. Such a row was minted from measurements, not left by a cluster merge, so the contract's `stranded` sentence still holds.
   - The row itself is untouched: never deleted, status unchanged, counted neither `updated` nor `unchanged`.
   - Live expectation: `clusters: 66`, `unchanged: 66`, `measurements_skipped: 7`, `created: []`, `stranded: []`.
4. **Runbook §3.8 recreate step (CAP-15).**
   - A new bold paragraph, **"Recreating a sandbox without losing the cost record"**, goes after the "sandbox store" drift paragraph (it ends l.670). Its numbered steps, all from the host:
     1. From Git Bash on the host, with no run in flight: `MSYS_NO_PATHCONV=1 sbx exec claude-<project> bash -lc 'cat ~/.tk-studio/measurements/*.jsonl' > ~/.tk-studio/measurements/sandbox-claude-<project>-$(date +%Y%m%d).jsonl`
     2. From the tk-studio checkout: `uv run --no-project python plugins/tk-studio/lib/meter.py harvest --run-dir .bmad-loop/runs/<run-id>` (once per run dir).
     3. Only then `sbx rm claude-<project>`, then create again (l.603–606).
   - The harvest goes after the export so that a harvest refusal never blocks the export.
   - The export lands in the host store as an extra file. `measurepush.py` pushes only `ledger.ledger_path()` (l.58/70), so the extra file is kept but never pushed. Merging it into the repo's `measurements/` is the operator's call; say so in one sentence.
   - State that meter rows can appear in both the exported file and the harvested ledger (different `user`/`machine`), and that the export is what carries 26-1 to 26-3 and every non-meter observation.
   - "Running an epic" item 4 gains one sentence: the meter also writes `observation.json`, and the host harvests it (Story 26.4).
