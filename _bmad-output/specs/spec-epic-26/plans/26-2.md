## Intent

Two planner holes. Hole 19: a story whose ACs need a schema entry, file or tag for an artifact that only a later story or the operator produces gets left as a Block If or an open question, so the dev session halts on something the design documents already settle. The fix is a task-planning rule: the planner records the settled shape in the epic SPEC's `## Design notes`, citing the constraining document. The launch consult scope then names schema shape as a planner matter when the documents constrain it, and an operator ruling only when they do not. Hole 6: `transcribe.py`'s dispatch note asks for `stories/<id>-<slug of the title>.md`, but the id already carries the slug, so the slug is repeated. The live 26-1 spec path is 189 characters. The fix is the note text `stories/<id>-spec.md`. Band L, reason: about 7 small files across the studio-pipeline plugin, the launch resource, a new test module with a fixture, and the runbook. Under 300 new lines.

## Acceptance Criteria

1. **Given** `.bmad-loop/plugins/studio-pipeline/task-planning.md` and the SPEC the planner writes **When** a story's acceptance criteria require a schema entry, a file or a tag for an artifact that only a later story or an operator action produces **Then** the planner records the settled shape in the SPEC's design notes (an optional or deferred entry, a per-platform map, a named placeholder rule) citing the design document that constrains it, and never leaves it as a Block If or an open question; the consult scope text in the launch customization names schema shape as a planner matter when the design documents constrain it, and an operator ruling only when they do not
2. **Given** the dispatch notes `transcribe.py` writes into `stories.yaml` **When** they name the executor spec file **Then** the name is `stories/<id>-spec.md` (the id already carries the title slug), the engine's glob `<id>-*.md` still resolves it, a bare `<id>.md` is still read as pending (hole 1 unchanged), and the longest resulting path on this box stays under 200 characters
3. **Given** the lib suite **When** the story closes **Then** the transcription tests pin the new name, a planner-note fixture pins the settled-shape rule, and the runbook §3.8 names both

## Settled shape (planner rulings, 2026-10-15; the AC text and this epic's bootstrap constrain these, so they are not Block Ifs)

1. **Where the settled shape goes.** task-planning.md §3 gains one rule, stated once.
   - **When it applies:** an AC needs a schema entry, file or tag for an artifact that only a later story or an operator action produces.
   - **What the planner does:** it appends a bullet to `<spec_folder>/SPEC.md` `## Design notes (settled shape, planner, <date>)`, creating the section if absent. The plan's own "Settled shape" section carries the detail.
   - **Bullet format:** `<CAP or story> — <artifact>: <shape> — per <design document path[§]>`. `<shape>` is one of `optional entry`, `deferred entry`, `per-platform map`, `named placeholder rule`, each with its concrete text.
   - **Never** a Block If or an `open_questions[]` item.
   - **When no design document constrains it:** it stays a Block If naming an operator ruling.

   The plan template's "Risks and open decisions" line gains the carve-out: settled shapes are not Block Ifs. Appending design notes to SPEC.md is a planner write, not a `bmad-spec` edit (AD-4 untouched).
2. **Consult scope.** Append one sentence to `scope` (keep the existing text): "Schema shape for an artifact a later story or an operator produces is a planner matter, settled in the SPEC's design notes, when the design documents constrain it; an operator ruling (`escalate`) only when they do not."
3. **Spec file name.** Only the `transcribe.py` sentence changes, to `` `stories/{key}-spec.md` ``. Leave the existing `stories.yaml` entries of Epic 26 untouched (the story's Never list), so they keep the old wording until the next transcription. task-planning.md l.30 gains no file-name text; the dispatch note is the one statement.
4. **Tests.** New `plugins/tk-studio/lib/tests/test_planner_rules.py` (one module for the story):
   - (a) `entry()` names `stories/<key>-spec.md`, keeps the glob and pending clauses, and never contains `<slug of the title>`.
   - (b) A `Path.glob(f"{key}-*.md")` over a tmp `stories/` dir resolves `<key>-spec.md`, and a bare `<key>.md` does not match.
   - (c) The worst-case path, `REPO_ROOT` + `_bmad-output/specs/spec-epic-99/stories/` + a 60-character-slug key + `-spec.md`, is under 200 characters.
   - (d) The planner-note fixture `plugins/tk-studio/lib/tests/fixtures/planner-note/SPEC.md` holds a `## Design notes (settled shape, planner, …)` section. Each bullet names one of the four shapes, cites a design document path, and never says `Block If` or `open question`. The test also asserts that task-planning.md states the rule (the section heading, the four shapes, "never a Block If").
   - (e) The shipped consult `scope` names schema shape as a planner matter and an operator ruling otherwise.
