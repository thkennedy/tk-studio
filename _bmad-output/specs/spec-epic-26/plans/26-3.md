## Intent

Epic 24.3's third arm needs a cheaper main model paired with a stronger advisor, and the meter must price the advisor's calls. Every routing leg gains an optional `advisor` (`opus | fable | off`, default `off`). `pipeline.py` validates it, including the pairing rule. `apply` writes it to `routing.current.json`, and the session's `claude -p` command line carries `--advisor`. The executor customization passes `model`, `effort` and the advisor on every subagent launch. The dispatch note states the consult triggers as advisor instructions. `meter.py` prices advisor usage as its own leg `advisor`. Contract §5 documents the field as an append to the existing 0.1.21 clause. The shipped route does not change: `advisor = "off"` on every leg (AD-14). Band L, because the story touches about 11 files across lib, the launch resource, the executor customization, the transcriber, the contract and three test modules, adding roughly 300–380 lines.

## Acceptance Criteria

1. **Given** `[pipeline.legs]` in the launch customization and a project's `.bmad-loop/routing.toml` **When** a leg carries `advisor = "opus" | "fable" | "off"` **Then** `pipeline.py check|resolve|apply` validate it (default `off`; the pairing rule: the advisor must rank at or above the leg's model; a violation is a named refusal), `apply` writes it into `routing.current.json`, and the session leg's `claude -p` command carries `--advisor <model>` only when the leg's advisor is not `off`
2. **Given** the implementer and reviewer launches the session makes **When** the routing is in force **Then** each launch passes `model`, `effort` and the advisor explicitly (the executor customization reads `routing.current.json`), and the dispatch note's consult triggers are stated as advisor instructions when an advisor is on ("consult the advisor on: verify-red, halt, deviation above 0, a high-severity finding, a tripwire, a file outside Files, and before declaring the story done"), with a Consult Log entry appended per advisor call so the audit trail survives
3. **Given** `lib/meter.py` **When** a story's transcripts carry advisor usage **Then** the meter prices it as its own leg `advisor` from the price table (a missing price is a named refusal, never a guess) and the observation names it beside the other legs
4. **Given** the driver contract §5 **When** the story closes **Then** it documents the `advisor` field and the pairing rule (0.1.21, additive), the lib suite pins the validation, the command line and the pricing, and conformance is green; the shipped defaults stay `advisor = "off"` on every leg (AD-14: nothing changes until Epic 24.4 records a verdict)

## Settled shape (planner rulings, 2026-10-15; the AC text, the advisor fit note and the bundled Claude API reference constrain these, so they are not Block Ifs)

1. **Vocabulary and pairing.**
   - `advisor` is a leg field. Its values are exactly `opus`, `fable` and `off`, and a missing field means `off`.
   - Rank, per SPEC Assumptions and `briefs/advisor-tool-fit-2026-10-09.md`: fable 3; opus 2; every other model 1.
     - `claude-fable-5-1` has rank 3.
     - `claude-opus-5-5` and `claude-opus-5` have rank 2.
     - `claude-sonnet-5` and `claude-haiku-4-5-20251001` have rank 1.
   - A leg whose resolved model outranks its advisor is refused. `off` is never ranked.
   - Refusal text, the stable token tests match on: `<where>.<leg>: advisor '<a>' ranks below model '<m>' (the advisor must rank at or above the leg's model)`.
   - The pairing check runs in three places:
     - per table, when the table carries both fields (resource, project defaults, rules, stories, runtime)
     - in `resolve`, on the overlaid route, so `apply` inherits it
     - in `check`, on the defaults-only effective route (resource overlaid by project `[defaults]`), reported in `problems[]`
   - `--advisor` takes the value verbatim (`--advisor opus` / `--advisor fable`). It is the Claude Code CLI alias, per the fit note.
   - `render_block` adds the flag to each engine-stage leg from that leg's own advisor. The session leg is the AC's case, and review/triage use the same loop, so a declared advisor is never silently dropped. The tests pin the session leg.
2. **Advisor usage in transcripts.** This is a named placeholder rule, because the first real advisor transcript comes from the operator's Epic 24.3 arm. The rule: in `message.usage`, each `usage.iterations[]` entry whose `type` is `"advisor_message"` is one advisor call. It carries its own `model` and the standard token fields (`input_tokens`, `output_tokens`, `cache_read_input_tokens`, `cache_creation_input_tokens`). Each one is priced at that model's rates under leg `advisor`.
   - Top-level `usage` stays the executor's, and advisor tokens are never added to it.
   - An `advisor_message` iteration with no string `model` is a named refusal (`advisor usage without a model`), never zero.
   - The constraints: the fit note (§Risks 1, "advisor usage is reported separately by the API") and the bundled claude-api reference, which says server-side steps itemize their tokens under `usage.iterations` (`shared/cost-optimization.md`; `fallback_message` precedent in `shared/model-migration.md`).
   - Keep the type name in one constant, `ADVISOR_ITERATION = "advisor_message"`, with a comment saying 24.3's first advisor transcript confirms it.
   - SPEC bullet for this shape (see Risks: not appended by the gate): `- CAP-10 — advisor usage in transcripts: named placeholder rule — usage.iterations[] entries of type "advisor_message" (own model + token fields) price under leg advisor; top-level usage stays the executor's; confirmed by Epic 24.3's first advisor transcript — per briefs/advisor-tool-fit-2026-10-09.md §Why it matters (risk 1)`.
3. **Explicit effort for subagent legs.** The resource tables stay as they are, with no effort on implementer, reviewers or consult (test_pipeline l.106–108 stands, AD-14).
   - In `resolve`, a subagent leg (implementer, reviewers, consult) that resolves no `effort` takes the session leg's resolved effort.
   - `sources[leg]["effort"]` names that as `"inherited-session"`.
   - So `routing.current.json` always carries an explicit effort for every leg the session launches. This makes today's behaviour explicit (in-process subagents run at the session's effort) and changes no shipped value.
4. **Executor and dispatch text.** The Agent tool has no advisor parameter, so the advisor is passed as the first line of each subagent prompt:
   - When the advisor is on: `Advisor: <value> — consult the advisor on: verify-red, halt, deviation above 0, a high-severity finding, a tripwire, a file outside Files, and before declaring the story done.`
   - When it is off: `Advisor: off — do not call the advisor.`

   **Dispatch note sentence** (transcribe.py): "Advisor: when routing.current.json gives the session an advisor other than `off`, consult the advisor on: verify-red, halt, deviation above 0, a high-severity finding, a tripwire, a file outside Files, and before declaring the story done; append a `## Consult Log` entry per advisor call."

   **Consult Log entry for an advisor call:** `- <UTC time> — advisor: <value> — trigger: <t|before-done> — guidance: <one line> — applied: <yes|declined: why>`.

   **The consult subagent is unchanged and coexists.** Whether the advisor replaces it is an operator ruling, per the fit note's "Rulings only Tim can make".
