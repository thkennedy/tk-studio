## Intent

The canonical plan never learns that a loop landed a story in another repository (hole 18), and a driver may not write canonical frontmatter itself (AD-4, AD-5). The fix is one new planning-adapter verb, `plansync.py status`: it sets a canonical story's `status`, stamps `updated`, records the caller and a note in an `external.driver` snapshot, then re-runs the existing `sync` so the projection and `plan/index.md` follow. Epic 27's supervisor calls it on PR-open (`review`) and PR-merge (`done`); calling it is a non-goal here.

Band L, stated reason: the files are few in kind, but the contract, its pin test, the conformance manifest and a new fixture add four files to the two lib files, about 8 files and 350–400 lines (most of them tests).

## Acceptance Criteria

1. **Given** `plansync.py status --directory <root> --id ST-NNN --status <enum> [--note <text>]` **When** it runs on a project whose canonical entity exists **Then** it sets the entity's `status` to the given canonical enum value, stamps `updated`, records the note and the caller in the entity's `external.driver` snapshot (never touching `external.<backend>` snapshots), re-syncs the projection and the index, and names every written file in its result (AD-5: status-class only; a value outside the enum is a named refusal; an unknown id is a named refusal)
2. **Given** a story that a loop landed in another repository (a transcribed epic) **When** the verb is called on the owning project with that story's canonical id **Then** it updates the canonical file there and nothing in the other repository, and the result says which plan it wrote
3. **Given** the driver contract §4 **When** the story closes **Then** the verb is documented as additive (0.1.21), the conformance manifest drives it (a headless success and a refused id), the lib suite pins the enum, the snapshot and the projection re-sync, and `plan/index.md` reflects the change after a run

## Settled shape

Gate session: per the gate's rules these are recorded here only; the SPEC.md bullet below is **not** appended (see Risks). The caller flag itself is already settled in SPEC.md Assumptions ("optional `--caller` flag, defaulting to the invoking surface name").

1. **`external.driver` snapshot (CAP-16).** Written by the verb on every non-dry run, replacing any earlier `driver` snapshot whole:
   - `key`: the caller (the required backend-identity field; for a driver, the driver's name).
   - `synced_at`: the same `_now()` value stamped into `updated`.
   - `content_hash`: `sha256` hex over `id`, `status`, `note`, NUL-separated (the `backlogmd._content_hash` construction).
   - `caller`: the caller; `status`: the status set; `note`: the note, `""` when absent; `previous_status`: the entity's status before the call.
   - `--caller` defaults to `tk-studio-plan-sync`; a blank caller is the refusal `caller must be a non-empty string`.
   - Every other `external.<name>` entry is left byte-for-byte as it was by the verb's own write.
2. **The verb and its result (CAP-16, CAP-17).** `plansync.py status --directory ROOT --id ST-NNN --status ENUM [--note TEXT] [--caller NAME] [--dry-run]`.
   - Order: validate `--status` against `interchange.STATUS_VALUES` → find the entity by `id` among `plan_dir(root)` entities → refuse a non-story → write the entity (status, `updated`, snapshot) → `sync(root, dry_run)` → result.
   - Always writes, even when the status is unchanged (each call is a driver event; reruns differ only in `updated`/`synced_at`).
   - Refusals (exit 2, nothing written): `status '<v>' is not in the canonical enum (draft, ready, in-progress, blocked, review, done, dropped)`; `unknown id <ID>: no canonical entity in <plan dir>` (also when the plan dir is absent); `<ID> is a <type>, not a story — status takes a story id`.
   - Result: `{"ok", "id", "status", "previous_status", "caller", "note", "path": <entity file>, "plan_dir": <the owning project's plan dir>, "dry_run", "sync": <sync result>, "written": [entity path, then sync's written, deduped], "removed": sync's removed}`. A blocked sync (jira preflight) returns `ok: false`, `blocked: true`, the sync `reason`, and still names the landed entity write in `written` (the l.636–642 precedent).
   - `--dry-run` writes nothing and names what it would write (the `normalize`/`sync` convention); it exists for the conformance success drive.
   - Only `--directory` is touched; a story landed elsewhere is found by its canonical id in the owning project's plan, and `plan_dir` is "which plan it wrote" (AC2).
3. **The note (CAP-16).** One line: a note containing `\n` or `\r` is the refusal `note must be a single line` (miniyaml cannot round-trip it).
4. **Conformance (CAP-18).** New fixture `contracts/conformance/fixtures/plan-status/_bmad-output/planning-artifacts/plan/` holding a valid `EP-001.md` and a valid story `ST-001.md` (parent `EP-001`, status `in-progress`); no `epics.md`, no index. Drives appended to `tk-studio-plan-sync`:
   - `{"assertion": "headless-clean", "argv": ["lib/plansync.py", "status", "--directory", "contracts/conformance/fixtures/plan-status", "--id", "ST-001", "--status", "review", "--dry-run"], "expect": "json"}` (dry run, so the committed fixture never changes).
   - `{"assertion": "blocked-on-ambiguity", "argv": ["lib/plansync.py", "status", "--directory", "{sandbox}", "--id", "ST-999", "--status", "review"], "expect": "refusal", "marker": "unknown id ST-999"}`.
