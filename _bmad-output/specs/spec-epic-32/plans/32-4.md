## Intent
In `scoping`, the planner writes the engagement's `scope.md` in six fixed sections. `engage.py scope` checks it, refuses a deliverable with no acceptance signal by name, and publishes it as the engagement's Confluence page (`Engagements/ENG-NNN`, provenance footer, skipped by content hash), recording `scope_page {id, url, version}`. Nothing becomes a plan entity before approval. While `scoping` the page is authoritative (D9). An owner edit in Confluence, mirrored by the next sync-back, replaces `scope.md` wholesale. A `revise` body from the Chat screen becomes the new page and `scope.md`, and a `revise` in `quoted` voids the quote (32.1's row). The planner's next turn reads the new scope (F2 step 3; B5 items 1 and 3).

## Acceptance Criteria
- AC1: **Given** `scoping` **When** the planner writes `engage.py scope` from the turn's `scope.md` (the sections, in order: goal; deliverables, each with its acceptance signal; exclusions; what the studio needs from the owner, each dependency dated; milestones; proposed epics and stories in `epics.md`'s story shape) **Then** 31.3's publish puts the page in the engagement's Confluence folder (`Engagements/ENG-NNN/Scope of Work`; provenance footer; skipped by content hash when unchanged) and `scope_page {id, url, version}` is recorded; the proposed epics and stories are not plan entities yet (nothing under `plan/` before approval, 32.6); a scope with a deliverable lacking an acceptance signal is refused by name
- AC2: **Given** the owner edits the page in Confluence, or sends `revise` with a body from the Chat screen **When** the next sync-back mirrors the page (31.4, `kb/confluence/`) or the input arrives **Then** the revision replaces `scope.md` wholesale (the page is authoritative while `scoping`, D9; a `revise` body becomes the new page), a `revise` in `quoted` returns the state to `scoping` and voids the quote, and the planner's next turn reads the new scope; the lib suite covers the round trip (Markdown to storage format to mirrored Markdown keeps every section), the replace rule and the refusal with a fake Confluence REST

## Settled shape
1. CAP-8: `scope.md` (`named placeholder rule`). `_bmad-output/engagements/<id>/scope.md` holds these `##` sections, in this order, each non-empty:
   1. `## Goal`
   2. `## Deliverables`: each deliverable is a `### <title>` holding a line that starts `Acceptance signal:` with text after it. A deliverable without one is `DeliverableWithoutSignal: <title>`.
   3. `## Exclusions`
   4. `## What the studio needs from you`: each list item carries an ISO date `YYYY-MM-DD`. An item without one is `ScopeInvalid: dependency <n> has no date`.
   5. `## Milestones`
   6. `## Proposed epics and stories`: `### Epic <k>: <title>` and `#### Story <k>.<m>: <title>`, each story with the `As a … / I want … / So that …` lines and `**Acceptance Criteria:**` as in `epics.md`. The numbers are local; 32.6 renumbers them at approve. At least one story is required.
   7. An optional `## Assumptions`, last (Settled shape 5).

   Text before `## Goal` (a `#` title) is allowed. An unknown `##` section is `ScopeInvalid`.

   Per Story 32.4 AC1 and `epics.md`'s story shape. SPEC.md bullet appended.
2. CAP-8: the page (`named placeholder rule`).
   - **Folder.** A top-level folder `Engagements` (found by title in `find_folders`, else `create_folder`), then its child folder `ENG-NNN` (`find_child_folder`, else `create_folder(..., parent_id)`). The folders are found by title on each publish, with no local record.
   - **Page.** The title is `ENG-NNN: Scope of Work`. Confluence titles are unique per space, so a bare `Scope of Work` would collide between engagements. 32.8's closeout follows as `ENG-NNN: Closeout`.
   - **Body.** `mdstorage.convert` plus `plansync.page_footer("_bmad-output/engagements/ENG-NNN/scope.md", _provenance(...), page_hash(title, storage, []))`. It is skipped when the remote footer's hash equals the digest.
   - **Recorded.** `scope_page {id, url, version}`, where `url` is `https://<planning.jira.site>/wiki<_links.webui>` (the relative webui when no site is recorded) and `version` is the page's version after the write. Nothing is written under `.tk-studio/` or `plan/`.

   Per Story 32.4 AC1, `plansync.py` 31.3 footer and hash rule, and `confluence.py`. SPEC.md bullet appended.
3. CAP-9: an owner edit mirrored back (`named placeholder rule`). At each sync-back tick, the page named by each record's `scope_page.id` is read by id. When its version is greater than `scope_page.version`:
   - Its storage, converted by `mdstorage.to_markdown` with the footer dropped, is written to `kb/confluence/<slug_for(title)>.md`. It carries the mirror header plus `engagement: ENG-NNN`, and its state goes under `sync-state.json` `engagement_pages[<page id>] = {path, version, content_hash}`.
   - In `scoping` only, that Markdown replaces `scope.md` wholesale. It is not shape-checked: the owner's page is authoritative (D9). `scope_page.version` is merged into the record (fresh read, `scope.lock`).
   - In any other state, the mirror is written, `scope.md` and the record stay unchanged, and `notes[]` says `scope edit of ENG-NNN not applied: state <s> (send revise)` once per version. No state ever moves.

   Per Story 32.4 AC2, D9, and `syncback.py` 31.4. SPEC.md bullet appended.
4. CAP-9: a `revise` body (`named placeholder rule`).
   - After an applied `revise` (the input route's hook) and at each `finally` pass, the supervisor's scope pass takes the newest `inputs[]` `revise` line that carries `payload.body`. If the record is in `scoping` and no `engagement-scope` event names that line's `at`, the pass runs `engage.py scope --revise-at <at>`.
   - The body becomes `scope.md` verbatim and is published as the page. Like a page edit, it is not shape-checked.
   - The pass emits `engagement-scope {engagement, project, revise_at, action: published | refused | skipped, page?, reason?}` once. A transient result emits nothing.
   - A `revise` with no body changes no file; the planner's next turn rewrites the scope.

   Per Story 32.4 AC2 and the CAP-2 payload rule (`revise {body?: string ≤ 32 KiB}`). SPEC.md bullet appended.
5. CAP-7/CAP-8: the assumptions on the scope page (`optional entry`). When the record's `assumptions[]` is non-empty, the planner's `scope.md` carries a last `## Assumptions` section that names each assumption's `question` id. A missing one is `AssumptionUnstated: <id>`.

   Per Story 32.3 AC2 ("named on the scope page"). SPEC.md bullet appended.
