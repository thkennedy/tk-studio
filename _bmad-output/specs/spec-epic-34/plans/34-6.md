## Intent

Every asset a slice needs is declared once, in a manifest the studio validates, and the ladder's first rung produces a greybox for each declared asset deterministically through headless Blender on the host, so the slice is playable with placeholders before any art exists. The story's text: `_bmad-output/planning-artifacts/epics.md` (Story 34.6). The verbs: `assets.py check`, `assets.py greybox`, `assets.py facts`; the Blender script `plugins/tk-studio/lib/blender/greybox.py`; the schema `plugins/tk-studio/contracts/asset-manifest.schema.json`; the lib suite with a fake `blender`; a conformance check for the manifest; README and kb rows.

## Settled shape (the rulings for (a) to (f))

1. **The manifest** lives at the path `.tk-studio/config.yaml` names under `assets.manifest` (default `assets/manifest.yaml`), and its art path at `assets.art_path` (default `art/greybox`; TUA's is `art/world/greybox`, following its `art/ART-BIBLE.md`, set by a TUA PR of the operator's). Both are project layout, so they are config keys, never manifest keys (ruling (b)). Shape, schema 1:

   ```yaml
   schema: 1
   categories:            # optional overrides of the default palette, "#rrggbb"
     prop: "#8a8a8a"
   assets:
     - name: crate-small  # the id: [a-z0-9-]+, unique, the file stem
       category: prop     # prop | character | environment | vehicle | ui | fx
       tri_budget: 500    # int > 0
       bounds: {x: 0.5, y: 0.5, z: 0.5}   # metres, each > 0
       origin: base-center   # base-center | center | base-min-corner
       collision: box        # none | box | capsule | sphere | mesh
       licence: greybox      # greybox | cc0 | cc-by | generated | proprietary
       rung: greybox         # greybox | cc0 | generated
       status: placeholder   # placeholder | candidate | accepted
       source: ""            # provenance for the cc0 and generated rungs (34.7); empty on greybox
   ```

   The value sets are closed (ruling (c)); `check` refuses an unknown value naming the entry and the field. `rung` is the rung the entry currently stands on; `status` is `placeholder` while the greybox is the file in place, `candidate` once a later rung produced a replacement that has not passed both gates, `accepted` once it has (34.7 moves it; this story only writes `placeholder`).

2. **The entry's file is derived, never declared** (ruling (d)): `<art_path>/<name>.glb`. "An entry without a file" means that path is absent on disk. `check` runs the `facts` gate on that path when it exists and reports `missing` when it does not; `greybox` writes it only when it is absent and never touches an existing file.

3. **The output is `.glb`** (ruling (e)): one binary glTF per asset, the label PNG embedded, no sidecars; Godot imports it as is. Blender's exporter runs with fixed options (`export_format='GLB'`, no copyright string, no extras, Y up, apply modifiers, no animation, no lights, no cameras) so the same inputs give the same bytes under the same Blender version; the generator string Blender writes (`asset.generator`) is part of that version pin and the kb row names it.

4. **The category colour map** (ruling (a), CAP-11): a default table in `greybox.py` and in `assets.py` (one source: `assets.py` passes the resolved colour to Blender as an argument), overridable per project through the manifest's top-level `categories` map. Defaults: `prop #8a8a8a`, `character #d98c3f`, `environment #5b8c5a`, `vehicle #4a78b5`, `ui #c7b84a`, `fx #9a5bb5`. A category outside the closed set is a `check` refusal, so no greybox is ever magenta (magenta is the judge's missing-texture signal, 34.3).

5. **The label texture** (ruling (f)): `assets.py` draws it itself with the stdlib, deterministically, the way TUA's `scripts/make-toy-media-art.py` draws its toy media: a 256×256 8-bit RGB PNG (`zlib` + `struct`, filter 0, no `tIME`, no text chunks), filled with the category colour, a 4 px black border, and the asset's name drawn in a 3×5 bitmap font in black, two lines when the name is long. It is written beside the output as `<art_path>/<name>.label.png`, handed to `greybox.py` as the base-colour image, embedded into the `.glb`, and left in place (it is the file the visual gate of 34.7 compares against). Same manifest, same PNG bytes.

6. **The greybox geometry** (from the story, made exact): a primitive sized to the bounds, chosen by category and collision: `box` and `none` give a cube, `capsule` a capsule, `sphere` a UV sphere, `mesh` a cube (the greybox never carries a mesh collider); the origin placed per the `origin` rule; a flat material in the category colour with the label image; triangle count within `tri_budget` (a cube is 12, a sphere's segments are reduced until it fits; a budget below 12 is a `check` refusal).

7. **`assets.py facts <file>`** reads the `.glb` with the stdlib (the 12-byte header, the JSON chunk, the BIN chunk): triangle count from the primitives' index accessors, bounds from the position accessors' `min`/`max`, the origin as the bounds' relation to zero (`base-center`, `center`, `base-min-corner`, else `other`), UV presence from `TEXCOORD_0`, the material count. `check` fails an entry whose facts break its budget or bounds (a 1 % tolerance on bounds) and reports every entry's rung, status and facts; a status block ends every verb (AD-11).

8. **Blender on the host**: `assets.py greybox` finds Blender through `BLENDER` (the user variable naming the exe, the runbook row 34.6 adds; on the box `C:\Program Files\Blender Foundation\Blender 5.2\blender.exe`), else `blender` on PATH; unset or missing is a refusal naming it before anything starts, and the lib suite fakes the binary. The call: `<blender> -b --python <plugin>/lib/blender/greybox.py -- --spec <json>` with one JSON spec per asset (name, category, colour, bounds, origin, collision, tri budget, label PNG path, output path). Deterministic (fixed seeds, no timestamps); the whole run bounded by a wall clock.

9. **Where it runs in the loop:** `assets.py check` is an engine verify command (tracked `verify-commands.toml` for tk-studio's own fixtures; a project adds its own line); `greybox` runs on the host (the supervisor's host leg in 34.8, or the operator by hand). This story ships the verbs, the schema, the tests and a fixture manifest; it does not wire the host leg (34.8).

- `facts` reading only the position accessors' `min`/`max` trusts the exporter to write them (it does).
- The visual gate (Workbench renders) is 34.7's, not this story's.
