## Intent

This story closes user flow F9. A game project engaged through the chat route gets the GDS quick-flow brief and GDD beside its scope. Approval mints `run-epic-N` instances of a new shipped type, `run-vertical-slice`. That type's host leg runs the engine gate (34.1), the asset ladder's `check`, `greybox` and `match` (34.6, 34.7) and the `playable-verify` leg (34.3). It carries the proof media (frames, a contact sheet, the report) into the run workspace, the PR and the engagement's page, and the slice's verdicts into the closeout report (32.8). The proof on TUA is an operator step on the box, recorded under `kb/`.

## Acceptance Criteria

1. AC1: **Given** a game project engaged through the chat route (EP-32) **When** the scope step runs on a project whose working set carries GDS **Then** it runs `gds-create-game-brief` and `gds-gdd` (quick flow) and publishes both to the engagement's Confluence page beside the scope; approval mints the epics as today, and the plan's `run-epic-N.json` instances carry `type: run-vertical-slice`
2. AC2: **Given** the shipped job type `plugins/tk-studio/jobs/run-vertical-slice.json` **When** a run of it executes **Then** the engine runs the story as `run-epic` does; the host leg runs the engine gate (34.1), the ladder's `check` and `greybox` (34.6; `match` when the mirror exists) and the `playable-verify` leg (34.3); the proof media (the frames, a contact sheet, the report) land in the run workspace, the PR body and the engagement's page; the closeout report (32.8) lists the slice's verdicts per story; guards and stop conditions per the job schema; the planner tier per the measured routing
3. AC3: **Given** TUA **When** the acceptance runs **Then** one `POST /jobs` (or one chat message) on TUA ends in a merged PR with a playable greybox scene, the frames in the PR, a `job-run` ledger line with the cost, conformance green over every surface (the contract at 0.1.29 or later), the three new skills' eval cases above the threshold, and the acceptance record under `kb/`; the design spec's feature ledger flips Phase 3 to built

## Settled shape

Each item is also a SPEC.md Design notes bullet (CAP-15, CAP-16).

1. **A game project.** Its tracked `.tk-studio/config.yaml` `working_set` has any role's list holding `gds`, or an entry starting `gds-`. `engage.py` decides this once, and it is never re-derived in TypeScript.
2. **The game docs.**
   - `engage.py scope` gains `--brief-file PATH` and `--gdd-file PATH`. On a game project both are required (refusal `GameDocsMissing: brief | gdd`, exit 2). On any other project they are refused (`NotAGameProject`).
   - Each is written as `_bmad-output/engagements/<id>/brief.md` and `gdd.md`, then published through `_publish_scope(title=, rel=)` in the same `Engagements/ENG-NNN` folder as `ENG-NNN: Game Brief` and `ENG-NNN: GDD`.
   - The record gains `brief_page` / `gdd_page` `{id, url, version}`, both optional and shaped like `scope_page`, plus `game: true`.
   - SKILL step 4 gains a step 4a for a game project: run `gds-create-game-brief`, then `gds-gdd`, each in quick flow, before writing the scope.
3. **Approval.** When the record carries `game: true`, `approve.ts` mints `run-epic-N` with `type: "run-vertical-slice"`. Otherwise it mints `"run-epic"`, unchanged. The ids stay `run-epic-N`.
4. **The type.** `plugins/tk-studio/jobs/run-vertical-slice.json` is `run-epic.json`'s shape with `id: "run-vertical-slice"` and its own description. It has no new schema field. The supervisor treats a run as a slice when its resolved definition's `type` or `id` is `run-vertical-slice`.
5. **The assets step.** It runs on a slice run only, after the host command and before the engine gate, so the import sees the placed files.
   - It is skipped (`no manifest`) when `assets/manifest.yaml` (or config `assets.manifest`) is absent at the worktree.
   - Otherwise it runs `check`, then `greybox`, then `match`. It never passes `--mirror` and never calls `generate`: zero calls satisfies the contract's "at most once".
   - Verdicts: `check` or `greybox` exit 1 or 2 makes the step red. A `match` exit 1 whose rows are action `failed` is `fault`: recorded, not red, and the placeholder stays. A `match` exit 2 is red.
   - It adds an optional `assets: {verdict: green | red | skipped, reason?, steps: [{verb, exit, status, duration_ms, stdout_tail?, stderr_tail?}]}` to `host-verify`. A red step makes the leg red, as engine red does.
   - The PR section gains an `Assets: green | red | skipped (<reason>)` line.
6. **The host-side commit.** After a green or fault assets step, the close-out commits only the changed paths under `assets.art_path`, the manifest, and the proof folder (shape 7). It uses `git add -- <paths>`, never `-A`, with the message `host leg: placed assets and proof (run <run_id>)`, through the `commitStep` idiom, before the push. A commit failure is the close-out's `error`.
7. **Proof media.**
   - New verb `playable.py sheet --frames DIR --out PNG [--columns 4] [--width 320]`. It is stdlib only, samples at most 16 frames evenly in name order, scales nearest-neighbour, and writes 8-bit RGB. Its status block is `intent: playable`.
   - `playableStep` runs it after `run`. `MEDIA` gains `contact-sheet.png`.
   - On a slice run the close-out copies `report.json`, `contact-sheet.png` and the sampled frames to `.tk-studio/proof/<run_id>/` in the worktree, and commits them (shape 6).
   - The PR section embeds `![contact sheet](<repo web url>/blob/<head sha>/.tk-studio/proof/<run_id>/contact-sheet.png?raw=true)` and lists the frame paths, on pass and fail alike.
   - The engagement's page is the closeout page (shape 8), with the contact sheet uploaded as an attachment.
8. **Slice verdicts in the closeout.**
   - `composeCloseout` passes `slices: [{story, engine, assets, playable, contact_sheet?}]` from each run's last `host-verify` event.
   - `render_closeout` adds a `## Slice verdicts` section (one line per story: `<key> — engine <v>; assets <v>; playable <v>`) and embeds each contact sheet through `upload_attachment`.
   - With no slice run, the section is absent.
9. **The three skills' eval cases.**
   - Two cases are per skill: the existing `gds-engine-godot-4-pinned-facts`, and the new `evals/tk-studio-playable-judge-verdict/` (a fixture `report.json` plus frames; the grader checks the verdict JSON shape and that the judge reads no code or spec).
   - The ladder, which ships as `assets.py` with no skill (the SPEC Assumption leaves this to this plan), counts as the third surface through the plugin-level case `evals/asset-ladder-generated-rung/`. That case asks how to turn the generated rung on, and the grader checks the cap in `budget-bands.yaml`, `TK_ASSETS_MESHY_KEY` as a User variable never in a file, and the per-invocation cap.
   - No skill wrapper is added.
   - Threshold: every case passes its grader on at least 2 of 3 runs. This is a planner default, recorded and retunable in the acceptance record.
10. **The acceptance record.**
    - `kb/acceptance-record-34-8-vertical-slice-on-tua.md` (frontmatter as 34-1's) holds the exact operator steps: TUA's config gains `playable`, `assets.art_path` and `assets/manifest.yaml` through a TUA PR; then one `POST /jobs` for a TUA `run-vertical-slice` instance; the eval runs.
    - It has an `## Evidence` section that the operator fills.
    - The feature ledger's Phase 3 row flips to `**built** (Epic 34; acceptance: kb/acceptance-record-34-8-vertical-slice-on-tua.md)` only after the operator's evidence answer in the consult log. Until then it reads `**built, TUA acceptance pending**`.
    - `kb/index.md` is regenerated with `kb.py index`.

## Risks and open decisions

- **Oversize.** This plan's Files list is about 25 files across Python, TypeScript, skills, contract, evals and kb, plainly past band L. It is not split here. The dev session halts if the Files list grows.
- Block If: the host-side commit (shape 6) contradicts a recorded rule that the close-out never commits on its own behalf. None was found in `driver-contract.md`, the supervisor README or `worktree.ts`. If the dev session finds one, consult before writing it.
- Block If: a contract or taxonomy test requires a version bump past 0.1.29 to pass.
- Block If: `gds-create-game-brief` or `gds-gdd` has no non-interactive quick-flow mode at the GDS pin. In that case the planner session cannot run them headless, so the dev session consults instead of inventing a mode.
- `.tk-studio/proof/<run_id>/` commits PNGs into the game repo on every slice run, which grows TUA. At most 16 frames plus one sheet keeps this bounded; pruning is out of scope.
- The visual gate's thresholds are untuned (34.7). A thin cc0 asset may stay `candidate`, which is not red, so the greybox scene still plays.
- The eval threshold (2 of 3) is a planner default with no design source.
- DW-67 stays open.
