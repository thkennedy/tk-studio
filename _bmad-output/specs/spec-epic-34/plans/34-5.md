## Intent
A dev session on a game project cannot run the project's tests, verify it, or take a frame from the engine without a human. This story has three parts:
- A spike on the box picks one engine MCP server per project. The installs and runs are the operator's step, asked for through the consult log.
- `kb/engine-mcp-godot.md` records the pick. The `game-godot` profile names it through 34.4's proposal, and only `recommend.py record --mcp` writes it into `.mcp.json`, on confirmation.
- For a run flagged `editor_in_the_loop`, the supervisor snapshots the project, starts the MCP on the host behind the tailnet address with a per-run bearer, and passes the URL and bearer into the sandbox by name. It stops the MCP at release.

The MCP is verify-only in this version. Its scene-editing tools never reach the dev session.

- **AC2** — **Given** a run whose job sets `editor_in_the_loop: true` **When** the supervisor pins the sandbox **Then** it snapshots the project with `robocopy` to `C:\agent-work\backups\<project>\<run>` (the brief's Phase 1 item 7), starts the engine MCP on the host bound to the tailnet address with a per-run bearer, passes its URL and the bearer to the sandbox by name (`-e`, never a file), and stops it at release; a run without the flag starts nothing; `bun test` covers the start, the stop, the snapshot and the refusals (no `.mcp.json`, no engine)
- **AC3** — **Given** the verify-only rule **When** the MCP is wired **Then** its scene-editing tools are not exposed to the dev session in this version (the engine skill says so and the server's allowlist enforces it where the server has one); the runbook names the port and the rule

## Settled shape
Each shape has its bullet under SPEC.md `## Design notes (settled shape, planner, 2026-10-27)`.

1. **The pick on the profile** (optional entry). `"suggests_mcp": ["<pick>"]` sits on `game-godot.json` only. It is passed through on the detect candidate (default `[]`).
   - `propose` adds it on a confident outcome as `kind: "mcp"`, with `detection:` evidence and `kb: kb/engine-mcp-godot.md`.
   - Its status is `configured` when the project's `.mcp.json` already has `mcpServers.<pick>`, else `not-configured`.
   - It is never proposed on an ask outcome.
   - The profile line lands only once the spike's ruling exists. Until then, the tests use a fixture profile.
2. **The `.mcp.json` entry** (named placeholder rule). Only `recommend.py record --mcp <name>`, with `<name>` confirmed and named by a profile's `suggests_mcp`, merges this into the project root's `.mcp.json`:

   `mcpServers.<name> = {"type": "http", "url": "${TK_ENGINE_MCP_URL}", "headers": {"Authorization": "Bearer ${TK_ENGINE_MCP_BEARER}"}}`

   - Other servers are untouched. The write is idempotent, honours `--dry-run`, and is atomic (the `job.py` JSON writer's precedent).
   - An unknown name, or malformed JSON, is a refusal with exit 2 and an AD-11 block.
   - Detection and `propose` never write it.
   - Claude Code expands `${VAR}` in `.mcp.json` `url` and `headers`, so the file carries no secret. If the box's `claude` rejects an unset variable in a run without the flag, use the `${VAR:-}` default form and record it as a DRIFT.
3. **The `editor_in_the_loop` job field** (optional entry). It is a boolean in `job.schema.json` definition fields, default `false`, validated in `job.py` like `durable`. The queued run's flag is the submission flag OR the definition's. Neither the API nor the CLI changes.
4. **Host config, port, bearer and events** (named placeholder rule).
   - **Config:** the tracked `.tk-studio/config.yaml` key `engine.mcp: {name: "<mcpServers key>", start: "<one command line>", port: <loopback port>}` is read at `base_ref` like `verify.host`.
     - `start` is split like `verify.host`, with no shell. The token `{worktree}` is replaced by the run's host worktree path.
     - The command runs with cwd = the worktree and env = the worker env plus `GODOT`.
     - The server listens on `127.0.0.1:<port>`.
   - **Forwarder:** the supervisor fronts the server with a Bun forwarder on `TK_SUPERVISOR_BIND:TK_SUPERVISOR_ENGINE_MCP_PORT`.
     - The default port is `8788` (operator-decisions §2: nothing else listens in the 8000 range; the runbook §4.2 row).
     - It forwards only requests that carry `Authorization: Bearer <per-run token>` (sha256 plus `timingSafeEqual`), streaming bodies both ways. Anything else gets 401.
   - **Bearer:** `randomBytes(32).toString("base64url")`, kept in memory only and never in an event, log or file.
   - **Sandbox env:** `-e TK_ENGINE_MCP_URL -e TK_ENGINE_MCP_BEARER`. The URL is `http://<bind>:<port>/<path of the server's endpoint>`.
   - **Events:** `engine-mcp-start {name, pid, start, url}` and `engine-mcp-stop {name, pid, why}`.
   - **Refusals** (the run ends `blocked`; a drained run goes through `recordedRefusal` with the keys below):
     - `engine-mcp:no-config`: no `engine.mcp`, or `engine.mcp` is malformed;
     - `engine-mcp:no-mcp-json`: no `.mcp.json` at the base, or it lacks `mcpServers.<name>`;
     - `engine-mcp:no-engine`: `GODOT` is unset or names no file;
     - `engine-mcp:start-failed`: the child exits, or the loopback port does not answer within a bound.
   - A run without the flag starts nothing and records nothing.
5. **The spike record** (named placeholder rule). `kb/engine-mcp-godot.md` (rank 64, `scope: project`) holds:
   - the candidates table: install, `run_project_tests`, `verify_project`, `game_screenshot`, Windows status, licence, last release, and **scene-edit tools and allowlist**;
   - `not measured` cells until the operator answers in the consult log;
   - `## Measurement commands` (the exact steps the operator runs);
   - `## Ruling`;
   - `## Seeds`, in the `knowledge.py` seed format, which the operator files with `research.py seed`;
   - a citation of `engine-mcps.yaml` by path.
