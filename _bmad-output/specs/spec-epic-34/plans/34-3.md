## Intent
"It builds" and "it plays" must be two different greens. This story adds a third step to the host leg, after 34.1's engine gate. The step runs 34.2's `playable.py run` on the host over the worktree. Then a routed judge session in the project's sandbox reads only `report.json` and the frames, and answers a fixed screenshot rubric with `pass | fail` and findings. The verdict rides the `host-verify` event and folds into the leg's `green`. A `fail` therefore ends the run `partial` with a draft PR carrying the findings, exactly as a red `verify.host` or engine gate does. A project without `playable` in its config is `skipped` and unchanged.

## Acceptance Criteria
1. AC1 — **Given** a project config that declares `playable: {scenario: <file>, seed: <n>, ticks: <t>}` (additive) **When** the host leg's engine gate is green **Then** the host leg runs 34.2's `playable.py run` in the worktree, writes the media under the run workspace (`~/.tk-studio/runs/<run>/playable/`) and the worktree's ignored `.bmad-loop/runs/<engine>/playable/`, then drives the judge: a `claude -p` session on the project's sandbox tier (`sbx exec`, the plugin's `tk-studio-playable-judge` skill, routed by `[pipeline.legs] playable-verify` with its own `model` and `effort` through `pipeline.py`'s tables) that reads only `report.json` and the frames (never the code or the spec), answers the rubric (the scene loaded; the player is visible and framed; no missing-texture magenta and no error overlay; the HUD reads; the scenario's named moments appear in the frames they name) with `verdict: pass | fail` and `findings[]` each naming a frame and a rubric line, and ends in a status block; the `host-verify` event carries `playable: pass | fail | skipped` and the findings
2. AC2 — **Given** a `fail` **When** the close-out continues **Then** the run ends `partial` with `host_verify: red (playable)`, the PR body carries the findings and the frames' paths, the inbox gets the line, and 33.8's `verify` re-runs the leg after a fix; `pass` lets the PR go ready; a project without `playable` is `skipped` and unchanged
3. AC3 — **Given** the suites **When** they run **Then** `bun test` covers the ordering, the event, the PR body and both verdicts with fakes; the lib suite covers the rubric parsing and the judge's refusals (no frames, a malformed report); conformance adds the skill's roster row and an e2e over a fake judge; contract 0.1.29 names the leg; the leg's cost lands in the ledger's `job-run` as its own line

## Settled shape
These shapes are the planner's rulings for this story. They bind the dev session as SPEC.md design notes do. They are recorded here only: the gate session that planned this story may not edit SPEC.md (gate.md Rules), so the next planner-tier writer appends them as CAP-5/CAP-6 bullets. Design sources: Story 34.3's criteria, the 34-1 gate note, 34.2's Settled shapes 2 and 3 (`plans/34-2.md`), `kb/playable-verify-on-the-box.md` §Ruling.

1. **`playable` in the project config (optional entry).**
   - Shape: `playable: {scenario: "<path relative to the project root, the worktree after checkout>", seed: <int ≥ 0>, ticks: <int > 0>}` in the tracked `.tk-studio/config.yaml`, read at `base_ref` with the same `git show` as `verify.host`.
   - Absent: `playable: {verdict: "skipped", reason: "no playable"}`.
   - Not a mapping, or a field missing or of the wrong type: `skipped` with the reason `playable is malformed: <field>`. This is 34.1's not-a-non-empty-string precedent.
   - The engine gate not green (red, or skipped for any reason): `skipped` with the reason `engine gate not green`. The story runs the leg only "when the host leg's engine gate is green".
   - The mode is never configured. `playable.py`'s default (`movie`, the ruling) applies.
2. **Media paths (named placeholder rule).**
   - `--out` is the run's store folder: `studioRunDir(p, studio_run_id)/playable/` (`sandbox.ts` :572). The story's `~/.tk-studio/runs/<run>/playable/` is that folder. A run with no studio run id uses `<studioHome>/runs/<engine_run_id>/playable/`.
   - The store is outside every project, so 34.2's `--out`-inside-the-project refusal cannot fire.
   - After `playable.py` ends, the leg copies `report.json`, `log.txt` and `frames/` into `<worktree>/.bmad-loop/runs/<engine_run_id>/playable/`. That is the only copy the sandboxed judge can read.
   - `--directory` is the worktree, `--scenario` is `<worktree>/<scenario>`, and `--wall-clock` is the leg's guard (`guardS`), as each step is bounded by the guard. The `GODOT` env comes from the leg's env.
3. **The judge (named placeholder rule; the skill is `tk-studio-playable-judge`, deterministic core `plugins/tk-studio/lib/playable_judge.py`).**
   - The core has two verbs, both stdlib, each ending in an AD-11 block with `intent: "tk-studio-playable-judge"`:
     - `prepare --media <dir>` validates `report.json` (34.2's Settled shape 2 keys, `verdict` pass or fail) and that every `frames[].file` exists. It prints the frame list, the moments and the rubric. Refusals (`blocked`, exit 2): `no report.json`, `malformed report: <field>`, `no frames`.
     - `verdict --media <dir> --answer <file>` parses the model's answer `{"verdict": "pass"|"fail", "findings": [{"frame": "frames/<name>.png", "rubric": "<id>", "note": "<one line>"}]}` and writes `<media>/judge.json`. Refusals: an unknown rubric id, a frame not in `frames[]`, a `fail` with no findings, and a malformed answer.
   - Rubric ids are fixed: `scene-loaded`, `player-visible`, `no-magenta-or-error-overlay`, `hud-reads`, `moments-shown` (one line each, the story's five).
   - The SKILL.md tells the session to read only `report.json` and the frames under the payload's `media` path, never the code or the spec. It carries the conformance runner's status-block line and the "If the deterministic core is unrunnable" phrase.
   - Invocation: `invokeSkill(worktreeRoot, "tk-studio-playable-judge", {tier, sandbox, model, effort, payload: {media: ".bmad-loop/runs/<engine>/playable"}}, spawner, {vmHostRoot: worktree})`, with `model` and `effort` from `route["playable-verify"]`.
   - The judge runs only when `playable.py` exits 0 with `verdict: pass`.
4. **`playable` on the `host-verify` event (optional entry, always written on a ran leg).**
   - Shape: `playable: {verdict: "pass"|"fail"|"skipped", reason?, exit?, status?, failed?, duration_ms?, store, media?, judge?: {status, verdict?, cost_usd?, model?, effort?}, findings?: [{frame, rubric, note?}], frames?: ["<store path>"]}`.
   - Exit 1 (a harness fail) is `fail`, and the judge is not run. It carries one finding `{frame: <failing tick's frame or null>, rubric: "harness: <invariant>", note: <detail>}`.
   - Exit 2 (a refusal) is `fail` with the reason `playable.py refused: <reason>`.
   - A judge that ends blocked or failed, or whose answer `verdict` refuses, is `fail` with the reason `judge: <reason>`.
   - `redReason` reads ``host verify red (playable): <first finding's rubric> at <frame>: <note> | <reason>``.
   - `prSection` gains `Playable: pass | fail | skipped (<reason>)`. On `fail` it lists the findings and every store frame path.
5. **Routing leg (named placeholder rule).** `playable-verify` joins `pipeline.py` `LEGS` with the default `{ model = "claude-sonnet-5", effort = "medium", advisor = "off" }` in `tk-studio-launch/customize.toml`, and §5.1 lists it. A route without the leg (an older served project) falls back to that default.
6. **The leg's cost in `job-run` (optional entry).**
   - `taxonomy.v1.json` `job-run` gains `playable_verify_cost_usd: {type: number, required: false, note: "Story 34.3: the playable-verify judge's total_cost_usd, also counted in total_cost_usd"}`.
   - `jobrun.py finish` gains `--playable-verify-cost-usd`, finite and non-negative, absent when not sent.
   - `finishStudio` passes the judge's `cost_usd` and adds it into `--total-cost-usd`.
   - This is additive, with no taxonomy version change: 32.5's fields on `observation` are the precedent.

## Risks and open decisions
- **Oversize.** About 21 files across the supervisor, the lib, a new skill, the contracts and the taxonomy: past band L. Do not split it here. Halt if the Files list grows beyond the list above (budget-bands L rule).
- **Block If: a missing display session or an unreachable sandbox must read `skipped`, not `fail`.** SPEC Open Question CAP-4/CAP-5 leaves the leg's verdict for a missing display unspecified. This plan rules the conservative reading: on a configured project every non-pass is `fail` (Settled shape 4). A dev session that finds it needs a `skipped` path (for example, the unattended supervisor has no desktop, so every TUA run would go red) halts for the operator's ruling, never decides alone.
- **Block If: `invokeSkill` cannot target the worktree mount with a payload `media` path** without a change to its signature or to the sbx command builder. That is a seam change in `server.ts` outside Files.
- **Block If: `ledger.validate` or the taxonomy tests reject the additive `job-run` field** without a taxonomy version bump. A bump is a contract decision, not the session's.
- 34.2 residual risks carry over: the C# harness has never compiled, and the movie tick-to-frame offset is unmeasured. The leg treats `playable.py`'s output as given; its tests fake `playable.py`.
- The judge's image reading inside `claude -p` (`Read` on PNGs under the mount) is assumed. The fake-judge e2e cannot prove it; the operator's host proof does.
