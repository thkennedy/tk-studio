## Intent

The ladder's second and third rungs. `assets.py match` replaces a greybox placeholder with a CC0 kit asset from a mirror on the box. `assets.py generate` replaces one with a generated mesh, but only behind a per-run credit cap the owner set on purpose. Both rungs normalise through headless Blender on the host and pass the 34.6 `facts` gate and a new visual gate before the placeholder goes. Everything builds on 34.6's `assets.py`, its schema, its contract section `## Asset manifest` and its Blender idiom. Story text: `_bmad-output/planning-artifacts/epics.md`, Story 34.7. The engine never runs Blender, the mirror or a live generator call. The box proof is the operator's step, asked for through the consult log as in 34.6.

## Acceptance Criteria

1. AC1: **Given** a mirror under `C:\agent-work\assets\<kit>` (Kenney, Quaternius, Poly Haven; each with its licence file and the index the mirror script writes) **When** `assets.py match --directory <project>` runs **Then** every manifest entry on the `cc0` rung is matched by category and tags to a kit asset, normalised through headless Blender (scaled to the bounds, the origin per the rule, decimated to the triangle budget, exported as glTF) into the project's art path, passed through the `facts` gate and a visual gate (a Workbench render from the manifest's camera, compared with the greybox render for silhouette coverage and with a blank for emptiness), and the placeholder is kept until both gates pass; the kit, the licence tag and the source path land in the entry's provenance
2. AC2: **Given** the `generated` rung **When** a manifest entry asks for it **Then** `assets.py generate` refuses unless the project's `budget-bands.yaml` carries an `assets.credit_cap` for the run and the generator's key exists as a User environment variable by name (`TK_ASSETS_MESHY_KEY`, never in a file), spends at most the cap, records every call and its cost in the ledger, and runs the same two gates; the rung is off by default and the runbook says how it is turned on
3. AC3: **Given** the suites **When** they run **Then** the lib suite covers the matching, the normalisation argv, both gates and the cap refusals with fakes; nothing generates natively on the host (the Windows rule stands)

## Settled shape

These are the planner's rulings, made so the dev session does not halt on the gaps 34.6 hit. Each one is appended to SPEC.md `## Design notes` (CAP-13, CAP-14).

1. **Manifest, additive, schema stays 1.** The new keys are optional; 34.6 manifests stay valid.
   - Entry `tags`: a flow list of `[a-z0-9-]+` strings, default `[]`. The reader accepts a flow list of plain scalars only. `[a, {b: c}]` and nested lists are still refusals.
   - Entry `prompt`: a string, read only on the `generated` rung. Its default is the name's words, then the category, then `low poly game asset`.
   - Top-level `camera`: `{yaw, pitch}` in degrees, default `{yaw: 45, pitch: 30}` (closed keys; numbers; pitch in [-89, 89]).
   - `source` stays a string. On `cc0` it is `<kit>/<path relative to the kit root, forward slashes>`; on `generated` it is `meshy:<task id>`.
   - `licence` takes `cc0` or `generated` when the replacement is accepted.
   - `rung` is the rung the entry is assigned to. `status` says which file is in place: `placeholder` (the greybox), `candidate` (a replacement failed a gate, so the greybox is kept), `accepted`. This reconciles plan 34-6 §1.
2. **The mirror** is a box-level folder, never project layout. Its root is `--mirror`, else the env `TK_ASSETS_MIRROR`, else `C:\agent-work\assets` when that folder exists. With no mirror, `match` ends `complete` with every cc0 entry `skipped: no mirror`, which is 34.8's "`match` when the mirror exists".
   - Each `<kit>/` holds its licence file and `index.json`, written by the new verb `assets.py mirror-index --kit <dir> --category <cat> [--licence cc0]`. That verb is stdlib, deterministic and atomic. It writes `{schema: 1, kit, licence, licence_file, assets: [{path, category, tags[]}]}`, sorted by path.
   - Tags are the lowercase tokens of the path's folders and stem, split on `-`, `_`, space, `.` and camelCase, with digits dropped.
   - The `.glb`, `.gltf`, `.fbx` and `.obj` files are indexed. No licence file (`LICENSE*`, `License*`, `*licen*e*.txt`) is a refusal.
   - Downloading Kenney, Quaternius and Poly Haven onto the box is the operator's step (consult log), not the engine's. This settles SPEC Open Question CAP-13.
3. **Matching** is deterministic. A candidate asset is in the same category, scored by the size of `(entry tags ∪ name tokens) ∩ asset tags`, with a score of at least 1. Ties go to the higher score, then the kit name, then the path. No candidate: the entry is `unmatched` and the placeholder is kept (not a failure).
   - Only entries with `rung: cc0` and `status: placeholder | candidate` are matched.
   - An `accepted` entry is skipped.
   - An entry whose greybox `.glb` is absent is skipped with `reason: run greybox first`.
4. **Normalisation** is `lib/blender/normalise.py`, called as `<blender> -b --python <plugin>/lib/blender/normalise.py -- --spec <json>`. Spec keys: `name, input, bounds, origin, tri_budget, output`.
   - Import by extension, apply every transform, join to one mesh, then scale non-uniformly so the extents equal the bounds (the gate is ±1 % per axis).
   - Bounds are on glTF axes, Y up, mapped to Blender X, Z, Y as in greybox. The origin follows the rule (`_offset`).
   - Decimate (collapse) until the triangles are at most `tri_budget`.
   - Export with greybox's fixed options. The output goes to a temp folder.
5. **Candidates and placement.** The normalised export is published (`_publish_new`) to `<art_path>/.candidates/<name>.glb`. A dot folder, so Godot skips it.
   - The `facts` gate runs on those bytes.
   - The visual gate runs next.
   - When both pass, `os.replace` moves the candidate over `<art_path>/<name>.glb`. This is the one sanctioned replace of a placeholder, so 34.6's "never touches an existing file" stays greybox's rule. The entry then becomes `status: accepted`, `licence: cc0`, `source: <kit>/<path>`.
   - When either gate fails, the placeholder is untouched, the entry becomes `status: candidate`, and the reasons are listed.
   - A greybox entry whose label is `stale` is never a visual-gate reference; it fails with the 34.6 reason.
6. **The visual gate** is `lib/blender/render.py` with spec keys `input, camera, bounds, size, output`.
   - Workbench engine, flat lighting, a single colour, a transparent film, 128×128.
   - An orthographic camera at the manifest's `camera` yaw and pitch, framed from the entry's bounds (not the mesh), so the greybox render and the candidate render share one frame.
   - Both renders go beside the candidate (`.candidates/<name>.greybox.png`, `.candidates/<name>.render.png`).
   - Masks come from alpha > 0, read by a stdlib PNG un-filter in `assets.py` (filter types 0–4; colour types 0, 2, 4 and 6; bit depth 8).
   - Pass when `coverage = |C ∩ G| / |G| ≥ 0.6` and `fill = |C| / 128² ≥ 0.005` (not blank).
   - The thresholds are named module constants recorded in the kb row.
7. **The generated rung** is `assets.py generate --directory <project> --run-id <id> [--blender PATH] [--wall S]`. It acts on entries with `rung: generated` and `status: placeholder | candidate`.
   - **Refusal 1** (exit 2, before any network call or write): the project's `.tk-studio/budget-bands.yaml` has no top-level `assets: {credit_cap: <number > 0>}`. The refusal names `assets.credit_cap`. The cap is in Meshy credits, applies per `generate` invocation, and its absence is the "off by default".
   - **Refusal 2**: no `TK_ASSETS_MESHY_KEY` in `HKCU\Environment` (Windows) or the process env. The refusal names the variable; the value never appears in output, a file, the ledger or argv.
   - **The cap.** Before each call: if `spent + MESHY_CREDITS_PER_TASK > cap`, the entry and every later one is `not-run: credit cap` and the run ends `partial`.
   - **The client.** The provider is a small client seam (`submit`, `poll`, `download`, using urllib, bounded by `--wall`) that tests replace with a fake. Meshy text-to-3D preview, `prompt` from Settled shape 1.
   - **The ledger.** Every call, failed ones included, emits one line through `ledger.emit("asset-generation", {run_id, asset, provider: "meshy", task_id?, credits, state: complete|failed, reason?}, project=<key>)`. `credits` is the provider's reported charge when the response carries one, else `MESHY_CREDITS_PER_TASK` with `estimated: true`.
   - **After download,** the asset goes through normalisation (4), the candidate and placement rules (5) and both gates (6). On acceptance the entry becomes `licence: generated`, `source: meshy:<task id>`.
   - **The Windows rule.** Generation runs at the provider (cloud); the host only downloads and runs Blender.
8. **Manifest write-back.** `match` and `generate` rewrite only the `status`, `licence` and `source` lines of the entries they moved. If `source` is absent, it is inserted after `status` at the entry's indent. Every other byte is kept, and the write is atomic. A manifest the reader cannot map line by line is a refusal before any work.
9. **DW-74 closed in `facts_of`.** Walk the default scene's nodes (`scene`, else scene 0, else every root node), compose TRS or `matrix` down the tree, and transform each mesh's accessor min/max box corners to get world bounds. Count triangles once per node that instances a mesh. A GLB with no scenes or nodes keeps 34.6's mesh-only reading. Greybox output (identity transforms) gives the same facts as before.
10. **Contract and taxonomy.** Both stay at 0.1.29 and are additive.
    - Contract: the `## Asset manifest` 34.7 paragraph (the verbs `mirror-index`, `match`, `generate`, the mirror layout, the candidate path, the gate thresholds, the write-back, the refusals) and the line-5 clause.
    - Taxonomy: `asset-generation` (emitter: `lib/assets.py generate` alone).
    - Status blocks use `complete | partial | blocked` (status-block.schema.json).

## Risks and open decisions

- **oversize.** About 15 paths, two Blender scripts, a network client and a contract/taxonomy extension: past band L. Not split here. The dev session halts if the Files list grows past this list.
- Block If: closing DW-74 (Settled shape 9) changes `check`'s verdict on a 34.6 fixture or test. That means the 34.6 contract text on bounds changes meaning; halt for an operator ruling.
- Block If: a contract or taxonomy test requires a version bump (0.1.29 → 0.1.30, or taxonomy v2) to pass.
- Block If: Meshy's API cannot be called without the key appearing in argv, a file or a log line. The rung then ships refusals and the seam only, with the client recorded as unverifiable-here.
- The visual-gate thresholds (0.6 coverage, 0.005 fill) are planner defaults, not measured. The operator's box run may retune them in the kb row. Not a blocker.
- The cap is per `generate` invocation; a second invocation in the same run can spend a second cap. 34.8 calls `generate` at most once per run; record this in the contract paragraph.
- Kenney ships mostly `.glb`/`.fbx`/`.obj`, Poly Haven `.gltf`/`.blend`. `.blend` is not indexed (out of scope); the index skips it silently and counts it in a `skipped` total.
