## Jev card (what it is, API, price, terms, backers, independent evidence)

**What it is.** A "System One" model from TypeSafe AI that returns typed decisions instead of text: give it a state and typed questions, get back a choice/score/boolean-like value with a probability distribution and (for Choice and Score) a confidence number. It cannot write prose or code. Launched 2026-09-15, early access. Named for Jevons (the paradox) and Kahneman's System 1 (Register; search snippets).

**API shape (primary: docs.typesafe.ai intro page).** `state` (string or JSON) + one or more questions of three primitives: Choice -> `{choice, probabilities, confidence}`; Score -> `{score, probabilities, confidence}`; Noul -> a 0–1 value. Questions evaluate in parallel and in isolation; adding questions barely changes latency. Design rule from the docs: one well-scoped thing per question; combine in code. Wire details seen in routers: base URL `https://api.typesafe.ai`, model id `jev-latest`, console at `console.typesafe.ai`, also reachable through Vercel AI Gateway (`ai-gateway.vercel.sh/typesafe`) and OpenRouter (separate `Jev 1.13` listing per a runtimewire snippet; not verified). SDKs: not reached (the docs intro page lists Quick Start and API reference pages I did not fetch).

**Latency and price (vendor claims, via Register).** 70–500 ms; $0.042/MTok input, $0 output. Order of magnitude corroborated by ediri's "key check costs about $0.00003". drewpayment budgets 800 ms for the whole call.

**Terms, data retention, rate limits.** Not reached. The routers send "the text of each new user turn" to Jev (flaviusapop), so under the studio's constraints this is code and prompts leaving the microVM to a second vendor whose retention terms I could not read.

**Backers.** $40M raised; investors not named in what I reached; CEO Diogo Almeida (ex-OpenAI; InstructGPT/RLHF lineage per Register and search snippets).

**Independent evidence.** None. Every speed, cost and accuracy figure traces to TypeSafe. The one accuracy number in circulation (about 68%) is unattributed in a search snippet. 33Audits' README is the only third-party measurement I found, and it is a single React build with a withdrawn headline claim.

## Router cards

### OpenRouter `typesafe/jev-router` (2026-09-25)
- Mechanism: an OpenRouter model id; a chat-completions request goes to it and Jev picks the model and reasoning effort (per OpenRouter blurb via runtimewire/KuCoin snippets). The fetched model page is only an API guide; it confirms `reasoning_effort` is an accepted request field and that 502s are not billed.
- Decision granularity: per request; "adapts as your conversation evolves" and is cache-aware (snippets).
- Models routed among: not stated anywhere reached.
- Pricing: listed at zero at launch (runtimewire snippet); the underlying model calls bill at the chosen model's OpenRouter price [inference].
- Credential: an OpenRouter API key. Irrelevant to a Max-subscription studio: this path bills OpenRouter, not the subscription, and sends traffic to non-Anthropic infrastructure.
- Claimed result: "82% more tasks than the previous Auto Router" (KuCoin flash; no published data per runtimewire).

### `gargpratyush/jev-router` (npm `jev-router`)
- Mechanism: loopback proxy; `ANTHROPIC_BASE_URL` points `claude` at it; forwards the existing authorization header verbatim; rewrites `model`; sentinel "Jev Router" entry in `/model`; injected status line; `/jev-explain` skill.
- Granularity: one Jev Choice per fresh user turn; tool-loop continuations keep the tier.
- Sub-agents: "Main conversations and sub-agents are pinned separately."
- Fallback: fail-open; low confidence never downgrades and caps upgrades at the balanced tier; large conversations refuse downgrades (prompt cache); unavailable tiers step upward; Fable only with `JEV_ALLOW_FABLE=1`.
- Credentials: `JEV_API_KEY` required ("routes only when `JEV_API_KEY` is set" per 33Audits); rides existing `claude login`; no Anthropic key.
- Windows: PowerShell instructions present. Temp files per session contain prompt text and Jev request/response (mode 600, 7-day cleanup).
- Licence/activity: MIT; 578 stars, 84 forks, 44 open issues; no push since 2026-09-19 (three weeks stale as of today).
- Savings claim: none in the README portion read.

### `33Audits/jev-auto` (npm `jev-auto`)
- Mechanism: rewrite of gargpratyush; same relay; sentinel "Jev Auto". Default decider is a local heuristic scorer (no key, no network); optional `llm` backend = one Haiku call through your own subscription; optional `jev` backend with `JEV_API_KEY`; `off`.
- Granularity: per fresh user turn; continuations pinned; an escalation sets a floor for the next few turns.
- Sub-agents: "every sub-agent [is] pinned separately."
- Fallback: fail-open at every level; every non-local backend falls back to the local answer.
- Learning: content-free outcome ledger (`~/.jev-auto/turns.jsonl`); boundaries move 0.03 per step, drift capped at 0.12, `jev reset` reverses; "Rejections are automatic, promotions are reported."
- Credentials: none required by default.
- Licence/activity: MIT; 1 star; pushed 2026-10-04 (most recently active of the five).
- Savings claim and basis: the README withdraws its own "75% cheaper / 18% faster" figure and explains why (it measured a malformed Jev request). Surviving measurement: pinned-cheapest did a React build for $0.46 vs $1.94 on Sonnet, but "default routing captured almost none of it (+3%)" because of the cache guard. The `jev stats` block showing "Saved $22.61 (73%)" is example output. All dollar figures are API list prices computed from token counts, not subscription quota.

### `flaviusapop/jev-router` (npm `@flaviusapop/jev-router`)
- Mechanism: fork of gargpratyush; proxy on `127.0.0.1` random port; rewrites model **and reasoning effort** (tiers are (model, effort) pairs); also Codex, Grok CLI, opencode.
- Granularity: per user turn; continuations pinned. Explicitly not routed: non-sentinel models (including Claude Code's internal Haiku calls), tool-loop continuations, calls carrying no tools, calls belonging to no agent session, a sub-agent's handback.
- Sub-agents: routed and pinned separately; when the user manually picks a model, sub-agents "are still routed" (the documented escape).
- Fallback: fail-open; low confidence never downgrades and caps upgrades at Sonnet; downgrade guard releases after three confident cheap turns; never up into Fable because it "bills extra usage credits".
- Credentials: `JEV_API_KEY` required; "Get a key from TypeSafe for free"; rides the CLI's login. The text of each new user turn leaves the machine to Jev.
- Observability caveat: the CLI UI shows the requested model, not the routed one.
- Windows: PowerShell instructions present.
- Licence/activity: MIT; 6 stars; created and last pushed on 2026-09-18 (one-day project as of today).
- Savings claim: none in the portion read.

### `drewpayment/jev-route` (Claude Code plugin)
- Mechanism: a hooks-module plugin, no proxy, "no shell hooks, no MCP server, no npm dependencies"; rewrites the model for every API request of a turn from inside Claude Code. Requires Claude Code >= 2.1.259 and `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1` (early access; "The plugin API may change between releases").
- Decision: two Jev questions per turn: capability tier (`fast`/`balanced`/`powerful`) and "how risky a careless answer would be"; `risky` can still move up past the context lock.
- Granularity: per turn; the whole turn shares one model; effort pinned with the model (`route_effort`), never changed on a kept model; downgrades blocked above `switch_lock_tokens` (50k).
- Sub-agents: not stated in the portion read.
- Fallback: on timeout (800 ms budget) the session model is kept; with no key, "Claude Code's built-in small-model classifier" (`fallback_classifier`) routes without a risk signal.
- Credentials: TypeSafe key or Vercel AI Gateway key, stored as a `sensitive` plugin config in Claude Code's secure storage (fallback: `JEV_API_KEY`/`AI_GATEWAY_API_KEY`/`TYPESAFE_API_KEY` in the settings `env` block, plaintext). No proxy touches the OAuth token.
- Licence/activity: MIT; 1 star; created and last pushed 2026-09-29.
- Savings claim: none in the portion read.

### `@ediri/jev-router` (repo `dirien/jev-router`)
- Mechanism: pass-through proxy run as a launchd agent or systemd user service; `setup` edits `~/.claude/settings.json` (with backup) to point Claude Code at it; live view at `127.0.0.1:4100`; `doctor`, `uninstall`.
- Granularity: decides only when a person writes; within a session only moves up (cites arXiv 2608.24358 on transcript-inheritance quality loss).
- Tiers: `fast`/`balanced`/`frontier`/optional `max` (Fable 5.1)/`trusted` (for sessions that contained a secret; details truncated). Optional Ollama Cloud tier for quick work, with the README's own warning that Anthropic doesn't support routing Claude Code to non-Claude models through a gateway.
- Credentials: Jev key from TypeSafe or OpenRouter; no Anthropic key; keys in `~/.config/jev-router/env`.
- Platform: "runs on your own Mac or Linux machine"; no service on containers; Windows not mentioned -> unsuitable for a Windows-first host as published.
- Licence/activity: Apache-2.0; npm 1.6.0 modified 2026-09-25. GitHub stars/pushed_at not reached (budget).
- Savings claim: none in the portion read.

## Risks (policy text quoted, quota mechanics, quality, credentials)

**Policy — what the text actually says.** Consumer Terms (2025-10-08) prohibit accessing the Services "through automated or non-human means, whether through a bot, script, or otherwise" except via API key or explicit permission, and prohibit sharing credentials; they say nothing about proxies or OAuth tokens. The Claude Code Legal and compliance page (undated, current) narrows OAuth to "ordinary use of Claude Code and other native Anthropic applications", forbids *third-party developers* from offering Claude.ai login or routing "through Free, Pro, or Max plan credentials on behalf of their users", and forbids developers to "collect, store, or intermediate Claude.ai credentials or session tokens". It also states "Advertised usage limits for Pro and Max plans assume ordinary, individual usage of Claude Code and the Agent SDK" and that the binary "must not be modified"; Anthropic "may [enforce] without prior notice".

**Reading for the studio [inference, both sides].** For: a loopback proxy run by the account holder, forwarding their own token to Anthropic, with the unmodified `claude` binary, is not a third-party developer routing on behalf of users, and `ANTHROPIC_BASE_URL`/gateways are a documented deployment shape. Against: the proxy literally intermediates the session token in third-party code (the policy's verb), and the February–April 2026 enforcement against third-party harnesses shows Anthropic acts on the "ordinary use" line technically, not only contractually; what counts as "ordinary, individual usage" for an unattended multi-sandbox studio is not defined anywhere I reached, and that exposure exists with or without Jev. The hooks-module plugin (drewpayment) avoids the token-intermediation reading entirely because nothing sits between Claude Code and Anthropic; its cost is the early-access flag. The OpenRouter router is out of scope under "never an API key" and sends traffic off Anthropic.

**Quota mechanics — the savings premise is undocumented.** The support article documents a five-hour session limit and a weekly limit shared across Claude and Claude Code, a separate weekly Fable limit on Max, and nothing about per-model weighting. The model-config page adds that Fable and some 1M variants bill to usage credits. I found no Anthropic statement of how Opus vs Sonnet vs Haiku turns consume Max quota. Every router's "savings" is dollars at API list prices computed from token counts; whether routing a turn to Haiku stretches a Max week is therefore unknown from primary sources. The only Haiku-specific signal in Anthropic's own material is that background requests already run on Haiku (`ANTHROPIC_DEFAULT_HAIKU_MODEL` "background functionality"; gateway background requests on Haiku 4.5 in 2.1.295), which suggests cheaper models are treated differently internally [inference, weak].

**Quality.** All routers decide from the user-turn text and context size; a wrong "fast" call on a hard turn is mitigated only by "never downgrade on low confidence" and by moving up next turn. ediri cites a paper that a stronger model inheriting a weak model's transcript recovers only part of the gap — which is why most routers only move up within a session, and why 33Audits found default routing captured +3% of the measured headroom. For an unattended studio, the legs are already fixed by the routing table; per-turn routing would re-decide inside a leg, undermining the table and the transcript-based pricing: the proxy routers leave the transcript's requested model wrong ("shows the model it asked for"), so story pricing would need the router's own log joined in.

**Credentials.** Proxy routers: the OAuth token transits a third-party Node process in every sandbox; `JEV_DUMP`/`JEV_DEBUG` write full request bodies (prompts and code) to disk; gargpratyush keeps prompt text in temp files. All Jev-backed routers need a TypeSafe/Vercel/OpenRouter key present in each microVM — a new secret-distribution path for a studio that currently needs none. The plugin stores its key in Claude Code secure storage (behaviour in a headless sandbox not verified). Every router except 33Audits' local backend sends the user turn text to TypeSafe, whose retention terms I could not read.

**Decision-call cost.** Negligible in money (about $0.00003–$0.0001 per call at $0.042/MTok input); 70–800 ms latency per fresh turn; a second vendor's availability on the critical path, mitigated by fail-open designs.

## How a studio would use typed decisions (patterns, with what is advocacy)

- **Tool-call guard (allow / deny / escalate).** Score a proposed command on separate questions (risk, remote execution, deletion, production impact), threshold in code. Source: LinkedIn reposts of TypeSafe copy and the Composio guide — vendor advocacy and partner advocacy. Real implementation: drewpayment's "risky" question. Studio fit: overlaps Claude Code's own auto-mode safety classifier and permission rules; the marginal value is a cheap second opinion with a probability, which the studio could log as evidence.
- **Escalation decider (route / retry / escalate / stop).** The studio's triggers are objective (failed verification, halt, deviation, high-severity finding) and need no classifier. Jev fits only the fuzzy sub-questions: "is this deviation material?", "is this finding high-severity?", "will a retry on the same model plausibly fix this?" — each a Choice or Score with a confidence the gate can threshold. Pattern source: TypeSafe docs ("act above a threshold, escalate below" is the Register's paraphrase of the vendor pitch).
- **Sizing at intake (XS–XL).** A single Choice over five options with the story text as state; a natural fit and the cheapest place to try Jev, because a wrong size only shifts a budget band and is auditable. Analogous to every router's "which tier" question. No documented example found; [inference].
- **Classifying review findings.** Choice over severity classes plus a Score for confidence; combine several narrow questions rather than one rubric (TypeSafe docs guidance; 33Audits' withdrawn claim is a cautionary tale about one-line rubrics).
- **Budget-band decisions.** Arithmetic on priced transcripts; no probabilistic judgment needed. Not a Jev use.
- **Calibration from outcomes.** 33Audits' ledger (escalations as ground truth, bounded drift, promotions reported not applied) is a pattern the studio can apply to its own routing table without Jev.
- Advocacy flags: HackerNoon "101 examples", Composio guide, LinkedIn posts and aiengineerinsights all read as launch-wave content echoing TypeSafe's framing; none reports a measured outcome.

## Benefits and drawbacks

### Adopt a Jev-based router for the unattended legs
- Benefits: cheapest tier per turn with fail-open safety; flaviusapop/drewpayment also set effort; drewpayment adds a risk signal; 33Audits needs no key at all.
- Drawbacks: re-decides inside legs the routing table already sized; proxy routers intermediate the OAuth token in third-party code and leave transcripts showing the wrong model, breaking transcript pricing; a Jev key must reach every microVM; the user turn text leaves to a second vendor; no evidence routing saves Max quota (undocumented) and 33Audits measured +3% capture in money terms; ediri is Mac/Linux only; the most-starred router (gargpratyush) has been idle since 09-19 with 44 open issues; the plugin needs an early-access flag.
- Policy: proxy routers sit in the "intermediate ... session tokens" gray zone; the plugin does not, but the "ordinary, individual usage" clause applies to the studio either way.

### Use Jev as a decision oracle for escalation, guards and sizing, keep the studio's routing table
- Benefits: no proxy, no token exposure, no change to model selection or pricing; calls are sub-cent and sub-second; typed probabilities give the gate a loggable confidence; sizing and finding-classification are low-blast-radius first uses; fail-open to the current rule.
- Drawbacks: adds a vendor dependency and a secret in sandboxes; prompts/findings text goes to TypeSafe under unread terms; no independent accuracy evidence, so each use needs a local shadow-mode evaluation before it gates anything; the objective triggers gain nothing.

### Stay native (routing table + advisor + effort levels)
- Benefits: per-leg `model` and `effort` in subagent definitions, `CLAUDE_CODE_SUBAGENT_MODEL`, Agent-tool `effort`, `opusplan`, fallback chains and the advisor already express everything the routing table needs; zero policy, credential or transcript-fidelity risk; Anthropic's own data says Opus 5.5 `medium` beats Opus 5 `high`, so effort is the first lever.
- Drawbacks: no per-turn difficulty signal; escalation stays rule-based; no probability attached to fuzzy judgments; Max quota per model remains unknown either way.
