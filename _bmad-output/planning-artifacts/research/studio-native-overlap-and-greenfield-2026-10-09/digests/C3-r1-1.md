Scope: which official Claude Code / Anthropic features, as of 2026-10-09, cover what the studio layer built for itself (capabilities 1–10 in the brief). Primary sources only (code.claude.com docs, platform.claude.com docs, anthropics/claude-code CHANGELOG + releases API, local `claude --help` at v2.1.286). No answer engines used.

Budget used: 16 of 18 surface calls (2 `gh api`, 14 `curl` fetches of official doc pages; 0 WebSearch, 0 WebFetch). Local free calls: `claude --version`, `claude --help`, `claude {agents,auto-mode,ultrareview,plugin,project,respawn,setup-token,mcp} --help`, local greps of the downloaded CHANGELOG.

Sources: 15 URLs retrieved = 13 official doc pages + 2 GitHub API endpoints on one repo (CHANGELOG.md, releases); counted as 14 distinct publishers' documents. ## Feature cards

### Agent view and the background daemon — https://code.claude.com/docs/en/agent-view
What: `claude agents` lists every background session (Needs input / Working / Completed), dispatches new ones, peeks and replies, attaches/detaches. A supervisor service hosts one process per session, restarts crashed processes, stops idle unattached processes after ~1 h (pin to keep), survives sleep and auto-updates, and persists state under `~/.claude/jobs/<id>/`. Shell: `claude --bg`, `attach`, `logs`, `stop|kill`, `respawn [--all]`, `rm`, `daemon status|logs|stop --any`, `agents --json [--all] [--cwd]`.
Limits: research preview; sessions are local and stop on shutdown; `--bg` rejects `-p`; bypass mode needs one-time interactive consent; jobs files are not a stable interface; each session draws subscription quota; `claude daemon` is absent from `claude --help` at v2.1.286.
Subscription sentence: "background sessions consume your subscription usage the same as interactive sessions, so running ten agents in parallel uses quota roughly ten times as fast as running one." ([AV], Limitations)

### `/loop` and session-scoped scheduled tasks — https://code.claude.com/docs/en/scheduled-tasks
What: `/loop [interval] [prompt|/skill]` re-runs a prompt on a cron interval (≥1 min) or self-paced (1 min–1 h, Claude chooses); bare `/loop` runs a maintenance prompt or `loop.md`; `CronCreate/CronList/CronDelete` tools; up to 50 tasks; jitter; 7-day expiry.
Limits: requires a running session (background sessions count); no catch-up; self-paced loops are not restored on resume; feature-flag-off persistence writes `.claude/scheduled_tasks.json` and is folder-bound.
Subscription sentence: "Dynamically chosen intervals and the built-in maintenance prompt work on every provider" ([ST]); routines (not `/loop`) are the subscription-gated scheduling path per [FA].

### `/goal` — https://code.claude.com/docs/en/goal
What: completion-condition loop; a small-fast-model evaluator judges after every turn; `/goal` status shows turns, duration, token spend; works in `-p` (single invocation runs to completion), desktop, Remote Control; retries transient failures, pauses on rate/usage limits, clears on unrecoverable errors.
Limits: evaluator reads only the transcript (cannot run commands); idle check-ins interactive-only; requires hooks enabled (not `disableAllHooks`/`allowManagedHooksOnly`).
Subscription sentence: "Evaluation tokens are billed on the small fast model configured for your provider and are typically negligible compared to main-turn spend." ([GL]) — no plan gating stated.

### Dynamic workflows (Workflow tool, `ultracode`, `/deep-research`, `/batch`) — https://code.claude.com/docs/en/workflows
What: Claude writes a JavaScript orchestration script; runtime runs dozens–hundreds of subagents in the background; `agent({schema, model, …})`, `parallel()`, `pipeline()`; adversarial cross-review pattern; scripts are saveable as commands and distributable in plugins; `/workflows` shows per-agent token use; resumable after pause/stall.
Limits: 16 concurrent agents by default (CPU-bound; 1–256 via env, v2.1.269+); no mid-run user input; usage-limit pause only in interactive subscription sessions; a run "can use meaningfully more tokens"; Pro must opt in via `/config`.
Subscription sentence: "Dynamic workflows are available on all paid plans, with Anthropic API access, and on Amazon Bedrock, Google Cloud's Agent Platform, and Microsoft Foundry. On Pro, turn them on from the Dynamic workflows row in `/config`." ([WF])

### Advisor tool — https://code.claude.com/docs/en/advisor
What: a server-side tool that lets the main model consult a stronger model (full transcript) at decision points; set via `/advisor`, `advisorModel`, hidden `--advisor`; subagents inherit it; pairing table enforced client- and server-side.
Limits: experimental; Anthropic API only (not Bedrock/Vertex/Foundry/AWS platform; gateways only if forwarded intact); requires feature-flag fetching; model decides when to call; advisor's own reads are never cached; Fable advisor bills to usage credits on some plans.
Subscription sentence: "The advisor runs server-side on Anthropic's infrastructure as a server tool, available to both subscription and API-billed accounts." and "Subscription plans: advisor usage counts toward your plan's usage limits". ([AD])

### Auto mode and its classifier — https://code.claude.com/docs/en/permission-modes
What: a classifier model reviews each action instead of prompting; blocks escalations (deploys, destructive git, secrets exfiltration, launching unsupervised agent loops); server-side review on direct API; `claude auto-mode config|critique|defaults|reset`; two-minute countdown then deny for critical-path `rm` in interactive sessions; immediate deny in `-p`/SDK (v2.1.281+).

## Gaps: studio capabilities with no official equivalent
- Story/epic-aware loop semantics (BMad story files, two named adversarial reviewers with triage, review gate scoring plan deviation, reconciliation against later stories, per-story journal). Official pieces (`/goal`, workflows, `/code-review`) are generic.
- Durable job queue with a public contract: `agents --json` is read-only; jobs dir "not a stable interface"; no enqueue API on the local daemon (routines' `/fire` is cloud-only).
- Pacer / budget bands / kill-and-restart rules tied to cost: `--max-budget-usd` is `-p`-only and per-invocation; no cross-run budget.
- Self-hosted HTTPS status page with phone sign-in and ntfy: Remote Control and channels replace the function (phone steering, approvals) but not a page you host; ntfy has no plugin in the official channel allowlist found.
- Worker tier "sandbox with bypass" on Windows: official built-in sandbox is macOS/Linux/WSL2; the Docker microVM tier stays studio-owned.
- Drift check against a pinned third-party skill base (BMad lockfile) and per-user store health.

## Benefits and drawbacks of adopting each official feature in place of the studio's own

1. Loop → `/goal` + auto mode + workflows + `/code-review`
   - Benefits: zero-maintenance turn driver that already handles rate/usage-limit pauses, auth-failure clearing, background-work check-ins; headless one-liner (`claude -p "/goal …"`); workflows give structured-output reviewers and adversarial cross-review with per-agent model choice; `/code-review` is tuned per model.
   - Drawbacks: evaluator is transcript-only (your verify step must print evidence); no story semantics; workflows do not pause on usage limits in `-p`/background (third hit fails the agent); `/loop` 7-day expiry; `ultracode` increases spend; adversarial reviewers lose your triage schema unless re-expressed as `agent({schema})`.

2. Supervisor → agent view daemon + Remote Control + channels (+ Projects for cloud)
   - Benefits: crash restart, sleep/update survival, idle reaping, `agents --json` state, notifications hook, Windows support, phone steering and approvals without hosting anything; cloud Projects remove the machine from the loop entirely.
   - Drawbacks: no queue/enqueue API, no pacer, stops on shutdown (no documented Windows service), research-preview flags can change, bypass mode in `--bg` needs interactive consent, Telegram plugin needs Bun, channels need a live session, Projects are cloud/GitHub.com-only and cannot see local files; `~/.claude/jobs` must not be parsed.

3. Routing/consult/gate → advisor + frontmatter `model`/`effort` + Agent `effort` + `maxEffortLevel`
   - Benefits: consult leg is server-side, subscription-billed, inherited by subagents, cache-neutral for the main model; effort caps and per-leg models are settings, not code.
   - Drawbacks: advisor is experimental, API-direct only (breaks behind gateways/Bedrock), trigger is model-driven (your "objective triggers" are not expressible), each call re-reads the whole transcript; no deviation scoring; keep your gate.

4. Meter → `/usage`/`/cost` + OTel + stream-json usage
   - Benefits: official per-model/cache/loop breakdowns, OTel `effort` and `vcs.*` attributes for free, `--max-budget-usd` hard stop in `-p`.
   - Drawbacks: no story keying, estimates at list price, Analytics API is Enterprise-only; keep the transcript-derived per-story roll-up but feed it from OTel/stream-json instead of parsing transcripts.

5. Ledger/evolve → hooks + OTel + `plugin eval` + `/skill-doctor` + `/insights`
   - Benefits: `plugin eval` gives scored, baseline-compared evidence for proposals; hook events (`StopFailure`, `TaskCompleted`, `PostModelSwitch`) are a cleaner observation source than transcript scraping.
   - Drawbacks: no ledger or proposal→PR loop; auto-memory cannot be enabled from background sessions; keep the JSONL ledger, source it from hooks.

6. Drift → `claude doctor`/`update`/`install <version>`, `daemon status`, managed version requirements, `plugin update|validate|tag`
   - Benefits: official version-skew warnings and respawn; `plugin tag` + marketplace keep plugin versions honest.
   - Drawbacks: nothing pins a third-party skill base; keep the lockfile check, add `claude doctor` and `daemon status` to it (today's machine is 10 releases behind).

7. Planning adapter → claude.ai MCP connectors + routines/Projects
   - Benefits: Linear/Jira-class connectors with OAuth via `claude mcp login`; routines can groom a tracker nightly.
   - Drawbacks: connectors only with claude.ai auth active; no Backlog.md/BMad normalisation; Projects are cloud-only; keep the adapter.

8. Research → `/deep-research` + Artifacts
   - Benefits: cross-checked, cited report in one bundled workflow; publishable pages.
   - Drawbacks: no charter/budget/digest schema; WebSearch hourly budget; keep the charter layer, call `/deep-research` as a fan-out engine.

9. Job contract → `agents --json` + `-p` JSON/stream-json + `--json-schema`
   - Benefits: official state vocabulary (`working/blocked/done/failed/stopped`, `waitingFor`); structured outputs without custom parsing.
   - Drawbacks: documented attended/headless divergences remain; keep the conformance suite but assert against the official contract.

10. Front end / engagement → agent view, Desktop Dispatch, Projects Overview, Artifacts
    - Benefits: free, maintained views of agent state; Artifacts can host client-facing pages.
    - Drawbacks: no office metaphor or story progress; no engagement loop; build on `agents --json` rather than jobs files.
