## Answers per lead

1. CC-BY-SA in a proprietary app. OGA's FAQ has no `q-proprietary` entry on the current page; its closed-source entry says yes, use the art, follow the licence, and it separates game code from media ("separate entities"). Creative Commons' own interpretation page says SA binds only "adaptations under copyright law", that "Simply including an SA work unmodified alongside unrelated materials does not produce an adaptation", and "The larger work may be licensed under any terms." Two caveats from the same page: the adaptation line "may differ across jurisdictions", and modifying the art (recolours, re-cuts, new frames) is an adaptation that must be SA. Neither page addresses software bundles explicitly. Posture: unmodified BY-SA sprites in a closed app are defensible per CC; edited BY-SA sprites must ship under BY-SA as asset files; attribution always.
2. LimeZu Modern Interiors. Licence quoted verbatim above: edit and use commercially; no resale or distribution; credits required. The page gives no separate free-edition licence and the free zip's licence file was not opened this run, so whether the free edition carries the same no-redistribution clause is unconfirmed. Walk/sit/typing are not named anywhere in the page description; the only list is "idle, run, gift, shoot, punch, pick up, read a book, lift, throw". Treat sit/typing as unverified until the v41.4 contents or a dev-log is inspected.
3. PixelLab. Plan prices not retrievable (JS-rendered pricing; no public plans JSON found at the probed paths). Hosted MCP: `https://api.pixellab.ai/mcp`, HTTP transport, bearer token, docs at `https://api.pixellab.ai/mcp/docs`. Metering is in "generations" per tool (1 for pixflux/pixen images and template animations; 10-25 for pro modes, inpainting and objects; tilesets 1-4). One mode is gated to "tier 1 subscription or higher". No ownership/licence statement for outputs was found on the MCP page or the MCP docs.
4. Retro Diffusion ToS. The ToS body is client-rendered and was not captured; the exact ownership wording is therefore not available from this run. The page's structured-data FAQ says "All generated art can be used commercially." and "All pixel art you generate with Retro Diffusion is yours to use for personal or commercial projects". Treat as a marketing claim pending a browser read of the rendered ToS.
5. itch.io build-time fetch. The documented server-side surface covers verification (`/games/GAME_ID/download_keys`) and listing the caller's own purchases (`/profile/owned-keys`), both with a bearer API key from /api-keys (unscoped when user-generated). A file-download endpoint is not on that page, so a build script can prove ownership but the actual download path is undocumented here; see Leads.
6. More CC0 candidates. Pixel Frog: CC0, attribution not required, but platformer side-view. 0x72 DungeonTileset II: CC0 1.0 assets, 16x16, dungeon theme. No CC0 16x16 top-down "modern/cozy office" pack was found on itch.io (CC0+office tag yields 3D packs) or via search; generic CC0 top-down templates exist (rgsdev, Ishtar Pixels) but are unverified and not office-themed.
7. PixiJS v8 integer zoom on phones. No primary doc page retrieved documents the recipe; the v8 Renderers guide omits the options entirely. Secondary sources give the standard pairing `resolution: window.devicePixelRatio` + `autoDensity: true`, and `roundPixels` as whole-pixel snapping. Fractional-DPR artefacts are reported (2021 forum; open 2026 issue #11486 about blurry/stretched mobile rendering; #11477 nearest-mode text artefacts). Confidence low; needs the v8 API reference and the #11486 thread.
8. Phaser 4 Next template. It does handle strict mode's double invocation, by destroy-and-recreate in `useLayoutEffect` cleanup rather than by skipping the second mount; `reactStrictMode` is not set in `next.config.mjs`. It has not moved past Phaser 4.0.0 (pinned 2026-04-10) while Phaser is at 4.2.1 (2026-07-09).
9. Godot C# web export. Still unsupported: stable docs say Godot 4 C# projects "currently cannot be exported to the web" and point to Godot 3; tracker #70796 remains open with no milestone (updated 2026-06-19). No "initial C# web" note was found on the 4.5/4.6/4.7 release pages.

## Recommended asset posture (updated)

- Core interior/character set: LimeZu Modern Interiors (paid, >= $1.50) remains the best-fit commercial pack. Its "Resell or distribute" prohibition means the pack must not be committed to any public repo; keep it in a private artifact store or private LFS/submodule and fetch at build time. Keep "Credits required" satisfied in-app. Do not rely on sit/typing animations until verified in the v41.4 zip.
- CC-BY-SA packs: acceptable only when used unmodified and attributed (per CC's interpretation page). Any edited BY-SA sprite must itself ship under BY-SA; prefer CC0 or LimeZu for anything the pipeline recolours or re-cuts.
- CC0 fill-ins: Pixel Frog (platformer) and 0x72 (dungeon) are clean CC0 but thematically wrong for an office; no CC0 office pack was found, so the gap is real.
- Generative fill-ins: PixelLab MCP is usable from Claude Code with generation metering, but no output-ownership statement was found; Retro Diffusion advertises commercial use and provenance-consented training but its ToS body is unread. Treat AI-generated assets as provisional until both ToS bodies are read in a rendered browser and quoted.
- Renderer implications: Phaser 4 is viable (template handles strict mode via destroy/recreate; bump from 4.0.0 to 4.2.1 on adoption). PixiJS integer-zoom on phones still lacks a primary recipe and has an open mobile blurriness issue. Godot C# is out for a web target; Godot would mean GDScript.
