### Pixel Agents — `pixel-agents-hq/pixel-agents` (formerly pablodelucca/pixel-agents)
- Metrics: 9,602 stars, 1,599 forks, 94 open issues, created 2026-02-08, pushed 2026-10-09; 7 releases, latest v1.4.1 2026-08-15 [https://api.github.com/repos/pixel-agents-hq/pixel-agents] [https://api.github.com/repos/pixel-agents-hq/pixel-agents/releases]
- Licence: MIT [API]; characters derive from JIK-A-4 Metro City pack [README]
- Stack: VS Code extension + standalone CLI (Node 20+); Canvas 2D engine with pathfinding and per-character state machines; React 19 + Vite webview; `core/`, `adapters/vscode`, `server/`, `webview-ui/` folders [https://raw.githubusercontent.com/pixel-agents-hq/pixel-agents/main/README.md] [repo tree via API]
- Event model: Claude Code hooks (SessionStart, PreToolUse, PermissionRequest, Stop) by default, JSONL transcript scan as fallback, both normalised to `AgentEvent`; wire contract is AsyncAPI (`core/asyncapi.yaml`) over WebSocket [README] [https://github.com/pixel-agents-hq/pixel-agents/blob/main/core/asyncapi.yaml]
- State vocabulary: `AgentActivityStatus` enum `active | waiting`; tool-level messages (ToolStart/ToolDone/ToolPermission, Subagent*), AgentContextUsage, AgentTeamInfo; rendered as walk-to-desk, sit, typing (edit), reading (search), running-command animation, speech bubble on waiting/permission [asyncapi.yaml] [README]
- Multi-agent / multi-project: one character per terminal; sub-agents and Agent Teams as separate characters; workspace folders map to office areas; "Watch All Sessions" spans workspaces; one office per project is future [README]
- Remote feed: CLI serves browser UI + WebSocket, `0.0.0.0` bind for LAN, `--no-terminal`, `SetGhostHeadlessAgents` message exists in the contract; only Claude Code hooks/transcripts feed it today [README] [asyncapi.yaml]
- Verdict: the reference implementation and the one with the most reusable artefacts (MIT, AsyncAPI contract, asset manifests, layout JSON). Reuse `core/` and `server/`; ignore `adapters/vscode`. Watch that release cadence has slowed to quarterly minors while commits continue.

### AI Town — `a16z-infra/ai-town` (prior art)

## Benefits and drawbacks

### By event source
- Hooks-fed (Pixel Agents default, claude-office, ririversoza/agent-office). Benefits: exact, low-latency, semantic events including the one that matters most to an operator, waiting-for-permission; Pixel Agents' contract shows the full set a hook feed can carry (tool start/done, permission, subagent, team, context usage) [asyncapi.yaml]. Drawbacks: requires installing hooks into each agent's settings (Pixel Agents has a HooksStatus install/notNow/never flow for this) [asyncapi.yaml]; vendor-specific, which is why Pixel Agents supports only Claude Code and claude-office needed a separate OpenCode plugin [READMEs].
- Transcript-tailed (AgentRoom; Pixel Agents fallback). Benefits: zero configuration, works across vendors that write JSONL (AgentRoom shows Claude Code, Codex, Gemini together) [AgentRoom README]. Drawbacks: heuristic and lagging, bound to the local filesystem so no remote feed, and treated as a fallback by the most mature project [Pixel Agents README]; AgentRoom itself did not survive its first day of development [API].
- Generic event feed (claude-office REST + WS; Pixel Agents AsyncAPI; munder-difflin hive). Benefits: decouples renderer from agent vendor; enables remote/headless producers, simulation fixtures (`make simulate`) and replay (Generative Agents `/replay`), and a stable contract a small team can test against [claude-office README] [Generative Agents README]. Drawbacks: someone must run the server and design the vocabulary; auth becomes your problem (claude-office's `?token=` and remote gate) [claude-office README].
- Host-the-agent (agent-office, munder-difflin, starnet). Benefits: perfect state because the office owns the PTY, and the office can command agents (hire, queue, send home, worktrees) [agent-office README] [munder-difflin README]. Drawbacks: the front end becomes the agent runtime, which doubles scope for a one-person studio and competes with an orchestrator the studio already has; both exemplars are Electron or Node-server apps with breaking-change caveats [READMEs].

### By renderer
- Hand-rolled Canvas 2D (Pixel Agents, AgentRoom): small, pixel-perfect at integer zoom, portable enough that AgentRoom ported it into Tauri; no WebGL dependency [READMEs]. Cost: you own pathfinding and state machines.
- PixiJS (claude-office, munder-difflin, AI Town via pixi-react): WebGL, scales to effects and many sprites, integrates with React; the only Next.js precedent uses it [claude-office README] [AI Town ARCHITECTURE.md]. Cost: a heavier dependency and SSR care in Next.js.
- 3D (agent-office, regisBafutwabo): striking and attracting stars fast, but asset pipeline (Blender) and performance budgets are larger, and the state grammar shown is thinner (needs-input, finished) than the 2D offices [agent-office README].
- DOM dashboard (moyuu-az; claude-office Command Center): the triage columns Needs-input / Running(Working) / Done / Ended recur across independent projects, which argues for keeping a DOM triage panel beside the scene rather than encoding everything in sprites [claude-office README] [moyuu-az release].

### Single vs multi agent / project
- Converging UI grammar: desk = agent; bubble or beacon = needs you; break room or couch = idle; area/floor = project (Pixel Agents areas per workspace folder, claude-office floor per session, agent-office floor per repo, munder-difflin New Floor per folder, AgentRoom focus per project) [all READMEs]. Subagents are children of a parent character everywhere they appear.
- Gap across all precedents: none renders task, story or epic progress. The nearest are agent-office's cork boards of GitHub issues/PRs, munder-difflin's current ticket and kanban, paperclip-office's "work moving between them", and ririversoza's checklist + branch PR [READMEs] [search API]. This is open ground for the studio.

### What to steal
- Pixel Agents' AsyncAPI message set as the studio's canonical agent-event vocabulary (MIT), extended with task/story/epic identifiers it lacks [asyncapi.yaml].
- AI Town's rule set: one authoritative mutator, diffs per step, history buffers for interpolation, an ordered inputs queue with status, LLM work that can only act by submitting inputs [ARCHITECTURE.md].
- claude-office's REST ingest + WebSocket fan-out + fixture simulator, and its Needs-you / Working / Done / Ended triage [claude-office README].
- The state union: idle, typing/writing, reading/searching, running command, delegating, waiting-for-input, waiting-for-permission, finished (ding/jump), context pressure, crashed, walking between desk and break room [Pixel Agents, claude-office, AgentRoom, munder-difflin, agent-office READMEs].
- Asset pipeline: Pixel Agents' furniture manifests (sprites, rotation groups, state groups, animation frames), external asset directories, JSON layouts up to 64×64; 32×32 tiles from SkyOffice [Pixel Agents README] [AgentRoom README].
- UI grammar: needs-input beacon with a keyboard jump (agent-office's N key), "Asked you" marker and crash strip (munder-difflin) [READMEs].

### What to avoid
- Transcript tailing as the primary source; VS Code-adapter coupling (`adapters/vscode`); embedding PTYs in the front end.
- AGPL (clawd-on-desk) and GPL (outworked) code, and asset packs with their own licences (LimeZu in munder-difflin; JIK-A-4 Metro City in Pixel Agents and AgentRoom, licence not checked this run) [API] [READMEs].
- Depending on dormant repos: AgentRoom, Star-Office-UI, claw-empire, outworked, samwang0723/agent-office [API].
