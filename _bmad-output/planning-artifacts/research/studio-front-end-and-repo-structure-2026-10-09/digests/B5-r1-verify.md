## Notes

- Claim B5.1: Verified for Cursor (TestingCatalog, learncursor.dev, mer.vin), Claude Code (anthropics/claude-code changelog, which also shows plan-mode enforcement leaks fixed as bugs: Bash `touch`/`rm` auto-run, `Edit(...)` allow rules bypassing plan mode), Factory (Sid Bharath guide, Vibe Kanban docs: autonomy level chosen at spec approval, level names vary by surface), Replit (fast.io, coworker.ai: Plan Mode exists; checkpoints belong to Build Mode) and Jules auto-approve default (Raycast and GatienBoquet third-party clients default `requirePlanApproval` to false). Not reached: the Jules countdown timer in the web UI and the "assumptions list" wording; Devin billing planning in ACUs (vendor docs only); the GitHub Copilot coding agent was not re-checked. The universal "no product quotes a price before running" cannot be verified exhaustively; every source reached is consistent with it, and the Replit third-party guide explicitly says the price is not knowable before the request.
- Claim B5.2: SOW practice verified by four different publishers (State of Montana procurement template, ClickUp agency SOW template, monday.com, UK G-Cloud 15 supplier contract with a "Client Dependency" definition); the specific phrases "three-layer acceptance" and "dated dependencies" were not independently confirmed. ProKanban 50/85/95 band verified only on prokanban.org's own pages (same publisher); Leanpub independently confirms the guide exists as "The Flow Forecasting Pocket Guide" by Vacanti and Johnson, which is a different title from the one the search surfaced ("When Will It Be Done? Pocket Edition"); the ledger should name the title it means. ChatDev verified from the GitHub releases API with nuance: v2.0.0 (2026-01-07) moves the framework "from a domain-specific virtual software company paradigm to a zero-code system"; v1.x is kept on the `chatdev1.0` branch "for maintenance" and the software-company flow survives as a `ChatDev_v1.yaml` workflow preset. "Retired" overstates slightly; "demoted to a legacy branch and a preset" is accurate.
- Claim B5.3: Jules API verified from two third-party TypeScript clients: the enum has STATE_UNSPECIFIED plus eight real states (QUEUED, PLANNING, AWAITING_PLAN_APPROVAL, AWAITING_USER_FEEDBACK, IN_PROGRESS, PAUSED, FAILED, COMPLETED), `requirePlanApproval` is optional and defaults to auto-approve, `approvePlan` is the approval route; `sendMessage` was not checked in third-party code. GitHub code search returns 322 files using both identifiers, so the enum names are stable across the ecosystem. Claude Code verified from the changelog with nuance: Ctrl+G plan editing and AskUserQuestion-as-tool are confirmed; the approval prompt's option set depends on configuration (auto mode availability adds "Yes, and use auto mode" as first option; a "clear context" option is hidden by default), so "three-option" is the default shape rather than a fixed count. Cursor leakage verified from additional forum threads with Cursor staff replies (weak independence: same forum, different reporters); staff responses reveal the mechanism, a model-invoked `SwitchMode` tool gated by an "Auto-Approved Mode Transitions" setting, which supports rather than overturns the ledger's "state transition, not prompt interpretation" inference. No Reddit or press reporting of the leakage surfaced.
- Claim B5.4: Flyvbjerg and Budzier 2011 verified by MIT Technology Review (2013) and RePEc: 1,471 projects, mean 27%, one in six Black Swans at 200% cost and ~70% schedule overrun; HBR byline and September 2011 issue confirmed on hbr.org (body paywalled). The 2022 JMIS paper verified via Oxford Research Archive and RePEc (5,392 projects, power-law tail); correction: it has six authors (Flyvbjerg, Budzier, Lee, Keil, Lunn, Bester), not "Flyvbjerg and Budzier" alone. Replit disputed on wording only: Plan Mode is billable per request at an effort-based rate; "per checkpoint" is Build Mode's unit. Devin sizing unverified independently: only Cognition's docs were reached; they add that size is a composite of ACU and message count (not ACU alone) and give Enterprise thresholds that are 10x the ledger's values, consistent with but not stating XS <= 2 / XL > 20. The green/yellow/red "completion likelihood" was not found in any source. "No surveyed product documents partial-delivery reporting" is a universal negative and remains unverified.
