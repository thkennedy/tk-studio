## Product cards

**Devin (Cognition)** — Intake: free-text task; docs push "clearly scoped tasks with a well-defined end goal" and splitting big work into parallel sub-task sessions; a Coach flags weak prompts pre-send [https://docs.devin.ai/llms-full.txt]. Scoping: CLI Plan and Ask modes [same]. Estimate/quote: none per task; billing is seat plans plus ACU metering, and planning time is billable [same]. Approval gate: per-operation permission prompts by mode (Normal, Accept Edits, Smart, Bypass) rather than a single plan sign-off [same]. Limits reporting: a static "Devin Limitations" statement and a 30-day session expiry; no structured "could not do" report found [same]. Verdict: the richest metering vocabulary (ACU, planning is billable) but no quote-before-run; its guidance on task shape is reusable as brief-quality rules.

**Replit Agent** — Intake: chat; Plan mode toggled by clicking "Plan" or asking [https://docs.replit.com/replitai/agent]. Scoping: "brainstorm, ask questions, and map out your project before Agent changes any code or data" into "an ordered task list you can review and refine" [same]. Estimate/quote: no figure before running; cost knobs are modes (Free/Auto/Power/Max) and Turbo "6x cost" [same]. Approval gate: building starts after plan approval; paid actions ask first ("Allow once") [same]. Limits: Free-mode allowances reset every five hours; background tasks 1 on Core, 10 on Pro [same]. Verdict: closest consumer analogue to "scope then approve", with checkpoints as the rollback/milestone unit; price is still revealed after the fact.

**Cursor Plan Mode** — Intake: agent prompt; Shift+Tab or auto-suggested on complex tasks [https://cursor.com/blog/plan-mode]. Scoping: codebase research plus clarifying questions, output is an editable Markdown plan with file paths [same]. Estimate: none [same]. Gate: user reviews then builds; no formal approval control described [same]. Limits: none stated [same]. Verdict: best precedent for "plan as an editable document the client marks up"; the loop lacks a quote and a hard gate.

**Claude Code plan mode (Anthropic)** — Intake: chat; `--permission-mode plan` or Shift+Tab [https://code.claude.com/docs/en/common-workflows]. Scoping: reads files, proposes a plan, "makes no edits until you approve" [same]. Estimate: none. Gate: hard, mode-enforced [same]. Limits: unattended (scheduled) runs "can't ask clarifying questions", so success must be spelled out in advance [same]. Verdict: cleanest hard gate; the unattended caveat is directly relevant to a studio whose owner is often away.

**Google Jules** — Intake: task; plan appears after environment setup [https://jules.google/docs/review-plan/]. Scoping: plan = description + steps + "any assumptions or setup steps"; feedback via chat including answering Jules's questions [same]. Estimate: none. Gate: explicit "approve plan" button, but a timer auto-approves if the user navigates away [same]. Limits reporting: not described [same]. Verdict: the explicit assumptions list is the best precedent for "what we are assuming and need from you"; the auto-approve timer is the anti-pattern to avoid for an absent product owner.

**GitHub Copilot cloud agent** — Intake: prompt (or issue). Scoping: generates a plan first if asked; user approves or gives feedback before code is written [https://github.blog/changelog/2026-04-01-research-plan-and-code-with-copilot-cloud-agent/]. Estimate: none found. Gate: in-conversation approval (UI not confirmed this run). Verdict (medium confidence): plan-on-request, not plan-by-default.

**Factory Droid** — Intake: CLI prompt; Spec Mode via Shift+Tab [https://docs.factory.ai/cli/user-guides/specification-mode]. Scoping: read-only spec, revisable on request [same]. Estimate: none found. Gate: ExitSpecMode approval that also sets the implementation autonomy level (Low/Medium/High), with large plans running in Mission Control [same]. Verdict (medium confidence): the only product observed binding "how much latitude" to the approval moment, and the closest "mission" vocabulary to a mission board.

**MetaGPT / MGX (FoundationAgents)** — Intake: "one line requirement" [https://github.com/FoundationAgents/MetaGPT]. Scoping: PM, architect, PM, engineer roles emit user stories, requirements, data structures, APIs before code [same]. Estimate: none. Gate: none in the open-source flow (SOP runs through). Sentiment on the hosted MGX: praised for fast prototypes and requirements docs; criticised for instability, generic output, context limits and credit burn [https://www.producthunt.com/products/metagpt-x/reviews] (low confidence). Verdict: strong precedent for intermediate documents (PRD, design) as client-reviewable artifacts; weak on gating and cost; repo last pushed 2026-01-21.

**ChatDev (OpenBMB)** — Intake: `--task` description; 1.0 "Virtual Software Company" with CEO/CTO/Programmer seminars and a "Human" interaction config [https://github.com/OpenBMB/ChatDev]. Scoping: role seminars for designing, coding, testing, documenting [same]. Estimate: none. Gate: none by default. Trajectory: 2.0 (2026-01-07) abandoned the software-company framing for a general zero-code orchestration platform [same]. Verdict: the "AI dev shop" role-play framing was retired by its own authors; borrow the phase vocabulary, not the architecture.

## Engagement-loop template

Stages the evidence supports, with vocabulary and precedent:

1. **Brief** (intake). A one-line requirement is enough to start [https://github.com/FoundationAgents/MetaGPT], but the studio should coach the brief toward "a well-defined end goal" before accepting it, as Devin's Coach does pre-send [https://docs.devin.ai/llms-full.txt].
2. **Clarifications**. Agent asks requirement questions before planning; answering them is framed as the lever on output quality [https://cursor.com/blog/plan-mode]; Replit and Jules do the same inside plan review [https://docs.replit.com/replitai/agent], [https://jules.google/docs/review-plan/]. Rule for an unattended owner: if nobody can answer, the brief must already state success [https://code.claude.com/docs/en/common-workflows].
3. **Scope of work**. An editable plan document with file paths and to-dos [https://cursor.com/blog/plan-mode], an ordered task list [https://docs.replit.com/replitai/agent], and an explicit assumptions list [https://jules.google/docs/review-plan/]; structure it with the agency SOW headings, notably "scope and exclusions" and "roles and responsibilities" [https://bestarion.com/statement-of-work/].
4. **What we need from you**. The client-side matrix: product owner, business rules, priorities, approval authority, plus repo/environment/API/test-data access "on time", each dependency dated with owner, impact and escalation [https://bestarion.com/statement-of-work/].
5. **Quote**. No surveyed agent product quotes before running (see "Looked for"). The studio can: forecast duration from its weekly throughput history with Monte Carlo and present 50/85/95 percentiles, committing on the band not the point [https://prokanban.org/forecasting-pocket-guide]; include scoping effort in the price because scoping is itself metered work [https://docs.devin.ai/llms-full.txt]; offer speed-versus-cost options the way Replit's modes do [https://docs.replit.com/replitai/agent].
6. **Contract** (approval gate). A hard, mode-enforced "no edits until you approve" [https://code.claude.com/docs/en/common-workflows], an explicit approve action [https://jules.google/docs/review-plan/], and an autonomy level chosen at approval [https://docs.factory.ai/cli/user-guides/specification-mode]. Avoid timer-based auto-approval [https://jules.google/docs/review-plan/].
7. **Milestones** (prototype or vertical slice to finished product). "Milestone 1: UX prototype. Milestone 2: API and backend" [https://bestarion.com/statement-of-work/]; execution tracked as a mission in Mission Control [https://docs.factory.ai/cli/user-guides/specification-mode]; checkpoints as rollback points [https://docs.replit.com/replitai/agent]; big work split into parallel sub-task sessions [https://docs.devin.ai/llms-full.txt].
8. **Acceptance**. Three-layer acceptance (deliverable, functional, quality) with a named acceptance signal per deliverable [https://bestarion.com/statement-of-work/].
9. **Change request**. Written approval before work begins on material scope changes, with revised schedule or fees [https://bestarion.com/statement-of-work/]; at the micro level, "always prompt" on high-risk operations [https://docs.devin.ai/llms-full.txt] and "Allow once" for paid actions [https://docs.replit.com/replitai/agent].
10. **Report of limits**. Standing limitations stated up front [https://docs.devin.ai/llms-full.txt] and per-job assumptions in the plan [https://jules.google/docs/review-plan/]; no product surveyed produces a structured "what we could not do" closeout (gap).

## Benefits and drawbacks

Per interaction pattern, for a chat-plus-board front end used by one product owner:

- **Clarifying questions before the scope** (Cursor, Replit, Jules). Benefit: vendors themselves tie it to output quality [https://cursor.com/blog/plan-mode]. Drawback: it blocks on a human; for an often-absent owner the studio needs a "brief completeness" check that converts unanswered questions into stated assumptions, as Jules's plan does [https://jules.google/docs/review-plan/], and a board state "awaiting your answers".
- **Editable plan document** (Cursor Markdown, Replit task list). Benefit: the owner edits scope directly instead of negotiating in prose, and the document persists as the contract artifact [https://cursor.com/blog/plan-mode]. Drawback: none of these documents carries cost or duration, so the studio must add quote fields itself (no precedent found).
- **Hard approval gate** (Claude Code, Jules, Factory). Benefit: a clear contract moment and no accidental spend [https://code.claude.com/docs/en/common-workflows]. Drawback: Jules shows the temptation to auto-approve on a timer to keep throughput up [https://jules.google/docs/review-plan/]; for a board, prefer an explicit "awaiting approval" lane with expiry-to-cancel, never expiry-to-start.
- **Autonomy chosen at approval** (Factory). Benefit: maps naturally to contract style (tight fixed scope versus latitude) in one control [https://docs.factory.ai/cli/user-guides/specification-mode]. Drawback: another knob for a solo owner; default it from the quote band.
- **Metered usage revealed afterwards** (Devin ACUs, Replit effort modes). Benefit: produces exactly the per-story history the studio already has for quoting [https://docs.devin.ai/llms-full.txt]. Drawback: price is not known before the run; Monte Carlo on that history is the fix, presented as a band at 50/85/95 [https://prokanban.org/forecasting-pocket-guide].
- **Role-play software company** (MetaGPT, ChatDev). Benefit: intermediate PRD/design/API documents give the owner something reviewable between brief and code [https://github.com/FoundationAgents/MetaGPT]. Drawback: user sentiment on the hosted version centres on generic output and credit burn [https://www.producthunt.com/products/metagpt-x/reviews], and ChatDev's authors retired the framing in 2.0 [https://github.com/OpenBMB/ChatDev]; keep the artifacts, drop the theatre.
- **Mission board with checkpoints** (Factory Mission Control, Replit checkpoints). Benefit: milestones and rollback points are visible without reading chat [https://docs.factory.ai/cli/user-guides/specification-mode], [https://docs.replit.com/replitai/agent]. Drawback: no evidence this run on how these boards report blockers or partial delivery.

Vocabulary the UX should use, with precedent: brief (Devin's "clearly scoped task"), clarifications (Cursor), scope of work with "scope and exclusions" (Bestarion), assumptions (Jules), what we need from you / roles and responsibilities (Bestarion), quote as a 50/85/95 band (ProKanban), approve plan / contract (Jules, Claude Code), autonomy level (Factory), milestones and mission (Bestarion, Factory), checkpoint (Replit), acceptance in three layers (Bestarion), change request requiring written approval before work begins (Bestarion).
