## Notes

- Claim 1: strongest independent evidence is the open Sept-2026 feature request (#93753); the earlier `update-all` request (#11676) closed `not_planned` by inactivity bot, and the PR a commenter cited (#11713) shows no sign of landing. The "auto-update off by default for third-party/local" sub-claim rests on a third-party tips page seen only as a search snippet (wmedia.es), which may itself paraphrase the official docs; treat as corroborated, not strongly independent.
- Claim 2: the maintainer's answer predates current docs (2024) but states the same semantics in the maintainer's own words, including the `uv help tool upgrade` text; no disagreement found.
- Claim 3, disagreement on mechanism (not on outcome): the original says packaged apps "cannot write HKLM"; Advanced Installer (and the third-party PowerShell `msix` module's MSIX.Limitations list, search snippet) say HKLM writes are silently diverted into a private per-package/per-user virtual hive, while a Microsoft Tech Community reply (search snippet) says HKLM is "generally not" writable in the container. Both positions agree nothing lands in the real HKLM; they differ on whether the write fails or is redirected. Code that relies on a write *failure* to detect packaging should not. The "no per-user services, session-0 only under system accounts" sub-claim was not settled by an independent publisher within budget: Advanced Installer only says admin rights are needed to install a package with services; the account list (LocalService/NetworkService/LocalSystem) appears only in Microsoft's own schema docs (same vendor as the original).
- Claim 4: PATH behaviour is well corroborated by community reports and an open maintainer-acknowledged feature request. The zip-with-nested-portable "since 1.5" date and `InstallerSha256` required were not independently reached; the wrong 1.5 release tag (servicing release v1.5.1881) was fetched. A follow-up should fetch the v1.5.1572 release notes and a non-Microsoft manifest-authoring guide.
- Claim 5: no source disputes it, but the only third-party page explicitly disclaims the 2.1.89 boundary, and the vendor's own CHANGELOG for 2.1.89 is silent on signing. The per-platform SHA256 `manifest.json` itself is corroborated by a third-party mirror tool (nancheung/cc-releases, search snippet) that verifies downloads against it. The "two newest versions side by side" retention policy has no independent source in this run.
- Budget: 10 tool calls used (1 tool load, 2 `gh api` batches, 5 WebSearch, 2 WebFetch).
