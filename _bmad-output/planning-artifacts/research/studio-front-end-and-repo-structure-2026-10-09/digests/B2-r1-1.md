All versions below were read on 2026-10-09 from the GitHub releases API and the npm registry; all other claims from the pages cited. Budget used: 17 tool calls, 12 publishers.

## Option cards

### PixiJS v8 (plain `pixi.js` in a client component, optionally @pixi/react)
- Current version: pixi.js 8.22.0, 2026-10-01 [https://api.github.com/repos/pixijs/pixijs/releases]; @pixi/react 8.0.5, 2025-12-01, react >=19 [https://registry.npmjs.org/@pixi%2freact].
- Next.js fit: works as a `'use client'` component loaded via `next/dynamic` with `ssr: false` from another client file [https://nextjs.org/docs/app/guides/lazy-loading]; importing on the server fails [https://github.com/pixijs/pixijs/issues/6990]. @pixi/react has an open strict-mode destroy bug (#652) and a stalled commit log since 2026-01-04 [https://github.com/pixijs/pixi-react/issues].
- Phone fit: nearest scaling via `TextureStyle.defaultOptions.scaleMode = 'nearest'` [https://github.com/pixijs/pixijs/discussions/11018]; integer zoom per devicePixelRatio is the practitioner pattern (lead, below).
- Bundle: 237 KB gzip full build measured; 265 KB gzip per Bundlephobia; sub-path imports with `manageImports: false` shrink it [https://pixijs.com/8.x/guides/migrations/v8].
- Asset pipeline: sprite sheets via `Assets.load`, string scale modes, bitmap fonts via `'pixi.js/text-bitmap'` [https://pixijs.com/8.x/guides/migrations/v8].
- Ecosystem: 15 releases/yr, pushed 2026-10-08, 48k stars, MIT [https://api.github.com/repos/pixijs/pixijs]; the React binding is the weak link (2 releases/yr, alpha never promoted) [https://registry.npmjs.org/@pixi%2freact].
- Effort: small for a first scene (scene graph + sprites + ticker); the v7→v8 migration was large (async init, Graphics, Texture) so pin a major [https://pixijs.com/8.x/guides/migrations/v8].
- Licence: MIT, no cost [https://api.github.com/repos/pixijs/pixijs].

### Phaser 4
- Current version: 4.2.1, 2026-07-09; 4.0.0 shipped 2026-04-10 [https://github.com/phaserjs/phaser/releases/tag/v4.0.0].
- Next.js fit: official template-nextjs on Next 15.3.1 / React 19 / Phaser 4.0.0 with an EventBus bridge [https://github.com/phaserjs/template-nextjs]; the game owns its own loop and scene state, React talks to it through events.
- Phone fit: ScaleManager handles resizing, but an open 2025-09 issue reports perpetual refresh once the page scrolls [https://github.com/phaserjs/phaser/issues/7203]; a Phaser canvas inside a scrolling phone layout needs testing.
- Bundle: 352 KB gzip measured (v3.88.2: 314 KB) [https://cdn.jsdelivr.net/npm/phaser@4.2.1/dist/phaser.min.js].
- Asset pipeline: full game toolkit (animations, tilemaps, input, GPU sprite/tilemap layers) [https://github.com/phaserjs/phaser/releases/tag/v4.0.0].
- Ecosystem: 40k stars, MIT, but only 3 commits in the last 90 days and last push 2026-08-21 [https://api.github.com/repos/phaserjs/phaser]; single company (Phaser Studio) behind it.
- Effort: small for a first scene thanks to batteries included; medium ongoing because two state worlds (React and Phaser) must be kept in sync through the bus [https://github.com/phaserjs/template-nextjs].
- Licence: MIT, no cost [https://api.github.com/repos/phaserjs/phaser].

### Godot 4 web export (iframe or custom shell inside the Next page)
- Current version: 4.7.2-stable, 2026-08-18 [https://api.github.com/repos/godotengine/godot/releases].
- Next.js fit: embed via `<iframe>` or custom HTML shell; the generated HTML is overwritten on export; no React interop beyond postMessage/JS bridge [https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html]. C# projects cannot export to web in Godot 4 — GDScript only [same].
- Phone fit: single-threaded export "works very well on macOS and iOS" per docs [same], but iOS Safari crash and memory reports continue into 2026 (#116750 on 4.5.1 / iOS 26.3; #104422 400 MB heap) [https://github.com/godotengine/godot/issues/116750].
- Bundle: engine .wasm ~40 MB raw / ~5 MB Brotli at 4.3 [https://godotengine.org/article/progress-report-web-export-in-4-3/]; docs say it compresses to about a quarter with gzip and recommend precompression [https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html].
- Asset pipeline: the editor the studio already uses; AnimatedSprite2D, tilemaps, pixel snapping (operator's existing knowledge; not re-verified this run).
- Ecosystem: 118k stars, monthly 4.x patch releases, MIT [https://api.github.com/repos/godotengine/godot].
- Effort: small for the scene itself (editor), large for integration: speech bubbles, chat, HUD and modals either live inside Godot or cross an iframe boundary; threaded builds need COOP/COEP that `output: 'export'` cannot set [https://nextjs.org/docs/app/guides/static-exports] — the Bun service would have to add them.
- Licence: MIT, no cost.

### CSS steps() sprite animation / plain DOM
- Current version: web platform; no dependency.
- Next.js fit: ordinary server-renderable React/CSS; no client-only hazards, no dynamic import [https://nextjs.org/docs/app/guides/static-exports].
- Phone fit: DOM layout is responsive by nature; `image-rendering: pixelated` gives nearest-neighbour scaling for background sprites, integer scale factors required for clean pixels [https://developer.mozilla.org/en-US/docs/Games/Techniques/Crisp_pixel_art_look].
- Bundle: zero library bytes.
- Asset pipeline: horizontal sprite strips animated with `background-position` + `steps(n)` [https://blog.teamtreehouse.com/css-sprite-sheet-animations-steps]; no atlas loader, no depth sorting, no camera; bubbles and progress bars are native HTML.
- Ecosystem: the platform; zero regret risk.
- Effort: smallest for the first scene with a handful of agents; grows if walking paths, layered depth or many simultaneous animations are added.
- Licence: none.

### Rive
- Current version: @rive-app/react-canvas 4.36.0, 2026-09-30; rive-wasm 2.44.1, 2026-10-09 [https://registry.npmjs.org/@rive-app%2freact-canvas].
- Next.js fit: React hooks, peer react up to ^19 [same]; WASM is fetched at instance creation (unpkg by default) so it must be self-hosted behind a cookie-gated Bun service [https://rive.app/docs/runtimes/runtime-sizes.md and search-cited preloading docs].
- Phone fit: handles DPR itself; it is a vector/state-machine tool, not a pixel-art pipeline (no evidence found of nearest-neighbour raster scaling).
- Bundle: canvas-lite 222 KB brotli per Rive; 313 KB gzip wasm + 109 KB gzip JS measured [https://unpkg.com/@rive-app/canvas-lite@2.44.1/rive.wasm].
- Asset pipeline: Rive editor; exports now require a paid plan [https://rive.app/blog/new-pricing].
- Ecosystem: weekly releases, MIT runtimes, VC-backed vendor; pricing policy changed in 2025-10 [https://rive.app/blog/new-pricing].
- Effort: medium (learn editor + state machines), ongoing dependency on the editor for every character change.
- Licence: runtime MIT; export seat from $9/month annual ($17 monthly) [https://rive.app/docs/account-admin/pricing].

## Benefits and drawbacks

PixiJS v8 — Benefits: the healthiest JS renderer by cadence (15 releases/yr) [GitHub], smallest capable canvas option (237 KB gzip, shrinkable) [jsDelivr], first-class nearest scaling and sprite sheets [pixijs.com], pure client code so static export is trivial. Drawbacks: must be isolated in a client-only dynamic import [nextjs.org, pixijs #6990]; @pixi/react is effectively unmaintained since January 2026 with an open strict-mode bug [pixi-react issues] — prefer a 40-line `useEffect` bridge over the binding; the v7→v8 migration shows majors can be disruptive [pixijs.com].

Phaser 4 — Benefits: everything a scene needs out of the box, official Next 15 / React 19 template [template-nextjs], MIT. Drawbacks: largest JS payload (352 KB gzip) [jsDelivr]; game-owns-the-page model fights a scrolling phone layout (issue #7203) [GitHub]; renderer just rebuilt in April 2026 with commit activity thin since July 2026 [GitHub] — a single-vendor bet at a transition point.

Godot 4 web — Benefits: the studio's existing editor and pipeline, strongest engine ecosystem [GitHub], single-threaded export needs no special headers [Godot docs]. Drawbacks: ~5 MB Brotli engine floor before any art [godotengine.org]; iOS Safari stability issues still open in 2026 [Godot issues]; no C# on web [Godot docs]; React UI must cross an iframe/JS bridge; threaded mode's COOP/COEP cannot be emitted by a static export [nextjs.org].

CSS/DOM — Benefits: zero bytes, zero risk, SSR-able, bubbles/progress/HUD are native HTML, crisp pixels via `image-rendering: pixelated` [MDN], steps() animation is a few lines [Treehouse]. Drawbacks: hand-rolled depth sorting, movement and camera; many simultaneous animated elements become layout/paint work; no atlas tooling.

Rive — Benefits: polished state-machine animation, React 19 support, MIT runtime, weekly releases [npm, GitHub]. Drawbacks: wrong tool for pixel art; 300+ KB gzip of WASM for canvas-lite [unpkg]; new exports gated behind a paid seat since 2025-10-20 [rive.app]; default WASM from unpkg must be self-hosted behind the session cookie.

Cells that decide between the top two (CSS/DOM vs PixiJS): "Pixel-art asset pipeline" (3 vs 5 — Pixi loads atlases and sorts depth natively [pixijs.com]; DOM is hand-rolled [Treehouse]) and "Bundle size" (5 vs 3 — 0 KB vs 237 KB gzip [jsDelivr]) with "Next.js fit" (5 vs 4 — DOM needs no client-only isolation and avoids the stalled @pixi/react [pixi-react issues]). If the operator raises the asset-pipeline weight above about 30 or expects more than a handful of moving characters, PixiJS overtakes; if the scene stays at a few idle-animated agents with bubbles and bars, DOM wins on every other column. A hybrid (DOM for bubbles/HUD/progress, one Pixi canvas for the floor and characters) keeps the DOM column's Next.js and static-export scores while buying Pixi's pipeline; it costs the Pixi bundle and the client-only wrapper.

- Godot 4.5 dev notes mention "initial C# support for web platforms" (gamefromscratch, dev4) but 4.7 stable docs still say no — track the Godot C# web tracker before planning a C# web build.
- Phaser activity dip after July 2026 (3 commits/90 days) is a single-source signal; re-check the repo in a month before scoring ecosystem health lower.
- Rive "preloading WASM"/self-host docs for cookie-gated hosting: https://rive.app/docs/runtimes/react/preloading-wasm.
