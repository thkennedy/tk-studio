## Notes

- Claim B1.1: Stars (9,603 vs ~9,602), MIT, pushed 2026-10-09, VS Code extension + `pixel-agents` CLI bin, Fastify + WebSocket standalone server, `core/asyncapi.yaml` with generate/validate scripts, and the `AgentEvent` normalisation type in `core/src/provider.ts` are all confirmed from files the originals did not cite. Two reservations: (1) the enum name `AgentActivityStatus` and its `active` member were not reached independently (only `status: 'waiting'` seen in `agentActivityResend.ts`); GitHub code search returned HTTP 403 rate-limit on all five queries. (2) "JSONL fallback" is the digest's wording; the code frames hooks as primary and transcripts (`*.jsonl`) as supplementary input (`transcriptPath` optional, used for teammate-spawn results and token usage), not as a standalone fallback path. Treat "fallback" as loose.
- Claim B1.2: Fully confirmed from package manifests, router registration, WebSocket/broadcast modules, i18n strings and zone layout. `/api/v1` is inferred from `settings.API_V1_STR` (name only; value not printed). `make simulate` was not re-checked (the Makefile was the original's own source). AgentRoom dormancy confirmed by both `pushed_at` and last-commit timestamp (2026-03-05T19:29:41Z); note its licence reads `NOASSERTION`, not MIT.
- Claim B1.3: agent-office figures are exact (687 stars, created 13 days ago). "One floor per repo" is confirmed by floor records carrying `repo`/`dir`/`clone` progress; "cork boards" is the README's phrasing - code calls them "the boards on the walls" (issues board, PR board, services board, task queue, machine monitor). munder-difflin stack, hive `log.jsonl` append-only log and LimeZu tilesets in-tree are confirmed. The negative claim "no precedent renders story or epic progress" was checked only at file-name level across five repo trees (no full-text grep); claude-office's `CommandCenterBoard` shows a todo done/total bar, which is task-level, not story/epic. Keep the negative claim as "not found", not proven.
- Claim B1.4: `TICK = 16` ms is 62.5 Hz, so "60 Hz" is an approximation; 1 s steps, batched ticks per step, ordered input queue with per-input `ok`/`error` return values, and `HistoricalObject` sample history are confirmed from engine source. Not reached: an explicit "diff per step" artefact (game.ts `saveStep` serialises world state via `serializedWorld`; whether that is a diff or a full snapshot was not read). "Single authoritative mutator" is supported structurally (only `runStep` -> `handleInput`/`tick` -> `saveStep` mutate), not by a named invariant in code.
- Claim B1.5: Bearer token in `~/.pixel-agents/server.json` and `/api/hooks` prefix confirmed from `server.ts`, `core/src/constants.ts` and the WS auth tests; the server also writes a multi-server registry at `~/.pixel-agents/servers/<pid>-<port>.json`. Correction of emphasis: port 3100 is only the example in `manual-hook-events.http`; the CLI default is an OS-assigned ephemeral port (`--port` to fix), so an external producer must read the port from server.json, not assume 3100. `SESSION_END_GRACE_MS = 2000` confirmed via test comment. `PERMISSION_TIMER_DELAY_MS 7000` and `TEXT_IDLE_DELAY_MS 5000` were NOT reached independently (not referenced in `hookEventHandler.ts`, `agentRuntime.ts` or the three runtime tests; the test's 5000 is `HOOK_EVENT_BUFFER_MS`, a different constant); those two values rest solely on the cited `constants.ts`. claude-office: 23-member `EventType` union confirmed from the generated frontend types; `EVENT_RATE_LIMIT = 1000` and a 60 s sliding window confirmed, but per-session keying was read only from the ENH-006 design doc (which proposes a separate `EVENT_RATE_LIMIT_PER_SESSION` default 600); whether the live limiter keys 1000/60 s per session or globally was not confirmed outside the cited `events.py`.
- Claim B1.6: `claude agents --json [--all]` is confirmed on the local binary (2.1.286) including a live JSON array; attach/logs/respawn/rm/stop and a hidden `claude daemon` command (run/status/logs/uninstall/stop, "runs on demand") exist. Dubois' third-party writeup corroborates research-preview status, v2.1.139+ and the per-user supervisor but does not mention `--json` or `daemon`. Paperclip's MIT licence and goals -> projects -> issues + approvals + heartbeat_runs (+ heartbeat_run_events) schema are confirmed from Drizzle schema files. paperclip-office's projection matches: state from the latest run status, issue status and pending approvals; "stuck" is more precisely "a live run with no output for N minutes" (default 10). munder-difflin ships LimeZu "Modern Interiors" tilesets in-tree under a split LICENSE-ASSETS note. Reservation for anyone copying that pattern: LimeZu's own page forbids "distribute the asset to others", so a public repo containing the PNGs is in tension with the asset licence regardless of the notice; the digest's claim (that they do ship it that way) stands.
