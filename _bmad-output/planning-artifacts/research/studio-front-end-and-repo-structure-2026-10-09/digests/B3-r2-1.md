## Answers per lead

1. **Hermes Agent.** Enable with `API_SERVER_ENABLED=true` + `API_SERVER_KEY` (required even on loopback) in `~/.hermes/.env` (native Windows data root is `%LOCALAPPDATA%\hermes` per windows-native.md) or `gateway.api_server:` in config.yaml; it comes up inside `hermes gateway` on 127.0.0.1:8642. Auth is one bearer key per profile (`/p/<profile>/` prefixes since the July 2026 change); CORS is opt-in via an explicit allowlist and SSE responses then carry CORS headers. `/v1/capabilities` exposes `auth` and a `features` map (`run_events_sse`, `run_stop`, `run_approval`, `reasoning_streaming`, `session_*` …) plus `endpoints.session_*` — the documented JSON sample is partial, so read the live payload. For a custom UI the two streaming surfaces are `GET /v1/runs/{id}/events` (durable, re-attachable: `message.delta`/`message.interim`, `tool.started`/`tool.completed`, `subagent.*`, `approval.request`, `run.completed`/`run.interrupted`; buffers expire after 5 min; `GET /v1/runs/{id}` for status after navigation) and `POST /api/sessions/{id}/chat/stream` (one-turn SSE: `assistant.delta`, `assistant.commentary`, `tool.started/completed/failed`, terminal `run.*`). `hermes.tool.progress` is a Chat-Completions-only named SSE event, togglable. Adding panels: yes, supported — dashboard UI plugins (tab/page/slot via `window.__HERMES_PLUGIN_SDK__`) and FastAPI backend plugins under `/api/plugins/<name>/`. Embedding Hermes chat in *our* UI: not via the dashboard's Chat tab (it is the TUI over a dashboard-token-authenticated `/api/pty` WebSocket); the supported route is the API server's SSE endpoints, which the docs explicitly aim at "dashboards, browser UIs, or control planes". The PTY contradiction resolves to native Windows support: windows-native.md (2026-10-06) says ConPTY via `pywinpty`, pyproject.toml declares `pywinpty` for win32 as a core dependency, and web-dashboard.md's WSL2-only paragraph is older text no recent commit revisited. No changelog file exists to cite.

2. **Pixel Agents** (`pixel-agents-hq/pixel-agents`, v1.4.1, constants last changed 2026-08-15): `SESSION_END_GRACE_MS = 2000`; `PERMISSION_TIMER_DELAY_MS = 7000`; `TEXT_IDLE_DELAY_MS = 5000`; `TOOL_DONE_DELAY_MS = 300`; `CLEAR_IDLE_THRESHOLD_MS = 2000`; `HOOK_EVENT_BUFFER_MS = 5000`; external-session adopt window 120 s, stale check 30 s, dismissal cooldown 180 s; hook body cap 64 KB; WS close codes 4001/4003. The heuristic timers are fallbacks that are suppressed when CLI hooks deliver events.

3. **Bun hosting.** Serve the Next `out/` tree from the existing Bun service with `routes`: explicit `/api/*` and SSE routes first (precedence is exact > param > wildcard > `/*`), then a `/*` handler that tries `Bun.file(out + pathname)` → `.exists()`, then `pathname + ".html"`, then `index.html`/404 (the `.html` and `index.html` steps are ours to write; Bun has no static-directory option and the community handlers only do file-or-index). SSE: return a `Response` with an async-generator/ReadableStream body and `text/event-stream`, and call `server.timeout(req, 0)` (or set `idleTimeout` appropriately) because the idle timer applies mid-stream; the docs' SSE example implies chunked delivery though they never say "unbuffered". WebSocket proxying is not a Bun feature; it requires a terminate-and-relay (`server.upgrade` + upstream `new WebSocket`) — avoidable if Hermes is consumed over SSE/REST server-to-server.

4. **Tailscale Serve.** Available on Windows: the installed 1.102.4 CLI exposes `serve` with `--https`, `--bg`, `--set-path`, `--service`. TLS is auto-provisioned for the node's MagicDNS name; certificates are 90-day Let's Encrypt and the HTTPS KB only promises automatic renewal for non-file-installed integrations — whether Serve renews on its own is not stated. Path-based fronting of two services under one hostname: the `--set-path` flag exists, but no retrieved page demonstrates two backends on one hostname or two concurrent `--https` ports; validate on the box before relying on it. Simplest proven shape: one Bun origin behind `tailscale serve --bg --https=443 <bun-port>`.

5. **Cookies across ports.** RFC 6265 §8.5 and 6265bis-19: cookies are shared across all ports of a host — a session cookie set by `host:3000` is sent to `host:8642`. `ts.net` is on the PSL (with `*.c.ts.net`), so `Domain=ts.net` is refused, but `Domain=<tailnet>.ts.net` is *not* refused — it is the registrable domain and would leak the cookie to every machine in the tailnet. Use host-only cookies (no Domain attribute) and keep one origin.

6. **iOS Safari EventSource.** The best evidence is the October 2024 Apple forum thread: on iOS 18 a backgrounded (~20 s) SSE connection dies silently — no `error`, `readyState` stays OPEN — whereas iOS 17 fired `error`. No fix was found in 2025–2026 searches, and WebKit's `visibilitychange` has its own long-standing gaps on suspend/kill. Mitigation (community pattern; the Hermes dashboard ships an equivalent for its WebSocket): server heartbeat + client last-event timestamp; on `visibilitychange` (visible), `pageshow`, `focus` and a watchdog tick, if silence exceeds the heartbeat budget call `close()` and construct a new `EventSource`, resuming with `Last-Event-ID`; never trust `readyState`.

## Hosting recommendation (updated)

- One origin: the existing Bun service serves the Next static export and all `/api/*` + SSE routes, and is the only thing fronted by `tailscale serve --bg --https=443 <bun-port>` on the Windows box. One MagicDNS hostname, one auto-provisioned certificate, host-only cookies — this sidesteps both the cookie-port-sharing rule and the `<tailnet>.ts.net` PSL nuance.
- Hermes stays loopback-only on 127.0.0.1:8642 with `API_SERVER_KEY` held by the Bun service; Bun calls `/api/sessions/{id}/chat/stream` or `/v1/runs` + `/v1/runs/{id}/events` server-to-server and re-emits a studio-shaped SSE stream to the browser. No CORS on Hermes, no second browser-facing port, no WebSocket proxy. Read `/v1/capabilities` at startup and gate features on `run_events_sse`, `run_approval`, `session_*`.
- Prefer the Runs API for the studio projection: re-attachable after navigation (`GET /v1/runs/{id}`, events stream), `Idempotency-Key` on submit, `approval.request` surfaced as a UI prompt resolved via `/v1/runs/{id}/approval`.
- Do not embed the dashboard Chat tab; if a terminal-style Hermes pane is wanted later, run the dashboard itself (native Windows is supported per windows-native.md + pyproject) and link to it, or write a dashboard UI plugin for Hermes-side panels.
- SSE hygiene in Bun: `server.timeout(req, 0)` on stream requests, forward Hermes' `: keepalive` (10 s) or emit our own heartbeat, and ship the iOS reconnect watchdog in the client.
- Open before committing: run `tailscale serve --set-path` with two backends on this box to confirm path mounts and cert renewal behaviour; confirm the `/chat` pane actually spawns under native Windows Python on the pinned version.
