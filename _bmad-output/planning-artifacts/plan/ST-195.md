As the owner,
I want the pass held to one open pull request and to a spend ceiling I set, and one plain line each morning that says what the night did,
So that an unattended job can never pile up work I have not looked at or spend past what I allowed, and a night that changed nothing still tells me so.

**Acceptance Criteria:**

**Given** Story 41.1's timed branch and its refusal events, the queue's `accounted` events (the worker's and the engine's `cost_usd` per run), the merge pass's record of a run's PR (`apps/supervisor/src/planstatus.ts`) and the job definition's `stop` fields (`plugins/tk-studio/contracts/job.schema.json:59-60`)
**When** Story 41.5 lands
**Then** two optional stop fields exist, additive, validated in `job.py` and evaluated by the supervisor before a timed mint or a `POST /jobs` of that job: `stop.while_pr_open: true` (no new run while an earlier run of the same job and checkout ended with a PR the merge pass has not recorded merged or closed) and `stop.spend: {window_days: N, usd_max: X}` (no new run while the job's runs in the window sum past `X` by their `accounted` figures, or while any run in the window is unpriced); a hold is one `timer-held {job, reason: "pr-open" | "spend" | "unpriced", detail}` service event per cause, updated in place, with one notifier line when the cause is new ("The nightly hygiene pass is waiting: last night's pull request #N is still open") and one when it clears; `GET /status`'s `timers[]` rows gain `held` with the same words; `maintenance-hygiene.json` carries `while_pr_open: true` and `spend {window_days: 7, usd_max: 60}` as shipped defaults a project's instance may lower or raise (the figure is a question on this plan's PR; the per-run bounds stay the guards: 80 turns, 3600 s of engine, 7200 s of host leg, and band S's size through `check-diff`); the tests pin each hold against a queue fixture, the in-place update, the cleared line, and that a job without the fields is never held.

**Given** a hygiene run's end (the close-out's record, the PR, the host leg's verdict, the metered cost) and the notifier (`apps/supervisor/src/hygiene.ts:274` `notify`, Story 22.3's run hygiene: one notification per terminal run)
**When** a hygiene run ends, by the clock or by hand
**Then** `apps/supervisor/src/night.ts` (new; the name `hygiene.ts` is taken by Story 22.3's run hygiene, which changes only in the line it sends for these runs) records one `hygiene-night {run_id, row, class, verdict: "consolidated" | "skipped" | "nothing-eligible" | "scan" | "failed", reason, pr_url, cost_usd, tokens, lines_added, lines_removed, host_leg_green, model, submitted_by}` service event and the notifier's line for that run is the night's report in a sentence a person reads ("Hygiene, HYG-007 (the four timestamp parsers): one helper in lib/_core.py, 4 files, +38 −112, host leg green, 6.40 USD on Claude Fable 5.2: pull request #N", or "Hygiene: HYG-009 skipped: two callers pass different not-found rules", or "Hygiene: nothing eligible; the scan added 2 rows"); a run with a PR reports the PR and a run without one reports itself, so no night is silent and nothing reaches `main` unseen; `GET /hygiene?project=` (cookie + CSRF, bearer for tools, in `cookieRoute`'s read list) answers the ledger's rows from `hygiene.py list --json` run on the host and the last thirty `hygiene-night` events; `apps/supervisor/test/night.test.ts` pins the event for each verdict, the sentence for each, and the route's shape; the contract names the two stop fields, the two events and the route (0.1.37).
