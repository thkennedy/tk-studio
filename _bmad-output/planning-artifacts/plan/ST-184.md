As the owner,
I want every landed story's time, cost, tokens and loop-health counts gathered from the Stage Logs, the queue, the ledger and git into one store the supervisor keeps current, with the history since Epic 35 read in once,
So that every figure the pages show has one source that is rebuilt from the records, never typed in and never parsed in the browser (addendum §3.4; D9).

**Acceptance Criteria:**

**Given** the Stage Log readers (`plugins/tk-studio/lib/plansync.py:3389-3420` `stage_documents`, `stage_rows`; `report.py:121-206` `rollup`), the queue (`apps/supervisor/src/queue.ts:647-683`; read-only from Python as `tools/verify_host.py:31` reads it), the host ledger (`measurements/README.md`; `jobrun.py:106-129` `job-run` lines), the gate records (`_bmad-output/implementation-artifacts/bmad-build-auto-result-<key>-studio-pipeline.gate-<N>.md`), the specs' `DEVIATION SCORE:` lines and `## Consult Log` entries, the plan entities' `band` and `status`, and `git log --numstat` between a run's `base_ref` and its `ended.closeout.commits`
**When** Story 40.1 lands
**Then** `uv run plugins/tk-studio/lib/analytics.py build --directory ROOT --queue PATH --store PATH [--since ISO] [--backfill] [--json]` (stdlib only, as `report.py`) writes a SQLite store with the tables `stories` (project, story_key, plan_id, epic, band, status, first_start, merged_at, cycle_s, hands_on_s, queue_wait_s, attempts, review_passes, findings_accepted, findings_patched, findings_rejected, deviation_score, consults, halts, guard_trips, host_leg_s, host_leg_first_green, pr_number, pr_files, pr_lines_added, pr_lines_removed, tokens_in, tokens_out, cache_read_tokens (null when unknown), cost_engine_usd, cost_worker_usd, cost_total_usd, route_json, source, built_at), `stages` (one row per Stage Log row keyed by `plansync.stage_row_key`, with run_id, seconds derived), `legs` (one row per suite per `host-verify` event: run_id, story_key, started_at, duration_ms, exit, green, suite, suite_s), `runs` (one row per queue run: enqueued, claimed, launched, ended, state, reason, worker_cost_usd, engine_cost_usd, guard_s, guard_tripped), `changes` (id, at, kind, leg, field, from_value, to_value, by, source, note) and `meta` (built_at, high-water marks per source); a row is upserted by its key, so a second build changes nothing (`--json` reports `rows {inserted, updated, unchanged}` per table); `--backfill` reads everything from the first spec folder (the Stage Log era per stage, the queue era per run, the twelve legacy meter observations of the committed ledger as `source: ledger-legacy` only when `--seed-legacy` is given: addendum §4 choice 3); without it the build reads from the marks in `meta`; a spec, event or ledger line it cannot parse is named in `problems[]` and skipped, never a refusal of the build; the figures match `report.py rollup` for every story that has one (`cycle_s`, `hands_on_s`, `by_stage` sums) to the second and the cent; `plugins/tk-studio/lib/tests/test_analytics.py` builds the store from fixtures cut from the real 38-1 and 36-6 specs, a queue fixture of one run's events and a ledger fixture, pins each table's row for them, the idempotent second build, the `problems[]` line and the rollup agreement, and runs on Windows (every open names `encoding="utf-8"`; paths joined with `pathlib`, the assertions on POSIX-normalised strings).

**Given** the changes the owner will want marked on a timeline: Epic 39's `settings-changed` service events (`queue.ts:2121-2133` `serviceEvents`), the git history of `.bmad-loop/routing.toml`, `.tk-studio/budget-bands.yaml`, `plugins/tk-studio/lib/prices.json` and `plugins/tk-studio/skills/tk-studio-launch/customize.toml` (`git log --format='%H %aI %s' -- <path>` with the TOML diff per leg), the job files' `guards` under `.tk-studio/jobs/`, and the supervisor's own restarts (the `start.ps1` log line, `apps/supervisor/README.md` **Starting at logon**)
**When** the build runs
**Then** `changes` carries one row per settings event (`kind: settings`, the leg, the field, from and to, `by: owner`), one per commit that changed a leg's model or effort, a band figure, a price or a guard (`kind: routing | bands | prices | guard`, `by: commit <sha>`), one per supervisor restart (`kind: restart`), each with its `at`; the Opus 5.5 trial of 2026-09-28 (`f006a3e9`) and the advisor-and-effort change of 2026-10-15 (`81823ad5`) are two of the rows the test pins; no change is inferred from the data itself.

**Given** the supervisor's end-of-run hygiene (`apps/supervisor/src/planstatus.ts:662-698` the supervisor's Stage Log rows, `:849` the `stage-post` event) and its serve start (`api.ts:1282` `serve`)
**When** this story lands
**Then** `apps/supervisor/src/analytics.ts` runs the build verb on the host after each ended run's `stage-post` pass (incremental; a failure is one `analytics-built {ok: false, reason}` service event and a log line, never a change to the run's state), once at serve start when the store is absent (a bounded first build, its progress in the supervisor log), and records `analytics-built {ok, rows, took_ms, backfill}` after each build; the store's path is `TK_SUPERVISOR_ANALYTICS`, defaulting to `analytics.db` beside the queue's file (`C:/agent-work/supervisor/analytics.db` on the box), never a checkout; nothing in `apps/studio-web` reads a spec, a ledger or the store (a test greps the web's sources for `_bmad-output`, `measurements/` and `.db` and fails on a hit); `analytics.test.ts` pins the pass's call, the serve-start build, the failure event and the path rule with a fake verb; the contract names the verb and the event (0.1.36, additive) and `apps/supervisor/README.md` gains **The analytics store (Story 40.1)**.
