As the owner,
I want the settings page to show, beside each leg's model and effort, what the current route has been costing and taking, and a link to the comparison once I have changed it,
So that I change a knob knowing what it does today and find the answer waiting when enough stories have run (addendum §3.2 F-K; the owner's "inform settings").

**Acceptance Criteria:**

**Given** the settings page of Story 39.8 (`apps/studio-web/src/settings/*`; `GET`/`PUT /settings/routing`; the `settings-changed` service event carrying the diff and the actor) and `GET /analytics/stories` and `GET /analytics/changes` (Story 40.2)
**When** `/app/settings` is opened after this story
**Then** each leg's row carries, beside its selects, the line "Last 10 stories on this route: median <stage> 48 min, 14.20 USD, 1.2 review passes (M band; 7 stories)" computed from the stories whose stage rows ran on the leg's current model and effort (the stage per leg from `plansync.STAGE_LEGS`: planner → plan, implementer → dev, reviewers → review and gate, consult → consult; a leg with no stage row, such as `supervise` or `seam`, reads "Not measured per story"), the band named when the window is one band and the mix named when it is not, "No stories on this route yet" when none; a leg changed since the last landed story carries "Changed <n> days ago → compare", linking to `/app/analytics/compare?change=<the settings event's id>`; the figures are read from the API, never computed in the page beyond the median of the rows it is given; the pending state reads "Loading the route's figures…"; `src/settings/model.test.ts` pins the line, the band words, the empty states and the link.

**Given** `PUT /settings/routing` (Story 39.8)
**When** the owner saves a change
**Then** the saved line of 39.8 ("Saved as service event settings-changed at <time>") gains "and marked on the analytics timeline; the comparison opens once 3 stories have run on the new route", and the `settings-changed` event's detail carries `leg`, `field`, `from` and `to` for each changed value (an additive detail the 40.1 build reads; `api.test.ts` pins it); the contract's `settings-changed` paragraph gains the fields (0.1.36, additive); `apps/studio-web/README.md` and `kb/execution-pipeline-model-routing.md` record the feedback loop.
