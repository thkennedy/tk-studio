As the owner,
I want a job that takes the next eligible row, consolidates that one class through the same build, review and host-verify path every story takes, and ends as one small pull request or as a `skip` with its reason,
So that the tidy an engineer would do in passing is done under the studio's own gates, and never as an edit nobody reviewed.

**Acceptance Criteria:**

**Given** the launch verbs (`plugins/tk-studio/lib/launch.py:1827` `start`: `bmad-loop run --project <root> --spec <rel> --run-id <rid>` detached in the run's worktree; `:2036` `sweep` and its refusals), the route step (`pipeline.py apply --directory <root> --story <key>`, `tk-studio-launch`'s first step), the hygiene ledger and `hygiene.py` (Story 41.3), and the supervisor's handling of a launched run (the worktree on `supervisor/run-<id>`, the host verify leg before the close-out's push, the PR with `## Metered cost` and `## Host verify`)
**When** Story 41.4 lands
**Then** `launch.py hygiene --directory DIR [--run-id ID] [--row HYG-NNN]` exists: it refuses, with `sweep`'s wording and blocks, when the project has no policy, no hygiene ledger, a live engine or a dirty tree; it takes `--row` or `hygiene.py next`; when no row is eligible it runs `hygiene.py scan --write`, commits the new rows if there are any, and ends `complete` with `hygiene: nothing eligible` (or `hygiene: scan added N rows`) without starting an engine; otherwise it marks the row `taken` (`tries` + 1), renders a one-story spec in the run's worktree from a template under `plugins/tk-studio/pipeline/` (`_bmad-output/specs/spec-hygiene-<nnn>/` with `SPEC.md`, `stories.yaml` and one plan; story key `hygiene-<nnn>`, band S; the plan carries the row's sites, callers, tests and home verbatim and the rules below as its acceptance criteria), applies the route for that key (so Story 41.2's `hygiene-*` rule decides the legs' model) and starts the engine as `start` does, so everything the supervisor does for a launched run applies unchanged; the engine and the base are not changed and no engine flag is added; `start`'s spawn-and-await block is called, not copied a third time (if this story must touch the copy `sweep` holds, it makes the one helper DW-86 asks for and the ledger row for that class is recorded `consolidated` by this story's PR).

**Given** TKSTUDIO-219's bounds (few callers, covered by tests, nothing dangerous, a `skip` when not safe) and DW-179's (one class, one small PR, no behaviour moved)
**When** the engine builds a hygiene story
**Then** the plan's acceptance criteria are fixed text from the template: one class and only that row; one shared home (the row's `home`, or a new private module beside its first site when `to decide`); no public signature, CLI flag, JSON key, exit code or message text changes; the callers' tests pass unchanged except their import lines; a new test pins the shared home once; if any of these cannot be met the story stops with the verdict `skip: <reason>`, reverts its code changes, and leaves a diff that is the ledger row alone (`state: skipped`, the reason); on success the row reads `consolidated` with the PR's number filled in at close-out; `tools/verify_host.py` runs `hygiene.py check-diff --base <base_ref> --row <row>` for a branch whose spec folder is `spec-hygiene-*` and fails the leg on a path outside the row's set (the subprocess names `encoding="utf-8"`); the PR body gains `## Hygiene` (the row, the class in words, the sites before and after, lines added and removed, the verdict) and the PR carries the label `hygiene`; the pass never merges its PR and never pushes to `main`: the PR is merged on green by the landing routine like any run's, or closed by the owner, in which case `hygiene.py record --state declined --reason` is the one hand step.

**Given** the job shapes (`plugins/tk-studio/jobs/maintenance-evals.json`, `run-sweep.json`) and Story 41.1's `cadence.on_busy`
**When** this story lands
**Then** `plugins/tk-studio/jobs/maintenance-hygiene.json` ships (skill `tk-studio-launch`, payload `{verb: "hygiene"}`, `trigger: cron` with a placeholder schedule the project's instance overrides, `cadence.on_busy: "skip"`, `requires.tier: sbx`, `guards {max_turns: 80, max_wall_clock_seconds: 3600, host_verify_seconds: 7200}`, `stop {on_status: ["blocked"]}`, `model: "claude-fable-5-2"`, `effort: "high"`), undeclared in every project until Story 41.6, so no night starts yet; a hand `POST /jobs {project: tk-studio, job: maintenance-hygiene}` after the hole 90 placement runs one class end to end, and this story's landing docs record that first hand-started run (its row, its verdict, its PR or its skip, its cost) as the story's proof; `test_launch.py` pins the refusals, the nothing-eligible end, the rendered spec for a fixture row and the `taken` mark; the contract names the job type and the verb (0.1.37) and `apps/supervisor/README.md` gains **The hygiene run (Story 41.4)**.
