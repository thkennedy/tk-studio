As the owner,
I want the duplicate classes named in DW-86, and the ones a scan finds later, kept as rows a run can take one at a time, each with its sites, its callers, the tests that cover it and its state,
So that the nightly pass has a backlog that says what is next and why, a class that is not safe is marked skipped with its reason instead of tried again every night, and DW-86 stops being a paragraph.

**Acceptance Criteria:**

**Given** DW-86's `status` line (the classes 36.7 left: the installer's user-env and binary copies in `apps.py` and `doctor.py`, the TypeScript resolver copies in `enginemcp.ts` and `hostverify.ts`, `measurepush.py _file_at_ref` and `promote.py`'s `cat-file`, the `_finish` variants, the differing `_write_atomic`s in `evals.py` and `launch.py`, the e2e `_checkout` copies, the judge validation pair, and the Epic 35 rows: the four ISO-8601 parsers, the leg verdict derived three times, the spawn-and-await copy in `launch.py sweep`, the lease loop inlined twice, the merge-state probes, the marker text), its `decision` line (TKSTUDIO-219) and the shared homes that exist (`lib/_core.py`, `lib/_proc.py`, `src/gitshow.ts`)
**When** Story 41.3 lands
**Then** `_bmad-output/implementation-artifacts/hygiene-ledger.md` (new) carries one `### HYG-NNN: <class in words>` row per class with the fields `source` (`DW-86` or `scan <date>`), `sites` (each `path:line-line`), `callers` (the count and the files), `tests` (the test files that exercise each site, or `none`), `home` (the shared module the one copy would live in, or `to decide`), `state` (`open | taken | consolidated | skipped | declined`), `reason` (for `skipped` and `declined`), `tries` and `pr`; every class of DW-86's remaining list is a row with its sites re-read from the code at this story's base (a line range that moved is corrected; a class already gone is a row in state `consolidated` with the PR that took it), and a test pins that each class named above has its row; the header says in words what the pass may and may not touch, quoting TKSTUDIO-219.

**Given** the ledger and the need for one reader that the run, the supervisor's report and a person all use
**When** this story lands
**Then** `uv run plugins/tk-studio/lib/hygiene.py` (new; stdlib only; every open names `encoding="utf-8"`; paths by `pathlib`) answers `list --directory ROOT [--state S] [--json]`, `next --directory ROOT [--json]` (the first eligible row, deterministically: state `open`, at most `hygiene.max_sites` sites (default 6), every site under `plugins/tk-studio/lib`, `apps/supervisor/src` or `tools`, every site's module with at least one test file in `tests`, `tries` under 2; DW-86 rows before scan rows, then fewest sites, then lowest id; `none` with the count of rows held back per reason when nothing is eligible), `record --row HYG-NNN --state S [--reason TEXT] [--pr URL]` (the one writer of a row's state; atomic write; a `skipped` or `declined` row requires a reason), `scan --directory ROOT [--write]` (finds function bodies in `plugins/tk-studio/lib/*.py` that are identical after `ast` normalisation of names and docstrings, of eight lines or more, in two or more modules, and reports each group as a candidate row; `--write` appends the new ones as `source: scan <date>`, never touching an existing row; TypeScript duplicates enter by DW-86's rows or by hand until a scan for them is worth its cost) and `check-diff --directory ROOT --base REF --row HYG-NNN` (passes only when the diff from `REF` touches the row's sites, their callers' import lines, the row's `home` module, that module's tests and the ledger, adds at most 150 lines and changes at most the files of band S plus the callers; names every path outside that set); `plugins/tk-studio/lib/tests/test_hygiene.py` pins `next`'s order and each hold-back reason, the scan on a fixture pair, the writer's refusals and `check-diff` on a clean and a straying diff, and runs on Windows.

**Given** DW-86 (`status: open`, "this entry's list is that pass's backlog") and DW-179
**When** this story lands
**Then** DW-86's status reads `closed by Story 41.3 (#PR): its remaining classes are rows HYG-001 to HYG-NNN of the hygiene ledger`, with the row ids listed, and DW-179 stays open until the first night (Story 41.6); if the owner answers on this plan's PR that DW-86 should stay open as a pointer, it reads `open: carried as the hygiene ledger's rows` instead and nothing else changes.
