## What went well

1. **The spine held.** Twenty ADs written before Epic 1 were binding through
   Epic 8 without one being reopened. The ruled decisions (O1–O8) were never
   re-litigated; ambiguity during build resolved by citing an AD, not by
   redesigning. The Capability → Architecture Map made "which rules govern
   this story" a lookup, not a judgment call.
2. **Contract-first scaled cleanly.** Every new skill paid a fixed toll —
   conformance manifest entry + driver-contract §2 row + MINOR bump — and the
   toll stayed cheap while making 14 surfaces continuously provable. Pinning
   the contract version in a test (`test_driver_contract.py`) turned "did you
   mean to change the contract?" into a failing test instead of a review
   catch.
3. **Never-silent invariants repeatedly paid for themselves.** The
   duplicate-id sync block (AD-4) caught the BOM corruption incident; AD-3
   write refusal caught machine paths; the auth preflight design meant Jira
   work never produced a silent 401; migration verification blocks partial
   states (AD-16). Each of these fired at least once during the build or its
   verification.
4. **tk harvest was high-leverage.** Migration safety rules (closed
   inventory, no-delete-before-clearance, copy-verify-flag), the issues-ledger
   row discipline, and the detector confidence floor all ported as designs
   from `legacy-council/` without forking any code — harvest-never-commit worked
   as intended.
5. **Session discipline sustained the whole build.** The handoff protocol
   (compact boundary handoff in persistent memory + a self-perpetuating
   resume prompt) carried the project across every session with no replayed
   history and no lost state — the same discipline ST-029 then productized.
6. **Dogfooding was real.** tk-studio planned itself through its own adapter:
   canonical plan files, committed id counter, Backlog.md projection, epic
   closes done through plansync. The 3.2 frontmatter fix and the BOM incident
   were both found *because* the studio was its own first user.

## What was hard / defect patterns

1. **The platform envelope had no conformance teeth.** The cp1252 stdout
   crash (json.dumps `ensure_ascii=False` + Windows console default encoding)
   existed in **every CLI since Epic 1** and surfaced only at Epic 8 close,
   live, while marking the plan done. NFR4 said "Windows-first" but nothing
   asserted it per-surface. Fixed by `16ce449` + the `3ee9117` sweep (all 27
   CLIs guarded) with two-layer regression (`test_utf8_guard.py`: static
   sweep over every CLI module + live cp1252 subprocess round-trip).
   *Lesson: every platform invariant needs a suite-level assertion on day 1,
   not per-story diligence.*
2. **Environment tooling is part of the platform envelope.** PowerShell
   `Set-Content`/`Out-File` writes a BOM that breaks frontmatter parsing on
   canonical plan files; plansync then minted duplicate ids. The AD-4 block
   caught it loudly (good), but the gotcha lived only in one operator's
   session memory (bad). *Lesson: machine-discovered hazards belong in `kb/`
   where every agent inherits them* (actioned below).
3. **Hand-rolled parsing has long-tail edges.** The frontmatter close
   delimiter swallowing the body's leading blank line (`366e01e`) is the
   classic cost of a stdlib-only miniyaml; the compensation — dense edge-case
   tests (`test_miniyaml.py`) — is working, but new edge classes should get a
   test *before* the fix commit next time.
4. **Upstream is noisy in ways lockstep must tolerate.** The very first
   ledger observation: the BMad 6.10.0 installer re-serializes list-valued
   config on `--yes` reinstall, producing cosmetic diffs. Drift checking had
   to distinguish real skew from re-serialization noise.
5. **The measurement loop is built, not yet lived.** FR27–FR30 all shipped
   and pass their tests, but: the repo has never been pushed, so
   measure-push has never opened a real PR, and consolidation has never
   produced a real `ISS-` row from accumulated multi-machine data. The O1
   revision channel is proven by tests, not by operation. This is the
   biggest gap between "done" and "true".

## Team agreements (carried forward)

1. A platform invariant is not "handled" until the conformance suite or a
   regression test asserts it across every surface it binds.
2. Machine/tooling hazards discovered mid-build get a `kb/` entry in the same
   session they are discovered, not just a memory note.
3. Contract bumps stay deliberate: version pinned in a test, bumped in the
   same commit as the contract change, never drive-by.
4. "Done" for a loop-shaped feature (measure → consolidate → fix) means it
   has *run in operation* at least once, not only in tests.
