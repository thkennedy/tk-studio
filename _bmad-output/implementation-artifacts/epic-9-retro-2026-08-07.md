## What went well

1. **"Execution-unproven" was treated as a definition-of-done, and it paid.**
   The planning pass flagged the source lifecycle's back half as
   design-verified but never run end-to-end. Epic 9 made the e2e run a
   conformance drive (`e2e_knowledge.py`: run-init → seed → boundary handoff
   with deltas → wrapper finish → queue → routing doc → gate opens) — the
   studio delivered the run the source never had, and it now re-proves itself
   on every suite pass.
2. **Adversarial review pre-merge kept finding real defects, not style.**
   The chain across this epic: 9.5's orphaned-committed-draft (silent
   permanent loss), 9.6's KeyError-on-hand-repaired-record (a crash the
   code's own guidance invited), the emit concurrency double-emit race, and
   the renumber PR's stale-doc catches. Every must-fix had a concrete failure
   scenario and now has a pinning regression.
3. **Pattern reuse compressed the risky story.** The promotion gate (9.5)
   rode the measure-push membrane shape (stable branch, sanitization
   pre-commit, PR-as-gate, never a base push) — proven git semantics meant
   the genuinely novel parts (promoted baseline, exactly-once emission) got
   the attention.
4. **Two-runner conformance is a defect-finding instrument, not ceremony.**
   The through-connector milestone caught harness lag (its own gap) AND a
   real skill defect the direct suite structurally cannot see: detect's
   SKILL.md let a headless run downgrade the core's exit-0 in-band `ask` to
   `complete` — the second ISS-002-class find in two milestones, both caught
   by machine. The §8 "a conforming driver runs the suite through itself"
   clause is earning its existence.
5. **The v1 retro's team agreements were applied.** Contract bumps stayed
   deliberate (agreement 3: pin + contract + taxonomy moved in one PR;
   ledger.py's un-rowed-event refusal made emission-before-row structurally
   impossible). The loop-shaped features ran in operation (agreement 4: the
   measurement loop produced real ISS rows; the knowledge loop's e2e drive
   runs on every conformance pass).
6. **A mid-close product ruling (pre-1.0 renumber) was absorbed cleanly.**
   Version 1.7.0 → 0.1.7 landed as its own reviewed PR with the mapping
   documented in the change policy, live artifacts swept, history left
   intact, and the consumer re-pinned to the 0.1 line — the old pin was
   verified to refuse the renumbered contract loudly rather than mis-parse.

## What was hard / lessons

1. **The second runner lagged the epic.** Stories 9.2–9.5 added manifest
   drives the through-connector harness could not express (unknown
   `expect: ok`, missing verb surfaces, fixture CLIs outside §2 cores) —
   discovered only when the milestone run failed 5 checks. *Lesson: a story
   that adds conformance drives owes a same-story answer to "can the
   through-connector runner express this?" — direct-only fixtures should be
   classified at authoring time, not at the milestone.*
2. **SKILL.md headless postures are contract surface, and exit-code
   shorthand is a defect generator.** Two ISS-002-class downgrades in two
   milestones (measure-push, detect), both from blanket "complete on exit 0"
   wording over cores with exit-0 in-band refusals. The PR #21 review swept
   all 16 SKILL.mds — the rest are clean. *Agreement below: refusal posture
   is stated per-outcome, never per-exit-code.*
3. **Guarantees drifted toward slogan.** "Exactly once per merged promotion
   PR" overpromised what local-git merge detection can know (two PRs merged
   between emits collapse into one event). Review caught it; wording now
   states the mechanism. *Lesson: state a guarantee as its mechanism plus
   its collapse cases, not its headline.*
4. **Versioning philosophy arrived after seven published bumps.** The
   pre-1.0 renumber is mapped and documented, but `1.1.0`–`1.7.0` exist as
   historical labels a future post-1.0 line could collide with. *Noted for
   the 1.0.0 decision: skip or annotate the colliding range.*
5. **The knowledge loop is proven in sandbox, not yet lived.** Same shape as
   the v1 retro's "built, not yet lived" finding, one level up: spine/seed/
   delta/promotion all pass e2e in throwaway stores, but no real project has
   a spine, no real run has emitted deltas, and no real promotion PR has
   merged. The research-ecosystem job instance (weekly burns, operator
   decision) is the switch that turns this from proven to lived.
