# Studio web renderer spike (Story 30.1, 2026-10-19)

> Retired by Story 30.7: the placeholder sheet and its script are gone; see [studio-web-assets.md](studio-web-assets.md).

The first code of the studio web (design spec §6.3, D5): `apps/studio-web`, a Vite plus React plus
TypeScript nested studio project, draws a floor of tiles and one character from the placeholder sheet
`apps/studio-web/public/sprites/placeholder.png` (our own pixels, D6, generated by
`apps/studio-web/scripts/make-placeholder.ts`) on one PixiJS v8 canvas, with a React DOM HUD over it
showing the zoom, the ratio and the frame rate. §10's risk table names a web app as new to the loop;
this spike settles the scaling recipe before the rest of Epic 30 is quoted.

## The recipe

- **Zoom** is device pixels per source pixel, an integer, chosen by
  `pickZoom(ratio, width, height, tile)` (`apps/studio-web/src/renderer/pickZoom.ts`, pure, no Pixi):

  `zoom = max(1, floor(min(width, height) * ratio / (tile * N)))`, with `N = 12` target tiles across
  the container's short side, `width`/`height` in CSS pixels, `ratio` the device pixel ratio.
  Non-finite or non-positive inputs give 1 (never 0, NaN or negative).
- **The scale rule.** The `Application` runs at `resolution = ratio` with `autoDensity: true` (the
  canvas backing store is in device pixels, its CSS size in CSS pixels) and the world container is
  scaled by `zoom / ratio`. One source pixel is then exactly `zoom` device pixels, so a 16-pixel tile is
  `16 * zoom` device pixels, whole by construction at any ratio. Whole-canvas crispness is claimed
  only for the integer ratios 1, 2 and 3: at a fractional ratio (1.25, 1.5) the canvas backing store
  is rounded to whole device pixels and the browser may resample it, unverified. Sprites sit at
  whole source-pixel positions (`col * 16`, `row * 16`).
- **Crisp edges.** `TextureSource.defaultOptions.scaleMode = "nearest"` (and the sheet's source set to
  `nearest` after `Assets.load`), `antialias: false`, `roundPixels: true`. Frames are cut from the
  sheet by `Rectangle` (`scene.ts` `loadSheet`).
- **Resize.** `resizeTo` the container; on a resize, or a ratio change (a `matchMedia("(resolution:
  <ratio>dppx)")` listener, re-armed for each new ratio, catches a move to another monitor with no
  window resize; the renderer is resized at the new resolution), the page re-applies `pickZoom` and
  rebuilds the floor to cover the container.
- **Where.** `createApp`, `loadSheet`, `drawFloor`, `placeCharacter`, `layoutScene` in
  `apps/studio-web/src/renderer/scene.ts`; the HUD in `apps/studio-web/src/App.tsx`. The builders take a
  `Container` and `Texture`s only, so later stories drive them without WebGL (30.4).

The zoom table (tile 16, N 12), pinned by `pickZoom.test.ts`:

| Container (CSS px) | ratio 1 | ratio 2 | ratio 3 |
|---|---|---|---|
| desktop 1920×1080 | 5 (80 device px per tile) | 11 (176) | 16 (256) |
| iPad landscape 1180×820 | 4 (64) | 8 (128) | 12 (192) |
| iPad portrait 820×1180 | 4 (64) | 8 (128) | 12 (192) |

The short side then shows 12.3 to 13.5 tiles across the grid (at least 12, a little more where the
integer floor rounds the zoom down).

To run it: `cd apps/studio-web && bun install --frozen-lockfile && bun run dev` (on the iPad, `bun run
dev --host` and open it over the tailnet, in landscape and in portrait). Record per ratio whether the
floor seams and the character's outline are crisp, single-pixel steps with no blur or uneven pixel
widths, and the HUD's zoom and ratio.

How the desktop reaches each ratio, with the browser's own zoom at 100%: set the operating system's
display scaling to 100%, 200% and 300% (Windows Settings > Display > Scale, custom scaling for 300%
if the list stops short), or use a monitor whose native ratio is that value. The CSS container is then
the screen's size divided by the scale, so a 1920×1080 monitor at 100%, a 3840×2160 one at 200% and a
5760×3240 one at 300% all exercise the desktop 1920×1080 row (zoom 5, 11, 16); other monitors give
other container sizes, read from the HUD. Browser zoom (Ctrl +) also changes the ratio, but it shrinks
the CSS container by the same factor: 200% browser zoom on a 1920×1080 ratio-1 monitor is ratio 2 in a
roughly 960×540 container (zoom 5, not 11), so it checks crispness at that ratio but not the table's
row.

## The frame cost of the canvas idle

Not recorded: no browser in the headless run. To read it: open the page, leave it idle for ten
seconds, and read the HUD's `fps` (`app.ticker.FPS`, sampled each second); the frame cost is
`1000 / fps` ms at the display's refresh cap, and a browser profiler's frame timings give the busy
share of each frame.
