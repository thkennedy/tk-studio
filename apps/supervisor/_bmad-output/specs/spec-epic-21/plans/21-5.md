## Intent

The studio's guards are data (`job.schema.json` `guards`, `stop`, `cadence.hint_seconds`), and the executing wrapper must enforce them (contract §4: "Budget guards and stop conditions terminate a run `partial` with the guard named in `reason`"; `jobrun.py account` "the executing wrapper MUST call each iteration and MUST obey"). Today the supervisor enforces wall-clock only through stand-ins. The `wake`/`submit` verb timeout is `jobGuardS + 120`, and the skill invocation runs under the capped `guardS`. The POSIX kill reaches only the direct child (DW-1), `account` is never called, and the pacer reads the studio's `status`, not the queue. This story adds a named wall-clock guard with a real process-tree kill (host and sbx), turn/token accounting through `account` after each worker iteration, and a pacer driven from the queue db that records `stop.on_status` in `events`.

## Acceptance Criteria

1. **AC1:** Given a run past its `max_wall_clock_seconds`, when the guard trips, then the worker's whole process tree is killed and the run finishes `partial` with the guard named in `reason`.
2. **AC2:** Given a job with `max_turns` or `max_tokens`, when the worker completes an iteration, then `account` is called with the turns and tokens read from the worker's transcript, and a tripped guard ends the run `partial` naming it.
3. **AC3:** Given a self-paced job with `hint_seconds`, when the pacer ticks, then the job is woken only after the hint has elapsed since its last run ended, and never while a run of it is `queued` or `running`.
4. **AC4:** Given a job whose `stop.on_status` matches a run's terminal status, when that run ends, then the job stops recurring and the stop condition is recorded in `events`.

Replan notes in `stories.yaml` (they bind):
- DW-1: on POSIX the timeout kills only the direct child. This story owns the process-group fix and closes DW-1 in `deferred-work.md`.
- The pacer reads `queued`/`running` from the queue db (`TK_SUPERVISOR_DB`). It keeps the tick's start-of-tick recovery and its counts (`StartError` refused, lock wait/already-running skipped).
- The named wall-clock guard replaces the stand-ins: the `wake`/`submit` verb timeout (guard + 120 s) and the capped skill invocation. With 21-6 this also covers DW-3.
- `stop.on_status` goes into the queue's `events` table. `finishArgsFor` and `knowledgeOf` in `tick.ts` are unused.
- (21-4) On sbx the worker runs as `sbx exec <sb> env -u ANTHROPIC_API_KEY -C <vm-root> claude -p …`. A host tree kill stops only `sbx exec`, so the guard must also end the in-VM worker (argv only, no shell) or name the survivor. Turns/tokens for sbx come through the VM or the JSON result's usage. The tier is on the queue run.

## Risks and open decisions

- **Block If** ending the in-VM sbx worker needs a shell, an interpolated prompt or a pattern kill. HALT naming it; do not fall back to `bash -lc`. The in-VM GNU `timeout` wrapper is the argv-only candidate; record it as a DRIFT (score 2, affects 21-6) if chosen.
- **Block If** the worker's transcript cannot be located from `session_id` on the host (no file, or several). Do not guess counts. Decide between a named `account` failure and the JSON result's `num_turns`/`usage`, and escalate that choice through the consult; it bends the AC's "read from the worker's transcript". For sbx the transcript is inside the microVM. Reading it through `sbx exec <sb> cat …` (argv) or the result's usage is a recorded DRIFT either way.
- A core job's wall-clock is enforced by `jobrun` inside `wake`, and the supervisor's +120 s is only a backstop. Its end path is `cancel` (reason `cancelled`), because 21-1 AC5b forbids `finish` on a core run. Naming the guard on a backstop trip is done on the **queue** run's reason and events, never with `finish` on a core run. If AC1 cannot hold for core runs without `finish`, HALT and consult.
- `detached: true` on win32 opens a new console for the child. Keep it POSIX-only, or 21-4's console hosting regresses.
- "Iteration": a skill run is one `claude -p` invocation today, so `account` runs once per invoke, before `finish`. Do not add `--max-turns` or any other worker flag to stand in for the guard (the supervisor enforces; AD-14 forbids choosing for the worker).
- `account` refuses a run that is not resumable. Call it before `finish`, never after. A failed `account` call is named in the finish reason and never swallowed.
- The stop event: the studio's `wake` already refuses a stopped job, so the pacer must not mint a queue run only to see `not-woken`. Skip it in the tick from the queue's recorded stop event and log the condition. `run`/`submit` by hand still go through the studio's refusal. Do not change `jobrun` (AD-2).
- DW-3 (a worker outliving a killed supervisor) stays with 21-6. This story only makes the tree kill real, so do not touch `Queue.recover` ownership.
- README :130 and the `tick.ts` header comment describe the stand-ins; update both.
