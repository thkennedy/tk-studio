## Intent

The ClaudeOS driver that ran studio jobs was retired on 2026-09-26. Its four files are lifted into this repo as a Bun/TypeScript library and CLI, with their ClaudeOS coupling stripped and the salvage defects this story owns fixed. Those defects are the host bypass default, auth proven by `claude --version` or an API key, and raw registry and job-file reads. When the story is done, the operator can wake one job, invoke it headless, and finish it from the command line. No queue, guards, or tiers yet: Stories 21.3–21.6 add those.

## Acceptance Criteria

1. **AC1:** Given the four source files at the tag, when they are lifted, then the repo carries them with their provenance (tag, path, commit) in its README, `js-yaml` as the only runtime dependency beyond Bun, no ClaudeOS registration, watchdog, or driver-name residue, and no machine path in any tracked file (AD-15): the studio root, store, and plugin root resolve from the environment.
2. **AC2:** Given the worker invocation, when the lifted code builds the `claude -p` command line, then the host default permission mode is `auto`, a bypass request on the host is refused with a named error before any process starts, the `permissions.deny` list in `~/.claude/settings.json` applies untouched, and the worker's environment never carries `ANTHROPIC_API_KEY` (ruling 3: the Max login pays).
3. **AC3:** Given the auth preflight, when the Max login is absent or expired, then the run ends `blocked` naming the missing login — never a silent 401, and never passed on the strength of `claude --version` alone.
4. **AC4:** Given a job id for a registered project, when it is submitted, then the project is read through the contract's registry read path and the job through the `resolve` verb (0.1.12), never from raw `.tk-studio/jobs/*.json` files.
5. **AC5:** Given a declared one-shot job whose target is the read-only `tk-studio-activate` surface (the story adds it to this repo as `.tk-studio/jobs/studio-health.json`), when it runs `wake` → invoke → `finish` from the CLI, then the status block is captured from the worker's JSON output, `finish` records it, and a `job-run` event lands in the agent PC's ledger.
6. **AC5b:** Given the shipped core-target `maintenance-conformance` job, when the supervisor wakes it, then `wake` runs the core itself and ends the run (no worker session, no `finish`), and the supervisor records the run's outcome from `status`. (Corrected 2026-09-28 in tk-studio#78 after this launch found the contradiction.)
7. **AC6:** Given the repo's test suite, when `bun test` runs, then command-line building, status-block extraction (the last balanced JSON object with string `status` and `intent`), and the missing-block case (a named conformance failure, AD-11) are pinned and green.

## Risks and open decisions

If the new or rewritten non-lifted lines grow past about 300, or the Files list grows past the list above, halt and record it.
- **Block If: the staged lift source is missing or altered.** If `.bmad-loop/cache/claudeos-salvage/PROVENANCE.txt` is absent, or any file's `git hash-object` differs from its recorded blob SHA, HALT `blocked` with `lift source unverified: <file>`. Never reconstruct the files from memory or from the salvage notes.
- **Block If: a `claude` CLI flag is missing.** The Max-login check must use a real signal, such as `claude auth status` or an equivalent non-billing probe. If the installed `claude` CLI exposes no such command, HALT rather than infer auth from `--version` or a paid call.
- **Out of scope here:** SQLite, locks, tiers, sbx, guards, the pacer, resume, and fixing `conformance.ts` or the tick. Those files are lifted unchanged, and their known defects belong to Stories 21.2–21.6.
