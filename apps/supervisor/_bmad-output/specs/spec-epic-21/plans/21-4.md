## Intent

Much of this story already exists after 21-1 to 21-3: the host command line, model and effort flags, and `total_cost_usd` into `finish`. What is missing is the **tier**. Each run chooses host or sbx, taking the tier from the submission or the supervisor's own per-job config and never from the plugin (AD-2). The tier is stored on the queue run so a later `drain` or tick drives it the same way. The sbx worker runs inside a Docker Sandboxes microVM through `sbx exec`, and bypass is permitted only there. Submission-level model and effort overrides are forwarded verbatim (§5, AD-14). Live legs (console hosting, the first sbx run's §3.5 checks) are `unverifiable-here` and get exact operator commands.

## Acceptance Criteria

1. **AC1:** Given a run on the host tier (the default; the tier comes from the submission or the supervisor's own per-job config, never from the plugin — AD-2), when the worker starts, then `claude -p` runs under the Max login with `--permission-mode auto` (or `acceptEdits` when the job asks), `--output-format json`, the deny list untouched, and the process console-hosted in the logged-on session — never a headless Task Scheduler spawn (runbook §8).
2. **AC2:** Given a run on the sbx tier, when the worker starts, then it runs inside a Docker Sandboxes microVM, where bypass is permitted; a bypass request on the host tier is refused before any process starts and the run ends `blocked` naming the refusal.
3. **AC3:** Given model and effort from the resolved job or the submission, when the worker starts, then they are forwarded verbatim as contract §5 specifies; the supervisor never chooses a model (AD-14).
4. **AC4:** Given the worker's JSON result, when the run ends, then the status block is extracted, `total_cost_usd` is passed to `finish` (Epic 20), and a missing block ends the run with a named conformance failure (AD-11).
5. **AC5:** Given the first sbx-tier run on the agent PC, when it completes, then the two runbook §3.5 first-run checks are recorded: bypass works inside the microVM, and `~/.ssh` and cloud-credential folders are not visible inside it.

Replan notes in `stories.yaml` (they bind):
- AC2's "the run ends `blocked`" means the submission is refused `blocked` with no run minted (exit 2).
- The prompt stays one argv item after `-p`, never stdin or a shell.
- `deny_profile` must be an absolute path. It is forwarded as `--settings` and never widened.
- The tier is stored on the queue run and re-checked at drive time.
- `finish` takes `studio_run_id`.

## Risks and open decisions

- **Block If** `sbx exec` cannot pass the prompt as one argv item without a shell (the replan forbids a shell: injection risk). HALT naming it; do not fall back to `bash -lc` with an interpolated prompt.
- **Block If** the sbx worker's cwd or mount mapping (host `C:\GitHub\<p>` to VM `/c/GitHub/<p>`) cannot be derived from the registry root and the sandbox name alone. HALT, and don't hard-code a path (AD-15).
- The per-job config is a design choice this plan makes: `TK_SUPERVISOR_CONFIG`, keyed by `<project-id>/<job-id>`. If the dev session finds a better seam, record it as a DRIFT at score 2 (Epic 22's `POST /jobs` `tier` and 22.3's `start.ps1` consume it).
- "`acceptEdits` when the job asks": `job.schema.json` has no such field, so "asks" means the submission's `--permission-mode` or the per-job config. Never infer it from the plugin.
- sbx default mode: `auto`, the same as the host. Bypass inside sbx only when requested (escalation is deliberate, AD-14). Record it as DRIFT if changed.
- **Console hosting (AC1).** `runProcess` spawns with `windowsHide: true`. On win32, libuv may map that to `CREATE_NO_WINDOW` (no console), which is close to the Task Scheduler condition that hangs `claude -p` (runbook §8). Check this on the agent PC before claiming AC1. If the host worker needs a console, change only the worker spawn and keep `uv`/`taskkill` hidden. Record it as DRIFT.
- The queue schema has no migration. New nullable columns on an existing file need an `ALTER TABLE … ADD COLUMN` guarded by a `PRAGMA table_info` check, or the README's recreate note (21-3 precedent). Prefer the guarded `ALTER`, and record it as DRIFT.
- Timeout or kill of an `sbx exec` host process may not stop the VM-side worker. 21-5 owns the tree kill, and DW-3 covers survivors. Name it under Risks in the Auto Run Result; do not solve it here.
- Band L. If the Files list grows past 10, halt and record `oversize`.
