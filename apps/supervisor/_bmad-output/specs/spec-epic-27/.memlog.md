- (constraint) The supervisor is the only starter of work and owner of every engine's life; the queue is the only way a run starts.
- (constraint) A run never switches the project checkout's branch; each run works in its own worktree under TK_SUPERVISOR_WORK; never a junction into the checkout.
- (constraint) Agent work arrives PR-only: never force-push, never merge; a default-branch base_ref is refused when the branch is unprotected on GitHub.
- (constraint) Engine holding is console-hosted: never from a Claude desktop-app session.
- (constraint) In-VM kills go through sbx exec with argv only, never a shell, and target the recorded pid's process group.
- (constraint) The host verify command comes from the project's tracked .tk-studio/config.yaml, never from the plugin (AD-2).
- (constraint) Close-out never re-implements a story; escalate or missing verdict always stays human.
- (constraint) Every behaviour is pinned in the supervisor suite on both hosts (Windows host + Linux engine) with fakes for gh, sbx and the engine.
- (constraint) Operator preconditions: the supervisor tab is stopped from the console before the loop builds the supervisor (single-checkout decision 2026-10-06); the supervisor sandbox is recreated with the read-only skills mount, WITH_BUN=1, and a second read-write mount of TK_SUPERVISOR_WORK so worktrees are visible in the microVM.
- (constraint) Repo: every story lands in the supervisor repo; only the runbook rows (s3.8, s4) land in tk-studio, which the engine sandbox mounts read-only.
- (decision) Non-goals: changes to the driver contract or plugin; the planning adapter status verb and meter.py harvest themselves (Epic 26, tk-studio); auto-merging PRs; re-implementing a landed story on close-out; the live acceptance on the-universe-awaits itself (Story 23.3, only re-planned); exposure or auth changes to the API beyond the resume route.
