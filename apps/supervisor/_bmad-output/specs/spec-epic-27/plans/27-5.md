## Intent

The plan index under-reports what is built (hole 18), and the supervisor's ledger still holds the queue's honesty debts: cost lost across resumes (DW-15), cancel races (DW-12, DW-13), kept locks the pacer ignores (DW-11), a slow win32 worker record (DW-19), a certificate that never renews (DW-21) and a refused `finish` that overwrites the worker's reason (DW-23). This story makes the supervisor call the owning project's planning adapter (`plansync.py status`, Story 26.5, at `$TK_STUDIO_ROOT`, operator-decisions §1) when a run's PR opens (`review`) and merges (`done`), and pays those entries. The replan notes add three restart cases: the orphan close-out with its pin release (DW-25), and a resume in flight across a restart (DW-29).

## Acceptance Criteria

1. **AC1:** **Given** a run that opens a PR **When** the `ended` event is written **Then** the supervisor calls the planning adapter's status verb (Story 26.5) on the project that owns the plan (the registry names it; a transcribed epic names its owner) for every story the run's spec marked done, setting `review`; the next tick that sees the PR merged sets `done`; both are recorded on the run's events, and a refused call never changes the run's state
2. **AC2:** **Given** a run resumed after a restart **When** it finishes **Then** `run.json`'s `total_cost_usd` is the sum across every iteration (per-iteration cost recorded as `accounted` events; DW-15)
3. **AC3:** **Given** a cancel racing a claim or a late studio-run record **When** both happen **Then** the cancel ends the studio run it finds on a re-read inside the end transaction, or the next recovery ends it, and no run is left unended (DW-12, DW-13); an ended run that keeps its lock counts as live for the pacer (DW-11)
4. **AC4:** **Given** the worker record on win32 **When** it is written **Then** the pid lands before the start time, and the start time is read natively (`GetProcessTimes` through `bun:ffi` or an equivalent that takes under 50 ms), so a supervisor killed inside the window still leaves a usable record (DW-19)
5. **AC5:** **Given** the TLS certificate and a refused `finish` **When** the certificate is within 14 days of expiry, or a skill run finished itself **Then** the keeper renews the certificate and restarts `serve` once, outside a live run, with an event (DW-21); and a refused `finish` on an already-terminal studio run leaves the run's reason as the worker's own status-block reason, never the refusal text (DW-23)
6. **AC6:** **Given** the supervisor's test suite **When** the story closes **Then** every case above is pinned on both hosts, the deferred-work entries are closed with their evidence, and the runbook §4 names the new events and the certificate rule

## Settled shape

The gate's write surface excludes `SPEC.md`, so these rulings live here only (as 27-3's did).

- **Owner of the plan.** Read the run project's `_bmad-output/planning-artifacts/epics.md` frontmatter at the run branch. When `status: transcribed` and `source` starts `<org>/<repo>`, the owner is the registry entry keyed `<repo>`; otherwise it is the run's own project. An owner absent from the registry, or with no `_bmad-output/planning-artifacts/plan/`, records one skipped event per phase, with the reason (`owner <repo> not in the registry`), and calls nothing.
- **Story id.** ST id = the owner plan's single `ST-*.md` whose frontmatter `source` is `epics.md#story-<N>.<M>`, N.M from the spec key. None or several → a skipped event for that story (`no plan entity for story N.M` / `several plan entities for story N.M`). Ids are deduped per run (a `-r<n>` remediation spec maps to its story).
- **Stories the run marked done.** Spec files changed in `git diff --name-only <base_ref>...supervisor/run-<run_id>` (run in the checkout, argv only) that `findSpec` would resolve and whose frontmatter at the run branch reads `status: done`.
- **Event kind `plan-status`**, one per story per phase, through `queue.note`: `{phase: "review"|"done", pr, owner, directory, story_key, id, ok, previous_status?, error?, blocked?, skipped?, reason?}`. `--caller tk-studio-supervisor`; `--note "run <run_id> PR <url>"` (one line). A refusal or a non-zero exit is `ok:false` with the verb's `error`/`reason`; it never changes state and is never retried for that phase.
- **When.** A pass after `closeOutPaused` in all three `finally` sites. Review: terminal runs, not external, with a worktree recorded, whose PR is on `ended.detail.pr`, else the latest `closed_out.detail.pr`, and that carry no `plan-status` `review` event. Merge: runs with a `review` event and no `done`/closed record; `gh pr view <pr> --json state,mergedAt`; `MERGED` → the `done` calls; `CLOSED` → one `plan-status` `{phase:"done", skipped:true, reason:"pr closed unmerged"}` and stop; `OPEN` or a `gh` failure → nothing recorded, try next tick.
- **Cost per iteration.** `accounted` events gain `cost_usd` (the iteration's worker cost, as `finishRun` sums it). `finishRun` seeds its sum from the run's recorded `accounted.cost_usd` (all iterations, never counting `launched` events), so a resumed run's `finish --total-cost-usd` is the whole sum. Engine runs: the close-out records the archived engine's metered cost (`meteredCost` read before `archiveStep`) as an `accounted` event `{cost_usd, engine_run_id, source: "engine"}`; the final close-out's cost is the sum of engine `accounted` costs plus the latest engine's `meteredCost` (fallback: that iteration's worker cost, as today).
- **Cancel re-read.** `Queue.end` takes the studio run id and the owner the cancel acted on; inside its transaction it re-reads both. A different `studio_run_id` is returned to the caller, which ends it with `studioRunEnder` after commit and records `studio-run-ended {studio_run_id, late: true}`. A different, live owner keeps the run lock for that driver (DW-12's rule). Recovery: a terminal `cancelled` run whose `studio_run_id` reads non-terminal through `jobrun status` is ended by the same ender on the next `recoverQueue`, with the same event.
- **Pacer.** `pacing().live` also counts a terminal run that still holds a `run` lock (the `releaseKeptLocks` query).
- **Orphan close-out.** After `recover` orphans a worktree run, a pass in `recoverQueue` takes it with `takeEndedCloseOut` once `closeOutBlocker` is null and the engine probes dead (`engineAliveAfterKill`; for a run whose latest move is `engine-resume`, the resumed engine's pid). It calls `closeOut({paused:false, …launchedCloseOutInput})` with no verify (the 27.4 leg never runs on an orphan), records `closed_out`, then `releasePin` (DW-25). DW-29: `recover` does not orphan a run whose latest move is `engine-resume` while that engine probes alive; `respawnHolds` re-holds it.
- **Worker record order.** `setWorker` splits: the pid (and `worker` event) commit first, the start time is written after it by a second update (`worker_start`). On win32 `processStartTime` uses `bun:ffi` `kernel32` `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)` + `GetProcessTimes` + `CloseHandle`, formatting the creation FILETIME exactly as PowerShell's `ToString('o')` UTC (`yyyy-MM-ddTHH:mm:ss.fffffffZ`, 7 fractional digits), so records written by either path compare equal. The PowerShell read stays only as the fallback when the FFI load fails. One `src/winproc.ts` holds the FFI.
- **Certificate.** `serve` checks the cert's `notAfter` (`node:crypto` `X509Certificate`) on each tick. When it is within 14 days, no run is `running` or `external`, and no `cert-renew-requested` is recorded in the last 24 h, it records `cert-renew-requested {cert, not_after, days_left}` and exits with code 75. The keeper, on 75, runs the same bounded `tailscale cert` block (a function shared with the main script) and restarts `serve` at once, without back-off. On the next start `serve` records `cert-renewed {not_after_before, not_after}` or `cert-renew-failed {not_after}`. These supervisor-scope events go to a new `service_events (seq, at, kind, detail)` table, since `events.run_id` is NOT NULL.
- **Refused finish.** The queue run keeps the worker's status-block reason. The refusal goes on a `finish-refused {error, actual_state}` event, and `studio_outcome` carries the actual state as today.
