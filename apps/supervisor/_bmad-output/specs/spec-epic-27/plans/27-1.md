## Intent

Today a run works directly in the registered project checkout. `runJob` claims the checkout lock, then calls `wake` and `claude -p` with `directory = root`, so two loops can share a tree and a run can switch the branch under the running service (hole 16). This story cuts a git worktree per claimed run from the submission's `base_ref`. It materialises the engine's untracked runtime there by the studio's own motions and points the worker and engine at the worktree. When the engine ends, it pushes the run branch and opens a PR against `base_ref`. It supersedes Story 23.2. The checkout itself is never switched.

## Acceptance Criteria

1. **AC1:** **Given** a submission with `base_ref` **When** the run is claimed **Then** the supervisor creates `git worktree add <TK_SUPERVISOR_WORK>/worktrees/<project>/<run_id> -b supervisor/run-<run_id> <base_ref>` from the project checkout, refuses a `base_ref` that is the repository's default branch when that branch is not protected on GitHub (`blocked`, naming it), and records the worktree path on the queue run; the checkout itself is never switched
2. **AC2:** **Given** the untracked runtime the engine needs in a worktree (`_bmad/` at the pin, `.bmad-loop/policy.toml` and `routing.current.json`, the project's local config overlay) **When** the worktree is prepared **Then** the supervisor materialises them by the studio's own motions (`tk install` at the pin inside the worktree; the policy and routing files copied from the checkout; never a junction into the checkout), `tk activate` is clean inside the worktree, and the engine's `--project` is the worktree
3. **AC3:** **Given** a run that launched an engine **When** the engine completes, pauses, or is stopped **Then** the supervisor pushes the run branch and opens a PR against `base_ref` whose body carries the launch status block, the engine run id, the landed commits and the metered cost, records the PR URL on the `ended` event, opens no PR when no commit landed ("no changes" recorded), never force-pushes and never merges; the worktree is removed after the PR opens unless the run is paused (a paused run keeps it for the resume)
4. **AC4:** **Given** the supervisor's test suite on the Windows host and the Linux engine **When** it runs **Then** worktree creation, the unprotected-base refusal, the runtime materialisation and the PR body are pinned against a fake `gh` and a real throwaway repository, and the live acceptance on the-universe-awaits (Story 23.3) is re-planned against this story

## Risks and open decisions

- **Oversize.** The plan expects 8 files and well over 300 new lines. That is past band M and at the top of L. Do not split it here. If the Files list grows past these 8, HALT and record it, so the story goes to `bmad-correct-course`.
- **Block If: when the `ended` event is written.** AC3 puts the PR URL on the `ended` event, but today `ended` is written by `mirror` when the launch skill returns, long before the detached engine ends. There are two readings:
  - (a) defer a launch run's end until its engine ends, with the run staying non-terminal while the engine holds the lock. This changes the pacer and DW-11 semantics that Story 27.5 owns.
  - (b) keep `ended` at launch end and record the PR on a follow-up event linked to it.

  Do not choose alone. This is a CONSULT on "two readings of the story".
- **Block If: a submission without `base_ref`.** The title says every run gets a worktree, but AC1 is stated for a submission with `base_ref`. Do not choose alone (CONSULT) between three options: default `base_ref` to the repo's default branch (which then meets the protection refusal), keep the old in-checkout path, or refuse.
- **Block If: the lock key.** The checkout lock (`checkoutKey(root)`) stays per checkout in this story. Making it per worktree would allow concurrent runs per project and is not asked for. Keep it and record it.
- The sbx tier only sees the worktree if the operator has added the second read-write mount of `TK_SUPERVISOR_WORK`. A worktree whose VM path is not visible must end the run `blocked` naming the precondition, never fall back to the checkout.
- `unverifiable-here`:
  - win32 worktree paths and long-path behaviour.
  - Real `gh` against GitHub branch protection.
  - The sbx mount, which only the operator's Windows host can show.
  - The re-plan of Story 23.3. That lives in tk-studio's canonical plan, which the engine mounts read-only, so it is not this repo's change. Record it as a hand-over line.
