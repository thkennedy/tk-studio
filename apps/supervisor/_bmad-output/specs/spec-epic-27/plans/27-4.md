## Intent

An sbx-tier run's engine runs on Linux in the microVM, so Windows-only defects reach branches unless an operator runs the suite on the host before each PR (holes 11, 12, 22). This story makes that the supervisor's job: when an sbx-tier engine completes, the supervisor runs the project's own `verify.host` command (from its tracked `.tk-studio/config.yaml`, never from the plugin, AD-2) on the host, in the run's worktree, under a host-tier worker's guards, and records a `host-verify` event before the PR opens. A red verify ends the run `partial` naming the command, still pushes, opens the PR as a draft carrying the failures, and the notification names them; no `verify.host` records a skip with its reason.

## Acceptance Criteria

1. **AC1:** **Given** a project's tracked `.tk-studio/config.yaml` with `verify.host: <command>` (tk-studio: the lib suite and conformance; the supervisor: `bun test`; the-universe-awaits: its verify script) **When** an sbx-tier run's engine completes **Then** the supervisor runs that command on the host tier in the worktree, console-hosted, under the same guards as a host-tier worker, and records its exit, duration and the last lines of output on a `host-verify` event; the command comes from the project's config, never from the plugin (AD-2)
2. **AC2:** **Given** a red host verify **When** the PR would open **Then** the run ends `partial` naming the failing command, the branch is still pushed, the PR opens as a draft whose body carries the host failures, and the notification names them
3. **AC3:** **Given** a project with no `verify.host` **When** a run ends **Then** the PR opens as before and the event says the leg was skipped with the reason
4. **AC4:** **Given** the supervisor's test suite and the runbook **When** the story closes **Then** green, red and absent commands are pinned on both hosts, and runbook §3.8 retires the "attended host run before each PR" rule in favour of this leg

## Settled shape

Planner rulings. The gate's write surface excludes `SPEC.md` (gate.md Rules), so they live here only, and no `SPEC.md` bullet was appended.

- **`verify.host`** (tracked `.tk-studio/config.yaml`, an operator writes it for tk-studio and the-universe-awaits, operator-decisions §4): optional entry — `verify: {host: "<one command line>"}`, a non-empty string. It is split into argv on whitespace, with `"…"` or `'…'` grouping and backslashes literal (Windows paths); never run through a shell, so no `&&`, pipes or redirection. A `.sh` script is written `bash scripts/verify.sh`. A missing key or `verify` block: skipped `no verify.host`; any other type or an empty string: skipped `verify.host is not a non-empty string`.
- **Where the command is read:** `git show <base_ref>:.tk-studio/config.yaml` in the checkout (`run.root`), never the worktree, so the run's own commits cannot change or remove the verify that judges them. Absent at the base: skipped `no .tk-studio/config.yaml at <base_ref>`; unparseable: skipped `config unreadable: <error>`.
- **When it runs:** on the sweep's main path, when the engine ended on its own (`st.phase === "ended"`, not paused, not `killed`) and the worktree exists. `run.tier === "sbx"` runs it; any other tier is skipped `host-tier run: the worker ran on the host`; a gone worktree is skipped `worktree gone`. Exactly one `host-verify` event per completed-engine close-out, written before `closeOut`. A pending record replayed by a later sweep never re-runs it.
- **`host-verify` detail:** ran: `{command, argv, cwd: <worktree>, exit: number|null, duration_ms, guard?: "guard: max_wall_clock_seconds (<n>s)", error?: <spawn error>, green: boolean, stdout_tail: string[], stderr_tail: string[]}`, each tail the last 20 lines, each line clipped to 300 chars with URL userinfo redacted (the `clip` rule). Skipped: `{skipped: true, reason}`. Green means exit 0; a timeout, a spawn failure or any non-zero exit is red.
- **Red:** state `partial`, reason `host verify red: \`<command>\` <exited <n> | timed out (<guard>) | failed to start: <error>>; last lines: <the last 5 stderr lines, else stdout, joined " | ">`. This overrides whichever end the sweep computed (`launched.end` or `engineEndState`) for `ended` and for `finishStudio`. The push happens as before; a new PR is `gh pr create --draft`; an existing PR (the paused run's draft, 27.1/27.3) skips `gh pr ready` and gets `gh pr edit <pr> --body-file <file>` with the regenerated body. The worktree is removed as for any ended run.
- **Green or skipped:** the PR opens or is marked ready exactly as today; the body's `## Host verify` section says green (command, duration) or skipped (reason).
- **This repo's own key:** `.tk-studio/config.yaml` gains `verify:\n  host: bun test` (operator-decisions §4).
