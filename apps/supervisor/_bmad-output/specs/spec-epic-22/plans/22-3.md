## Intent

The supervisor must come back after every reboot of the agent PC. It must be console-hosted in the studio account's session: never a "run whether user is logged on or not" task, and never started from a Claude desktop-app session (MSIX AppData virtualization; runbook §3.5, §4). The run hygiene the box needs is built in: an editor-in-the-loop snapshot before a flagged Godot run, a notification on every terminal run, and a per-run transcript copy. Add `start.ps1`, and have the supervisor do the snapshot, notify and backup steps itself. The operator dispatch (DW-5, DW-10) also makes the CLI end-to-end suites runnable and green on win32, the production host.

## Acceptance Criteria

1. **Given** `start.ps1` in the repo **When** it runs **Then** it reads the bind address and token from the user environment, starts the sbx daemon from `$HOME` when it is not already running (so the "Docker Sandboxes daemon" sign-in task can later be retired by the operator), and starts the API and the pacer
2. **Given** the logon path **When** the story hands it over **Then** the operator receives the exact command for the `shell:startup` shortcut (`wt.exe -w studio nt --title supervisor pwsh -NoExit -File <repo>\start.ps1`, runbook §4); nothing registers a "run whether user is logged on or not" task, and nothing starts the supervisor from a Claude desktop-app session
3. **Given** a run flagged as editor-in-the-loop on a Godot project **When** it is about to start **Then** a `robocopy /E` snapshot (never `/MIR`) of the project lands in the work folder and its path is recorded on the run
4. **Given** any terminal run **When** it ends **Then** a notification goes out (ntfy or Telegram, chosen by the environment) naming the run, its status, its reason, and its PR when there is one, and the run's session transcript is copied to the backup folder (the nightly task remains the catch-all)
5. **Given** a reboot of the agent PC **When** auto-logon completes **Then** `curl -H "Authorization: Bearer <token>" http://<tailscale-ip>:<port>/status` from another device answers

## Risks and open decisions

- **Oversize.** The Files list is 11 entries. That is well past the L band's intent (5 files / 300 lines), and it plainly exceeds the largest band. Per the planning rule the story is not split here. **Halt** and record it if the Files list grows past these 11. The operator may split it (for example start.ps1 + win32 e2e / snapshot / notify + transcript copy) through `bmad-correct-course`.
- **The pacer interval and drain cadence** are not in operator-decisions.
  - Use a `start.ps1` parameter with a stated default, not a new environment variable, and record a DRIFT.
  - **Block If** driving API-submitted runs needs a new long-lived CLI verb or a change to the tick's scope (for example ticking non-self-paced jobs). That changes what the operator observes; `drain` on the loop is the existing path.
- **Recover once before the first tick (21-6 note).** Every tick and every `drain` already recovers at start (`recoverQueue`), and concurrent recoverers are safe by design (README :71). `start.ps1` runs `bun src/cli.ts recover` (or `drain`) once before starting the loop. Do not remove the tick's own recovery.
- **The notification end hook.** Ends happen in several processes: the drain/tick drivers, and `serve` for API cancels. They also happen inside `writeEnd`'s transaction.
  - Two approaches:
    - Hook every end call site.
    - Sweep: terminal runs with no `notified` event, after each end and at start. The sweep survives a crash between the end and the send.
  - **Block If** the sweep would notify runs that ended before this story shipped. Bound it, for example to ends after a recorded baseline, and never flood the operator with history.
  - Never send inside a transaction.
- **"Its PR when there is one."** No PR field exists. Take a GitHub pull-request URL from the status block's `artifacts[]`; otherwise omit it. **Block If** the story would need a new status-block field or a contract change (AD-2: the contract is tk-studio's).
- **sbx transcripts** live inside the microVM, and the nightly task never sees them.
  - Copy host-tier transcripts.
  - For sbx, record in `events` that the per-run copy was skipped (VM-resident).
  - **Block If** copying out of the VM needs a new `sbx` command shape beyond `sbx exec`.
- **Credentials (NFR5).** The Telegram token sits in the Bot API URL. Never log the URL, never put it in an event or an error, and never pass it to `start.ps1` output. The API token likewise.
- **`start.ps1` and the environment.** It reads the variables from the User scope: `[Environment]::GetEnvironmentVariable(<name>,'User')`, falling back to the process value. A shortcut-launched `wt` may predate a later `setx`.
  - Missing `TK_SUPERVISOR_BIND`/`TOKEN` fail loudly, naming the variable and never its value. `serve` already refuses with named errors.
  - Keep the tab open (`-NoExit`). Never `Start-Process -WindowStyle Hidden` a worker (runbook §8, console hygiene).
- **Win32 e2e fakes.** A `.cmd` shim is spawned differently from an `.exe` (Bun/Node `spawn` of a `.cmd` without a shell). If `runProcess` cannot exec a `.cmd` worker without `shell: true`, do not add `shell: true` to production spawns. **Block If** win32 enablement needs a change to the production spawn path; record that under DW-5.
- **Never** register a scheduled task, never use `/MIR`, and never start or test-start the supervisor from a Claude desktop-app session (AC2; runbook §3.5).
- **Out of scope:** the runbook text itself (Story 22.4, tk-studio kb), retiring the sbx sign-in task (the operator's), DW-15 (resumed-run cost), and any change to the 22.1/22.2 routes beyond the submit field.
