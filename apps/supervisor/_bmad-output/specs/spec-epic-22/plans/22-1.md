No plan was written for this story at bootstrap: the spec folder had no `plans/`, and the dev session built from the story section and the spec's own Code Map. The studio gate created this file to hold the story's acceptance audit.

## Acceptance — 2026-09-28

- AC1: met — `src/api.ts` `checkBind`/`serve` and the `src/env.ts` getters. `test/api.test.ts` "bind, port and token (AC1)" pins `0.0.0.0`, addresses outside `100.64.0.0/10`, a missing token and a bad port. The `serve` verb exits 2 without binding and without printing the token. The real tailnet bind is unverifiable-here: the operator runs `curl -H "Authorization: Bearer $TK_SUPERVISOR_TOKEN" http://$TK_SUPERVISOR_BIND:8787/status` from another device.
- AC2: met — `test/api.test.ts` "auth (AC2)": 401 on every route, unknown paths included, with the token never echoed. The token is absent from captured output and is stripped from worker env (`src/server.ts` `buildWorkerEnv`, pinned in `test/command-line.test.ts`).
- AC3: met — `test/api.test.ts` "POST /jobs (AC3)" plus the real-path block (unknown project/job, `TierRefused`, a valid submit with `base_ref`). A valid submit goes through `submitProject` → `submitJob` → `enqueue` and answers with `run_id` and `studio_run_id`. Malformed JSON and schema errors get 400.
- AC4: met — `test/api.test.ts` "read routes (AC4)" and "cancel (AC4, AC5)". `/jobs`, `/runs/{id}`, `/status` and `/events` (JSON and SSE) all answer from the queue. Cancel ends the run `cancelled` through `Queue.end`. A launched engine gets `launch.py stop --graceful`, whose argv is pinned by a fake `uv`.
- AC5: met — pinned: auth refusal, malformed JSON, unknown project, unknown job, double cancel (409 `RunTerminal`). Gate re-run by this session: `bun test` 470 pass / 0 fail, `bunx tsc --noEmit` exit 0.
- Unverifiable-here: the tailnet smoke `curl` from another device (above). The real-process kill and `launchStopGraceful` tests are skipped on win32.
- Verdict: accepted
