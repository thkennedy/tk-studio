## Intent

The operator wants to see at a glance what the box is doing, and the studio plugin grows no UI (contract §7 row 6: the supervisor's status page is the consumer that carries UI). Add one server-rendered HTML page, with no JavaScript and no client framework, to the 22.1 HTTP API's handler. It uses the same bind and the same bearer check. It reads the queue, the per-user store (`run.json`, `handoff.json`, this machine's ledger tail) and the registry's published read path. It writes nothing.

## Acceptance Criteria

1. **Given** the status page **When** it is requested **Then** it is served on the same bind and behind the same auth as the API, with no client-side framework, and it reads well at phone width
2. **Given** the page **When** it renders **Then** it shows the queue (jobs, and runs with state, reason, and cost), the latest status blocks, run workspaces (`run.json`, `handoff.json`), the tail of this machine's ledger file, and the registry's projects
3. **Given** any page route **When** it is exercised in the test suite **Then** it is a GET that writes nothing to the queue or to `~/.tk-studio`, and it renders no credential-shaped value (NFR5)

Dispatch notes (stories.yaml, binding):
- 21-6: show `held` runs and ended runs that keep a lock. Show a run's resume count and its cost summed across resumed iterations. Wrap long reasons; never cut them.
- 22-1: read kept locks through `Queue.locks()`/`LockRow`. Show a deadline only where one exists. Render `worker-kill`/`lock-released` as stored.

## Code Map

- `src/api.ts`, the 22.1 handler, is where the page plugs in.
  - `createApi(deps)` :127 returns the request handler. `authorized(req)` runs first, at :260, for every path. The route dispatch starts at :267.
  - Add the page route there so it inherits the same auth and bind. Keep the `allow()` 405 pattern (:266) for a non-GET.
  - `status()` :170 already builds `counts`, `live` and `locks` (via `queue.locks()` and `holderOf` :108). Reuse `holderOf`, and export it or move it beside the page code. Do not re-derive it.
  - `redact` :146 strips the API token from text. The page needs a broader redaction (see Risks).
  - `ApiDeps` :55 is the injection seam. Add optional page deps (store root, registry reader, clock) so tests run without `uv` or a real store.
  - `serve()` :297 needs no change beyond what the deps require.
- `src/queue.ts`, read-only use only:
  - `runs()` :668, `get` :664, `jobs()` :682, `events(runId?, since?)` :673, `locks()` :693 (`LockRow` :484), `lock(root)` :724.
  - `resumeCount(runId)` :1094 is the resume count.
  - `isTerminal` tells an ended run that still keeps its lock.
  - `recordedWorker(run, false)` :767 gives the sbx in-VM `deadline` (`WorkerKill.deadline` :541). Call it only with `kill=false`: `true` kills.
  - Telling kept locks apart:
    - A `LockRow` with `kind:"run"` whose run is terminal is kept.
    - On sbx with a recorded worker, it is kept until the deadline.
    - With no worker recorded, it is kept for its live driver (`driverLive`, 22-1). It has no deadline.
  - A `held` run appears in `RecoverReport.held` and as events, not as a state. Show a run whose lock is kept, plus its `recovering`/`worker`/`worker-kill`/`lock-released` events as stored.
  - Never call `claim`, `recover`, `end`, `drain` or `enqueue` from the page.
- `src/server.ts`:
  - `registryShow()` :65 is the registry's projects through `registry.py show` (the published read path, never the registry file). It spawns `uv`, so inject it for tests. A failure renders as a section message, never a 500.
  - `readProjectConfig(root)` :735 reads `project_id`.
- `src/cli.ts` :267 `projectIdOf(root)` is private. It computes `project_id ?? basename(root)`, the studio's project key rule (contract: the run workspace is `~/.tk-studio/projects/<key>/runs/<run-id>/`; the key is that id through `safe_name` = replace `[^A-Za-z0-9._\-]` with `_`). Export it or reuse `readProjectConfig`; do not copy plugin code.
- The store root is `TK_STUDIO_HOME` when set, else `homedir()/.tk-studio`. `src/queue.ts` :131 already reads it that way. `src/env.ts` says it never reads TK_STUDIO_HOME, so either add a getter there (one env surface, AD-15) or keep the read local and say why.
- The per-user store files, all read-only:
  - `projects/<key>/runs/<studio_run_id>/run.json` holds `state`, `reason`, `status_block`, `started`/`ended` and `total_cost_usd` (contract §4 `finish`; the supervisor already sums iterations before `finish`, `src/cli.ts` :1416). This is the queue run's cost.
  - `handoff.json` sits in the same workspace (contract `tk-studio-session`: 16 KB max). It may be absent.
  - The ledger is `measurements/<user>-<machine>.jsonl`.
    - `<user>` is Python `getpass.getuser()`: env `LOGNAME`, `USER`, `LNAME`, `USERNAME`, then the account name.
    - `<machine>` is `platform.node()`, the hostname.
    - Both go through `safe_name`. Read only the tail (last N lines, from the file's end), never the whole file.
- "Latest status blocks" are the `status_block` of the most recent studio runs' `run.json`, newest first.
- Test patterns:
  - `test/api.test.ts` :36 `fixture()` is the temp-queue plus `createApi` pattern.
  - `test/queue.test.ts` :18-40 `fakeProbes`.
  - Use a temp `TK_STUDIO_HOME` tree with hand-written `run.json`, `handoff.json` and ledger lines.

## Risks and open decisions

- **Band L, oversize risk.** There are 4–5 files; the renderer plus the test suite likely exceed 300 new lines. If the Files list grows past these five, halt and record it rather than widen the story.
- **Phone browsers cannot send a bearer header** from the address bar. AC1 says "behind the same auth as the API", so build exactly that. **Block If** the story would need a second auth scheme (a cookie, a query-string token, Basic auth, a login form) for a stock browser. That changes what the operator observes and is the operator's decision. Record the limitation in the Auto Run Result under unverifiable-here instead.
- **Credential redaction (NFR5).** Never copy `classify.py`'s patterns: the house rule is no plugin internals (AD-2). Write the supervisor's own redaction:
  - the API token and every `TK_SUPERVISOR_*TOKEN*` value from the environment
  - values under credential-named keys (`token`, `secret`, `password`, `api_key`, `authorization`, `credential`, case-insensitive)
  - `Bearer <x>`
  - common key-shaped strings
  
  Apply it after HTML escaping has been decided on the raw text, and before rendering.
- **Writes nothing.** `Queue.open` may run migrations, but it runs once at `serve` and never per request. The page must not call a verb that writes: `registry.py show` and `recordedWorker(…, false)` only. **Block If** a needed datum is reachable only through a writing verb.
- **Missing or unreadable store files** (no `studio_run_id`, no workspace, bad JSON, no ledger file) render as a short note in that section, never a 500 and never a thrown page.
- **The ledger user name.** Node's `os.userInfo().username` can differ from `getpass.getuser()`. Resolve it in getpass order. If no file matches, name the path tried (store-relative, never an absolute machine path).
- **Out of scope:** no `start.ps1`, notifier or snapshot (22.3). No write route, and no change to the 22.1 JSON routes' answers.
